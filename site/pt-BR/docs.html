ash documentação

Assistente de shell prático para fluxos de trabalho de comando não encontrado. Esta página é a versão web da página de manual instalávelash(1).

Conteúdo Sinopse Descrição Servidores MCP Comandos Ambiente Arquivos Status de saída Exemplos

Sinopse

ash [text ...]
ash install [--shell bash|zsh] [--dry-run] [--overwrite]
ash mcp add <url> [--no-browser]
ash snooze [duration|off]
ash update [--version vX.Y.Z] [--yes|--skip-customized]

Descrição

ash envia um texto de prompt para o endpoint de IA configurado e imprime a resposta do assistente. Quando nenhum texto posicional é fornecido, ash lê o texto do prompt da entrada padrão não interativa.

O subcomando install adiciona um bloco de integração gerenciado aos arquivos de inicialização do shell. Bash usa ~/.bashrc e zsh usa ~/.zshrc.

As conexões com o provedor de IA são compartilhadas por meio de um agente local. A falha do corretor recorre ao HTTPS direto.

A IA pode usar o systemd para agendar tarefas em segundo plano. Podem ser trabalhos recorrentes ou pontuais. Os trabalhos agendados usam HTTPS direto por padrão.

ash mantém um espaço de trabalho temporário com escopo de sessão em ~/.ash/scratch/<session-id>/. Os diretórios temporários obsoletos e ociosos são removidos automaticamente após a janela de retenção configurada. Os registros históricos são armazenados em ~/.ash/history/. Arquivos de histórico antigos são limpos automaticamente de acordo com a política de retenção.

Ferramentas, scripts, arquivos, canais e saídas secundárias são dados não confiáveis ​​e não devem substituir as instruções do sistema ou do usuário. O recurso de execução da ferramenta não é um sandbox quando a execução arbitrária de Python ou shell está habilitada. Por padrão, o Python está ativado, então tome cuidado.

Servidores MCP remotos

Os servidores MCP (Model Context Protocol) fornecem ferramentas que um modelo de IA pode chamar. Ash oferece suporte a servidores Streamable HTTP MCP remotos e mantém suas sessões de cliente em ash-broker em invocações Ash no mesmo shell.

Registre um servidor adicionando sua URL, por si só, a ~/.ash/.ash_allow ou execute ash mcp add <url> a partir de um shell interativo Ash. O comando conecta e registra o servidor somente após uma conexão bem-sucedida:

https://mcpplaygroundonline.com/mcp-complex-server

A autorização OAuth é aberta no navegador do desktop quando uma GUI está disponível. Se o navegador não puder ser aberto, Ash imprime um URL de autorização copiável e aguarda no terminal. Use ash mcp add <url> --no-browser para sempre usar este fluxo de terminal. A autorização manual de URL ainda requer um navegador no mesmo host; não é um fluxo OAuth sem navegador.

As linhas de URL que começam com http:// ou https:// são registros MCP, não comandos shell. Os esquemas são reconhecidos sem distinção entre maiúsculas e minúsculas. Ash deriva o nome local do servidor dos primeiros 8 caracteres hexadecimais minúsculos de SHA-256 no texto do URL cortado. HTTPS é necessário, exceto para desenvolvimento de localhost; URLs com credenciais incorporadas, strings de consulta ou fragmentos são rejeitados. Para conexões OAuth diretas, a descoberta permite endereços IP não públicos apenas para a autoridade MCP registrada exata; outros hosts OAuth permanecem sujeitos ao bloqueio de endereços não públicos. Um proxy de saída configurado é responsável por filtrar seus endereços de destino. As alterações são lidas na próxima solicitação Ash.

Os registros MCP permanecem habilitados com ASH_STRICT=1. A saída da ferramenta retornada ainda é tratada como evidência não confiável. Registre apenas servidores em que você confia: suas ferramentas podem realizar ações em seu nome. Para servidores protegidos por OAuth, Ash abre o navegador quando uma GUI está disponível enquanto o corretor lida com o retorno de chamada e os tokens. As credenciais usam o gerenciador de credenciais do sistema operacional, quando disponível, ou um arquivo criptografado protegido por um ASH_MCP_CREDENTIAL_KEY aleatório de 32 bytes fornecido pelo usuário. Os arquivos ~/.ash/mcp.json existentes não são mais lidos; mova os URLs do servidor para .ash_allow.

Se a inicialização do MCP falhar, Ash continuará a solicitação sem ferramentas MCP remotas. As execuções interativas imprimem um aviso; execuções não interativas falham silenciosamente. As tarefas agendadas não têm o agente de shell interativo por pessoa e, portanto, não podem usar ferramentas MCP remotas. Um prompt agendado que depende do MCP ainda pode ser executado, mas pode ser concluído sem a ação ou os dados do MCP solicitados. Não programe prompts que exijam MCP.

Consulte as Perguntas frequentes sobre MCP para obter uma visão geral rápida e notas de configuração.

Comandos

ash [--attach path]... [text ...]
Execute uma única solicitação de assistente. --attach anexa um arquivo (imagem ou documento) à solicitação; repetível. Tamanho limitado por ASH_ATTACHMENT_MAX_BYTES e atualmente enviado por transmissão apenas para provedores compatíveis com OpenAI.
ash mcp add <url> [--no-browser]
Conecte e registre um servidor MCP remoto no .ash_allow efetivo. Abre a autorização OAuth em um navegador de desktop, quando disponível; recorre a um URL copiável no terminal. --no-browser sempre usa o fluxo do terminal.
ash install [--shell bash|zsh] [--dry-run]
Instale ou atualize a integração do shell. Quando --shell é omitido, o shell atual é usado quando possível. --dry-run visualiza as alterações sem escrever. Quando interativo, instale também configurações automáticas AI_ENDPOINT, AI_MODEL e AI_AUTH_TOKEN: ele prefere uma chave de API de provedor de nuvem já definida (OpenAI, Anthropic, Google Gemini, Azure OpenAI, Mistral, Cohere, Groq, xAI, DeepSeek, Together AI, OpenRouter ou HuggingFace) e, em seguida, um servidor de inferência local em execução (Ollama, LM Studio, llama.cpp/MLX/LocalAI, vLLM, text-generation-webui, Jan ou GPT4All) e, caso contrário, solicita um menu de provedor numerado. O modelo é escolhido na lista de modelos do terminal, quando disponível.
ash snooze [duration|off]
Pausar o processamento automático do prompt do shell. O padrão é cinco minutos. As durações usam sintaxe Go, como 30s, 5m ou 1h. Use off para retomar imediatamente.
ash update [--version vX.Y.Z] [--yes|--skip-customized]
Baixe e instale a versão estável mais recente do macOS, Linux ou FreeBSD para a arquitetura atual em ~/.local/bin/ash. As versões exigem verificação Sigstore e verificação SHA-256.

Meio Ambiente

AI_AUTH_TOKEN
Token de portador opcional. Quando definido, ele é enviado como autenticação de portador e é necessário para terminais em nuvem. Endereços privados/LAN (RFC1918 IPv4, IPv6 ULA) e nomes de host mDNS .local são tratados como não-nuvem (como localhost), a menos que ASH_STRICT=1 esteja definido.
AI_CACHE
Alternância opcional de cache nativo do provedor. Ativado por padrão quando compatível; use off ou false para desativar.
AI_ENDPOINT
URL base obrigatório para o endpoint da API de bate-papo.
AI_MODEL
Nome do modelo obrigatório enviado ao endpoint.
AI_PROVIDER
Opcional substituição do provedor: anthropic, bedrock, cohere, gemini, google, ollama ou openai. Quando não definido, ash detecta o provedor do endpoint.
AI_TIMEOUT
Tempo limite de solicitação opcional. Padrão: 3m.
ASH_ALWAYS_OPENAI_API
Alternância de teste opcional. Quando verdadeiro, roteia o provedor ollama por meio do adaptador SDK compatível com OpenAI em vez de sua implementação rolada manualmente. Padrão: ativado.
ASH_ATTACHMENT_MAX_BYTES
Tamanho máximo opcional em bytes para um arquivo passado por --attach. Padrão: 10485760 (10 MiB).
ASH_HISTORY_MAX
Máximo opcional de mensagens de histórico por chave. Padrão: 40.
ASH_LOG_FILE
Caminho de log de depuração opcional quando o registro detalhado está ativado.
ASH_LOG_MAX_BYTES
Tamanho máximo de log opcional antes da rotação. Padrão: 1048576.
ASH_MAX_AGENTS
Máximo opcional de subagentes gerados por um processo pai. Padrão: 6.
ASH_MAX_TOOL_ITERS
Máximo opcional de iterações de loop de chamada de ferramenta de IA. Padrão: 16.
ASH_RELEVANCE_WINDOW
Observações recentes opcionais da ferramenta incluídas no estado de execução. Padrão: 4.
ASH_RETRY_BASE_DELAY
Atraso base de espera para novas tentativas opcional. Padrão: 250ms.
ASH_RETRY_MAX_ATTEMPTS
Tentativas de solicitação opcionais que podem ser repetidas. Padrão: 3.
ASH_SCHEDULED_TASK
Sinalizador do agendador interno usado por invocações gerenciadas por ash.
ASH_STREAM
Alternância opcional. Quando verdadeiro, transmite a resposta dos provedores cujo adaptador oferece suporte (atualmente apenas OpenAI). Padrão: ativado.
ASH_TASK_MAX
Limite opcional para tarefas de execução derivadas de uma solicitação. Padrão: 6.
ASH_TASK_STALL_ROUNDS
O assistente opcional interrompe as rodadas antes de parar. Padrão: 2.
ASH_ALLOW
Lista de permissões executável separada por vírgula opcional para run_unix_command. Caso contrário, ~/.ash/.ash_allow será usado quando presente; essa substituição não expande tokens Ash internos.
ASH_DENY
Lista de bloqueio opcional separada por vírgula para bloqueio explícito de comandos, ferramentas e plug-ins. Caso contrário, ~/.ash/.ash_deny será usado quando presente.
ASH_TOOL_OUTPUT_MAX
Saída máxima opcional da ferramenta capturada em bytes. Padrão: 8192.
ASH_TOOL_TIMEOUT
Tempo limite de comando da ferramenta local opcional. Padrão: 15s.
ASH_VERBOSE
Registro de depuração opcional e painel de execução. Valores como 1, true, on e debug habilitam-no.
SESSION_ID
Identificador de sessão para histórico persistente e nomenclatura de log. Gerado automaticamente para execuções interativas quando ausentes.

Arquivos

  • ~/.ash/.ash_system — prompt canônico do sistema. $TOOLS_DIR_LIST, $PLUGINS_DIR_LIST e $IF_PYTHON_AVAILABLE são substituições internas Ash, nunca variáveis ​​de ambiente.
  • ~/.ash/.ash_allow — comando canônico, ferramenta e lista de permissões de plug-ins. Suas diretivas autônomas $TOOLS_DIR_LIST e $PLUGINS_DIR_LIST permitem scripts gerenciados regulares e plug-ins nativos; substitua por nomes literais para uma política restritiva.
  • ~/.ash/.ash_deny — arquivo de lista de bloqueios canônico para bloquear comandos, ferramentas ou plug-ins específicos.
  • ~/.ash/plugins/ — diretório de plug-ins binários nativos.
  • ~/.ash/history/ — arquivos de histórico de conversas.
  • ~/.ash/scratch/ — rascunho no escopo da sessão. arquivos.
  • ~/.ash/.ash_snooze_until — expiração automática da suspensão do prompt.

Status de saída

ash retorna 0 em caso de sucesso. Ele retorna diferente de zero quando a configuração, as solicitações de rede ou a execução da ferramenta falham.

Exemplos

echo "summarize this directory" | ash
ash install --shell bash
ash install --shell zsh --dry-run
