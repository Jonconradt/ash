Antes de começar

  1. Um sistema e shell suportados: macOS ou Linux em amd64/x86_64 ou arm64/aarch64, ou FreeBSD em amd64. Use Bash, zsh ou peixe. Os pacotes Arch são apenas x86_64. Não há instalador nativo do Windows/PowerShell.
  2. Acesso para download: uma conexão ativa com a Internet e acesso HTTPS confiável ao GitHub, ao repositório de pacotes selecionado e ao seu provedor de modelo. A inferência local ainda precisa de um download inicial do modelo.
  3. Permissões: um diretório inicial gravável para ativos por usuário. Os pacotes do sistema Linux e macOS .pkg precisam de acesso de administrador; execute Homebrew e ash install como seu usuário normal.
  4. Um modelo: um servidor de inferência local com um modelo baixado ou uma conta de nuvem/chave de API. Escolha um modelo que suporte chamada de ferramenta, não um modelo somente de imagem/áudio. As necessidades locais de RAM, disco e GPU dependem desse modelo.

Os pacotes pré-construídos ash não requerem ferramentas de compilação Go, Rust, Node.js ou Xcode. Um gerenciador de pacotes pode ter seus próprios pré-requisitos; siga primeiro as instruções oficiais de configuração.

Opcional: ferramentas Python incluídas

Básicoasho uso não requer Python. As ferramentas Python incluídas precisam do Python 3 comvenveensurepip, além de acesso para baixar suas dependências. No Debian/Ubuntu, instalepython3epython3-venv; Homebrew Python inclui suporte venv. No FreeBSD, use o pacote pip correspondente à sua versão do Python. Em seguida, execute novamenteash install. A instalação cria um ambiente isolado sob$XDG_DATA_HOME/ash/venv(padrão~/.local/share/ash/venv); uma falha desativa essas ferramentas, não as básicasash.

macOS

Recomendado: cerveja caseira

Pré-requisitos:Cerveja caseira, seu ambiente macOS compatível e um ambiente funcionalbrewcomando. A torneira seleciona o arquivo Intel ou Apple Silicon automaticamente. O Homebrew 6 não confia implicitamente nesta torneira de terceiros. Se o Homebrew se recusar a carregar a fórmula como não confiável, revise o editor e a fórmula e confie apenas nesta fórmula (não na torneira inteira):

brew trust --formula jonconradt/ash/ash
brew install Jonconradt/ash/ash
ash version

Homebrew se lembra dessa decisão de confiança local. A torneira não pode permitir a confiança em seu nome; confiando em toda a torneirabrew trust jonconradt/ashé mais amplo e permite carregar também suas outras fórmulas. Para confiar em Beta ou Nightly, use o nome da fórmula correspondente,jonconradt/ash/ash-betaoujonconradt/ash/ash-nightly. O Homebrew possui os binários, plug-ins nativos, páginas de manual e avisos de licença em seu prefixo (normalmente/opt/homebrewno Apple Silicon ou/usr/localna Intel). Ele verifica o arquivo em relação à soma de verificação SHA-256 da fórmula. Ele não configura seu provedor nem edita seu arquivo de inicialização do shell: continue parainicialização por usuário. Usarbrew upgrade ashpara atualizações ebrew uninstall ashpara remover Liberação; verfórmulas de canalpara Beta/Noturno.

Alternativa: .pkg nativo

Baixe odarwin-arm64.pkgativo para Apple Silicon oudarwin-amd64.pkgpara a Intel de umlançamento publicado.Verifique seu manifesto de soma de verificação assinadoantes de abrir o instalador. É necessário acesso de administrador.

O pacote macOS não é assinado nem autenticado. O manifesto de lançamento fornece verificação separada do editor/soma de verificação, não reconhecimento de firma da Apple. Não desative o Gatekeeper ou ignore um aviso de segurança apenas para instalar ash; prefira o Homebrew se sua política de segurança exigir.

O pacote escreveasheash-brokerpara/usr/local/bin, plug-ins para/usr/local/lib/ash/plugins, páginas de manual para/usr/local/share/mane avisos para/usr/local/share/licenses/ash. O recibo édev.ash.cli. Não instale-o sobre uma cópia de propriedade do Homebrew.

Linux

Use o gerenciador de pacotes da sua distribuição sempre que possível. Esses pacotes possuem/usr/bin/ash,/usr/bin/ash-broker,/usr/lib/ash/plugins, páginas de manual abaixo/usr/share/mane avisos de licença. Eles deixam as configurações do provedor e os ganchos do shell parainicialização por usuário.

Debian e Ubuntu: APT

Pré-requisitos: amd64 ou arm64, acesso de administrador, APT,curl,gpge certificados de CA. Instale ferramentas de download/chave ausentes usando sua distribuição antes de adicionar o repositório. A versão é nomeadastable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Antes de importar qualquer chave de repositório, verifique sua impressão digital em uma fonte de editor confiável. A impressão digital da chave VersionX é32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. O APT verifica os metadados do repositório assinado e os resumos do pacote que ele contém; a chave tem escopo comsigned-by. Atualizar comsudo apt update && sudo apt upgrade ash; remover comsudo apt remove ash.

Sistemas compatíveis com Fedora e RHEL: DNF

Pré-requisitos: x86_64 ou aarch64, acesso de administrador, DNF/RPM,curl,gpge certificados de CA. Instale as ferramentas que faltam na sua distribuição. Inspecione a chave e compare a impressão digital acima antes de importá-la:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

Os arquivos RPM não são assinados individualmente.repo_gpgcheck=1verifica os metadados do repositório cobrindo suas somas de verificação;gpgcheck=0reflete a ausência de assinaturas por pacote, e não a verificação de repositório desabilitada. Se sua política exigir cargas RPM assinadas, este repositório não atenderá. Atualizar comsudo dnf upgrade ash; remover comsudo dnf remove ash.

Arch Linux: Pacman

Pré-requisitos: x86_64, acesso de administrador, Pacman com seu chaveiro inicializado,curl, egpg. Verifique se a impressão digital da chave exibida corresponde à acima antes de confiar nela. Adicione o repositório uma vez, não em todas as atualizações:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman verifica assinaturas de pacotes e bancos de dados. Mantenha o Arch sincronizado comsudo pacman -Syu, não uma atualização parcial; removerashcomsudo pacman -R ash.

Inicializar e verificar

Depois de instalar os binários, execute a configuração interativamente como seu usuário normal. Se não desejar integração com shell, você poderá instalar apenas Ash. Provavelmente não é isso que você deseja. O valor real de ash é a integração do shell abaixo. A configuração somente de ativos deixa seus arquivos de inicialização inalterados:

ash install

A instalação que você provavelmente deseja usar envolve integração com shell. Isso mudará seu .bashrc (ou o equivalente para seu shell) para incluir Ash. Para ativar a integração de comando não encontrado, escolha exatamente um comando para o shell que você usa:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Peixe

ash install --shell fish --shell-integration

Bash usa~/.bashrc, zsh usa~/.zshrc, e peixes usam$XDG_CONFIG_HOME/fish/config.fish(padrão~/.config/fish/config.fish). Abra um novo shell depois; os shells existentes mantêm seu corretor em execução. Pré-anexos de integração~/.local/binpara PATH: remova uma cópia local do usuário antiga antes de esperar que um pacote do sistema seja selecionado.

Se as configurações do provedor estiverem faltando, a instalação detectará as chaves do provedor existentes ou um servidor local em execução; caso contrário, oferece um menu de provedor e solicita credenciais. Escolha um modelo disponível com capacidade de ferramenta. As configurações válidas existentes são preservadas, portanto, executar novamente a configuração não é um comando de troca de provedor.

As configurações são armazenadas em$XDG_CONFIG_HOME/ash/.ash_env(padrão~/.config/ash/.ash_env, permissões de arquivo privado). A integração gerenciada os carrega. Sem integração, os usuários do Bash/zsh podem obter esse arquivo em sua configuração normal de inicialização; Os usuários de peixes devem definir o correspondenteASH_AI_*variáveis ​​​​usando a sintaxe Fish, não originando o arquivo no formato Bash. Proteja qualquer arquivo que contenha tokens e nunca o confirme.

Para uma instalação local do usuário sem integração, adicione seu diretório real ao PATH. Bash/zsh:export PATH="$HOME/.local/bin:$PATH". Peixe:fish_add_path "$HOME/.local/bin". Persista usando a configuração de inicialização do seu shell; substitua seu diretório de instalação personalizado quando aplicável.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

Os primeiros comandos devem resolver a instalação que você escolheu. O prompt precisa de um servidor em execução ou de credenciais de nuvem válidas; instalar ash não instala um modelo.

Ollama local: não é necessária nenhuma conta na nuvem

Você não precisa ter uma IA local para usarash. No entanto, se quiser executar modelos localmente sem depender de um provedor de nuvem, você pode configurar um servidor Ollama local.

Ollama também oferece um serviço em nuvem para executar modelos remotamente, mas não é necessário para uso local comash. O servidor em nuvem inclui um nível gratuito e o modelo de nuvem Gemma 4 31b do Google (gemma4-31b:nuvem) funciona muito bem comash. Este é o modelo utilizado pelo projeto para gerar notas de lançamento e realizar tarefas de devops.

Instale o Ollama usando seuinstruções oficiais do sistema operacional. Inicie o aplicativo/serviço Ollama ou executeollama serveem um terminal separado se um servidor ainda não estiver em execução. No FreeBSD,ashO suporte do não implica um instalador nativo do Ollama: use um servidor acessível em outro host compatível, se necessário.

Baixe um modelo com capacidade de ferramenta adequado ao seu hardware;llama3.1:8bé um exemplo, não um requisito mínimo. Verifique ocatálogo de ferramentas atualpara alternativas:

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

Sem nenhuma chave de nuvem definida, a configuração pode detectar o servidor local e oferecer o modelo baixado. Se outro provedor já estiver configurado, altere manualmente o endpoint/modelo. Exemplo Bash/zsh:

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Equivalente a peixe:

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Essas alterações afetam apenas o shell atual. Persista-os em seu protegidoasharquivo de ambiente ou configuração de shell apropriada, substituindo quaisquer substituições antigas do provedor. Ollama local não precisa de token. Mantenha o servidor em loopback, a menos que você proteja deliberadamente o acesso; um servidor remoto recebe seus prompts e resultados da ferramenta.

Opcional: definirOLLAMA_KEEP_ALIVE=30mnoServidor Ollamaambiente e reinicie o servidor para manter os modelos aquecidos.-1os mantém carregados indefinidamente, mas consome memória entre as solicitações. Definir isso apenas noashterminal do cliente não reconfigura um servidor já em execução.

A inferência local não possui fatura de API do provedor, mas usa seu hardware/armazenamento/eletricidade.Nuvem de Ollamaé um serviço separado com autenticação e limites de plano; não é o mesmo que esta configuração local.

Instalação de script: uma alternativa, não a primeira escolha

Prefira Homebrew, APT, DNF ou Pacman: eles rastreiam arquivos próprios, verificam downloads usando sua configuração confiável e fornecem atualizações/remoções familiares. Eles ainda exigem editores confiáveis ​​e ações de instalação de pacotes.

Um script de site executa código com as permissões da sua conta. Um site, editor ou script alterado pode ler segredos, alterar arquivos ou instalar outro software. HTTPS protege o transporte, não as intenções desse código. Canalizar um URL diretamente para um shell o executa antes que você possa revisá-lo. As verificações de assinatura de arquivo do script não autenticam o script em si. Nunca execute-o com sudo ou desative sua verificação.

Pré-requisitos: um sistema operacional/arquitetura compatível,$SHELLidentificando Bash/zsh/Fish,Fiança Sigstore,tar,uname,install, utilitários de shell padrão, um comando SHA-256 (sha256sum,shasum, ousha256) e um downloader (curl,wgetou Python). O exemplo usa curl. O FreeBSD também precisa do Bash. Seu diretório inicial/instalação deve ser gravável.

Baixe para um arquivo local, inspecione-o com um editor e execute somente se você confiar em sua origem e comportamento. A inspeção não é garantia de segurança; não execute estas etapas cegamente:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

Após a inspeção, execute a cópia salva como seu usuário normal:

sh ./ash-install.sh
rm ./ash-install.sh

install.shbaixa a versão mais recente, verifica seu manifesto de soma de verificação assinado pelo Sigstore e resumo de arquivo e instalaash/ash-brokerem~/.local/bin. Plug-ins nativos desaparecem$XDG_DATA_HOME/ash/plugins. Ele executa a configuração por usuário e pergunta antes de ativar a integração do shell. Sem um terminal interativo, os prompts de provedor/integração podem ser ignorados: executeash installinterativamente depois.

Você pode definirASH_INSTALL_DIRantes de executar o script para escolher outro destino. Adicione esse destino ao PATH você mesmo.A autoatualização é suportada apenas em~/.local/bin; destinos personalizados exigem substituição manual. O script não possui seletor Beta/Nightly.

Verifique um pacote ou arquivo direto

Pré-requisitos: fiança e um utilitário SHA-256. Na mesma versão publicada, baixe seu pacote/arquivo,SHA256SUMS, eSHA256SUMS.sigstore.json. Trabalhe em um novo diretório. SubstituirvX.Y.Zcom a tag exata, incluindo um sufixo de pré-lançamento, se aplicável:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Somente depois disso, calcule o resumo do seu arquivo comshasum -a 256 PACKAGEno macOS,sha256sum PACKAGEno Linux, ousha256 -q PACKAGEno FreeBSD. SubstituirPACKAGEcom o nome do arquivo baixado e compare-o exatamente com a entrada desse nome de arquivo no manifesto verificado. Pare em uma entrada ausente ou em qualquer incompatibilidade. Uma soma de verificação não assinada baixada ao lado de um arquivo não é equivalente aos metadados verificados do editor.

Atualizações e os três canais

  • Liberação (recomendado):versões publicadas estáveis, comovX.Y.Z; configuração do repositório chama issostable.
  • Beta:teste de pré-lançamento, marcadovX.Y.Z-beta.N; espere mudanças e regressões.
  • Todas as noites:alterações recentes na ramificação padrão, marcadasvX.Y.Z-nightly.YYYYMMDD.N; o maior risco de regressão. As compilações são agendadas, mas podem ser ignoradas quando nada muda ou a publicação falha.

Uma versão publicada atualiza a fórmula Homebrew correspondente ou o repositório Linux assinado. Você o recebe quando executa o comando de atualização do gerente proprietário (ou sua própria política de atualização do sistema operacional). A publicação, as atualizações do repositório e a implantação do site podem atrasar umas às outras; verifique a disponibilidade antes de mudar de canal. ash não instala atualizações binárias em segundo plano silenciosamente.

Homebrew: instale ou troque fórmulas

Para uma nova instalação Beta/Nightly, use o nome completo da fórmula correspondente acima em brew install. Ao mudar, primeiro desinstale a fórmula atualmente instalada: todas as três fornecem os mesmos binários. Exemplo, versão beta:

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

Usarash-nightlypara noturno ouashpara Release nos comandos de instalação/atualização. Desinstalar a fórmula real do canal antigo, nem sempreash. As configurações do usuário são mantidas; abra um novo shell após a troca.

Linux: selecione um canal de repositório

APTO:use oConfiguração do APTcom exatamente uma distribuição da tabela. Para mudar uma instalação existente, edite/etc/apt/sources.list.d/versionx.list, substituindostablecombetaounightly(ou de volta parastable), então:

sudo apt update
sudo apt install --allow-downgrades ash

DNF:use oConfiguração DNFcom o URL base selecionado. Para uma instalação existente, substituabaseurlem/etc/yum.repos.d/versionx.repo, mantendo suas configurações de assinatura, então:

sudo dnf --refresh distro-sync ash

Atualizações de versão local do usuário

ash update

Isso verifica e instala uma versão estável somente quando o ativoashexecutável está sob~/.local/bin. Ele também atualiza ativos/plugins agrupados, com opções para arquivos personalizados.ash update --version vX.Y.Zseleciona uma tag estável, não um canal; não é um comando de downgrade. Não há--channelopção. Instalações de gerenciador de pacotes, instalações de .pkg do macOS e destinos de script personalizados devem usar seu gerenciador/instalador proprietário. O FreeBSD Beta/Nightly usa arquivos verificados manualmente, não uma assinatura de autoatualizador. Abra um novo shell após a atualização.

Desinstale sem remover arquivos não relacionados

1. Desative a integração do shell primeiro

Antes de remover os binários, execute o comando para cada shell onde você ativou a integração:

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Peixe

ash install --shell fish --disable-shell-integration

Seashjá está faltando, edite o arquivo de inicialização relevante eminicializaçãoe remova apenas o bloco entre# >>> ash install >>>e# <<< ash install <<<. Remova qualquerash-linhas PATH/ambiente específicas que você adicionou manualmente, e não configurações de shell não relacionadas. Fecharash-enabled shells posteriormente para que seus corretores de propriedade do shell saiam.

2. Deixe o gerenciador de pacotes proprietário remover seus arquivos

Homebrew (lançamento)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

Escolha apenas o seu método de instalação; para Homebrew Beta/uso noturnoash-beta/ash-nightly. APT/DNF/Pacman remove binários, plug-ins e páginas de manual de propriedade do pacote, não a configuração/histórico do seu diretório inicial. Não exclua manualmente os arquivos de propriedade do pacote.

Limpeza opcional do repositório: remova oasharquivo de origem/etc/apt/sources.list.d/versionx.liste é dedicado/etc/apt/keyrings/versionx-keyring.gpg, ou oasharquivo de repositório/etc/yum.repos.d/versionx.repo, ou oash [versionx]seção de/etc/pacman.conf. Primeiro verifique se nenhum outro pacote os utiliza. Remova uma chave confiável RPM/Pacman importada somente após confirmar sua impressão digital e que nada mais depende dela; nunca exclua o chaveiro compartilhado de uma distribuição.

3a. Remoção manual do macOS .pkg

O instalador do macOS registra um recibo, mas não temashdesinstalador. Confirme se esta é uma instalação .pkg, não Homebrew, e inspecione sua carga exata:

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

Usando esse recibo como inventário, remova apenas o seuasharquivos de propriedade:/usr/local/bin/ash,/usr/local/bin/ash-broker, os arquivos em/usr/local/lib/ash/plugins,/usr/local/share/man/man1/ash.1, o listado localizadoash.1páginas e avisos em/usr/local/share/licenses/ash. São necessários privilégios de administrador. Verifique a propriedade se outro instalador substituiu esses arquivos posteriormente; não remova sua cópia. Remover vazioash-somente diretórios, não compartilhados/usr/local,bin, ou diretórios man.

Depois de remover a carga útil, remova opcionalmente o recibo:

sudo pkgutil --forget dev.ash.cli

Esquecer um recibo não remove nenhum arquivo instalado.Preserve-o até terminar de verificar a carga útil.

3b. Remoção manual de arquivo local do usuário / Linux / FreeBSD

Localize a cópia ativa comcommand -v ashecommand -v ash-broker. Para a instalação do script padrão, após desabilitar os ganchos, remova esses dois arquivos específicos:

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

ParaASH_INSTALL_DIRou um arquivo extraído manualmente, remova apenas o arquivo realmente instaladoash/caminhos do corretor. Remova plug-ins de arquivo/páginas de manual/avisos que você instalou usando seu inventário de arquivos original; plug-ins de script estão noashdiretório de dados do usuário. Se os arquivos estiverem sob/usr/bin, verifique primeiro a propriedade comdpkg -S /usr/bin/ash,rpm -qf /usr/bin/ash, oupacman -Qo /usr/bin/ashconforme apropriado. Uma cópia de propriedade do pacote deve ser removida por meio desse gerenciador, mesmo se instalada a partir de um download independente.

4. Opcional: apague configurações, ferramentas e histórico local

Faça backup de tudo o que você deseja manter. Essa etapa separada pode apagar configurações/tokens do provedor, ferramentas/plug-ins personalizados, histórico de conversas e arquivos temporários. A desinstalação de binários não implica consentimento para apagá-los.

  • Configuração:$XDG_CONFIG_HOME/ash, padrão~/.config/ash.
  • Dados, plug-ins e ambiente Python:$XDG_DATA_HOME/ash, padrão~/.local/share/ash.
  • História e estado:$XDG_STATE_HOME/ash, padrão~/.local/state/ash.
  • Cache:$XDG_CACHE_HOME/ash, padrão~/.cache/ash.
  • Tempo de execução do corretor:$XDG_RUNTIME_DIR/ash, ou$XDG_STATE_HOME/ash/runtimequando nenhuma raiz de tempo de execução estiver disponível.

Inspecione suas substituições XDG absolutas reais antes de excluir apenas esses subdiretórios ash; nunca exclua uma raiz XDG ou seu diretório inicial. Depois que todos os shells habilitados para ash forem fechados, remova os arquivos de tempo de execução ash restantes, se necessário. As credenciais do MCP OAuth também podem permanecer no gerenciador de credenciais do sistema operacional: remova as entradas específicas ash e revogue o acesso no provedor MCP. Revogar chaves de IA não utilizadas em suas contas de provedores; excluir um arquivo local não revoga uma chave. Não desinstale Ollama/models, Python ou dependências compartilhadas como parte da remoção de ash.

Solução rápida de problemas

Comando não encontrado ou versão errada
Verifique PATH ecommand -v ash/command -v ash-broker. Um velho~/.local/bincopy pode sombrear um pacote. Use um proprietário/canal por vez e abra um novo shell.
O menu do provedor não apareceu
Correrash installde um terminal interativo. As configurações válidas existentes são preservadas; usarconfiguração manualpara mudar de provedor. Sem integração, certifique-se de que as configurações sejam exportadas para o ambiente da CLI.
Nenhum modelo ou conexão recusada
Para Ollama, confirme se seu servidor está funcionando eollama listinclui o modelo escolhido. Para serviços em nuvem, verifique o endpoint, a elegibilidade do modelo, HTTPS, token e cota de conta; nunca compartilhe logs com tokens.
Repositório ou canal indisponível
Verifique a arquitetura e o lançamento/repositório publicado. A publicação pode atrasar; não desative a verificação de assinatura para contornar um repositório indisponível.
Falha na configuração da ferramenta Python
Instale o Python com venv/ensurepip e permita downloads de dependências e execute novamenteash install. Básicoashpermanece utilizável sem essas ferramentas.
