Antes de começar

  1. Sistema e shell compatíveis: macOS ou Linux em amd64/x86_64 ou arm64/aarch64, ou FreeBSD em amd64. Use Bash, zsh ou Fish. Pacotes Arch são apenas x86_64. Não existe instalador nativo Windows/PowerShell.
  2. Acesso a downloads: conexão à Internet funcional e acesso HTTPS confiável ao GitHub, repositório escolhido e provedor do modelo. Inferência local também requer baixar um modelo inicialmente.
  3. Permissões: diretório pessoal gravável para arquivos do usuário. Pacotes de sistema Linux e .pkg macOS requerem administração; execute Homebrew e ash install como usuário normal.
  4. Um modelo: servidor local com modelo baixado ou conta/chave API na nuvem. Escolha um modelo com chamadas de ferramentas, não exclusivo de imagem/áudio. RAM, disco e GPU locais dependem do modelo.

Pacotes pré-compilados do ash não exigem Go, Rust, Node.js ou ferramentas Xcode. O gerenciador pode ter pré-requisitos próprios; siga primeiro sua configuração oficial.

Opcional: ferramentas Python incluídas

O uso básico não exige Python. As ferramentas incluídas precisam de Python 3 com venv e ensurepip e acesso para baixar dependências. No Debian/Ubuntu instale python3 e python3-venv; Python Homebrew inclui venv. No FreeBSD use o pacote pip correspondente à versão Python. Execute novamente ash install. Cria-se um ambiente isolado em $XDG_DATA_HOME/ash/venv (padrão ~/.local/share/ash/venv); falhas desativam essas ferramentas, não o ash básico.

macOS

Recomendado: Homebrew

Pré-requisitos: Homebrew, ambiente macOS compatível e comando brew funcionando. O tap escolhe automaticamente o arquivo Intel ou Apple Silicon. Instale Release sem sudo:

brew install Jonconradt/ash/ash
ash version

Homebrew gerencia binários, plugins nativos, manuais e avisos de licença no prefixo (normalmente /opt/homebrew no Apple Silicon ou /usr/local no Intel). Verifica o arquivo pelo SHA-256 da fórmula. Não configura provedor nem início do shell: continue na inicialização por usuário. Atualize com brew upgrade ash, remova Release com brew uninstall ash; veja fórmulas dos canais para Beta/Nightly.

Alternativa: .pkg nativo

Baixe darwin-arm64.pkg para Apple Silicon ou darwin-amd64.pkg para Intel de uma versão publicada. Verifique o manifesto assinado de somas de verificação antes de abrir o instalador. Exige administração.

O pacote macOS não é assinado nem notarizado. O manifesto verifica separadamente editor/somas, não fornece notarização Apple. Não desative Gatekeeper nem ignore avisos só para instalar ash; prefira Homebrew se sua política exigir.

O pacote grava ash e ash-broker em /usr/local/bin, plugins em /usr/local/lib/ash/plugins, manuais em /usr/local/share/man, avisos em /usr/local/share/licenses/ash. O recibo é dev.ash.cli. Não inicializa usuários nem assina atualizações: inicialize depois, atualize substituindo por um .pkg mais recente verificado e use a remoção manual para desinstalar. Não instale sobre uma cópia Homebrew.

Linux

Use o gerenciador da distribuição quando possível. Esses pacotes gerenciam /usr/bin/ash, /usr/bin/ash-broker, /usr/lib/ash/plugins, manuais em /usr/share/man e avisos de licença. Configuração do provedor e hooks ficam para a inicialização por usuário.

Debian e Ubuntu: APT

Pré-requisitos: amd64 ou arm64, administração, APT, curl, gpg e certificados CA. Instale ferramentas de download/chaves ausentes pela distribuição antes do repositório. Release chama-se stable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Antes de importar chaves, verifique a impressão digital numa fonte confiável do editor. A impressão VersionX é 32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. APT verifica metadados assinados e resumos dos pacotes incluídos; signed-by limita o escopo da chave. Atualize com sudo apt update && sudo apt upgrade ash; remova com sudo apt remove ash.

Fedora e sistemas compatíveis RHEL: DNF

Pré-requisitos: x86_64 ou aarch64, administração, DNF/RPM, curl, gpg e certificados CA. Instale ferramentas ausentes pela distribuição. Inspecione a chave e compare a impressão acima antes de importar:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

Arquivos RPM não são assinados individualmente. repo_gpgcheck=1 verifica metadados cobrindo suas somas; gpgcheck=0 reflete a ausência de assinaturas dos pacotes, não a desativação da verificação do repositório. Se sua política exige conteúdo RPM assinado, este repositório não atende. Atualize com sudo dnf upgrade ash; remova com sudo dnf remove ash.

Arch Linux: Pacman

Pré-requisitos: x86_64, administração, Pacman com chaveiro inicializado, curl e gpg. Confira se a impressão exibida corresponde à anterior antes de confiar. Adicione o repositório uma vez, não a cada atualização:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman verifica assinaturas dos pacotes e do banco. Sincronize Arch com sudo pacman -Syu, evitando atualização parcial; remova ash com sudo pacman -R ash.

Outros métodos Linux

Já usa Homebrew no Linux? As mesmas instruções do tap aceitam amd64 e arm64; Brew gerencia os arquivos, não APT/DNF. Caso contrário, use script/arquivo verificado ou download .deb/.rpm correspondente. Instale .deb verificado com sudo apt install ./PACKAGE.deb, ou .rpm com sudo dnf install ./PACKAGE.rpm (substitua nomes). O pacote direto continua gerenciado, mas não adiciona repositório nem assinatura automática de versões futuras. O RPM atual não é assinado; siga a política da distribuição, não desative verificações.

FreeBSD

Pré-requisitos: amd64, Bash (mesmo usando zsh ou Fish interativamente), ferramentas de download/verificação e diretório gravável. Instale Bash pelo gerenciador nativo FreeBSD:

sudo pkg install bash

O pkg do FreeBSD gerencia pré-requisitos, não ash: atualmente não há repositório ash .pkg nem arquivo arm64. Use o script verificado, ou verifique um tarball FreeBSD amd64, extraia num diretório temporário e instale o binário ash versionado como ~/.local/bin/ash, junto a ash-broker. Copie plugins nativos para $XDG_DATA_HOME/ash/plugins (padrão ~/.local/share/ash/plugins), depois inicialize. Você gerencia os arquivos; pkg delete não os remove. Use autoatualizações Release no local padrão ou substitua arquivos verificados manualmente.

Inicializar e verificar

Após os binários, configure interativamente como usuário normal. Configurar apenas arquivos não altera o início do shell:

ash install

Para integrar também comandos não encontrados, escolha exatamente um comando para seu shell:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Fish

ash install --shell fish --shell-integration

Bash usa ~/.bashrc, zsh ~/.zshrc, Fish $XDG_CONFIG_HOME/fish/config.fish (padrão ~/.config/fish/config.fish). Abra outro shell depois; os existentes mantêm seu broker. A integração coloca ~/.local/bin no início do PATH: remova cópias locais antigas antes de esperar selecionar um pacote de sistema.

Se faltarem configurações, detectam-se chaves existentes ou servidor local ativo; senão aparece menu de provedores e pedido de credenciais. Escolha um modelo disponível com ferramentas. Configurações válidas permanecem: repetir não troca provedor.

Configurações ficam em $XDG_CONFIG_HOME/ash/.ash_env (padrão ~/.config/ash/.ash_env, permissões privadas). A integração as carrega. Sem ela, Bash/zsh podem carregar o arquivo no início; Fish deve definir as variáveis ASH_AI_* em sintaxe Fish, não carregar arquivo Bash. Proteja arquivos com tokens e nunca faça commit deles.

Sem integração, adicione ao PATH o diretório real da instalação local. Bash/zsh: export PATH="$HOME/.local/bin:$PATH". Fish: fish_add_path "$HOME/.local/bin". Persista na configuração inicial; substitua seu diretório personalizado quando necessário.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

Os primeiros comandos devem apontar à instalação escolhida. A pergunta exige servidor ativo ou credenciais cloud válidas; instalar ash não instala modelo.

Ollama local: sem conta na nuvem

Instale Ollama com suas instruções oficiais do sistema. Inicie app/serviço ou execute ollama serve noutro terminal se não houver servidor ativo. Suporte ash FreeBSD não implica instalador Ollama nativo: use servidor acessível noutro host compatível se necessário.

Baixe um modelo com ferramentas adequado ao hardware; llama3.1:8b é exemplo, não mínimo. Consulte o catálogo atual de ferramentas para alternativas:

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

Sem chaves cloud definidas, a configuração pode detectar o servidor local e oferecer o modelo baixado. Se outro provedor já estiver configurado, altere endpoint/modelo manualmente. Exemplo Bash/zsh:

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Equivalente Fish:

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Essas alterações só afetam o shell atual. Salve no arquivo de ambiente ash protegido ou configuração apropriada, substituindo ajustes antigos. Ollama local não exige token. Mantenha o servidor em loopback salvo acesso deliberadamente protegido; servidor remoto recebe perguntas e resultados das ferramentas.

Opcional: defina OLLAMA_KEEP_ALIVE=30m no ambiente do servidor Ollama e reinicie-o para manter modelos carregados. -1 mantém indefinidamente, mas consome memória entre solicitações. Definir apenas no terminal cliente ash não reconfigura servidor ativo.

Inferência local não cobra API, mas usa hardware/armazenamento/eletricidade. Ollama cloud é serviço separado com autenticação e limites de plano; não é essa configuração local.

Planos gratuitos na nuvem

Gratuito não significa ilimitado nem privado. Contas, regiões, cotas, modelos e políticas de dados variam e mudam. Perguntas e resultados relevantes saem do computador. Confira limites e termos; ative cobrança paga só se quiser pagar.

Crie uma chave pelos links, execute ash install interativamente e escolha provedor. Solicita-se token e listam-se modelos quando possível. Escolha um modelo de texto gratuito com ferramentas disponível; estar listado não garante gratuidade para sua conta.

Configuração manual ou troca de provedor

Substitua o endpoint abaixo pelo valor da tabela e MODEL_ID por modelo verificado na conta. Se a chave já estiver exportada como GROQ_API_KEY, este exemplo Bash/zsh a reutiliza sem digitar o segredo:

export ASH_AI_ENDPOINT="https://api.groq.com/openai/v1"
export ASH_AI_MODEL="MODEL_ID"
export ASH_AI_AUTH_TOKEN="$GROQ_API_KEY"

Equivalente Fish:

set -gx ASH_AI_ENDPOINT https://api.groq.com/openai/v1
set -gx ASH_AI_MODEL MODEL_ID
set -gx ASH_AI_AUTH_TOKEN "$GROQ_API_KEY"

Para Gemini/OpenRouter use respectivos endpoints e variáveis reconhecidas. Salve configurações seguramente para shells futuros. Cloud exige HTTPS e token; HTTP local não é atalho cloud. Veja referência de ambiente e outros provedores compatíveis para serviços pagos e ajustes avançados.

Instalação por script: alternativa, não primeira escolha

Prefira Homebrew, APT, DNF ou Pacman: registram arquivos próprios, verificam downloads com sua confiança e oferecem atualizações/remoção conhecidas. Ainda exigem confiança nos editores e ações de instalação.

Um script web executa código com permissões da sua conta. Site/editor comprometido ou script alterado pode ler segredos, modificar arquivos ou instalar software. HTTPS protege transporte, não intenções. Enviar URL direto ao shell executa antes de revisar. Verificar assinaturas de arquivos não autentica o script. Nunca execute com sudo nem desative sua verificação.

Pré-requisitos: sistema/arquitetura compatíveis, $SHELL identificando Bash/zsh/Fish, Sigstore cosign, tar, uname, install, utilitários padrão, comando SHA-256 (sha256sum, shasum ou sha256) e downloader (curl, wget ou Python). O exemplo usa curl. FreeBSD também exige Bash. Diretório pessoal/de instalação deve ser gravável.

Baixe arquivo local, inspecione num editor e execute só confiando em fonte e comportamento. Inspeção não garante segurança; não siga cegamente:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

Após inspeção, execute a cópia salva como usuário normal:

sh ./ash-install.sh
rm ./ash-install.sh

install.sh baixa o último Release, verifica manifesto assinado Sigstore e resumo do arquivo, instala ash/ash-broker em ~/.local/bin. Plugins vão em $XDG_DATA_HOME/ash/plugins. Configura o usuário e pergunta antes da integração shell. Sem terminal interativo pode ignorar perguntas provedor/integração: execute depois ash install interativamente.

Defina ASH_INSTALL_DIR antes do script para outro destino. Adicione-o ao PATH por conta própria. Autoatualização só é suportada em ~/.local/bin; destinos personalizados exigem substituição manual. O script não seleciona Beta/Nightly.

Verificar pacote ou arquivo direto

Pré-requisitos: cosign e utilitário SHA-256. Baixe pacote/arquivo, SHA256SUMS e SHA256SUMS.sigstore.json da mesma versão publicada. Trabalhe num diretório novo. Substitua vX.Y.Z pela tag exata, incluindo sufixo preliminar se aplicável:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Só após sucesso calcule resumo com shasum -a 256 PACKAGE no macOS, sha256sum PACKAGE no Linux ou sha256 -q PACKAGE no FreeBSD. Substitua PACKAGE pelo nome baixado e compare exatamente com sua entrada no manifesto verificado. Pare se faltar ou divergir. Soma não assinada junto ao arquivo não equivale a metadados verificados do editor.

Atualizações e três canais

  • Release (recomendado): versões estáveis como vX.Y.Z; no repositório chama-se stable.
  • Beta: testes preliminares, tag vX.Y.Z-beta.N; espere mudanças e regressões.
  • Nightly: mudanças recentes do branch padrão, tag vX.Y.Z-nightly.YYYYMMDD.N; maior risco de regressão. Compilações agendadas podem ser omitidas sem mudanças ou com falha na publicação.

Uma publicação atualiza fórmula Homebrew ou repositório Linux assinado correspondente. Você recebe executando atualização do gerenciador responsável, ou pela política do sistema. Publicação, repositórios e site podem estar defasados; confira disponibilidade antes de trocar canal. ash não instala binários silenciosamente em segundo plano.

Homebrew: instalar ou trocar fórmulas

Em novas instalações Beta/Nightly use o nome completo acima em brew install. Na troca, desinstale primeiro a fórmula atual: todas fornecem os mesmos binários. Exemplo Release para Beta:

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

Use ash-nightly para Nightly ou ash para Release em instalação/atualização. Remova a fórmula real do canal antigo, não sempre ash. Configurações permanecem; abra novo shell depois.

Linux: escolher um canal de repositório

APT: use a configuração APT com exatamente uma distribuição da tabela. Para trocar edite /etc/apt/sources.list.d/versionx.list, substituindo stable por beta ou nightly (ou volte a stable), depois:

sudo apt update
sudo apt install --allow-downgrades ash

DNF: use a configuração DNF com baseurl escolhida. Em instalação existente substitua baseurl em /etc/yum.repos.d/versionx.repo, mantendo assinaturas, depois:

sudo dnf --refresh distro-sync ash

Pacman: use a configuração Pacman com URL Server escolhida. Mantenha seção [versionx]: todo canal publica banco versionx.db. Altere Server nessa seção, não adicione banco com outro nome. Para trocar, incluindo downgrade:

sudo pacman -Syuu ash

Revise a transação: voltar a Release pode rebaixar ash; o duplo u do Pacman também outros pacotes. Faça backup antes. Depois use atualizações normais APT/DNF/Pacman das seções do sistema; não mantenha várias fontes de canais ash ativas.

Atualizações Release locais

ash update

Verifica e instala versão estável só se o ash ativo estiver em ~/.local/bin. Atualiza arquivos/plugins incluídos, com escolhas para personalizados. ash update --version vX.Y.Z seleciona tag estável, não canal; não faz downgrade. Não há --channel. Instalações gerenciadas, .pkg e scripts em destinos próprios usam gerenciador/instalador. FreeBSD Beta/Nightly usa arquivos verificados manuais, não assinatura do autoatualizador. Abra outro shell depois.

Desinstalar sem apagar arquivos alheios

1. Desativar primeiro integração shell

Antes dos binários, execute o comando para cada shell com integração:

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Fish

ash install --shell fish --disable-shell-integration

Se ash já faltar, edite o início indicado na inicialização e remova só o bloco entre # >>> ash install >>> e # <<< ash install <<<. Remova linhas PATH/ambiente ash adicionadas manualmente, não outros ajustes. Feche shells ash para encerrar seus brokers.

2. Deixar o gerenciador responsável remover seus arquivos

Homebrew (Release)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

Escolha só seu método; em Homebrew Beta/Nightly use ash-beta/ash-nightly. APT/DNF/Pacman removem binários, plugins e manuais próprios, não configuração/histórico pessoal. Não apague arquivos gerenciados manualmente.

Limpeza opcional: remova fonte ash /etc/apt/sources.list.d/versionx.list e chave dedicada /etc/apt/keyrings/versionx-keyring.gpg, repositório /etc/yum.repos.d/versionx.repo, ou seção ash [versionx] de /etc/pacman.conf. Confira antes que outros pacotes não usam. Remova chaves RPM/Pacman só após verificar impressão e ausência de dependentes; nunca apague chaveiro compartilhado da distribuição.

3a. Remoção manual .pkg macOS

macOS Installer registra recibo mas não tem desinstalador ash. Confirme .pkg, não Homebrew, e inspecione conteúdo exato:

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

Usando recibo como inventário, remova só arquivos ash: /usr/local/bin/ash, /usr/local/bin/ash-broker, arquivos em /usr/local/lib/ash/plugins, /usr/local/share/man/man1/ash.1, páginas ash.1 traduzidas listadas e avisos em /usr/local/share/licenses/ash. Exige administração. Se outro instalador substituiu, confira propriedade; não remova sua cópia. Remova diretórios vazios exclusivos, não compartilhados /usr/local, bin ou manuais.

Após arquivos, remova opcionalmente o recibo:

sudo pkgutil --forget dev.ash.cli

Esquecer um recibo não remove arquivos instalados. Preserve até terminar a verificação do conteúdo.

3b. Remoção manual local / Linux / FreeBSD

Localize cópia ativa com command -v ash e command -v ash-broker. No script padrão, após desativar hooks, remova exatamente esses dois arquivos:

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

Para ASH_INSTALL_DIR ou arquivo extraído manualmente, remova só caminhos reais ash/broker. Retire plugins/manuais/avisos conforme inventário original; plugins do script ficam nos dados do usuário ash. Sob /usr/bin confira propriedade com dpkg -S /usr/bin/ash, rpm -qf /usr/bin/ash ou pacman -Qo /usr/bin/ash. Cópia gerenciada deve ser removida pelo gerenciador, mesmo baixada individualmente.

4. Opcional: apagar configurações, ferramentas e histórico

Faça backup do que quiser guardar. Esse passo separado pode apagar configurações/tokens, ferramentas/plugins próprios, conversas e arquivos de trabalho. Desinstalar binários não implica consentimento para apagá-los.

  • Configuração: $XDG_CONFIG_HOME/ash, padrão ~/.config/ash.
  • Dados, plugins e ambiente Python: $XDG_DATA_HOME/ash, padrão ~/.local/share/ash.
  • Histórico e estado: $XDG_STATE_HOME/ash, padrão ~/.local/state/ash.
  • Cache: $XDG_CACHE_HOME/ash, padrão ~/.cache/ash.
  • Runtime do broker: $XDG_RUNTIME_DIR/ash, ou $XDG_STATE_HOME/ash/runtime sem raiz de runtime disponível.

Inspecione substituições XDG absolutas reais antes de apagar só subdiretórios ash; nunca raiz XDG nem diretório pessoal. Após fechar todos os shells ash, limpe restos de runtime se necessário. Credenciais MCP OAuth podem ficar no gerenciador do sistema: retire entradas ash e revogue acesso no MCP. Revogue chaves IA sem uso nas contas; apagar arquivo não revoga chave. Não desinstale Ollama/modelos, Python ou dependências compartilhadas ao remover ash.

Solução rápida de problemas

Comando ausente ou versão errada
Confira PATH e command -v ash/command -v ash-broker. Cópia antiga em ~/.local/bin pode ocultar pacote. Use um responsável/canal por vez e abra outro shell.
Menu de provedores não apareceu
Execute ash install interativamente. Ajustes válidos permanecem; use configuração manual para trocar. Sem integração, exporte ajustes ao ambiente CLI.
Sem modelo ou conexão recusada
No Ollama confira servidor e modelo em ollama list. Na nuvem confira endpoint, elegibilidade, HTTPS, token e cota; nunca compartilhe logs com tokens.
Repositório ou canal indisponível
Confira arquitetura e versão/repositório publicados. Publicação pode atrasar; não desative assinaturas para contornar indisponibilidade.
Configuração Python falhou
Instale Python com venv/ensurepip, permita downloads de dependências e repita ash install. ash básico continua usável sem ferramentas.
