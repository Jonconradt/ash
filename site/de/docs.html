Auf Debian oder Ubuntu installieren

Das signierte VersionX APT-Repository unterstütztamd64Undarm64. Fügen Sie den öffentlichen Signaturschlüssel und die Paketquelle hinzu und installieren Sie esash:

sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key |
  sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash

Überprüfen Sie den installierten Befehl mitash --version. Paketmanager-Installationen werden mit aktualisiertsudo apt update && sudo apt upgrade.

Installation unter Fedora oder RHEL-kompatiblem Linux

Das signierte VersionX-DNF-Repository unterstütztx86_64Undaarch64. Importieren Sie den öffentlichen Schlüssel und konfigurieren Sie das Repository:

sudo rpm --import https://www.versionx.ai/rpm/gpg.key
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash

Signierte Repository-Metadaten überprüfen die Prüfsummen des RPM-Pakets. Paketdateien sind nicht einzeln RPM-signiert. Aktualisieren Sie ash mit sudo dnf upgrade ash.

Auf Arch Linux installieren

Das signierte VersionX Pacman-Repository unterstütztx86_64. Überprüfen Sie, ob der unten angezeigte Fingerabdruck des Signaturschlüssels übereinstimmt32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F, dann importieren und lokal vertrauen:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o /tmp/versionx.gpg
gpg --show-keys --with-fingerprint /tmp/versionx.gpg
sudo pacman-key --add /tmp/versionx.gpg
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
rm /tmp/versionx.gpg
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash

Pacman überprüft sowohl Paket- als auch Repository-Signaturen. Aktualisieren Sie ash mit sudo pacman -Syu.

Beschreibung

ashSendet einen Eingabeaufforderungstext an den konfigurierten KI-Endpunkt und druckt die Antwort des Assistenten aus. Wenn kein Positionstext angegeben ist,ashLiest Eingabeaufforderungstext aus der nicht interaktiven Standardeingabe.

DerinstallDer Unterbefehl installiert verwaltete Assets. Shell-Startdateien werden nur geändert, wenn Sie dies ausdrücklich anfordern--shell-integration; Bash verwendet~/.bashrc, zsh verwendet~/.zshrc, und Fisch verwendet$XDG_CONFIG_HOME/fish/config.fish.

Verbindungen zum KI-Anbieter werden über einen lokalen Broker geteilt. Ein Broker-Ausfall fällt auf direktes HTTPS zurück.

Die KI kann systemd verwenden, um Hintergrundaufgaben zu planen. Dabei kann es sich um wiederkehrende oder einmalige Aufträge handeln. Geplante Jobs verwenden standardmäßig direktes HTTPS.

ashFolgt den XDG-Basisverzeichnissen: Konfiguration und persistente Arbeitsbereichsdateien unter$XDG_CONFIG_HOME/ash(Standard~/.config/ash), Tools und Plugins unter$XDG_DATA_HOME/ash(Standard~/.local/share/ash), Verlauf und Sitzungsscratch unten$XDG_STATE_HOME/ash(Standard~/.local/state/ash) und zwischenspeichern$XDG_CACHE_HOME/ash(Standard~/.cache/ash). Verwendung von Broker-Sockets$XDG_RUNTIME_DIR/ashmit einem State-Directory-Fallback. Explizite XDG-Pfade müssen absolut sein.

Tool-, Skript-, Datei-, Pipeline- und untergeordnete Ausgaben sind nicht vertrauenswürdige Daten und dürfen System- oder Benutzeranweisungen nicht außer Kraft setzen. Die Tool-Ausführungsfunktion ist keine Sandbox, wenn die beliebige Python- oder Shell-Ausführung aktiviert ist. Standardmäßig ist Python aktiviert, seien Sie also vorsichtig.

Remote-MCP-Server

MCP-Server (Model Context Protocol) stellen Tools bereit, die ein KI-Modell aufrufen kann.Ashunterstützt Remote-Streamable-HTTP-MCP-Server und hält ihre Client-Sitzungen aufrechtash-brokerüberAshAufrufe in derselben Shell.

Registrieren Sie einen vertrauenswürdigen Server, indem Sie Folgendes ausführenash mcp add <url>von einem interaktivenAshShell oder durch Hinzufügen der URL zu$XDG_CONFIG_HOME/ash/.ash_allow(Standard~/.config/ash/.ash_allow). Standardmäßig ist kein Remote-Server aktiviert.

Die OAuth-Autorisierung wird im Desktop-Browser geöffnet, wenn eine GUI verfügbar ist. Sollte sich der Browser nicht öffnen lassen,Ashgibt eine kopierbare Autorisierungs-URL aus und wartet im Terminal. Verwendenash mcp add <url> --no-browserdiesen Terminalfluss immer zu verwenden. Für die manuelle URL-Autorisierung ist weiterhin ein Browser auf demselben Host erforderlich. Es handelt sich nicht um einen browserlosen OAuth-Fluss.

URL-Zeilen beginnend mithttp://oderhttps://sind MCP-Registrierungen, keine Shell-Befehle. Schemata werden ohne Berücksichtigung der Groß-/Kleinschreibung erkannt.Ashleitet den lokalen Namen des Servers aus den ersten acht hexadezimalen Kleinbuchstaben von SHA-256 über dem gekürzten URL-Text ab. HTTPS ist außer für die Localhost-Entwicklung erforderlich; URLs mit eingebetteten Anmeldeinformationen, Abfragezeichenfolgen oder Fragmenten werden abgelehnt. Bei direkten OAuth-Verbindungen lässt die Erkennung nicht öffentliche IP-Adressen nur für die genau registrierte MCP-Autorität zu; Andere OAuth-Hosts unterliegen weiterhin der Blockierung nicht öffentlicher Adressen. Ein konfigurierter Egress-Proxy ist für die Filterung seiner Zieladressen verantwortlich. Änderungen werden auf der nächsten Seite gelesenAshAnfrage.

MCP-Registrierungen bleiben mit aktiviertASH_STRICT=1. Zurückgesandte Werkzeugausgaben werden weiterhin als nicht vertrauenswürdige Beweise behandelt. Registrieren Sie nur Server, denen Sie vertrauen: Ihre Tools können in Ihrem Namen Aktionen ausführen. Für OAuth-geschützte Server:AshÖffnet den Browser, wenn eine GUI verfügbar ist, während der Broker den Rückruf und die Token verarbeitet. Anmeldeinformationen verwenden den Anmeldeinformations-Manager des Betriebssystems, sofern verfügbar, oder eine verschlüsselte Datei, die durch eine vom Benutzer bereitgestellte zufällige 32-Byte-Datei geschützt istASH_MCP_CREDENTIAL_KEYIn$XDG_DATA_HOME/ash/mcp/.

Wenn die MCP-Initialisierung fehlschlägt,Ashsetzt die Anfrage ohne Remote-MCP-Tools fort. Interaktive Läufe geben eine Warnung aus; Nicht interaktive Läufe schlagen stillschweigend fehl.Geplante Jobs verfügen nicht über den Per-Interactive-Shell-Broker und können daher keine Remote-MCP-Tools verwenden.Eine geplante Eingabeaufforderung, die von MCP abhängt, wird möglicherweise weiterhin ausgeführt, kann jedoch ohne die angeforderte MCP-Aktion oder die angeforderten MCP-Daten beendet werden. Planen Sie keine Eingabeaufforderungen, die MCP erfordern.

Siehe dieMCP-FAQfür einen schnellen Überblick und Einrichtungshinweise.

Befehle

ash [--attach path]... [text ...]
Führen Sie eine einzelne Assistentenanfrage aus.--attachhängt der Anfrage eine Datei (Bild oder Dokument) an; wiederholbar. Größenbegrenzt durchASH_ATTACHMENT_MAX_BYTESund werden derzeit nur an OpenAI-kompatible Anbieter per Kabel gesendet.
ash mcp add <url> [--no-browser]
Stellen Sie eine Verbindung her und registrieren Sie einen Remote-MCP-Server.ash_allow. Öffnet die OAuth-Autorisierung in einem Desktop-Browser, sofern verfügbar; greift auf eine kopierbare URL im Terminal zurück.--no-browserVerwendet immer den Terminalfluss.
ash install [--shell bash|zsh|fish] [--shell-integration|--disable-shell-integration] [--dry-run]
Installieren Sie Assets standardmäßig, ohne die Shell-Startdateien zu ändern.--shell-integrationentscheidet sich für das Hinzufügen/Aktualisieren des verwalteten Blocks;--disable-shell-integrationEntfernt nur diesen Block und behält den umgebenden Benutzerinhalt bei. Wenn Sie interaktiv sind, installieren Sie die automatische KonfigurationASH_AI_ENDPOINT,ASH_AI_MODEL, UndASH_AI_AUTH_TOKENBei Bedarf wird ein vorhandener Anbieterschlüssel oder ein lokaler Endpunkt bevorzugt, bevor ein Anbietermenü angezeigt wird.
ash snooze [duration|off]
Unterbrechen Sie die automatische Verarbeitung der Shell-Eingabeaufforderung. Der Standardwert beträgt fünf Minuten. Dauern verwenden Go-Syntax wie z30s,5m, oder1h. Verwendenoffsofort fortfahren.
ash update [--version vX.Y.Z] [--yes|--skip-customized]
Laden Sie die neueste stabile macOS-, Linux- oder FreeBSD-Version für die aktuelle Architektur herunter und installieren Sie sie~/.local/bin/ash. Für Veröffentlichungen ist eine Sigstore-Verifizierung und eine SHA-256-Verifizierung erforderlich.

Optionaler Inhabertoken. Erforderlich für Cloud-Endpunkte außer AWS Bedrock. Private/LAN-Adressen und.localHostnamen werden als Nicht-Cloud-Hostnamen behandelt, es sei dennASH_STRICT=1.

Optionale anbieternative Cache-Umschaltung. Standardmäßig aktiviert, sofern unterstützt; akzeptiert1,true,yes,on,enabled,0,false,no,off, oderdisabled(Groß- und Kleinschreibung wird nicht beachtet).

Erforderliche Basis-URL für den Chat-API-Endpunkt.

ASH_AI_PROVIDER
Optionale Anbieterüberschreibung. Wenn nicht aktiviert,ashErkennt den Anbieter vom Endpunkt aus.
ASH_AI_TIMEOUT

Optionaler Testschalter. Wenn es wahr ist, werden die Routen weitergeleitetollamaAnbieter über den OpenAI-kompatiblen SDK-Adapter anstelle seiner manuellen Implementierung. Akzeptiert die gleichen booleschen Werte wieASH_AI_CACHE. Standard: ein.

Optionale maximale Iterationen der AI-Tool-Call-Schleife. Standard:16.
ASH_RELEVANCE_WINDOW
Optionale aktuelle Werkzeugbeobachtungen im Ausführungsstatus enthalten. Standard:4.
ASH_RETRY_BASE_DELAY
Optionale Backoff-Basisverzögerung für Wiederholungsversuche. Standard:250ms.

Internes Scheduler-Flag, das von verwendet wirdash-verwaltete Aufrufe.

Optionaler Umschalter. Bei true-like wird die Antwort von Anbietern gestreamt, deren Adapter dies unterstützt (derzeit nur OpenAI). Akzeptiert die gleichen booleschen Werte wieASH_AI_CACHE. Standard: ein.

Explizite numerische und Dauereinstellungen werden validiert. Ganzzahlgrenzen müssen positiv sein, außerASH_MAX_TOOL_ITERS, was Null sein kann. KI-/Tool-Timeouts müssen positiv sein; Wiederholungsverzögerungen können Null, aber nicht negativ sein. Dauern verwenden Go-Syntax wie z30s,5m, oder1h. Falsch formatierte oder außerhalb des gültigen Bereichs liegende Werte führen zu einem Konfigurationsfehler, anstatt stillschweigend Standardwerte zu verwenden.

Dateien

  • $XDG_CONFIG_HOME/ash/(Standard~/.config/ash/)—kanonische Eingabeaufforderungs-, Richtlinien- und persistente Arbeitsbereichsdateien.
  • $XDG_DATA_HOME/ash/(Standard~/.local/share/ash/)—gebündelte Tools, Plugins, Sprachpakete und MCP-Anmeldeinformationen.
  • $XDG_STATE_HOME/ash/(Standard~/.local/state/ash/)—Verlauf, Scratch, Protokolle und Schlummerstatus.
  • $XDG_CACHE_HOME/ash/(Standard~/.cache/ash/)—regenerierbare Cache-Dateien.

Exit-Status

ash gibt bei Erfolg 0 zurück. Es wird ein Wert ungleich Null zurückgegeben, wenn Konfiguration, Netzwerkanforderungen oder Toolausführung fehlschlagen.
