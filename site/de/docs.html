Zusammenfassung

ash [text ...]

Beschreibung

ash sendet einen Eingabeaufforderungstext an den konfigurierten KI-Endpunkt und druckt die Antwort des Assistenten. Wenn kein Positionstext bereitgestellt wird, liest ash Eingabeaufforderungstext aus der nicht interaktiven Standardeingabe.

Der Unterbefehl install fügt einen verwalteten Integrationsblock zu Shell-Startdateien hinzu. Bash verwendet ~/.bashrc und zsh verwendet ~/.zshrc.

Verbindungen zum KI-Anbieter werden über einen lokalen Broker geteilt. Ein Broker-Ausfall fällt auf direktes HTTPS zurück.

Die KI kann systemd verwenden, um Hintergrundaufgaben zu planen. Dabei kann es sich um wiederkehrende oder einmalige Aufträge handeln. Geplante Jobs verwenden standardmäßig direktes HTTPS.

ash verwaltet einen sitzungsbezogenen Scratch-Arbeitsbereich unter ~/.ash/scratch/<session-id>/. Veraltete und inaktive Arbeitsverzeichnisse werden nach Ablauf des konfigurierten Aufbewahrungsfensters automatisch entfernt. Die Verlaufsprotokolle werden unter ~/.ash/history/ gespeichert. Alte Verlaufsdateien werden gemäß der Aufbewahrungsrichtlinie automatisch bereinigt.

Tool-, Skript-, Datei-, Pipe- und untergeordnete Ausgaben sind nicht vertrauenswürdige Daten und dürfen keine System- oder Benutzeranweisungen außer Kraft setzen. Die Tool-Ausführungsfunktion ist keine Sandbox, wenn die beliebige Python- oder Shell-Ausführung aktiviert ist. Standardmäßig ist Python aktiviert, seien Sie also vorsichtig.

Remote-MCP-Server

MCP-Server (Model Context Protocol) stellen Tools bereit, die ein KI-Modell aufrufen kann. Ash unterstützt Remote-Streamable-HTTP-MCP-Server und behält ihre Client-Sitzungen in ash-broker über Ash-Aufrufe in derselben Shell bei.

Registrieren Sie einen Server, indem Sie seine URL allein zu ~/.ash/.ash_allow hinzufügen, oder führen Sie ash mcp add <url> von einem interaktiven Gerät aus aus Ash Schale. Der Befehl verbindet und registriert den Server erst nach einer erfolgreichen Verbindung:

https://mcpplaygroundonline.com/mcp-complex-server

Die OAuth-Autorisierung wird im Desktop-Browser geöffnet, wenn eine GUI verfügbar ist. Wenn der Browser nicht geöffnet werden kann, gibt Ash eine kopierbare Autorisierungs-URL aus und wartet im Terminal. Verwenden Sie ash mcp add <url> --no-browser, um diesen Terminalfluss immer zu verwenden. Für die manuelle URL-Autorisierung ist weiterhin ein Browser auf demselben Host erforderlich. Es handelt sich nicht um einen browserlosen OAuth-Ablauf.

URL-Zeilen, die mit http:// oder https:// beginnen, sind MCP-Registrierungen, keine Shell-Befehle. Schemata werden ohne Berücksichtigung der Groß-/Kleinschreibung erkannt. Ash leitet den lokalen Namen des Servers aus den ersten 8 hexadezimalen Kleinbuchstaben von SHA-256 über dem gekürzten URL-Text ab. HTTPS ist außer für die Localhost-Entwicklung erforderlich; URLs mit eingebetteten Anmeldeinformationen, Abfragezeichenfolgen oder Fragmenten werden abgelehnt. Bei direkten OAuth-Verbindungen lässt die Erkennung nicht öffentliche IP-Adressen nur für die genau registrierte MCP-Autorität zu; Andere OAuth-Hosts unterliegen weiterhin der Blockierung nicht öffentlicher Adressen. Ein konfigurierter Egress-Proxy ist für die Filterung seiner Zieladressen verantwortlich. Änderungen werden bei der nächsten Ash-Anfrage gelesen.

MCP-Registrierungen bleiben mit ASH_STRICT=1 aktiviert. Zurückgesandte Werkzeugausgaben werden weiterhin als nicht vertrauenswürdige Beweise behandelt. Registrieren Sie nur Server, denen Sie vertrauen: Ihre Tools können in Ihrem Namen Aktionen ausführen. Bei OAuth-geschützten Servern öffnet Ash den Browser, wenn eine GUI verfügbar ist, während der Broker den Rückruf und die Token verarbeitet. Anmeldeinformationen verwenden den Anmeldeinformations-Manager des Betriebssystems, sofern verfügbar, oder eine verschlüsselte Datei, die durch eine vom Benutzer bereitgestellte zufällige 32-Byte-Datei ASH_MCP_CREDENTIAL_KEY geschützt ist. Vorhandene ~/.ash/mcp.json-Dateien werden nicht mehr gelesen; Verschieben Sie Server-URLs nach .ash_allow.

Wenn die MCP-Initialisierung fehlschlägt, setzt Ash die Anforderung ohne Remote-MCP-Tools fort. Interaktive Läufe geben eine Warnung aus; Nicht interaktive Läufe schlagen stillschweigend fehl. Geplante Jobs verfügen nicht über den Pro-Interactive-Shell-Broker und können daher keine Remote-MCP-Tools verwenden. Eine geplante Eingabeaufforderung, die von MCP abhängt, wird möglicherweise weiterhin ausgeführt, kann jedoch ohne die angeforderte MCP-Aktion oder -Daten abgeschlossen werden. Planen Sie keine Aufforderungen, die MCP erfordern.

Eine kurze Übersicht und Einrichtungshinweise finden Sie in den MCP-FAQ.

Befehle

ash [--attach path]... [text ...]
Führen Sie eine einzelne Assistentenanfrage aus. --attach hängt eine Datei (Bild oder Dokument) an die Anfrage an; wiederholbar. Größenbeschränkt durch ASH_ATTACHMENT_MAX_BYTES und derzeit nur an OpenAI-kompatible Anbieter gesendet.
ash mcp add <url> [--no-browser]
Verbinden und registrieren Sie einen Remote-MCP-Server im gültigen .ash_allow. Öffnet die OAuth-Autorisierung in einem Desktop-Browser, sofern verfügbar; greift auf eine kopierbare URL im Terminal zurück. --no-browser verwendet immer den Terminal-Flow.
ash install [--shell bash|zsh] [--dry-run]
Shell-Integration installieren oder aktualisieren. Wenn --shell weggelassen wird, wird nach Möglichkeit die aktuelle Shell verwendet. --dry-run zeigt eine Vorschau der Änderungen an, ohne sie zu schreiben. Bei interaktiver Installation werden auch AI_ENDPOINT, AI_MODEL und AI_AUTH_TOKEN automatisch konfiguriert: Es bevorzugt einen bereits festgelegten Cloud-Anbieter-API-Schlüssel (OpenAI, Anthropic, Google Gemini, Azure OpenAI, Mistral, Cohere, Groq, xAI, DeepSeek, Together AI, OpenRouter oder HuggingFace) und dann einen laufenden lokalen Inferenzserver (Ollama, LM Studio, llama.cpp/MLX/LocalAI, vLLM, text-generation-webui, Jan oder GPT4All) und ansonsten Eingabeaufforderungen mit einem nummerierten Anbietermenü. Das Modell wird aus der Modellliste des Endpunkts ausgewählt, sofern verfügbar.
ash snooze [duration|off]
Automatische Verarbeitung der Shell-Eingabeaufforderung anhalten. Der Standardwert beträgt fünf Minuten. Dauern verwenden Go-Syntax wie 30s, 5m oder 1h. Verwenden Sie off, um sofort fortzufahren.
ash update [--version vX.Y.Z] [--yes|--skip-customized]
Laden Sie die neueste stabile macOS-, Linux- oder FreeBSD-Version für die aktuelle Architektur herunter und installieren Sie sie in ~/.local/bin/ash. Veröffentlichungen erfordern eine Sigstore-Verifizierung und eine SHA-256-Verifizierung.

Umgebung

AI_AUTH_TOKEN
Optionaler Inhaber-Token. Wenn sie festgelegt ist, wird sie als Trägerauthentifizierung gesendet und ist für Cloud-Endpunkte erforderlich. Private/LAN-Adressen (RFC1918 IPv4, IPv6 ULA) und .local mDNS-Hostnamen werden als Nicht-Cloud-Hostnamen behandelt (wie localhost), es sei denn, ASH_STRICT=1 ist festgelegt.
AI_CACHE
Optionale anbieternative Cache-Umschaltung. Standardmäßig aktiviert, sofern unterstützt; Verwenden Sie zum Deaktivieren off oder false.
AI_ENDPOINT
Erforderliche Basis-URL für den Chat-API-Endpunkt.
AI_MODEL
Erforderlicher Modellname, der an gesendet wird Endpunkt.
AI_PROVIDER
Optionale Anbieterüberschreibung: anthropic, bedrock, cohere, gemini, google, ollama oder openai. Wenn diese Option deaktiviert ist, erkennt ash den Anbieter vom Endpunkt aus.
AI_TIMEOUT
Optionales Anforderungszeitlimit. Standard: 3m.
ASH_ALWAYS_OPENAI_API
Optionale Testumschaltung. Wenn dies der Fall ist, wird der ollama-Anbieter über den OpenAI-kompatiblen SDK-Adapter und nicht über seine handgerollte Implementierung weitergeleitet. Standard: aktiviert.
ASH_ATTACHMENT_MAX_BYTES
Optionale maximale Größe in Bytes für eine Datei, die über --attach übergeben wird. Standard: 10485760 (10 MiB).
ASH_HISTORY_MAX
Optionale maximale Verlaufsnachrichten pro Schlüssel. Standard: 40.
ASH_LOG_FILE
Optionaler Debug-Protokollpfad, wenn die ausführliche Protokollierung aktiviert ist.
ASH_LOG_MAX_BYTES
Optionale maximale Protokollgröße vor der Rotation. Standard: 1048576.
ASH_MAX_AGENTS
Optionale maximale Anzahl von Unteragenten, die von einem übergeordneten Prozess generiert werden. Standard: 6.
ASH_MAX_TOOL_ITERS
Optionale maximale AI-Tool-Call-Schleifeniterationen. Standard: 16.
ASH_RELEVANCE_WINDOW
Optionale aktuelle Werkzeugbeobachtungen im Ausführungsstatus enthalten. Standard: 4.
ASH_RETRY_BASE_DELAY
Optionale Backoff-Basisverzögerung für Wiederholungen. Standard: 250ms.
ASH_RETRY_MAX_ATTEMPTS
Optional wiederholbare Anforderungsversuche. Standard: 3.
ASH_SCHEDULED_TASK
Internes Scheduler-Flag, das von ash-verwalteten Aufrufen verwendet wird.
ASH_STREAM
Optionales Umschalten. Bei true-like wird die Antwort von Anbietern gestreamt, deren Adapter dies unterstützt (derzeit nur OpenAI). Standard: Ein.
ASH_TASK_MAX
Optionale Obergrenze für Ausführungsaufgaben, die von einer Anfrage abgeleitet werden. Standard: 6.
ASH_TASK_STALL_ROUNDS
Optionale Helfer-Stallrunden vor dem Anhalten. Standard: 2.
ASH_ALLOW
Optionale durch Kommas getrennte ausführbare Liste für run_unix_command. Andernfalls wird ~/.ash/.ash_allow verwendet, sofern vorhanden; Durch diese Überschreibung werden interne Ash-Tokens nicht erweitert.
ASH_DENY
Optionale durch Kommas getrennte Sperrliste zum expliziten Blockieren von Befehlen, Tools und Plugins. Andernfalls wird ~/.ash/.ash_deny verwendet, sofern vorhanden.
ASH_TOOL_OUTPUT_MAX
Optionale maximale erfasste Werkzeugausgabe in Bytes. Standard: 8192.
ASH_TOOL_TIMEOUT
Optionales Zeitlimit für lokale Werkzeugbefehle. Standard: 15s.
ASH_VERBOSE
Optionale Debug-Protokollierung und Ausführungs-Dashboard. Werte wie 1, true, on und debug aktivieren es.
SESSION_ID
Sitzungskennung für persistenten Verlauf und Protokollbenennung. Wird automatisch für interaktive Läufe generiert, wenn sie fehlen.

Dateien

  • ~/.ash/.ash_system – kanonische Systemeingabeaufforderung. $TOOLS_DIR_LIST, $PLUGINS_DIR_LIST und $IF_PYTHON_AVAILABLE sind interne Ash-Ersetzungen, niemals Umgebungsvariablen.
  • ~/.ash/.ash_allow – kanonische Befehls-, Tool- und Plugin-Zulassungsliste. Seine eigenständigen Direktiven $TOOLS_DIR_LIST und $PLUGINS_DIR_LIST ermöglichen erlaubte reguläre verwaltete Skripte und native Plugins; Ersetzen Sie durch wörtliche Namen für eine restriktive Richtlinie.
  • ~/.ash/.ash_deny – kanonische Sperrlistendatei zum Blockieren bestimmter Befehle, Tools oder Plugins.
  • ~/.ash/plugins/ – natives Binär-Plugin-Verzeichnis.
  • ~/.ash/history/ – Konversationsverlaufsdateien.
  • ~/.ash/scratch/ – sitzungsbezogener Scratch Dateien.
  • ~/.ash/.ash_snooze_until – Ablauf der automatischen Snooze-Eingabeaufforderung.

Exit-Status

ash gibt bei Erfolg 0 zurück. Es wird ein Wert ungleich Null zurückgegeben, wenn Konfiguration, Netzwerkanforderungen oder Toolausführung fehlschlagen.

Beispiele

echo "summarize this directory" | ash
ash install --shell bash
ash install --shell zsh --dry-run
