Erste Schritte

Was benötige ich, bevor ich ash verwenden kann?

Sie benötigen die ausführbare Datei ash, einen KI-Endpunkt und einen Modellnamen. Durch Ausführen von ash install werden diese automatisch konfiguriert: Es verwendet einen bereits festgelegten Cloud-Anbieter-API-Schlüssel oder einen laufenden lokalen Inferenzserver, wenn es gefunden wird. Andernfalls wird ein nummeriertes Anbietermenü angezeigt und zur Eingabe eines API-Schlüssels aufgefordert. Anschließend können Sie ein Modell aus der Modellliste des Endpunkts auswählen. Sie können AI_ENDPOINT und AI_MODEL auch manuell einstellen. Ein lokaler Endpunkt wie Ollama kann http://localhost:11434 verwenden, und ein LAN-Host wie http://brain.local:11434 oder eine private IP wird ebenfalls als lokal behandelt (es sei denn ASH_STRICT=1); Cloud-Endpunkte müssen HTTPS verwenden und erfordern außerdem AI_AUTH_TOKEN. Die Shell-Integration ist optional: Sie können ash "your question" immer direkt ausführen.

Wo wird ash installiert und wie überprüfe ich, ob meine Shell es finden kann?

Das verifizierte Installationsprogramm platziert ash in ~/.local/bin/ash und ash install fügt dieses Verzeichnis zu Ihrem hinzu PATH über die verwaltete Datei ~/.ash/.ash_env. Öffnen Sie ein neues Terminal und führen Sie dann zur Bestätigung command -v ash aus. Der Selbstaktualisierer installiert seine Ersatzbinärdatei am selben Speicherort ~/.local/bin/ash.

Wie verwende ich ash, ohne meine Shell zu ändern?

Übergeben Sie direkt eine zitierte Eingabeaufforderung: ash "how do I find large files?". Ohne Argumente akzeptiert ash auch eine nicht interaktive Standardeingabeaufforderung wie git diff | ash. Die direkte Verwendung ist die am wenigsten überraschende Option, wenn Sie ash lernen oder ein Skript schreiben.

Warum sagt ash, dass meine KI-Konfiguration unvollständig ist?

Überprüfen Sie, dass AI_ENDPOINT und AI_MODEL in der Umgebung, in der ash ausgeführt wird, nicht leer sind. Legen Sie für einen Cloud-Hostnamen auch AI_AUTH_TOKEN fest. Führen Sie printf '%s\n' "$AI_ENDPOINT" "$AI_MODEL" aus, um zu bestätigen, dass die ersten beiden Werte vorhanden sind, aber drucken Sie kein Authentifizierungstoken in eine Terminalaufzeichnung oder ein freigegebenes Protokoll.

Installieren und Aktualisieren

Funktioniert ash unter Windows 11?

Nicht nativ. ash unterstützt Bash, ZSH und Fish unter macOS, Linux und FreeBSD; Es gibt kein PowerShell-Installationsziel. Verwenden Sie WSL für das unterstützte Linux-Erlebnis.

Wie installiere ich ash im Windows-Subsystem für Linux (WSL)?

Installieren Sie es in Ihrer WSL-Distribution als Linux: curl -fsSL https://jonconradt.github.io/ash/install.sh | sh. Konfigurieren Sie dann AI_ENDPOINT und AI_MODEL und führen Sie ash install für die Shell aus, die in der WSL ausgeführt wird.

Wie aktualisiere ich ash auf die neueste Release-Version?

Führen Sie ash update unter macOS, Linux oder FreeBSD aus. Es lädt das neueste stabile passende Archiv herunter, überprüft das Release-Manifest mit seinem Sigstore-Bundle und SHA-256-Digest und installiert dann unter ~/.local/bin/ash. Wenn die Signaturprüfung fehlschlägt oder das Archiv nicht unterstützte Einträge enthält, ist eine interaktive Bestätigung erforderlich; Genehmigen Sie eine fehlgeschlagene Signatur nicht, es sei denn, Sie vertrauen unabhängig der Veröffentlichungsquelle. Nicht unterstützte Nutzlasten werden übersprungen und nicht interaktive Ausführungen lehnen diese Ausnahmen ab. Verwenden Sie ash update --version vX.Y.Z für eine bestimmte Version; Verwenden Sie --yes nur, wenn Sie benutzerdefinierte verwaltete Dateien ersetzen möchten.

Ich habe ash install ausgeführt. Warum ändert sich in diesem Terminal nichts?

Die Installation aktualisiert eine Startdatei; Der bereits laufende Shell-Prozess wird nicht neu geschrieben. Öffnen Sie ein neues Terminal oder laden Sie die Datei für Ihre Shell neu: source ~/.bashrc für Bash, source ~/.zshrc für zsh oder source ~/.config/fish/config.fish für Fish, es sei denn, Sie verwenden ein benutzerdefiniertes XDG_CONFIG_HOME.

Unbekannte Befehle sagen immer noch „nicht gefunden“. Wie behebe ich Probleme bei der Shell-Integration?

Führen Sie zuerst command -v ash aus; Der Wrapper kann keine Binärdatei aufrufen, die Ihre Shell nicht finden kann. Laden Sie dann die Shell neu oder starten Sie sie neu und prüfen Sie, ob ihre Startdatei den verwalteten Block >>> ash install >>> enthält. Führen Sie abschließend ash snooze off aus, da ein Snooze absichtlich unbekannte Befehle als normale „nicht gefunden“-Fehler zurücklässt.

Welche Dateien ändert ash install und kann ich eine Vorschau davon anzeigen?

Es fügt einen markierten ash-Block in der ausgewählten Shell-Startdatei hinzu oder aktualisiert ihn und verwaltet Dateien unter ~/.ash, einschließlich Konfiguration, Wrapper und gebündelte Tools. Führen Sie ash install --shell bash --dry-run aus, um eine Vorschau der Änderung der Startdatei anzuzeigen, ohne sie zu schreiben. Eine erneute Installation ist idempotent; Verwenden Sie --overwrite nur, wenn Sie verwaltete Bootstrap-Dateien aktualisieren möchten.

Unterstützt ash Fish?

Ja. Führen Sie ash install --shell fish aus. ash fügt einen verwalteten Block zu $XDG_CONFIG_HOME/fish/config.fish oder ~/.config/fish/config.fish hinzu, wenn XDG_CONFIG_HOME nicht festgelegt ist. Fish verwendet fish_command_not_found, sodass ein nicht aufgelöster Befehl ash mit seinen ursprünglichen Argumenten erreicht.

Warum nicht test und type in Kleinbuchstaben in Fish?

Fish reserviert diese Kleinbuchstaben als wesentliche integrierte Funktionen und lässt nicht zu, dass eine Funktion sie ersetzt. Verwenden Sie Test ... oder Type ..., um die Absicht von ash auszudrücken, oder rufen Sie ash "..." direkt auf. Andere kompatible Kollisions-Wrapper bleiben verfügbar.

Was ist mit ksh93?

ksh93 wird für die Shell-Integration nicht unterstützt. Sein FPATH-Verhalten kann nur eine Datei laden, die nach einem unbekannten Befehl benannt ist; Es gibt keinen generischen „Befehl-nicht-gefunden“-Rückruf, der das ash-Prompt-Routing oder den Broker-Lebenszyklus sicher implementieren kann.

KI und Verbindungen

Beinhaltet ash die KI?

Nein. ash ist ein Client für einen KI-Endpunkt, den Sie konfigurieren. Stellen Sie AI_ENDPOINT und AI_MODEL ein; ash unterstützt lokale Ollama- und andere lokale OpenAI-kompatible Server (LM Studio, llama.cpp, MLX, LocalAI, vLLM, text-generation-webui, Jan, GPT4All) und erkennt unterstützte Cloud-Provider-Adapter vom Endpunkt aus mit einer optionalen AI_PROVIDER-Überschreibung.

Was sind MCP-Server und wie füge ich sie hinzu? eins?

MCP-Server (Model Context Protocol) stellen Tools bereit, die ein KI-Modell aufrufen kann, beispielsweise Suche, Analyse oder dienstspezifische Aktionen. Um einen Remote-Streamable-HTTP-MCP-Server hinzuzufügen, geben Sie dessen URL in eine eigene Zeile in ~/.ash/.ash_allow ein und führen Sie dann ash erneut aus. Zum Beispiel: https://mcpplaygroundonline.com/mcp-complex-server. Ash stellt über seinen Broker eine Verbindung her und bietet dem Modell die Tools des Servers an. Verwenden Sie nur Server, denen Sie vertrauen: Deren Tools können in Ihrem Namen Aktionen ausführen. HTTPS ist erforderlich, außer für Localhost-Entwicklungsserver. Vorhandene ~/.ash/mcp.json-Dateien werden nicht mehr gelesen; Verschieben Sie ihre URLs nach .ash_allow. Wenn die MCP-Initialisierung fehlschlägt, wird ash ohne Remote-MCP-Tools fortgesetzt: Es warnt in interaktiven Sitzungen und bleibt in nicht interaktiven Sitzungen stumm.

Können geplante Jobs MCP-Server verwenden?

Nein. Geplante und andere nicht interaktive Jobs erben nicht den Broker einer interaktiven Shell, sodass Remote-MCP-Tools nicht verfügbar sind. Ash führt die Eingabeaufforderung weiterhin ohne MCP-Tools aus und unterdrückt diesen erwarteten Initialisierungsfehler. Eine Eingabeaufforderung, die auf MCP basiert, kann daher ohne die angeforderten Daten oder Aktionen beendet werden. Planen Sie keine Eingabeaufforderungen, die MCP erfordern.

Funktioniert MCP, wenn ASH_STRICT=1?

Ja. Eine HTTP(S)-URL-Zeile registriert explizit einen MCP-Server und wird nicht als ausführbare Shell-Datei behandelt. Der strikte Modus deaktiviert konfigurierte MCP-Server nicht. Der Schutz vor nicht vertrauenswürdigen Ausgaben von Ash wird weiterhin auf zurückgegebene Tool-Inhalte angewendet.

Wie funktioniert MCP OAuth und wo werden Anmeldeinformationen gespeichert?

Für einen OAuth-geschützten Server öffnet Ash die Autorisierungsseite im Desktop-Browser, wenn eine GUI verfügbar ist; Wenn kein Browser geöffnet werden kann, wird eine URL zur manuellen Autorisierung in einem Browser auf demselben Host gedruckt. Verwenden Sie ash mcp add <url> --no-browser, um immer den Terminalfluss zu verwenden. Bei direkten OAuth-Verbindungen lässt die Erkennung nicht öffentliche IP-Adressen nur für die genau registrierte MCP-Autorität zu; Andere OAuth-Hosts unterliegen weiterhin der Blockierung nicht öffentlicher Adressen. Ein konfigurierter Egress-Proxy ist für die Filterung seiner Zieladressen verantwortlich. Der Broker übernimmt den Rückruf, den Token-Austausch, die Aktualisierung und die dauerhafte MCP-Sitzung. Anmeldeinformationen werden im Anmeldeinformations-Manager des Betriebssystems gespeichert, sofern verfügbar. Wenn es nicht verfügbar ist, konfigurieren Sie den Fallback für verschlüsselte Dateien mit einem zufälligen 32-Byte-ASH_MCP_CREDENTIAL_KEY; Ash speichert niemals den Schlüssel selbst.

Wo finde ich den AUTH_KEY für die beliebtesten Cloud-KI-Anbieter?

ash nennt diesen Wert AI_AUTH_TOKEN; Es werden keine Anbieterschlüssel erstellt oder verteilt. Erstellen Sie einen Schlüssel in Ihrem Anbieterkonto, z. B. OpenAI, Anthropic, Google AI Studio, Azure OpenAI, Mistral, Cohere, Groq, xAI, DeepSeek, Together AI, OpenRouter, HuggingFace oder Ollama und exportieren Sie es dann als Umgebungsvariable des Anbieters (oder direkt AI_AUTH_TOKEN). ash install erkennt die meisten dieser anbieterspezifischen Umgebungsvariablen automatisch. Cloud-Endpunkte müssen HTTPS verwenden und ein Token erfordern; Private/LAN-Adressen und .local-Hostnamen werden nicht als Cloud-Endpunkte behandelt, es sei denn, ASH_STRICT=1 ist festgelegt.

Öffnet ash jedes Mal eine neue Verbindung?

Nicht für die normale interaktive Nutzung der Unix-Shell. Bash, zsh und Fish starten einen Broker pro Shell-Sitzung, kommunizieren mit ihm über einen privaten Unix-Socket und verwenden seinen begrenzten HTTP-Verbindungspool wieder. Der Broker wird nach Inaktivität beendet. Geplante Jobs verwenden direkte Anfragen anstelle eines persistenten Shell-Brokers.

Verwendet Fish den Broker?

Ja. Der Fish-Wrapper startet und verwendet pro Sitzung denselben Broker wie bash und zsh, aktualisiert seine Lease unmittelbar vor einer ash-Anfrage und hält die Broker-Einrichtung ruhig.

Was passiert, wenn eine Anfrage langsam oder nicht verfügbar ist oder ich meine Meinung ändere?

Drücken Sie Ctrl-C, um eine laufende Anfrage abzubrechen. Das standardmäßige Zeitlimit für AI-Anfragen beträgt drei Minuten. Setzen Sie AI_TIMEOUT, zum Beispiel AI_TIMEOUT=90s, um es zu ändern. ash Wiederholbare KI-Fehler werden standardmäßig bis zu dreimal mit einem kurzen begrenzten Backoff wiederholt. Optimieren Sie dieses Verhalten mit ASH_RETRY_MAX_ATTEMPTS, ASH_RETRY_BASE_DELAY und ASH_RETRY_MAX_DELAY.

Sicherheit und Kontrolle

Wie sperre ich ash, um sicherer zu sein, und welche Auswirkungen hat das?

Halten Sie die Liste der ausführbaren Dateien eng, bevorzugen Sie schreibgeschützte Tools und fügen Sie keine privilegierten oder destruktiven Befehle hinzu. Legen Sie ASH_STRICT=1 fest, um erkannte Eingabeaufforderungsinjektionsmuster aus der Ausgabe nicht vertrauenswürdiger Tools, Dateien, Skripts, Pipelines und untergeordneter Agenten zu blockieren. Dadurch kann auch legitimer Text ausgeblendet werden, der einem Injektionsversuch ähnelt. Die Zulassungsliste ist eine Ausführungsgrenze, keine Sandbox: ash und zugelassene Tools laufen weiterhin wie Sie.

Kann ash destruktive Befehle wie rm ausführen?

Nicht mit der installierten Standard-Zulassungsliste. Von rm, mv, dd, chmod, chown, kill und sudo wird ausdrücklich abgeraten. Wenn Sie eines davon hinzufügen, kann ash es mit Ihren Berechtigungen anfordern; Überprüfen Sie diese Entscheidung sorgfältig.

Wie ändere ich die Befehle, die ash ausführen darf?

Bearbeiten Sie ~/.ash/.ash_allow und listen Sie die Namen der nackten ausführbaren Dateien auf, einen pro Zeile oder durch Kommas getrennt. Seine eigenständigen Direktiven $TOOLS_DIR_LIST und $PLUGINS_DIR_LIST ermöglichen berechtigte verwaltete Skripte und native Plugins; Ersetzen Sie sie durch wörtliche Namen für eine restriktive Richtlinie. Geeignete Skripte und Plugins sind reguläre Dateien in ~/.ash/tools/ oder ~/.ash/plugins/ mit Lese- und Ausführungsbits. Sie können Befehle auch explizit verweigern, indem Sie sie zu ~/.ash/.ash_deny hinzufügen. Alternativ können Sie ASH_ALLOW oder ASH_DENY auf eine durch Kommas getrennte Liste setzen. Änderungen werden bei der nächsten ash-Anfrage gelesen.

Unter welchem ​​Benutzer läuft ash?

ash und jedes erlaubte Tool wird als der Benutzer ausgeführt, der ash startet. Dadurch werden die Privilegien nicht erhöht. Der verwaltete ~/.ash-Arbeitsbereich ist berechtigungsgeschützt, seine Inhalte bleiben jedoch für Ihren Benutzer und jeden Prozess, den Sie ausdrücklich zulassen, zugänglich.

Vertraut ash dem per Pipe empfangenen Text genauso wie dem Benutzertext? Welche Schutzmaßnahmen gibt es für bösartige Daten?

Ja. Wenn ash keine Befehlszeilenargumente empfängt und die Standardeingabe weitergeleitet wird, wird diese Eingabe als Benutzeraufforderung behandelt. Leiten Sie nicht vertrauenswürdige Webseiten, Protokolle oder generierten Text nicht direkt an ash weiter, es sei denn, Sie beabsichtigen, dies als Eingabeaufforderung zu autorisieren. Dies unterscheidet sich von der durch ash verwalteten Tool-, Datei-, Skript-, Pipeline- und untergeordneten Agentenausgabe: ash kennzeichnet diese Ergebnisse als nicht vertrauenswürdige Beweise und weist das Modell an, niemals den daraus resultierenden Anweisungen zu folgen. Legen Sie ASH_STRICT=1 fest, um erkannte Prompt-Injection-Phrasen zusätzlich in nicht vertrauenswürdigen Beweisen zu ersetzen. Die Ausführungsregeln „Zulassungsliste“ und „Direct-Argv“ gelten weiterhin für die Tool-Ausführung.

Sind meine ash-Dateien für andere Benutzer auf diesem Computer privat?

Während der Installation härtet ash das Verzeichnis ~/.ash auf Berechtigungen, die nur dem Eigentümer vorbehalten sind, und verwaltete Dateien auf Berechtigungen aus, die vom Eigentümer gelesen und beschreibbar sind. Dies schützt vor anderen lokalen Konten mit normalen Unix-Berechtigungen, jedoch nicht vor Ihrem eigenen Konto, Administratoren, Backups oder Software, die Sie mit Zugriff auf Ihr Home-Verzeichnis ausführen möchten.

Tools und Workflow

Unterstützt ash Pipes und andere Unix-Traditionen?

Ja. Sie können Text als Eingabeaufforderung an ash weiterleiten, zum Beispiel git diff | ash. Für von KI angeforderte Tool-Pipelines unterstützt ash zwei bis sechzehn ausführbare Dateien auf der Zulassungsliste, die direkt ohne Shell verbunden sind, wie z. B. ls | grep pattern | pbcopy. Shell-Steuerungsmuster in Tool-Argumenten werden blockiert und jede ausführbare Datei in einer von ash verwalteten Pipeline muss auf die Zulassungsliste gesetzt werden.

Wird ash Befehle in meinen Shell-Skripten, SSH-Befehlen oder Cron-Jobs neu interpretieren?

Nein. Die Bash- und ZSH-Integrations-Wrapper kehren in nicht interaktiven Shells sofort zurück, sodass Skripte, CI-Jobs, SSH-Einzeiler und Cron-Befehle das normale Verhalten bei nicht gefundenen Befehlen beibehalten. Verwenden Sie einen expliziten Aufruf wie ash "summarize this log" oder some-command | ash, wenn die Automatisierung ash aufrufen soll.

Wie verhindere ich, dass ash meine Befehle für ein paar Minuten interpretiert?

Führen Sie ash snooze standardmäßig fünf Minuten lang aus oder geben Sie eine Dauer an, z ash snooze 30s oder ash snooze 1h. Führen Sie ash snooze off aus, um sofort fortzufahren. Snooze unterbricht die automatische Weiterleitung bei nicht gefundenen Befehlen und das Wrapper-Routing. explizite ash ...-Befehle funktionieren weiterhin.

Wie kann ich ash debuggen und weitere Informationen zu seiner Funktion sehen?

Setzen Sie ASH_VERBOSE=1, bevor Sie ash ausführen, um eine strukturierte Debug-Ausgabe und ein Terminalausführungs-Dashboard zu aktivieren. Legen Sie ASH_LOG_FILE fest, um Debug-JSON in eine Datei zu schreiben; ASH_LOG_MAX_BYTES steuert die Rotation und ist standardmäßig auf 1 MiB eingestellt, wenn eine Protokolldatei konfiguriert ist.

Welche Grenzwerte gelten, wenn ash Tools ausführt?

Standardmäßig hat jeder Tool-Aufruf eine Zeitüberschreitung von 15 Sekunden und erfasst bis zu 8192 Byte Ausgabe. Eine KI-Anfrage kann bis zu 16 Tool-Loop-Iterationen umfassen, und eine von ash verwaltete Pipeline hat zwei bis sechzehn Stufen. Passen Sie das Tool-Timeout und die Ausgabegrenze mit ASH_TOOL_TIMEOUT und ASH_TOOL_OUTPUT_MAX an; Halten Sie die Ausgabe mit Befehlen wie head, tail oder grep im Fokus.

Wo ist die Standard-Systemeingabeaufforderung?

Die kanonische Eingabeaufforderungsdatei ist ~/.ash/.ash_system und wird standardmäßig aus dem Paket installiert, wenn Sie ash install ausführen. ash liest diese Datei zuerst. Wenn es nicht vorhanden ist, greift ash auf .ash_system im aktuellen Arbeitsverzeichnis und dann auf ~/.ash_system zurück. Gewöhnliche $VARIABLE-Werte werden aus der Umgebung erweitert, aber $TOOLS_DIR_LIST, $PLUGINS_DIR_LIST und $IF_PYTHON_AVAILABLE sind reservierte interne Ash-Ersetzungen und werden niemals von der Umgebung abgeleitet.

Wohin lege ich meine eigenen Skripte und nativen Plugins? ash als Tools aufrufen?

Python-Skripte in ~/.ash/tools/ und kompilierte native Binär-Plugins in ~/.ash/plugins/ einfügen. Stellen Sie sicher, dass sie ausführbar sind, und fügen Sie den bloßen Namen der ausführbaren Datei zu ~/.ash/.ash_allow hinzu (oder verlassen Sie sich auf $TOOLS_DIR_LIST / $PLUGINS_DIR_LIST). ash ruft keine Shell für zulässige Unix-Befehle und Plugins auf.

Was sind Best Practices für ein Tool oder Plugin, damit die KI seinen Zweck und seine Verwendung versteht?

Folgen Sie dem Standard-Tool-/Plugin-Muster: Stellen Sie vorhersehbare Optionen mit CLI-Argumenten bereit; und implementieren Sie eine --ai-docs-Option, die Funktionen, jedes Argument und jeden Standard, Ausgabeschema, Fehlerzustände und wann die KI das Tool verwenden soll, erklärt. Geben Sie kompakt strukturiertes JSON mit einem status-Feld und umsetzbaren Fehlerdetails aus, statt Prosa mit Daten vermischt. Halten Sie die Ausgabe begrenzt, validieren Sie Eingaben, legen Sie Netzwerk-Timeouts fest, behandeln Sie erwartete Fehler und sorgen Sie dafür, dass das Tool wiederholt aufgerufen werden kann. Fügen Sie den bloßen Dateinamen zu ~/.ash/.ash_allow hinzu; ash kann es nur ausführen, wenn es auf der Zulassungsliste steht und nicht in ~/.ash/.ash_deny aufgeführt ist.

Was sind die bereitgestellten Tool-Skripte und nativen Plugins?

Die installierten Bootstrap-Python-Skripte sind headlines.py, wikipedia.py und yfinance.py in ~/.ash/tools/. Die bereitgestellten nativen Plugins sind what_time_is_it (Go), flip_a_coin (Rust) und calculator (TypeScript) in ~/.ash/plugins/.

Kann ash Subagenten aufrufen?

Ja. Ein übergeordneter Agent kann run_sub_agent für eine fokussierte, unabhängige Aufgabe verwenden. Ein untergeordnetes Element erbt das Arbeitsverzeichnis, die Konfiguration, die Tools und die Betriebssystemberechtigungen, gibt ein begrenztes Ergebnis zurück und kann kein weiteres untergeordnetes Element erstellen. Das Standardmaximum beträgt sechs Unteragenten pro übergeordnetem Lauf und kann mit ASH_MAX_AGENTS geändert werden.

Kann ash Speicherdateien generieren, um komplexe Aufgaben und das, was es in der Sitzung gelernt hat, zu verfolgen?

Ja. Es kann persistente Arbeitsbereichsdateien unter ~/.ash schreiben, die in ~/.ash/inventory.md verfolgt werden, und sitzungsbezogene Scratch-Dateien unter ~/.ash/scratch/<session-id>/. Verwenden Sie persistente Arbeitsbereichsdateien für Informationen, die Sie behalten möchten. Verwenden Sie Arbeitsdateien für temporäre Pläne, Notizen und Hilfsartefakte.

Kann ash Arbeiten für später planen?

Ja, über seine KI-Tools. Unter macOS verwendet die einmalige Planung einen benutzerspezifischen launchd LaunchAgent und erfordert launchctl. Unter Linux werden wiederkehrende Zeitpläne über Ihren Benutzer crontab unterstützt; ash verwaltet nur seine eigenen markierten Einträge. Der einmalige launchd-Scheduler ist unter Linux nicht verfügbar. Verwenden Sie daher einen Cron-Eintrag oder einen anderen Linux-Scheduler für einen einmaligen Linux-Job. Geplante Ausführungen erhalten eine eingeschränkte Umgebung und verwenden direktes HTTPS anstelle eines interaktiven Shell-Brokers. Stellen Sie daher sicher, dass die erforderliche KI-Konfiguration für den geplanten Job verfügbar ist. Sie können keine Remote-MCP-Tools verwenden. Ash läuft ohne sie und warnt nicht in nicht interaktiven Sitzungen. Planen Sie keine Eingabeaufforderungen, die MCP erfordern.

Sitzungen und Speicher

Wo sind die Verlaufs- oder Protokolldateien für ash?

Der Gesprächsverlauf wird als JSON in ~/.ash/history/<SESSION_ID>.json gespeichert; Geplante Läufe verwenden task_<SESSION_ID>.json. Wenn die geplante Debug-Protokollierung aktiviert ist, ist der Standardspeicherort für das Protokoll ~/.ash/logs/task_<SESSION_ID>.log. Mit ASH_LOG_FILE können Sie einen anderen Debug-Protokollpfad auswählen.

Wie lange werden Verlaufsdateien aufbewahrt?

ash entfernt Verlaufs-JSON-Dateien, die älter als 14 Tage sind, während der normalen Anwendungsbereinigung mit einem Bereinigungsbudget von 300 ms, sodass der Abschluss nicht verzögert wird. Das Fenster „Letzte Nachrichten“ ist separat: Es speichert standardmäßig bis zu 40 Nachrichten pro Konversation und kann mit ASH_HISTORY_MAX geändert werden.

Wie lösche ich eine Konversation oder beginne neu?

Der Verlauf ist nach Sitzungs-ID und KI-Endpunkt/Modellschlüssel getrennt. Starten Sie eine neue Terminalsitzung für eine neue Sitzungs-ID oder entfernen Sie die entsprechende JSON-Datei unter ~/.ash/history/, wenn Sie den lokalen Konversationsverlauf absichtlich verwerfen möchten. Durch das Entfernen einer Verlaufsdatei wird weder ein Anbieterschlüssel widerrufen noch anbieterseitige Daten gelöscht. Verwalten Sie diese separat mit dem Anbieter.

Was ist SESSION_ID und wo wird es generiert?

Es handelt sich um die sitzungsspezifische Kennung, die zum Trennen von Verlauf, Arbeitsspeicher, Broker-Sockets und geplanten Protokollnamen verwendet wird. Die verwaltete Shell-Umgebung generiert beim Start der Shell einen zufälligen 16-stelligen alphanumerischen Wert aus /dev/urandom; ash erstellt auch eine, wenn ein interaktiver Aufruf keinen Wert hat.

Kann ich die Implementierung des SESSION_ID-Generators ersetzen?

Sie können Ihr eigenes SESSION_ID bereitstellen, bevor Sie mit ash beginnen, oder Ihre lokal verwaltete Umgebungsdatei anpassen, aber ash validiert sie. Gültige IDs sind maximal 128 Zeichen lang und bestehen aus Buchstaben, Ziffern, Unterstrichen und Bindestrichen sowie einem optionalen Punktsuffix für die untergeordnete Sitzung. Verwenden Sie keine nicht vertrauenswürdigen oder gemeinsam genutzten Werte: Kollisionen kombinieren Sitzungsverlauf und Laufzeitstatus.

Support und Community

Wie melde ich einen Fehler?

Öffnen Sie ein Problem unter github.com/Jonconradt/ash/issues mit der ash-Version oder einem Commit, Ihrem Betriebssystem und Ihrer Shell sowie der für das Problem relevanten Konfiguration Geheimnisse entfernt, reproduzierbare Schritte und das beobachtete Ergebnis.
