¿Qué son los servidores MCP y cómo agrego uno?

Los servidores MCP (Protocolo de contexto de modelo) exponen herramientas a las que un modelo de IA puede llamar, como búsqueda, análisis o acciones específicas de servicio. Los servidores remotos no están habilitados de forma predeterminada. Para agregar un servidor HTTP MCP Streamable confiable, useash mcp add <url>o agregue su URL en su propia línea en$XDG_CONFIG_HOME/ash/.ash_allow(por defecto~/.config/ash/.ash_allow).Ashse conecta a través de su broker y ofrece las herramientas del servidor al modelo. Utilice únicamente servidores en los que confíe: sus herramientas pueden realizar acciones en su nombre. Se requiere HTTPS excepto para los servidores de desarrollo localhost. Si la inicialización de MCP falla,ashcontinúa sin herramientas MCP remotas: advierte en sesiones interactivas y permanece en silencio en sesiones no interactivas.

¿Pueden los trabajos programados utilizar servidores MCP?

No. Las tareas programadas y otras tareas no interactivas no heredan el intermediario de un shell interactivo, por lo que las herramientas MCP remotas no están disponibles.Ashaún ejecuta el mensaje sin herramientas MCP y suprime este error de inicialización esperado. Por lo tanto, un mensaje que se basa en MCP puede finalizar sin los datos o la acción solicitada. No programe mensajes que requieran MCP.

¿Funciona MCP cuandoASH_STRICT=1?

Sí. Una línea URL HTTP(S) registra explícitamente un servidor MCP y no se trata como un ejecutable de shell. El modo estricto no deshabilita los servidores MCP configurados. todavía se aplicaAshProtecciones de salida no confiables para el contenido de la herramienta devuelta.

¿Cómo funciona MCP OAuth y dónde se almacenan las credenciales?

Para un servidor protegido con OAuth,Ashabre la página de autorización en el navegador de escritorio cuando hay una GUI disponible; si no puede abrir un navegador, imprime una URL para autorizar manualmente en un navegador en el mismo host. Usarash mcp add <url> --no-browserutilizar siempre el flujo terminal. Para conexiones OAuth directas, el descubrimiento permite direcciones IP no públicas solo para la autoridad MCP registrada exacta; otros hosts de OAuth siguen sujetos al bloqueo de direcciones no públicas. Un proxy de salida configurado es responsable de filtrar sus direcciones de destino. El corredor maneja la devolución de llamada, el intercambio de tokens, la actualización y la sesión MCP persistente. Las credenciales se almacenan en el administrador de credenciales del sistema operativo cuando están disponibles. Si no está disponible, configure el respaldo del archivo cifrado usando un archivo aleatorio de 32 bytes.ASH_MCP_CREDENTIAL_KEY;Ashnunca almacena la clave en sí.

Sesiones y almacenamiento

¿Dónde están los archivos de historial o registro deash?

El historial de conversaciones se almacena como JSON en$XDG_STATE_HOME/ash/history/(por defecto~/.local/state/ash/history/). El historial programado y los registros de depuración se almacenan en ese mismo directorio de estado. Puede elegir otra ruta de registro de depuración conASH_LOG_FILE.

¿Cuánto tiempo se conservan los archivos históricos?

ashelimina los archivos JSON del historial de más de 14 días durante la limpieza normal de la aplicación, con un presupuesto de limpieza de 300 ms para que la salida no se retrase. La ventana de mensajes recientes está separada: mantiene hasta 40 mensajes por conversación de forma predeterminada y se puede cambiar conASH_HISTORY_MAX.

¿Cómo borro una conversación o empiezo de nuevo?

El historial está separado por ID de sesión y clave de modelo/punto final de IA. Inicie una nueva sesión de terminal para una nueva ID de sesión o elimine el archivo JSON relevante en$XDG_STATE_HOME/ash/history/(por defecto~/.local/state/ash/history/) cuando intencionalmente deseas descartar ese historial de conversación local. Eliminar un archivo de historial no revoca una clave de proveedor ni elimina datos del lado del proveedor; gestionarlos por separado con el proveedor.

Qué esASH_SESSION_IDy donde se genera?

es elAsh-Identificador de propiedad por sesión que se utiliza para separar el historial, el espacio temporal, los sockets del intermediario y los nombres de los registros programados. El entorno de shell administrado crea uno cuando se inicia el shell y lo conserva cuando se obtienen recursos;Ashcrea uno para invocaciones sin un valor proporcionado por el shell. un genéricoSESSION_IDes ignorado.

¿Puedo proporcionar el mío?ASH_SESSION_ID?

Sí.Ashvalida los ID explícitos y rechaza los valores no válidos en lugar de reemplazarlos silenciosamente. Los ID válidos tienen como máximo 128 caracteres y utilizan letras, dígitos, guiones bajos y guiones, con un sufijo de punto opcional para la sesión secundaria. No utilice valores compartidos o que no sean de confianza: las colisiones combinan el historial de sesiones y el estado de tiempo de ejecución.
