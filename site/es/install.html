Antes de comenzar

  1. Un sistema y shell compatibles: macOS o Linux en amd64/x86_64 o arm64/aarch64, o FreeBSD en amd64. Utilice Bash, zsh o Fish. Los paquetes de Arch son solo x86_64. No hay un instalador nativo de Windows/PowerShell.
  2. Acceso de descarga: una conexión a Internet que funcione y acceso HTTPS confiable a GitHub, el repositorio de paquetes seleccionado y su proveedor de modelo. La inferencia local aún necesita una descarga del modelo inicial.
  3. Permisos: un directorio de inicio grabable para recursos por usuario. Los paquetes del sistema Linux y macOS .pkg necesitan acceso de administrador; ejecute Homebrew y ash install como su usuario normal.
  4. Un modelo: ya sea un servidor de inferencia local con un modelo descargado o una cuenta de nube/clave API. Elija un modelo que admita la llamada de herramientas, no un modelo de solo imagen/audio. Las necesidades de RAM, disco y GPU locales dependen de ese modelo.

Los paquetes prediseñados ash no requieren herramientas de compilación Go, Rust, Node.js o Xcode. Un administrador de paquetes puede tener sus propios requisitos previos; Siga primero las instrucciones de configuración oficiales.

Opcional: herramientas Python incluidas

Básicoashsu uso no requiere Python. Las herramientas Python incluidas necesitan Python 3 convenvyensurepip, además de acceso para descargar sus dependencias. En Debian/Ubuntu, instalepython3ypython3-venv; Homebrew Python incluye soporte para venv. En FreeBSD, utilice el paquete pip que coincida con su versión de Python. Luego vuelva a ejecutarash install. La instalación crea un entorno aislado bajo$XDG_DATA_HOME/ash/venv(por defecto~/.local/share/ash/venv); una falla desactiva esas herramientas, no las básicasash.

Debian y Ubuntu: APT

Requisitos previos: amd64 o arm64, acceso de administrador, APT,curl,gpgy certificados de CA. Instale las herramientas clave/descarga que faltan usando su distribución antes de agregar el repositorio. La liberación se llamastable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Antes de importar cualquier clave de repositorio, verifique su huella digital con una fuente de editor confiable. La huella digital de la clave VersionX es32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. APT verifica los metadatos del repositorio firmados y los resúmenes del paquete que contiene; la clave tiene un alcance consigned-by. Actualizar consudo apt update && sudo apt upgrade ash; eliminar consudo apt remove ash.

Sistemas compatibles con Fedora y RHEL: DNF

Requisitos previos: x86_64 o aarch64, acceso de administrador, DNF/RPM,curl,gpgy certificados de CA. Instale las herramientas que faltan en su distribución. Inspeccione la clave y compare la huella digital anterior antes de importarla:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

Los archivos RPM no están firmados individualmente.repo_gpgcheck=1verifica los metadatos del repositorio que cubren sus sumas de verificación;gpgcheck=0refleja las firmas ausentes por paquete, no la verificación del repositorio deshabilitada. Si su política requiere cargas útiles RPM firmadas, este repositorio no la cumple. Actualizar consudo dnf upgrade ash; eliminar consudo dnf remove ash.

Arco Linux: Pacman

Requisitos previos: x86_64, acceso de administrador, Pacman con su llavero inicializado,curl, ygpg. Verifique que la huella digital de la clave mostrada coincida con la anterior antes de confiar en ella. Agregue el repositorio una vez, no en cada actualización:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman verifica las firmas de paquetes y bases de datos. Mantenga Arch sincronizado consudo pacman -Syu, no una actualización parcial; eliminarashconsudo pacman -R ash.

Inicializar y verificar

Después de instalar los binarios, ejecute la configuración de forma interactiva como su usuario normal. Si no desea la integración del shell, puede instalar solo Ash. Probablemente esto no sea lo que quieres. El valor real de ash es la integración del shell a continuación. La configuración de solo recursos no modifica los archivos de inicio:

ash install

La instalación que probablemente desee utilizar implica la integración del shell. Esto cambiará su .bashrc (o el equivalente de su shell) para incluir Ash. Para habilitar la integración de comando no encontrado, elija exactamente un comando para el shell que utiliza:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Pescado

ash install --shell fish --shell-integration

usos de bash~/.bashrc, usos zsh~/.zshrcy usos del pescado$XDG_CONFIG_HOME/fish/config.fish(por defecto~/.config/fish/config.fish). Abra un nuevo shell después; los shells existentes conservan su intermediario en ejecución. La integración antepone~/.local/bina RUTA: elimine una copia local del usuario anterior antes de esperar que se seleccione un paquete del sistema.

Si falta la configuración del proveedor, la configuración detecta claves de proveedor existentes o un servidor local en ejecución; de lo contrario, ofrece un menú de proveedores y solicita credenciales. Elija un modelo disponible con capacidad para herramientas. Se conservan las configuraciones válidas existentes, por lo que volver a ejecutar la instalación no es un comando de cambio de proveedor.

Los ajustes se almacenan en$XDG_CONFIG_HOME/ash/.ash_env(por defecto~/.config/ash/.ash_env, permisos de archivos privados). La integración administrada los carga. Sin integración, los usuarios de Bash/zsh pueden obtener ese archivo en su configuración de inicio normal; Los usuarios de peces deben establecer el correspondienteASH_AI_*variables que utilizan la sintaxis de Fish, no generan el archivo en formato Bash. Proteja cualquier archivo que contenga tokens y nunca lo confirme.

Para una instalación local de usuario sin integración, agregue su directorio real a PATH. bash/zsh:export PATH="$HOME/.local/bin:$PATH". Pez:fish_add_path "$HOME/.local/bin". Persiste en esto usando la configuración de inicio de tu shell; sustituya su directorio de instalación personalizado cuando corresponda.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

Los primeros comandos deberían resolverse en la instalación que eligió. El mensaje necesita un servidor en ejecución o credenciales de nube válidas; instalar ash no instala un modelo.

Este es el modelo utilizado por el proyecto para generar notas de la versión y realizar tareas de desarrollo.

Instalación de scripts: una alternativa, no la primera opción

Prefiere Homebrew, APT, DNF o Pacman: rastrean los archivos de su propiedad, verifican las descargas usando su configuración de confianza y proporcionan actualizaciones/eliminación familiares. Todavía requieren editores confiables y acciones de instalación de paquetes.

La secuencia de comandos de un sitio web ejecuta código con los permisos de su cuenta. Un sitio web, un editor o una secuencia de comandos cambiante comprometidos pueden leer secretos, alterar archivos o instalar otro software. HTTPS protege el transporte, no las intenciones de ese código. Canalizar una URL directamente a un shell la ejecuta antes de que puedas revisarla. Las comprobaciones de firmas de archivo del script no autentican el script en sí. Nunca lo ejecutes con sudo ni desactives su verificación.

Requisitos previos: un sistema operativo/arquitectura compatible,$SHELLidentificando Bash/zsh/Fish,aval de tienda de firmas,tar,uname,install, utilidades de shell estándar, un comando SHA-256 (sha256sum,shasum, osha256), y un descargador (curl,wget, o Python). El ejemplo usa curl. FreeBSD también necesita Bash. Su directorio de inicio/instalación debe poder escribirse.

Descárguelo en un archivo local, inspecciónelo con un editor y ejecútelo solo si confía en su fuente y comportamiento. La inspección no es garantía de seguridad; No ejecute estos pasos a ciegas:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

Después de la inspección, ejecute la copia guardada como su usuario normal:

sh ./ash-install.sh
rm ./ash-install.sh

install.shdescarga la última versión, verifica su resumen de archivo y manifiesto de suma de comprobación firmado por Sigstore, e instalaash/ash-brokeren~/.local/bin. Los complementos nativos desaparecen$XDG_DATA_HOME/ash/plugins. Ejecuta la configuración por usuario y pregunta antes de habilitar la integración del shell. Sin una terminal interactiva, es posible que se omitan las indicaciones del proveedor/integración: ejecutarash installinteractivamente después.

Puedes configurarASH_INSTALL_DIRantes de ejecutar el script para elegir otro destino. Agregue ese destino a PATH usted mismo.La actualización automática solo se admite en~/.local/bin; los destinos personalizados requieren reemplazo manual. El script no tiene selector Beta/Nightly.

Verificar un paquete o archivo directo

Requisitos previos: cofirmante y una utilidad SHA-256. Desde la misma versión publicada, descargue su paquete/archivo,SHA256SUMS, ySHA256SUMS.sigstore.json. Trabajar en un nuevo directorio. ReemplazarvX.Y.Zcon la etiqueta exacta, incluido un sufijo previo al lanzamiento, si corresponde:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Sólo después de que esto tenga éxito, calcule el resumen de su archivo conshasum -a 256 PACKAGEen MacOS,sha256sum PACKAGEen Linux, osha256 -q PACKAGEen FreeBSD. ReemplazarPACKAGEcon el nombre del archivo descargado y compárelo exactamente con la entrada de ese nombre de archivo en el manifiesto verificado. Deténgase si falta una entrada o si no coincide. Una suma de comprobación sin firmar descargada junto a un archivo no equivale a metadatos de editor verificados.

Actualizaciones y los tres canales

  • Lanzamiento (recomendado):versiones publicadas estables comovX.Y.Z; la configuración del repositorio llama a estostable.
  • Beta:pruebas previas al lanzamiento, etiquetadovX.Y.Z-beta.N; esperar cambios y regresiones.
  • Nocturno:cambios recientes en la rama predeterminada, etiquetadosvX.Y.Z-nightly.YYYYMMDD.N; el mayor riesgo de regresión. Las compilaciones están programadas, pero pueden omitirse si nada cambia o falla la publicación.

Una versión publicada actualiza la fórmula Homebrew correspondiente o el repositorio de Linux firmado. Lo recibe cuando ejecuta el comando de actualización del administrador propietario (o lo hace su propia política de actualización del sistema operativo). La publicación, las actualizaciones del repositorio y la implementación del sitio web pueden retrasarse entre sí; Consulta disponibilidad antes de cambiar de canal. ash no instala silenciosamente actualizaciones binarias en segundo plano.

Haga una copia de seguridad de la configuración antes de cambiar. Luego use los comandos de actualización normales de APT/DNF/Pacman desde las secciones del sistema operativo; no deje varias fuentes de canal ash habilitadas.

Actualizaciones de la versión local del usuario

ash update

Esto verifica e instala una versión estable solo cuando el activoashejecutable está bajo~/.local/bin. También actualiza los activos/complementos incluidos, con opciones para archivos personalizados.ash update --version vX.Y.Zselecciona una etiqueta estable, no un canal; no es un comando de degradación. no hay--channelopción. Las instalaciones del administrador de paquetes, las instalaciones .pkg de macOS y los destinos de scripts personalizados deben utilizar su administrador/instalador propietario. Bash

zsh

ash install --shell zsh --disable-shell-integration

Pescado

Eliminar cualquierash-líneas de RUTA/entorno específicas que agregó manualmente, no configuración de shell no relacionada. Cercaash-habilitó los shells posteriormente para que sus intermediarios propiedad del shell salgan.

2. Deje que el administrador de paquetes propietario elimine sus archivos.

Cerveza casera (lanzamiento)

brew uninstall ash

APTO

Abandono

Pacman

Limpieza de repositorio opcional: elimine elasharchivo fuente/etc/apt/sources.list.d/versionx.listy su dedicado/etc/apt/keyrings/versionx-keyring.gpg, o elasharchivo del repositorio/etc/yum.repos.d/versionx.repo, o elash [versionx]sección de/etc/pacman.conf. Elimine una clave de confianza RPM/Pacman importada solo después de confirmar su huella digital y que nada más dependa de ella; nunca elimine el conjunto de claves compartido de una distribución.

3a. Eliminación manual de .pkg de macOS

El instalador de macOS registra un recibo pero no tieneashdesinstalador. Confirme que se trata de una instalación .pkg, no de Homebrew, e inspeccione su carga útil exacta:

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

Usando ese recibo como inventario, retire sólo suash-archivos de propiedad:/usr/local/bin/ash,/usr/local/bin/ash-broker, los archivos en/usr/local/lib/ash/plugins,/usr/local/share/man/man1/ash.1, el listado localizadoash.1páginas y avisos en/usr/local/share/licenses/ash. Se necesitan privilegios de administrador. Verifique la propiedad si otro instalador reemplazó estos archivos posteriormente; no elimine su copia. Quitar vacíoash-solo directorios, no compartidos/usr/local,bin, o directorios man.

Después de eliminar la carga útil, opcionalmente elimine el recibo:

sudo pkgutil --forget dev.ash.cli

Olvidar un recibo no elimina ningún archivo instalado.Consérvelo hasta que haya terminado de comprobar la carga útil.

Localice la copia activa concommand -v ashycommand -v ash-broker. Para la instalación del script predeterminado, después de deshabilitar los enlaces, elimine esos dos archivos específicos:

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

ParaASH_INSTALL_DIRo un archivo extraído manualmente, elimine sólo el archivo realmente instaladoash/rutas de intermediario. Elimine los complementos de archivo/páginas de manual/avisos que instaló utilizando su inventario de archivos original; Los complementos de script están en elashdirectorio de datos de usuario. Si los archivos están bajo/usr/bin, verifique la propiedad primero condpkg -S /usr/bin/ash,rpm -qf /usr/bin/ash, opacman -Qo /usr/bin/ashsegún corresponda. Una copia propiedad del paquete debe eliminarse a través de ese administrador, incluso si se instala desde una descarga independiente.

4. Opcional: borrar la configuración, las herramientas y el historial locales

Haga una copia de seguridad de todo lo que desee conservar. Este paso independiente puede borrar la configuración/tokens del proveedor, las herramientas/complementos personalizados, el historial de conversaciones y los archivos borrador. Desinstalar binarios no implica consentimiento para borrarlos.

  • Configuración:$XDG_CONFIG_HOME/ash, por defecto~/.config/ash.
  • Datos, complementos y entorno Python:$XDG_DATA_HOME/ash, por defecto~/.local/share/ash.
  • Historia y estado:$XDG_STATE_HOME/ash, por defecto~/.local/state/ash.
  • Cache:$XDG_CACHE_HOME/ash, por defecto~/.cache/ash.
  • Tiempo de ejecución del corredor:$XDG_RUNTIME_DIR/ash, o$XDG_STATE_HOME/ash/runtimecuando no hay raíz de tiempo de ejecución disponible.

Inspeccione sus anulaciones XDG absolutas reales antes de eliminar solo estos subdirectorios ash; nunca elimine una raíz XDG o su directorio de inicio. Después de que se hayan cerrado todos los shells habilitados para ash, elimine los archivos de tiempo de ejecución ash sobrantes si es necesario. Las credenciales de MCP OAuth también pueden permanecer en el administrador de credenciales del sistema operativo: elimine las entradas específicas de ash allí y revoque el acceso en el proveedor de MCP. Revocar las claves AI no utilizadas en sus cuentas de proveedor; eliminar un archivo local no revoca una clave. No desinstale Ollama/models, Python ni las dependencias compartidas como parte de la eliminación de ash.

Solución rápida de problemas

Comando no encontrado o versión incorrecta
Marque RUTA ycommand -v ash/command -v ash-broker. un viejo~/.local/binLa copia puede seguir un paquete. Utilice un propietario/canal a la vez y abra un nuevo shell.
El menú del proveedor no apareció.
Correrash installdesde una terminal interactiva. Se conservan las configuraciones válidas existentes; usarconfiguración manualpara cambiar de proveedor. Sin integración, asegúrese de que la configuración se exporte al entorno de la CLI.
Ningún modelo o conexión rechazada
Para Ollama, confirme que su servidor esté funcionando yollama listIncluye el modelo elegido. Para servicios en la nube, verifique el punto final, la elegibilidad del modelo, HTTPS, token y cuota de cuenta; nunca comparta registros que contengan tokens.
Repositorio o canal no disponible
Verifique la arquitectura y la versión/repositorio publicado. La publicación puede retrasarse; No desactive la verificación de firmas para solucionar un repositorio no disponible.
Error en la configuración de la herramienta Python
Instale Python con venv/ensurepip y permita descargas de dependencias, luego vuelva a ejecutarash install. Básicoashsigue siendo utilizable sin estas herramientas.
