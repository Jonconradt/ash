Antes de empezar

  1. Sistema y shell compatibles: macOS o Linux en amd64/x86_64 o arm64/aarch64, o FreeBSD en amd64. Usa Bash, zsh o Fish. Los paquetes Arch solo admiten x86_64. No hay instalador nativo para Windows/PowerShell.
  2. Acceso a descargas: conexión a Internet funcional y acceso HTTPS fiable a GitHub, al repositorio elegido y al proveedor del modelo. La inferencia local también requiere descargar primero un modelo.
  3. Permisos: directorio personal escribible para archivos de usuario. Los paquetes de sistema Linux y .pkg de macOS requieren administración; ejecuta Homebrew y ash install como usuario normal.
  4. Un modelo: servidor de inferencia local con modelo descargado o cuenta/clave API en la nube. Elige un modelo con llamadas a herramientas, no uno exclusivamente de imagen/audio. Los requisitos locales de RAM, disco y GPU dependen del modelo.

Los paquetes precompilados de ash no necesitan Go, Rust, Node.js ni herramientas Xcode. El gestor puede tener requisitos propios; sigue primero su configuración oficial.

Opcional: herramientas Python incluidas

El uso básico no necesita Python. Las herramientas incluidas requieren Python 3 con venv y ensurepip y acceso para descargar dependencias. En Debian/Ubuntu instala python3 y python3-venv; Python de Homebrew incluye venv. En FreeBSD usa el paquete pip de tu versión de Python. Repite ash install. Se crea un entorno aislado en $XDG_DATA_HOME/ash/venv (predeterminado ~/.local/share/ash/venv); un fallo desactiva esas herramientas, no ash básico.

macOS

Recomendado: Homebrew

Requisitos: Homebrew, un entorno macOS compatible y el comando brew operativo. El tap elige automáticamente el archivo Intel o Apple Silicon. Instala Release sin sudo:

brew install Jonconradt/ash/ash
ash version

Homebrew administra binarios, plugins nativos, manuales y avisos de licencia en su prefijo (normalmente /opt/homebrew en Apple Silicon o /usr/local en Intel). Comprueba el archivo con el SHA-256 de la fórmula. No configura el proveedor ni el inicio del shell: continúa con la inicialización por usuario. Actualiza con brew upgrade ash y elimina Release con brew uninstall ash; consulta fórmulas por canal para Beta/Nightly.

Alternativa: .pkg nativo

Descarga darwin-arm64.pkg para Apple Silicon o darwin-amd64.pkg para Intel de una versión publicada. Verifica el manifiesto firmado de sumas de comprobación antes de abrir el instalador. Requiere permisos de administración.

El paquete macOS no está firmado ni notarizado. El manifiesto verifica por separado editor/sumas, no la notarización Apple. No desactives Gatekeeper ni ignores avisos solo para instalar ash; prefiere Homebrew si tu política lo exige.

El paquete escribe ash y ash-broker en /usr/local/bin, plugins en /usr/local/lib/ash/plugins, manuales en /usr/local/share/man y avisos en /usr/local/share/licenses/ash. El recibo es dev.ash.cli. No inicializa usuarios ni suscribe actualizaciones: inicializa después, actualiza reemplazándolo por un .pkg nuevo verificado y usa la eliminación manual para desinstalar. No lo instales sobre una copia de Homebrew.

Linux

Usa el gestor de tu distribución cuando sea posible. Estos paquetes administran /usr/bin/ash, /usr/bin/ash-broker, /usr/lib/ash/plugins, manuales en /usr/share/man y avisos de licencia. La configuración del proveedor y los hooks del shell corresponden a la inicialización por usuario.

Debian y Ubuntu: APT

Requisitos: amd64 o arm64, administración, APT, curl, gpg y certificados CA. Instala herramientas de descarga/claves que falten desde tu distribución antes de añadir el repositorio. Release se llama stable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Antes de importar claves, verifica su huella con una fuente fiable del editor. La huella VersionX es 32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. APT comprueba metadatos firmados y los resúmenes de paquetes incluidos; signed-by limita el alcance de la clave. Actualiza con sudo apt update && sudo apt upgrade ash; elimina con sudo apt remove ash.

Fedora y sistemas compatibles con RHEL: DNF

Requisitos: x86_64 o aarch64, administración, DNF/RPM, curl, gpg y certificados CA. Instala herramientas que falten desde tu distribución. Inspecciona la clave y compara la huella anterior antes de importarla:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

Los RPM no están firmados individualmente. repo_gpgcheck=1 verifica los metadatos que cubren sus sumas; gpgcheck=0 refleja las firmas de paquetes ausentes, no la desactivación de verificar el repositorio. Si tu política exige cargas RPM firmadas, este repositorio no la cumple. Actualiza con sudo dnf upgrade ash; elimina con sudo dnf remove ash.

Arch Linux: Pacman

Requisitos: x86_64, administración, Pacman con llavero inicializado, curl y gpg. Comprueba que la huella mostrada coincide con la anterior antes de confiar. Añade el repositorio una vez, no en cada actualización:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman verifica firmas de paquetes y base de datos. Sincroniza Arch con sudo pacman -Syu, no con actualizaciones parciales; elimina ash con sudo pacman -R ash.

Otros métodos en Linux

¿Ya usas Homebrew en Linux? Las mismas instrucciones del tap admiten amd64 y arm64; Brew administra los archivos, no APT/DNF. Si no, usa una instalación verificada por script/archivo o una descarga .deb/.rpm correspondiente. Instala un .deb verificado con sudo apt install ./PACKAGE.deb o un .rpm con sudo dnf install ./PACKAGE.rpm (sustituye los nombres). El paquete directo sigue administrado, pero no añade repositorio ni suscripción automática a futuras versiones. El RPM actual no está firmado; sigue la política de la distribución, no desactives comprobaciones.

FreeBSD

Requisitos: amd64, Bash (aunque uses zsh o Fish interactivamente), herramientas de descarga/verificación y directorio escribible. Instala Bash con el gestor nativo de FreeBSD:

sudo pkg install bash

El pkg de FreeBSD administra requisitos, no ash: actualmente no hay repositorio ash .pkg ni archivo arm64. Usa el script verificado, o verifica un tarball FreeBSD amd64, extráelo a un directorio temporal e instala su binario ash versionado como ~/.local/bin/ash, junto a ash-broker. Copia plugins nativos a $XDG_DATA_HOME/ash/plugins (predeterminado ~/.local/share/ash/plugins), luego inicializa. Tú administras esos archivos; pkg delete no los elimina. Usa autoactualizaciones Release en la ubicación predeterminada o reemplaza manualmente archivos verificados.

Inicializar y comprobar

Tras instalar binarios, configura interactivamente como usuario normal. La configuración solo de archivos no cambia el inicio:

ash install

Para integrar también comandos no encontrados, elige exactamente un comando para tu shell:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Fish

ash install --shell fish --shell-integration

Bash usa ~/.bashrc, zsh ~/.zshrc y Fish $XDG_CONFIG_HOME/fish/config.fish (predeterminado ~/.config/fish/config.fish). Abre un shell nuevo; los existentes mantienen su broker. La integración antepone ~/.local/bin al PATH: elimina copias locales antiguas antes de esperar seleccionar un paquete del sistema.

Si falta configuración, se detectan claves existentes o un servidor local activo; si no, se ofrece un menú y se piden credenciales. Elige un modelo disponible con herramientas. Se conserva la configuración válida: repetir la instalación no cambia de proveedor.

Los ajustes están en $XDG_CONFIG_HOME/ash/.ash_env (predeterminado ~/.config/ash/.ash_env, permisos privados). La integración los carga. Sin ella, Bash/zsh pueden cargar el archivo en su inicio; Fish debe definir las variables ASH_AI_* con sintaxis Fish, sin cargar el archivo Bash. Protege archivos con tokens y nunca los incluyas en commits.

Sin integración, añade al PATH el directorio real de instalación local. Bash/zsh: export PATH="$HOME/.local/bin:$PATH". Fish: fish_add_path "$HOME/.local/bin". Persístelo en el inicio del shell; sustituye tu directorio personalizado si corresponde.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

Los primeros comandos deben apuntar a la instalación elegida. La consulta necesita servidor activo o credenciales cloud válidas; instalar ash no instala modelos.

Ollama local: sin cuenta en la nube

Instala Ollama siguiendo sus instrucciones oficiales del sistema. Inicia la aplicación/servicio o ejecuta ollama serve en otro terminal si no hay servidor. El soporte FreeBSD de ash no implica instalador nativo Ollama: usa un servidor accesible en otro equipo compatible si es necesario.

Descarga un modelo con herramientas que quepa en tu hardware; llama3.1:8b es un ejemplo, no un mínimo. Consulta el catálogo actual con herramientas para alternativas:

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

Sin claves cloud definidas, la configuración puede detectar el servidor local y ofrecer el modelo descargado. Si ya hay otro proveedor, cambia manualmente endpoint/modelo. Ejemplo Bash/zsh:

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Equivalente Fish:

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Estos cambios afectan solo al shell actual. Guárdalos en el archivo protegido de entorno ash o configuración adecuada, sustituyendo ajustes antiguos. Ollama local no necesita token. Mantén el servidor en loopback salvo acceso deliberadamente protegido; un servidor remoto recibe consultas y resultados de herramientas.

Opcional: define OLLAMA_KEEP_ALIVE=30m en el entorno del servidor Ollama y reinícialo para mantener modelos cargados. -1 los conserva indefinidamente, consumiendo memoria entre solicitudes. Definirlo solo en el terminal cliente ash no reconfigura un servidor activo.

La inferencia local no factura API, pero utiliza hardware/almacenamiento/electricidad. Ollama cloud es un servicio separado con autenticación y límites de plan; no equivale a esta configuración local.

Planes gratuitos en la nube

Gratis no significa ilimitado ni privado. Cuentas, regiones, cuotas, modelos y políticas varían y pueden cambiar. Consultas y resultados relevantes salen de tu equipo. Revisa límites y condiciones actuales; activa facturación de pago solo si deseas pagar.

Crea una clave mediante los enlaces, ejecuta ash install interactivamente y elige el proveedor. Se solicita el token y se listan modelos cuando sea posible. Elige un modelo de texto con herramientas del plan gratuito disponible; aparecer en la lista no garantiza gratuidad para tu cuenta.

Configuración manual o cambio de proveedor

Sustituye el endpoint siguiente por el de la tabla y MODEL_ID por un modelo verificado en tu cuenta. Si ya exportaste la clave como GROQ_API_KEY, este ejemplo Bash/zsh la reutiliza sin escribir el secreto:

export ASH_AI_ENDPOINT="https://api.groq.com/openai/v1"
export ASH_AI_MODEL="MODEL_ID"
export ASH_AI_AUTH_TOKEN="$GROQ_API_KEY"

Equivalente Fish:

set -gx ASH_AI_ENDPOINT https://api.groq.com/openai/v1
set -gx ASH_AI_MODEL MODEL_ID
set -gx ASH_AI_AUTH_TOKEN "$GROQ_API_KEY"

Para Gemini/OpenRouter usa sus endpoints y variables reconocidas. Guarda los ajustes con seguridad para futuros shells. La nube requiere HTTPS y token; HTTP local no es un atajo a servicios cloud. Consulta la referencia del entorno y otros proveedores compatibles para servicios de pago y ajustes avanzados.

Instalación con script: alternativa, no primera opción

Prefiere Homebrew, APT, DNF o Pacman: registran archivos, verifican descargas según su confianza y ofrecen actualización/eliminación conocidas. Aun así debes confiar en editores y acciones de instalación.

Un script web ejecuta código con permisos de tu cuenta. Un sitio/editor comprometido o script modificado puede leer secretos, alterar archivos o instalar software. HTTPS protege el transporte, no las intenciones. Enviar una URL directamente al shell ejecuta antes de revisar. Verificar archivos firmados no autentica el script. Nunca lo ejecutes con sudo ni desactives su verificación.

Requisitos: sistema/arquitectura compatibles, $SHELL indicando Bash/zsh/Fish, Sigstore cosign, tar, uname, install, utilidades estándar, comando SHA-256 (sha256sum, shasum o sha256) y descargador (curl, wget o Python). El ejemplo usa curl. FreeBSD también necesita Bash. Tu directorio personal/de instalación debe ser escribible.

Descarga un archivo local, inspecciónalo con un editor y ejecútalo solo si confías en origen y comportamiento. Revisarlo no garantiza seguridad; no sigas ciegamente estos pasos:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

Tras revisarlo, ejecuta la copia guardada como usuario normal:

sh ./ash-install.sh
rm ./ash-install.sh

install.sh descarga el último Release, verifica el manifiesto firmado Sigstore y resumen del archivo e instala ash/ash-broker en ~/.local/bin. Los plugins van en $XDG_DATA_HOME/ash/plugins. Configura al usuario y pregunta antes de integrar el shell. Sin terminal interactivo pueden omitirse preguntas de proveedor/integración: ejecuta después ash install interactivamente.

Define ASH_INSTALL_DIR antes del script para otra ubicación. Añádela al PATH tú mismo. La autoactualización solo admite ~/.local/bin; ubicaciones personalizadas requieren reemplazo manual. No hay selector Beta/Nightly en el script.

Verificar un paquete o archivo directo

Requisitos: cosign y utilidad SHA-256. Descarga paquete/archivo, SHA256SUMS y SHA256SUMS.sigstore.json de la misma versión publicada. Trabaja en un directorio nuevo. Sustituye vX.Y.Z por la etiqueta exacta, incluido el sufijo preliminar si procede:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Solo tras el éxito calcula el resumen con shasum -a 256 PACKAGE en macOS, sha256sum PACKAGE en Linux o sha256 -q PACKAGE en FreeBSD. Sustituye PACKAGE por el nombre descargado y compáralo exactamente con su entrada del manifiesto verificado. Detente si falta o difiere. Una suma sin firmar junto al archivo no equivale a metadatos del editor verificados.

Actualizaciones y los tres canales

  • Release (recomendado): versiones estables como vX.Y.Z; el repositorio lo llama stable.
  • Beta: pruebas preliminares con etiqueta vX.Y.Z-beta.N; espera cambios y regresiones.
  • Nightly: cambios recientes de la rama predeterminada, etiqueta vX.Y.Z-nightly.YYYYMMDD.N; máximo riesgo de regresión. Las compilaciones programadas pueden omitirse sin cambios o si falla publicar.

Una publicación actualiza la fórmula Homebrew o repositorio Linux firmado correspondiente. La recibes ejecutando la actualización del gestor responsable o según la política del sistema. Publicación, repositorios y web pueden retrasarse entre sí; comprueba disponibilidad antes de cambiar canal. ash no instala binarios silenciosamente en segundo plano.

Homebrew: instalar o cambiar fórmulas

Para nuevas instalaciones Beta/Nightly usa el nombre completo anterior en brew install. Al cambiar, desinstala primero la fórmula actual: las tres aportan los mismos binarios. Ejemplo Release a Beta:

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

Usa ash-nightly para Nightly o ash para Release en instalación/actualización. Desinstala la fórmula real del canal antiguo, no siempre ash. Los ajustes se conservan; abre otro shell después.

Linux: elegir un canal de repositorio

APT: usa la configuración APT con exactamente una distribución de la tabla. Para cambiar edita /etc/apt/sources.list.d/versionx.list, sustituyendo stable por beta o nightly (o vuelve a stable), luego:

sudo apt update
sudo apt install --allow-downgrades ash

DNF: usa la configuración DNF con la baseurl elegida. En instalaciones existentes sustituye baseurl en /etc/yum.repos.d/versionx.repo, conservando los ajustes de firma, luego:

sudo dnf --refresh distro-sync ash

Pacman: usa la configuración Pacman con la URL Server elegida. Conserva la sección [versionx]: cada canal publica una base versionx.db. Cambia Server en esa sección, no añadas una base con otro nombre. Para cambiar, incluso bajar de versión:

sudo pacman -Syuu ash

Revisa la transacción: volver a Release puede bajar ash, y el doble u de Pacman también otros paquetes. Respalda ajustes antes. Después usa actualizaciones normales APT/DNF/Pacman de las secciones del sistema; no mantengas varias fuentes de canales ash activas.

Actualizaciones Release locales

ash update

Esto verifica e instala una versión estable solo si el ash activo está en ~/.local/bin. También actualiza archivos/plugins incluidos, con opciones para personalizados. ash update --version vX.Y.Z selecciona etiqueta estable, no canal; no baja versiones. No existe --channel. Instalaciones gestionadas, .pkg y scripts en directorios personalizados requieren su gestor/instalador. FreeBSD Beta/Nightly usa archivos verificados manuales, no suscripción al autoactualizador. Abre otro shell después.

Desinstalar sin borrar archivos ajenos

1. Desactivar primero integración del shell

Antes de borrar binarios, ejecuta el comando para cada shell con integración:

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Fish

ash install --shell fish --disable-shell-integration

Si ash ya falta, edita el inicio indicado en inicialización y elimina solo el bloque entre # >>> ash install >>> y # <<< ash install <<<. Elimina líneas PATH/entorno específicas añadidas a mano, no configuración ajena. Cierra shells ash para que terminen sus brokers.

2. Dejar que el gestor responsable elimine sus archivos

Homebrew (Release)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

Elige solo tu método; para Homebrew Beta/Nightly usa ash-beta/ash-nightly. APT/DNF/Pacman eliminan binarios, plugins y manuales propios, no configuración/historial personal. No borres archivos gestionados manualmente.

Limpieza opcional: elimina la fuente ash /etc/apt/sources.list.d/versionx.list y su clave dedicada /etc/apt/keyrings/versionx-keyring.gpg, el archivo de repositorio /etc/yum.repos.d/versionx.repo, o sección ash [versionx] de /etc/pacman.conf. Comprueba primero que otros paquetes no los usan. Retira claves RPM/Pacman solo tras verificar huella y ausencia de dependientes; nunca borres el llavero compartido de una distribución.

3a. Eliminación manual de .pkg macOS

macOS Installer registra recibo pero no incluye desinstalador ash. Confirma instalación .pkg, no Homebrew, e inspecciona su contenido exacto:

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

Usando el recibo como inventario, elimina solo archivos ash: /usr/local/bin/ash, /usr/local/bin/ash-broker, archivos en /usr/local/lib/ash/plugins, /usr/local/share/man/man1/ash.1, páginas ash.1 traducidas listadas y avisos en /usr/local/share/licenses/ash. Requiere administración. Si otro instalador los reemplazó, comprueba propiedad y no elimines su copia. Borra directorios vacíos exclusivos, no compartidos /usr/local, bin ni manuales.

Tras eliminar archivos, opcionalmente elimina el recibo:

sudo pkgutil --forget dev.ash.cli

Olvidar un recibo no elimina archivos instalados. Consérvalo hasta acabar de comprobar el contenido.

3b. Eliminación manual local / Linux / FreeBSD

Localiza la copia activa con command -v ash y command -v ash-broker. Para el script predeterminado, tras desactivar hooks, elimina solo estos dos archivos:

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

Para ASH_INSTALL_DIR o archivos extraídos a mano, elimina solo rutas ash/broker reales. Retira plugins/manuales/avisos según tu inventario original; los plugins del script están en datos de usuario ash. Bajo /usr/bin, comprueba propiedad con dpkg -S /usr/bin/ash, rpm -qf /usr/bin/ash o pacman -Qo /usr/bin/ash. Una copia gestionada debe eliminarse con su gestor, aunque proceda de descarga independiente.

4. Opcional: borrar ajustes, herramientas e historial

Respalda lo que quieras conservar. Este paso separado puede borrar ajustes/tokens, herramientas/plugins personalizados, conversaciones y archivos de trabajo. Desinstalar binarios no implica aceptar borrarlos.

  • Configuración: $XDG_CONFIG_HOME/ash, predeterminado ~/.config/ash.
  • Datos, plugins y entorno Python: $XDG_DATA_HOME/ash, predeterminado ~/.local/share/ash.
  • Historial y estado: $XDG_STATE_HOME/ash, predeterminado ~/.local/state/ash.
  • Caché: $XDG_CACHE_HOME/ash, predeterminado ~/.cache/ash.
  • Ejecución del broker: $XDG_RUNTIME_DIR/ash, o $XDG_STATE_HOME/ash/runtime si no hay raíz de ejecución.

Inspecciona sustituciones XDG absolutas reales antes de borrar solo subdirectorios ash; nunca borres una raíz XDG ni tu directorio personal. Tras cerrar todos los shells ash, limpia restos de ejecución si hace falta. Credenciales MCP OAuth pueden permanecer en el gestor del sistema: elimina entradas ash y revoca acceso en el proveedor MCP. Revoca claves IA sin uso en sus cuentas; borrar archivos no las revoca. No desinstales Ollama/modelos, Python ni dependencias compartidas al quitar ash.

Solución rápida de problemas

Comando ausente o versión incorrecta
Comprueba PATH y command -v ash/command -v ash-broker. Una copia antigua en ~/.local/bin puede ocultar un paquete. Usa un responsable/canal a la vez y abre otro shell.
No apareció el menú de proveedores
Ejecuta ash install interactivamente. Se conservan ajustes válidos; usa configuración manual para cambiar. Sin integración, exporta ajustes al entorno CLI.
Sin modelo o conexión rechazada
Para Ollama verifica servidor y modelo en ollama list. Para la nube comprueba endpoint, elegibilidad, HTTPS, token y cuota; nunca compartas registros con tokens.
Repositorio o canal no disponible
Comprueba arquitectura y versión/repositorio publicado. Puede retrasarse; no desactives firmas para evitar un repositorio inaccesible.
Falló la configuración Python
Instala Python con venv/ensurepip, permite descargar dependencias y repite ash install. ash básico sigue funcionando sin estas herramientas.
