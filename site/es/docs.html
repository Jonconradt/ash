Sinopsis

ash [text ...]
ash install [--shell bash|zsh] [--dry-run] [--overwrite]
ash mcp add <url> [--no-browser]
ash snooze [duration|off]
ash update [--version vX.Y.Z] [--yes|--skip-customized]

Descripción

ash envía un texto de aviso al punto final de IA configurado e imprime la respuesta del asistente. Cuando no se proporciona ningún texto posicional, ash lee el texto de solicitud de la entrada estándar no interactiva.

El subcomando install agrega un bloque de integración administrado a los archivos de inicio del shell. Bash usa ~/.bashrc y zsh usa ~/.zshrc.

Las conexiones al proveedor de IA se comparten a través de un corredor local. El fallo del intermediario recurre al HTTPS directo.

La IA puede utilizar systemd para programar tareas en segundo plano. Pueden ser trabajos recurrentes o puntuales. Los trabajos programados utilizan HTTPS directo de forma predeterminada.

ash mantiene un espacio de trabajo temporal con ámbito de sesión en ~/.ash/scratch/<session-id>/. Los directorios temporales obsoletos e inactivos se eliminan automáticamente después de la ventana de retención configurada. Los registros históricos se almacenan en ~/.ash/history/. Los archivos históricos antiguos se limpian automáticamente de acuerdo con la política de retención.

Las herramientas, secuencias de comandos, archivos, canalizaciones y resultados secundarios son datos que no son confiables y no deben anular las instrucciones del sistema o del usuario. La función de ejecución de la herramienta no es un espacio aislado cuando está habilitada la ejecución arbitraria de Python o Shell. De forma predeterminada, Python está habilitado, así que tenga cuidado.

Servidores MCP remotos

Los servidores MCP (Protocolo de contexto de modelo) proporcionan herramientas a las que un modelo de IA puede llamar. Ash admite servidores HTTP MCP Streamable remotos y mantiene sus sesiones de cliente en ash-broker a través de invocaciones Ash en el mismo shell.

Registre un servidor agregando su URL, por sí mismo, a ~/.ash/.ash_allow, o ejecute ash mcp add <url> desde un interactivo Ash concha. El comando conecta y registra el servidor solo después de una conexión exitosa:

https://mcpplaygroundonline.com/mcp-complex-server

La autorización OAuth se abre en el navegador de escritorio cuando hay una GUI disponible. Si no se puede abrir el navegador, Ash imprime una URL de autorización copiable y espera en la terminal. Utilice ash mcp add <url> --no-browser para utilizar siempre este flujo de terminal. La autorización manual de URL aún requiere un navegador en el mismo host; no es un flujo OAuth sin navegador.

Las líneas URL que comienzan con http:// o https:// son registros de MCP, no comandos de shell. Los esquemas se reconocen sin distinguir entre mayúsculas y minúsculas. Ash deriva el nombre local del servidor a partir de los primeros 8 caracteres hexadecimales en minúscula de SHA-256 sobre el texto de la URL recortado. Se requiere HTTPS excepto para el desarrollo de localhost; Se rechazan las URL con credenciales integradas, cadenas de consulta o fragmentos. Para conexiones OAuth directas, el descubrimiento permite direcciones IP no públicas solo para la autoridad MCP registrada exacta; otros hosts de OAuth siguen sujetos al bloqueo de direcciones no públicas. Un proxy de salida configurado es responsable de filtrar sus direcciones de destino. Los cambios se leen en la siguiente solicitud Ash.

Los registros de MCP permanecen habilitados con ASH_STRICT=1. Los resultados de la herramienta devueltos todavía se tratan como evidencia no confiable. Registre únicamente servidores en los que confíe: sus herramientas pueden realizar acciones en su nombre. Para servidores protegidos por OAuth, Ash abre el navegador cuando hay una GUI disponible mientras el corredor maneja la devolución de llamada y los tokens. Las credenciales utilizan el administrador de credenciales del sistema operativo cuando esté disponible, o un archivo cifrado protegido por un ASH_MCP_CREDENTIAL_KEY aleatorio de 32 bytes proporcionado por el usuario. Los archivos ~/.ash/mcp.json existentes ya no se leen; mueva las URL del servidor a .ash_allow.

Si falla la inicialización de MCP, Ash continúa la solicitud sin herramientas MCP remotas. Las ejecuciones interactivas imprimen una advertencia; Las ejecuciones no interactivas fallan silenciosamente. Las tareas programadas no tienen el intermediario de shell interactivo y, por lo tanto, no pueden usar herramientas MCP remotas. Un mensaje programado que depende de MCP aún puede ejecutarse, pero puede finalizar sin la acción o los datos de MCP solicitados. No programe mensajes que requieran MCP.

Consulte las Preguntas frecuentes sobre MCP para obtener una descripción general rápida y notas de configuración.

Comandos

ash [--attach path]... [text ...]
Ejecutar una única solicitud de asistente. --attach adjunta un archivo (imagen o documento) a la solicitud; repetible. Tamaño limitado por ASH_ATTACHMENT_MAX_BYTES y actualmente enviado por cable solo a proveedores compatibles con OpenAI.
ash mcp add <url> [--no-browser]
Conecte y registre un servidor MCP remoto en el .ash_allow efectivo. Abre la autorización OAuth en un navegador de escritorio cuando esté disponible; recurre a una URL copiable en la terminal. --no-browser siempre usa el flujo de terminal.
ash install [--shell bash|zsh] [--dry-run]
Instalar o actualizar la integración del shell. Cuando se omite --shell, se utiliza el shell actual siempre que sea posible. --dry-run previsualiza los cambios sin escribir. Cuando sea interactivo, instale también las configuraciones automáticas AI_ENDPOINT, AI_MODEL y AI_AUTH_TOKEN: prefiere una clave API de proveedor de nube ya configurada (OpenAI, Anthropic, Google Gemini, Azure OpenAI, Mistral, Cohere, Groq, xAI, DeepSeek, Together AI, OpenRouter o HuggingFace), luego un servidor de inferencia local en ejecución. (Ollama, LM Studio, llama.cpp/MLX/LocalAI, vLLM, text-generation-webui, Jan o GPT4All) y otros mensajes con un menú de proveedores numerado. El modelo se elige de la lista de modelos del punto final cuando esté disponible.
ash snooze [duration|off]
Pausar el procesamiento automático del indicador de shell. El valor predeterminado es cinco minutos. Las duraciones utilizan la sintaxis Go, como 30s, 5m o 1h. Utilice off para reanudar inmediatamente.
ash update [--version vX.Y.Z] [--yes|--skip-customized]
Descargue e instale la última versión estable de macOS, Linux o FreeBSD para la arquitectura actual en ~/.local/bin/ash. Las versiones requieren verificación Sigstore y verificación SHA-256.

Medio ambiente

AI_AUTH_TOKEN
Token al portador opcional. Cuando se configura, se envía como autenticación de portador y es necesaria para los puntos finales en la nube. Las direcciones privadas/LAN (RFC1918 IPv4, IPv6 ULA) y los nombres de host mDNS .local se tratan como no en la nube (como localhost) a menos que se configure ASH_STRICT=1.
AI_CACHE
Alternancia de caché nativa del proveedor opcional. Habilitado de forma predeterminada cuando es compatible; use off o false para deshabilitarlo.
AI_ENDPOINT
URL base requerida para el punto final de la API de chat.
AI_MODEL
Nombre de modelo requerido enviado al endpoint.
AI_PROVIDER
Anulación de proveedor opcional: anthropic, bedrock, cohere, gemini, google, ollama o openai. Cuando no está configurado, ash detecta el proveedor desde el punto final.
AI_TIMEOUT
Tiempo de espera de solicitud opcional. Valor predeterminado: 3m.
ASH_ALWAYS_OPENAI_API
Alternancia de prueba opcional. Cuando es verdadero, enruta el proveedor ollama a través del adaptador SDK compatible con OpenAI en lugar de su implementación manual. Valor predeterminado: activado.
ASH_ATTACHMENT_MAX_BYTES
Tamaño máximo opcional en bytes para un archivo pasado a través de --attach. Valor predeterminado: 10485760 (10 MiB).
ASH_HISTORY_MAX
Mensajes de historial máximo opcionales por clave. Valor predeterminado: 40.
ASH_LOG_FILE
Ruta de registro de depuración opcional cuando el registro detallado está habilitado.
ASH_LOG_MAX_BYTES
Tamaño de registro máximo opcional antes de la rotación. Valor predeterminado: 1048576.
ASH_MAX_AGENTS
Subagentes máximos opcionales generados por un proceso principal. Valor predeterminado: 6.
ASH_MAX_TOOL_ITERS
Iteraciones de bucle de llamada de herramienta de IA máximas opcionales. Valor predeterminado: 16.
ASH_RELEVANCE_WINDOW
Observaciones de herramientas recientes opcionales incluidas en el estado de ejecución. Valor predeterminado: 4.
ASH_RETRY_BASE_DELAY
Retraso base de reintento opcional. Valor predeterminado: 250ms.
ASH_RETRY_MAX_ATTEMPTS
Intentos de solicitud reintentables opcionales. Valor predeterminado: 3.
ASH_SCHEDULED_TASK
Indicador de programador interno utilizado por las invocaciones administradas por ash.
ASH_STREAM
Alternancia opcional. Cuando es verdadero, transmite la respuesta de los proveedores cuyo adaptador lo admite (actualmente solo OpenAI). Predeterminado: activado.
ASH_TASK_MAX
Límite opcional en tareas de ejecución derivadas de una solicitud. Predeterminado: 6.
ASH_TASK_STALL_ROUNDS
El asistente opcional realiza rondas de parada antes de detenerse. Valor predeterminado: 2.
ASH_ALLOW
Lista de permitidos ejecutables opcionales separados por comas para run_unix_command. De lo contrario, se utiliza ~/.ash/.ash_allow cuando está presente; esta anulación no expande los tokens Ash internos.
ASH_DENY
Lista de denegación opcional separada por comas para bloquear explícitamente comandos, herramientas y complementos. De lo contrario, se utiliza ~/.ash/.ash_deny cuando esté presente.
ASH_TOOL_OUTPUT_MAX
Salida máxima opcional de la herramienta capturada en bytes. Valor predeterminado: 8192.
ASH_TOOL_TIMEOUT
Tiempo de espera de comando de herramienta local opcional. Valor predeterminado: 15s.
ASH_VERBOSE
Panel de control de ejecución y registro de depuración opcional. Valores como 1, true, on y debug lo habilitan.
SESSION_ID
Identificador de sesión para historial persistente y nombres de registros. Generado automáticamente para ejecuciones interactivas cuando falta.

Archivos

  • ~/.ash/.ash_system: mensaje del sistema canónico. $TOOLS_DIR_LIST, $PLUGINS_DIR_LIST y $IF_PYTHON_AVAILABLE son sustituciones internas de Ash, nunca variables de entorno.
  • ~/.ash/.ash_allow: lista de comandos canónicos, herramientas y complementos permitidos. Sus directivas independientes $TOOLS_DIR_LIST y $PLUGINS_DIR_LIST permiten scripts administrados regulares y complementos nativos; reemplácelo con nombres literales para una política restrictiva.
  • ~/.ash/.ash_deny: archivo de lista de denegados canónico para bloquear comandos, herramientas o complementos específicos.
  • ~/.ash/plugins/: directorio de complementos binarios nativos.
  • ~/.ash/history/: archivos de historial de conversaciones.
  • ~/.ash/scratch/: borrador con alcance de sesión archivos.
  • ~/.ash/.ash_snooze_until — vencimiento automático de la repetición de alarma.

Estado de salida

ash devuelve 0 en caso de éxito. Devuelve un valor distinto de cero cuando falla la configuración, las solicitudes de red o la ejecución de herramientas.

Ejemplos

echo "summarize this directory" | ash
ash install --shell bash
ash install --shell zsh --dry-run
