Instalar en Debian o Ubuntu

El repositorio firmado de VersionX APT admiteamd64yarm64. Agregue su clave de firma pública y la fuente del paquete, luego instaleash:

sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key |
  sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash

Verifique el comando instalado conash --version. Las instalaciones del administrador de paquetes se actualizan consudo apt update && sudo apt upgrade.

Instalar en Fedora o Linux compatible con RHEL

El repositorio firmado de VersionX DNF admitex86_64yaarch64. Importe su clave pública y configure el repositorio:

sudo rpm --import https://www.versionx.ai/rpm/gpg.key
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash

Los metadatos del repositorio firmado verifican las sumas de comprobación del paquete RPM; Los archivos del paquete no están firmados individualmente con RPM. Actualiza ash con sudo dnf upgrade ash.

Instalar en Arch Linux

El repositorio firmado de VersionX Pacman admitex86_64. Verifique que la huella digital de la clave de firma que se muestra a continuación coincida32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F, luego impórtelo y confíe localmente en él:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o /tmp/versionx.gpg
gpg --show-keys --with-fingerprint /tmp/versionx.gpg
sudo pacman-key --add /tmp/versionx.gpg
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
rm /tmp/versionx.gpg
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash

Pacman verifica las firmas del paquete y del repositorio. Actualiza ash con sudo pacman -Syu.

Sinopsis

ash [text ...]
ash install [--shell bash|zsh] [--dry-run] [--overwrite]
ash mcp add <url> [--no-browser]
ash snooze [duration|off]
ash update [--version vX.Y.Z] [--yes|--skip-customized]

Descripción

ashenvía un mensaje de texto al punto final de IA configurado e imprime la respuesta del asistente. Cuando no se proporciona ningún texto posicional,ashlee el texto del mensaje de entrada estándar no interactiva.

ElinstallEl subcomando instala los activos administrados. Los archivos de inicio del Shell se cambian solo cuando usted lo solicita explícitamente--shell-integration; usos de bash~/.bashrc, usos zsh~/.zshrcy usos del pescado$XDG_CONFIG_HOME/fish/config.fish.

Las conexiones con el proveedor de IA se comparten a través de un corredor local. El fallo del intermediario recurre al HTTPS directo.

La IA puede usar systemd para programar tareas en segundo plano. Pueden ser trabajos recurrentes o puntuales. Los trabajos programados utilizan HTTPS directo de forma predeterminada.

ashsigue los directorios base de XDG: configuración y archivos de espacio de trabajo persistentes en$XDG_CONFIG_HOME/ash(por defecto~/.config/ash), herramientas y complementos en$XDG_DATA_HOME/ash(por defecto~/.local/share/ash), historial y borrador de sesión en$XDG_STATE_HOME/ash(por defecto~/.local/state/ash), y almacenar en caché en$XDG_CACHE_HOME/ash(por defecto~/.cache/ash). Uso de sockets de intermediario$XDG_RUNTIME_DIR/ashcon un respaldo de directorio de estado. Las rutas XDG explícitas deben ser absolutas.

La salida de herramientas, secuencias de comandos, archivos, canalizaciones y elementos secundarios son datos que no son de confianza y no deben anular las instrucciones del sistema o del usuario. La función de ejecución de la herramienta no es un espacio aislado cuando está habilitada la ejecución arbitraria de Python o Shell. De forma predeterminada, Python está habilitado, así que tenga cuidado.

Servidores MCP remotos

Los servidores MCP (Protocolo de contexto de modelo) proporcionan herramientas a las que un modelo de IA puede llamar.Ashadmite servidores remotos Streamable HTTP MCP y mantiene las sesiones de sus clientes enash-brokeral otro lado deAshinvocaciones en el mismo shell.

Registre un servidor confiable ejecutandoash mcp add <url>desde un interactivoAshshell, o agregando su URL a$XDG_CONFIG_HOME/ash/.ash_allow(por defecto~/.config/ash/.ash_allow). No hay ningún servidor remoto habilitado de forma predeterminada.

La autorización OAuth se abre en el navegador de escritorio cuando hay una GUI disponible. Si no se puede abrir el navegador,Ashimprime una URL de autorización copiable y espera en la terminal. Usarash mcp add <url> --no-browserutilizar siempre este flujo terminal. La autorización manual de URL aún requiere un navegador en el mismo host; no es un flujo OAuth sin navegador.

Líneas URL que comienzan conhttp://ohttps://son registros de MCP, no comandos de shell. Los esquemas se reconocen sin distinguir entre mayúsculas y minúsculas.Ashderiva el nombre local del servidor a partir de los primeros 8 caracteres hexadecimales en minúscula de SHA-256 sobre el texto URL recortado. Se requiere HTTPS excepto para el desarrollo de localhost; Se rechazan las URL con credenciales integradas, cadenas de consulta o fragmentos. Para conexiones OAuth directas, el descubrimiento permite direcciones IP no públicas solo para la autoridad MCP registrada exacta; otros hosts de OAuth siguen sujetos al bloqueo de direcciones no públicas. Un proxy de salida configurado es responsable de filtrar sus direcciones de destino. Los cambios se leen en el siguiente.Ashpedido.

Los registros de MCP permanecen habilitados conASH_STRICT=1. Los resultados de la herramienta devueltos todavía se tratan como evidencia no confiable. Registre únicamente servidores en los que confíe: sus herramientas pueden realizar acciones en su nombre. Para servidores protegidos por OAuth,Ashabre el navegador cuando hay una GUI disponible mientras el corredor maneja la devolución de llamada y los tokens. Las credenciales utilizan el administrador de credenciales del sistema operativo cuando esté disponible, o un archivo cifrado protegido por un archivo aleatorio de 32 bytes proporcionado por el usuario.ASH_MCP_CREDENTIAL_KEYen$XDG_DATA_HOME/ash/mcp/.

Si la inicialización de MCP falla,Ashcontinúa la solicitud sin herramientas MCP remotas. Las ejecuciones interactivas imprimen una advertencia; Las ejecuciones no interactivas fallan silenciosamente.Los trabajos programados no tienen el intermediario por shell interactivo y, por lo tanto, no pueden usar herramientas MCP remotas.Es posible que aún se ejecute un mensaje programado que depende de MCP, pero puede finalizar sin la acción o los datos de MCP solicitados. No programe mensajes que requieran MCP.

Ver elPreguntas frecuentes sobre MCPpara obtener una descripción general rápida y notas de configuración.

Comandos

ash [--attach path]... [text ...]
Ejecute una única solicitud de asistente.--attachadjunta un archivo (imagen o documento) a la solicitud; repetible. Tamaño limitado porASH_ATTACHMENT_MAX_BYTESy actualmente se envía por cable solo a proveedores compatibles con OpenAI.
ash mcp add <url> [--no-browser]
Conecte y registre un servidor MCP remoto en el formato efectivo.ash_allow. Abre la autorización OAuth en un navegador de escritorio cuando esté disponible; recurre a una URL copiable en la terminal.--no-browsersiempre utiliza el flujo terminal.
ash install [--shell bash|zsh|fish] [--shell-integration|--disable-shell-integration] [--dry-run]
Instale recursos sin cambiar los archivos de inicio del shell de forma predeterminada.--shell-integrationopta por agregar/actualizar el bloque administrado;--disable-shell-integrationelimina solo ese bloque y preserva el contenido del usuario circundante. Cuando sea interactivo, instale configuraciones automáticasASH_AI_ENDPOINT,ASH_AI_MODEL, yASH_AI_AUTH_TOKENcuando sea necesario, prefiriendo una clave de proveedor existente o un punto final local antes de mostrar un menú de proveedor.
ash snooze [duration|off]
Pausar el procesamiento automático del indicador de shell. El valor predeterminado es cinco minutos. Las duraciones usan la sintaxis Go, como30s,5m, o1h. Usaroffpara reanudar inmediatamente.
ash update [--version vX.Y.Z] [--yes|--skip-customized]
Descargue e instale la última versión estable de macOS, Linux o FreeBSD para la arquitectura actual en~/.local/bin/ash. Las versiones requieren verificación Sigstore y verificación SHA-256.

Medio ambiente

ASH_AI_AUTH_TOKEN
Token al portador opcional. Requerido para puntos finales en la nube excepto AWS Bedrock. Direcciones privadas/LAN y.localLos nombres de host se tratan como no en la nube a menos queASH_STRICT=1.
ASH_AI_CACHE
Alternancia opcional de caché nativa del proveedor. Habilitado de forma predeterminada cuando es compatible; acepta1,true,yes,on,enabled,0,false,no,off, odisabled(no distingue entre mayúsculas y minúsculas).
ASH_AI_ENDPOINT
URL base requerida para el punto final de la API de chat.
ASH_AI_MODEL
Nombre del modelo requerido enviado al punto final.
ASH_AI_PROVIDER
Anulación de proveedor opcional. Cuando está desarmado,ashdetecta el proveedor desde el punto final.
ASH_AI_TIMEOUT
Tiempo de espera de solicitud opcional. Por defecto:3m.
ASH_ALWAYS_OPENAI_API
Alternancia de prueba opcional. Cuando es verdadero, dirige elollamaproveedor a través del adaptador SDK compatible con OpenAI en lugar de su implementación manual. Acepta los mismos valores booleanos queASH_AI_CACHE. Valor predeterminado: activado.
ASH_ATTACHMENT_MAX_BYTES
Tamaño máximo opcional en bytes para un archivo pasado a través de--attach. Por defecto:10485760(10 MB).
ASH_HISTORY_MAX
Mensajes históricos máximos opcionales por clave. Por defecto:40.
ASH_LOG_FILE
Ruta de registro de depuración opcional cuando el registro detallado está habilitado.
ASH_LOG_MAX_BYTES
Tamaño máximo de registro opcional antes de la rotación. Por defecto:1048576.
ASH_MAX_AGENTS
Subagentes máximos opcionales generados por un proceso principal. Por defecto:6.
ASH_MAX_TOOL_ITERS
Iteraciones de bucle de llamada de herramienta de IA máximas opcionales. Por defecto:16.
ASH_RELEVANCE_WINDOW
Observaciones de herramientas recientes opcionales incluidas en el estado de ejecución. Por defecto:4.
ASH_RETRY_BASE_DELAY
Retraso base de reintento opcional. Por defecto:250ms.
ASH_RETRY_MAX_ATTEMPTS
Intentos de solicitud reintentables opcionales. Por defecto:3.
ASH_SCHEDULED_TASK
Bandera del programador interno utilizada porash-invocaciones gestionadas.
ASH_STREAM
Alternancia opcional. Cuando es verdadero, transmite la respuesta de los proveedores cuyo adaptador lo admite (actualmente solo OpenAI). Acepta los mismos valores booleanos queASH_AI_CACHE. Valor predeterminado: activado.
ASH_TASK_MAX
Límite opcional de tareas de ejecución derivadas de una solicitud. Por defecto:6.
ASH_TASK_STALL_ROUNDS
El asistente opcional hace rondas antes de detenerse. Por defecto:2.
ASH_ALLOW
Lista de permisos ejecutables opcionales separados por comas pararun_unix_command. De lo contrario$XDG_CONFIG_HOME/ash/.ash_allow(por defecto~/.config/ash/.ash_allow) se utiliza; esta anulación no se expande internamenteAshfichas.
ASH_DENY
Lista de denegación opcional separada por comas para bloquear explícitamente comandos, herramientas y complementos. De lo contrario$XDG_CONFIG_HOME/ash/.ash_deny(por defecto~/.config/ash/.ash_deny) se utiliza.
ASH_TOOL_OUTPUT_MAX
Salida máxima opcional de la herramienta capturada en bytes. Por defecto:8192.
ASH_TOOL_TIMEOUT
Tiempo de espera del comando de herramienta local opcional. Por defecto:15s.
ASH_VERBOSE
Panel de ejecución y registro de depuración opcional. Valores como1,true,on, ydebughabilitarlo.
ASH_SESSION_ID
Ashidentificador de sesión para historial persistente y denominación de registros. Generado en ausencia; Se rechazan los valores explícitos no válidos. GenéricoSESSION_IDes ignorado.

Se validan las configuraciones numéricas y de duración explícitas. Los límites de enteros deben ser positivos exceptoASH_MAX_TOOL_ITERS, que puede ser cero. Los tiempos de espera de la IA/herramientas deben ser positivos; Los retrasos en los reintentos pueden ser cero pero no negativos. Las duraciones usan la sintaxis Go, como30s,5m, o1h. Los valores con formato incorrecto o fuera de rango producen un error de configuración en lugar de utilizar los valores predeterminados de forma silenciosa.

Archivos

  • $XDG_CONFIG_HOME/ash/(por defecto~/.config/ash/)—Archivos canónicos de avisos, políticas y espacios de trabajo persistentes.
  • $XDG_DATA_HOME/ash/(por defecto~/.local/share/ash/)—herramientas incluidas, complementos, paquetes de idiomas y credenciales de MCP.
  • $XDG_STATE_HOME/ash/(por defecto~/.local/state/ash/)—historial, scratch, registros y estado de repetición.
  • $XDG_CACHE_HOME/ash/(por defecto~/.cache/ash/)—archivos de caché regenerables.

Estado de salida

ash devuelve 0 en caso de éxito. Devuelve un valor distinto de cero cuando falla la configuración, las solicitudes de red o la ejecución de herramientas.

Ejemplos

echo "summarize this directory" | ash
ash install --shell bash
ash install --shell zsh --dry-run
