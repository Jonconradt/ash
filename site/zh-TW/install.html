第一次提問。

開始之前

  1. 支援的系統與 shell：amd64/x86_64 或 arm64/aarch64 的 macOS、Linux，或 amd64 的 FreeBSD。使用 Bash、zsh 或 Fish。Arch 套件僅支援 x86_64。無原生 Windows/PowerShell 安裝程式。
  2. 下載存取：可用的網際網路及對 GitHub、選定軟體庫與模型供應商的可信 HTTPS 存取。本機推論也須先下載模型。
  3. 權限：家目錄須可寫入以保存使用者檔案。Linux 系統套件與 macOS .pkg 需管理員；以一般使用者執行 Homebrew 與 ash install。
  4. 模型：已下載模型的本機推論伺服器，或雲端帳戶/API 金鑰。選擇支援工具呼叫的模型，不要僅影像/音訊模型。本機 RAM、磁碟與 GPU 需求依模型而定。

預先編譯的 ash 套件不需 Go、Rust、Node.js 或 Xcode 建置工具。套件管理器可能有自有需求；先遵循官方設定說明。

選用：內建 Python 工具

基本使用不需 Python。內建工具需具有 venv 和 ensurepip 的 Python 3，且能下載相依項目。Debian/Ubuntu 安裝 python3、python3-venv；Homebrew Python 包含 venv 支援。FreeBSD 使用符合 Python 版本的 pip 套件。再執行 ash install。設定在 $XDG_DATA_HOME/ash/venv（預設 ~/.local/share/ash/venv）建立隔離環境；失敗僅停用這些工具，不影響基本 ash。

macOS

推薦：Homebrew

需求：Homebrew、支援的 macOS 環境和可用的 brew 指令。tap 自動選 Intel 或 Apple Silicon 封存檔。安裝 Release 不需 sudo：

brew install Jonconradt/ash/ash
ash version

Homebrew 管理前綴內的二進位、原生外掛、手冊及授權聲明（Apple Silicon 通常 /opt/homebrew，Intel 為 /usr/local）。以配方 SHA-256 驗證封存檔。不設定供應商或修改 shell 啟動檔：請繼續使用者初始化。以 brew upgrade ash 更新、brew uninstall ash 移除 Release；Beta/Nightly 見通道配方。

替代方案：原生 .pkg

從已發布版本下載 Apple Silicon 的 darwin-arm64.pkg 或 Intel 的 darwin-amd64.pkg。開啟安裝程式前，驗證簽署的校驗和清單。需要管理員。

macOS 套件未簽署或公證。發布清單提供獨立的發行者/校驗和驗證，不是 Apple 公證。不要只為安裝 ash 停用 Gatekeeper 或略過安全警告；若政策要求，優先用 Homebrew。

套件把 ash、ash-broker 寫入 /usr/local/bin，外掛至 /usr/local/lib/ash/plugins，手冊至 /usr/local/share/man，聲明至 /usr/local/share/licenses/ash。收據為 dev.ash.cli。不初始化使用者或訂閱更新：安裝後初始化，更新時換成已驗證的新 .pkg，解除安裝請依手動移除程序。勿覆蓋 Homebrew 管理的版本。

Linux

盡量使用發行版的套件管理器。套件管理 /usr/bin/ash、/usr/bin/ash-broker、/usr/lib/ash/plugins、/usr/share/man 下手冊及授權聲明。供應商設定與 shell 掛鉤留給使用者初始化。

Debian 與 Ubuntu：APT

需求：amd64/arm64、管理員、APT、curl、gpg 與 CA 憑證。加入軟體庫前，透過發行版安裝缺少的下載/金鑰工具。Release 名為 stable：

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

匯入任何金鑰前，以可信發行者來源核對指紋。VersionX 指紋為 32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F。APT 驗證簽署的中繼資料及內含套件摘要；signed-by 限制金鑰範圍。更新：sudo apt update && sudo apt upgrade ash；移除：sudo apt remove ash。

Fedora 與相容 RHEL 系統：DNF

需求：x86_64/aarch64、管理員、DNF/RPM、curl、gpg 與 CA 憑證。由發行版安裝缺少工具。匯入前檢視金鑰並核對上述指紋：

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

RPM 未逐一簽署。repo_gpgcheck=1 驗證涵蓋校驗和的軟體庫中繼資料；gpgcheck=0 表示無單套件簽章，不是停用軟體庫驗證。若政策要求已簽署 RPM 內容，此軟體庫不符合。更新：sudo dnf upgrade ash；移除：sudo dnf remove ash。

Arch Linux：Pacman

需求：x86_64、管理員、金鑰環已初始化的 Pacman、curl、gpg。信任前確認顯示指紋與上述相符。只加一次軟體庫，勿每次更新都加：

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman 驗證套件與資料庫簽章。以 sudo pacman -Syu 同步 Arch，勿部分升級；以 sudo pacman -R ash 移除 ash。

其他 Linux 安裝方式

已使用 Linux 上的 Homebrew？相同 tap 說明支援 amd64/arm64；檔案由 Brew 管理，不是 APT/DNF。否則用已驗證的指令碼/封存檔安裝或匹配的 .deb/.rpm 下載。以 sudo apt install ./PACKAGE.deb 安裝已驗證 .deb，或 sudo dnf install ./PACKAGE.rpm 安裝 .rpm（替換檔名）。直接套件仍由管理器管理，但不加軟體庫或自動訂閱未來版本。目前 RPM 內容未簽署；遵循發行版政策，勿停用簽章檢查。

FreeBSD

需求：amd64、Bash（即使互動 shell 是 zsh/Fish）、下載/驗證工具及可寫安裝目錄。透過 FreeBSD 原生管理器安裝 Bash：

sudo pkg install bash

FreeBSD 的 pkg 管理前置元件，不管理 ash：目前無 ash .pkg 軟體庫或 arm64 封存檔。用已驗證指令碼，或驗證 FreeBSD amd64 tarball，解壓至暫存目錄，將版本化 ash 二進位安裝為 ~/.local/bin/ash，與 ash-broker 放在一起。原生外掛複製至 $XDG_DATA_HOME/ash/plugins（預設 ~/.local/share/ash/plugins），再初始化。由您管理這些檔案，pkg delete 不會移除。在預設位置使用 Release 自我更新，或手動替換已驗證檔案。

初始化與驗證

安裝二進位後，以一般使用者互動執行設定。僅設定檔案不改動啟動檔：

ash install

若要啟用「找不到指令」整合，依您的 shell 選且只選一條指令：

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Fish

ash install --shell fish --shell-integration

Bash 用 ~/.bashrc，zsh 用 ~/.zshrc，Fish 用 $XDG_CONFIG_HOME/fish/config.fish（預設 ~/.config/fish/config.fish）。之後開新 shell；已有 shell 保留執行中的 broker。整合將 ~/.local/bin 加到 PATH 前方：要選到系統套件，先移除舊使用者本機版本。

若缺供應商設定，會偵測金鑰或執行中本機伺服器；否則顯示選單並要求憑證。選可用且支援工具的模型。有效設定會保留；重新設定不會切換供應商。

設定存於 $XDG_CONFIG_HOME/ash/.ash_env（預設 ~/.config/ash/.ash_env，私有檔案權限）。受管理整合會載入。無整合時 Bash/zsh 可在啟動設定載入；Fish 應以自身語法設定 ASH_AI_* 變數，不載入 Bash 格式檔。保護含權杖檔案，切勿提交至版本庫。

本機安裝無整合時，將實際目錄加到 PATH。Bash/zsh：export PATH="$HOME/.local/bin:$PATH"。Fish：fish_add_path "$HOME/.local/bin"。在啟動設定保存；適用時換為自訂安裝目錄。

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

前幾條指令應指向選定安裝。提問需執行中伺服器或有效雲端憑證；安裝 ash 不會安裝模型。

本機 Ollama：無需雲端帳戶

依官方作業系統說明安裝 Ollama。啟動應用/服務；未有伺服器時可於另一終端執行 ollama serve。ash 支援 FreeBSD 不代表原生 Ollama 安裝程式：必要時用其他支援主機上的可連線伺服器。

下載符合硬體且支援工具呼叫的模型；llama3.1:8b 是範例，不是最低需求。其他選擇見目前工具模型目錄：

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

未設定雲端金鑰時可偵測本機伺服器並提供已下載模型。若已設其他供應商，手動改端點/模型。Bash/zsh 範例：

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Fish 等效指令：

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

變更僅影響目前 shell。在受保護的 ash 環境檔或適當 shell 設定保存，取代舊供應商覆寫。本機 Ollama 不需權杖。除非刻意保護遠端存取，保持伺服器在 loopback；遠端會接收提問及工具輸出。

選用：在 Ollama 伺服器環境設 OLLAMA_KEEP_ALIVE=30m 並重啟，保持模型載入。-1 無限保持但請求間仍耗記憶體。僅設在 ash 用戶端終端，不會重設已執行伺服器。

本機推論無 API 帳單，但使用硬體/儲存/電力。Ollama 雲端為獨立服務，有驗證及方案限制，不等於本機設定。

手動設定或切換供應商

以下端點換為表中值，MODEL_ID 換為帳戶已核實模型。若金鑰已匯出為 GROQ_API_KEY，Bash/zsh 範例可免輸入秘密重用：

export ASH_AI_ENDPOINT="https://api.groq.com/openai/v1"
export ASH_AI_MODEL="MODEL_ID"
export ASH_AI_AUTH_TOKEN="$GROQ_API_KEY"

Fish 等效指令：

set -gx ASH_AI_ENDPOINT https://api.groq.com/openai/v1
set -gx ASH_AI_MODEL MODEL_ID
set -gx ASH_AI_AUTH_TOKEN "$GROQ_API_KEY"

Gemini/OpenRouter 用其端點與識別金鑰變數。安全保存供未來 shell。雲端需 HTTPS 與權杖；本機 HTTP 不是雲端捷徑。付費服務與進階覆寫見環境參考與其他支援供應商。

指令碼安裝：替代方案，非首選

優先 Homebrew、APT、DNF 或 Pacman：追蹤所屬檔案，按信任設定驗證下載並提供熟悉更新/移除。但仍需信任發行者及套件安裝動作。

網站指令碼以您的帳戶權限執行程式碼。受入侵網站/發行者或變動指令碼可讀秘密、改檔或安裝軟體。HTTPS 保護傳輸，不保護意圖。直接把 URL 管線傳給 shell，會在檢查前執行。封存檔簽章不驗證指令碼本身。勿用 sudo 或停用驗證。

需求：支援系統/架構、識別 Bash/zsh/Fish 的 $SHELL、Sigstore cosign、tar、uname、install、標準 shell 工具、SHA-256 指令（sha256sum、shasum 或 sha256）及下載器（curl、wget 或 Python）。範例用 curl。FreeBSD 另需 Bash。家/安裝目錄須可寫。

下載至本機檔案，用編輯器檢視，只在信任來源與行為時執行。檢查不保證安全；勿盲目執行：

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

檢查後，以一般使用者執行儲存的副本：

sh ./ash-install.sh
rm ./ash-install.sh

install.sh 下載最新 Release，驗證 Sigstore 簽署清單及封存檔摘要，安裝 ash/ash-broker 至 ~/.local/bin。原生外掛至 $XDG_DATA_HOME/ash/plugins。執行使用者設定，啟用整合前詢問。無互動終端可能跳過供應商/整合提示：之後互動執行 ash install。

執行前設 ASH_INSTALL_DIR 可選其他目錄。自行加入 PATH。自我更新僅支援 ~/.local/bin；自訂目錄需手動替換。無 Beta/Nightly 選擇器。

驗證直接下載的套件或封存檔

需求：cosign 與 SHA-256 工具。從同版下載套件/封存檔、SHA256SUMS、SHA256SUMS.sigstore.json。在新目錄操作。vX.Y.Z 換為精確標籤，必要時含預發布後綴：

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

僅成功後，用 macOS shasum -a 256 PACKAGE、Linux sha256sum PACKAGE 或 FreeBSD sha256 -q PACKAGE 計算摘要。PACKAGE 換為下載檔名，與已驗證清單該項精確比對。缺項或不符即停止。隨檔案下載的未簽署校驗和不等於已驗證發行者中繼資料。

更新與三個通道

  • Release（推薦）：如 vX.Y.Z 的穩定版；軟體庫稱 stable。
  • Beta：預發布測試，標籤 vX.Y.Z-beta.N；可能改動及回歸。
  • Nightly：預設分支近期改動，標籤 vX.Y.Z-nightly.YYYYMMDD.N；回歸風險最高。建置按排程，但無變更或發布失敗可能略過。

發布會更新對應 Homebrew 配方或簽署 Linux 軟體庫。執行所屬管理器升級（或由系統政策執行）才收到。發布、軟體庫和網站可能不同步；切換前查可用性。ash 不會靜默安裝背景二進位更新。

Homebrew：安裝或切換配方

新裝 Beta/Nightly 時，於 brew install 用上表完整配方名稱。切換先移除現有配方：三者提供同樣二進位。Release 轉 Beta：

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

安裝/升級中，Nightly 用 ash-nightly，Release 用 ash。移除舊通道實際配方，不一定 ash。設定保留；切換後開新 shell。

Linux：選一個軟體庫通道

APT：按APT 設定只用表中一個通道。切換時編輯 /etc/apt/sources.list.d/versionx.list，把 stable 換為 beta 或 nightly（或回 stable），然後：

sudo apt update
sudo apt install --allow-downgrades ash

DNF：按DNF 設定用選定 baseurl。在 /etc/yum.repos.d/versionx.repo 替換 baseurl，保留簽章設定，然後：

sudo dnf --refresh distro-sync ash

Pacman：按Pacman 設定用選定 Server URL。保留節名 [versionx]：各通道都發布 versionx.db 資料庫。改同節 Server，不加異名資料庫。切換（含降級）：

sudo pacman -Syuu ash

檢查交易：回 Release 可降級 ash，Pacman 雙 u 也可能降其他套件。先備份設定。之後依系統章節正常升級 APT/DNF/Pacman；勿同時啟用多個 ash 來源。

使用者本機 Release 更新

ash update

僅目前 ash 在 ~/.local/bin 才驗證及安裝穩定版。也更新內建檔案/外掛，自訂檔有選項。ash update --version vX.Y.Z 選穩定標籤非通道；非降級指令。無 --channel。管理器、.pkg 和自訂指令碼目錄須用所屬管理器/安裝程式。FreeBSD Beta/Nightly 用手動驗證封存檔，不訂閱自我更新。之後開新 shell。

解除安裝而不刪無關檔案

1. 先停用 shell 整合

刪二進位前，為每個啟用整合的 shell 執行指令：

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Fish

ash install --shell fish --disable-shell-integration

若 ash 已不在，依初始化編輯啟動檔，僅刪 # >>> ash install >>> 和 # <<< ash install <<< 間區塊。移除手動新增 ash PATH/環境行，不刪無關設定。關閉 ash shell，讓其 broker 結束。

2. 讓所屬管理器移除檔案

Homebrew (Release)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

只選實際方法；Homebrew Beta/Nightly 用 ash-beta/ash-nightly。APT/DNF/Pacman 移除二進位、外掛、手冊，不刪家目錄設定/歷史。勿手動刪套件檔。

選用清理：刪 ash 來源 /etc/apt/sources.list.d/versionx.list 與專用 /etc/apt/keyrings/versionx-keyring.gpg，或軟體庫 /etc/yum.repos.d/versionx.repo，或 /etc/pacman.conf 的 ash [versionx] 節。先查無其他套件使用。確認指紋且無依賴後才移除 RPM/Pacman 信任金鑰；勿刪發行版共用金鑰環。

3a. 手動移除 macOS .pkg

macOS Installer 有收據，無 ash 移除程式。確認 .pkg 而非 Homebrew，檢查精確內容：

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

依收據僅刪 ash：/usr/local/bin/ash、/usr/local/bin/ash-broker、/usr/local/lib/ash/plugins 檔案、/usr/local/share/man/man1/ash.1、列出的在地化 ash.1 頁及 /usr/local/share/licenses/ash 聲明。需管理員。若被其他安裝程式替換，查所屬後勿刪其副本。只刪空的 ash 專用目錄，不刪共用 /usr/local、bin 或手冊目錄。

刪內容後，可選移除收據：

sudo pkgutil --forget dev.ash.cli

遺忘收據不會刪除已安裝檔案。保留到內容查驗完成。

3b. 手動移除本機 / Linux / FreeBSD 封存檔

以 command -v ash、command -v ash-broker 找目前版本。預設指令碼安裝停用掛鉤後，僅刪這兩個檔：

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

對 ASH_INSTALL_DIR 或手動解壓，僅刪實際 ash/broker 路徑。按原清單移除外掛/手冊/聲明；指令碼外掛在 ash 使用者資料目錄。在 /usr/bin 先以 dpkg -S /usr/bin/ash、rpm -qf /usr/bin/ash 或 pacman -Qo /usr/bin/ash 查所屬。套件版本即使獨立下載，也須由管理器移除。

4. 選用：清除本機設定、工具與歷史

備份所有想保留的內容。獨立步驟可刪設定/權杖、自訂工具/外掛、交談及工作檔。移除二進位不等於同意清除。

  • 設定：$XDG_CONFIG_HOME/ash，預設 ~/.config/ash。
  • 資料、外掛與 Python 環境：$XDG_DATA_HOME/ash，預設 ~/.local/share/ash。
  • 歷史與狀態：$XDG_STATE_HOME/ash，預設 ~/.local/state/ash。
  • 快取：$XDG_CACHE_HOME/ash，預設 ~/.cache/ash。
  • Broker 執行資料：$XDG_RUNTIME_DIR/ash；無執行根目錄時為 $XDG_STATE_HOME/ash/runtime。

查實際絕對 XDG 覆寫路徑，只刪 ash 子目錄；勿刪 XDG 根或家目錄。所有 ash shell 關閉後清理殘留。MCP OAuth 憑證可留系統管理器：刪 ash 專屬項，並向 MCP 撤銷存取。在供應商帳戶撤銷不用的 AI 金鑰；刪本機檔不撤銷金鑰。勿隨 ash 移除 Ollama/模型、Python 或共用相依項。

快速疑難排解

指令不存在或版本錯誤
查 PATH 和 command -v ash/command -v ash-broker。~/.local/bin 舊版可遮蔽套件。一次只用一管理方/通道，開新 shell。
未顯示供應商選單
互動執行 ash install。有效設定保留；以手動設定切換。無整合請確保設定匯出至 CLI 環境。
無模型或連線遭拒
Ollama 查伺服器及 ollama list 是否含模型。雲端查端點、資格、HTTPS、權杖、額度；勿分享含權杖紀錄。
軟體庫或通道不可用
查架構和發布版本/軟體庫。發布可滯後；勿停用簽章驗證繞過。
Python 工具設定失敗
安裝含 venv/ensurepip 的 Python，允許相依下載，再執行 ash install。無這些工具仍可用基本 ash。
