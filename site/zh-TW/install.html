開始之前

  1. 支援的系統和 shell：amd64/x86_64 或 arm64/aarch64 上的 macOS 或 Linux，或 amd64 上的 FreeBSD。使用 Bash、zsh 或 Fish。 Arch 軟體包僅限 x86_64。沒有本機 Windows/PowerShell 安裝程式。
  2. 下載存取：有效的網際網路連線以及對 GitHub、所選包儲存庫和模型提供者的可信任 HTTPS 存取。本地推理仍然需要初始模型下載。
  3. 權限：每個使用者資產的可寫入主目錄。 Linux系統套件和macOS .pkg需要管理員權限；以普通使用者身分執行 Homebrew 和 ash install。
  4. 模型：包含下載模型的本機推理伺服器或雲端帳戶/API 金鑰。選擇支援工具呼叫的模型，而不是僅圖像/音訊的模型。本地 RAM、磁碟和 GPU 需求取決於該型號。

預先建置的 ash 套件不需要 Go、Rust、Node.js 或 Xcode 建置工具。套件管理器可能有其自己的先決條件；首先按照其官方設定說明進行操作。

可選：捆綁的 Python 工具

基本的ash使用不需要Python。捆綁的 Python 工具需要 Python 3venv和ensurepip，以及下載其依賴項的權限。在 Debian/Ubuntu 上，安裝python3和python3-venv; Homebrew Python 包含 venv 支持。在 FreeBSD 上，使用与您的 Python 版本匹配的 pip 包。然後重新運行ash install。安裝程式在下面建立一個隔離環境$XDG_DATA_HOME/ash/venv(預設~/.local/share/ash/venv）；失敗會停用這些工具，而不是基本工具ash。

macOS

推薦：自製

先決條件：自製、其支援的 macOS 環境以及工作brew命令。點選會自動選擇 Intel 或 Apple Silicon 檔案。無需 sudo 安裝發行版：

brew install Jonconradt/ash/ash
ash version

Homebrew 擁有其前綴中的二進位檔案、捆綁的本機插件、手冊頁和許可證聲明（通常/opt/homebrew在 Apple Silicon 上或/usr/local英特爾）。它根據公式的 SHA-256 校驗和檢查存檔。它不會配置您的提供者或編輯您的 shell 啟動檔案：繼續每個用戶初始化。使用brew upgrade ash用於更新和brew uninstall ash刪除發布；看頻道公式對於測試版/每晚。

替代方案：本機 .pkg

下載darwin-arm64.pkgApple Silicon 的資產或darwin-amd64.pkg對英特爾來說已發布的版本。驗證其簽署的校驗和清單在打開安裝程式之前。需要管理員存取權限。

cOS 軟體包未簽署且未經公證。 發布清單提供單獨的發布者/校驗和驗證，而不是 Apple 公證。不要僅僅為了安裝 ash 而停用 Gatekeeper 或繞過安全警告；如果您的安全策略需要，則首選 Homebrew。

包包裡寫著ash和ash-broker到/usr/local/bin, 插件/usr/local/lib/ash/plugins，手冊頁到/usr/local/share/man，並通知/usr/local/share/licenses/ash。收據是dev.ash.cli。它不運行每個用戶初始化或訂閱更新：初始化安裝後，將其替換為經過驗證的較新的.pkg進行更新，並使用手動移除程序解除安裝.不要將其安裝在 Homebrew 擁有的副本上。

Linux

盡可能使用您的發行版的套件管理器。這些包擁有/usr/bin/ash,/usr/bin/ash-broker,/usr/lib/ash/plugins，手冊頁下/usr/share/man和許可通知。他們將提供程式設定和 shell 掛鉤留給每個用戶初始化。

Debian 和 Ubuntu：APT

先修條件：amd64 或 arm64、管理員存取權限、APT、curl,gpg和 CA 憑證。在新增儲存庫之前，使用您的發行版安裝缺少的下載/金鑰工具。發布被命名為stable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

在导入任何存储库密钥之前，请根据受信任的发布者源验证其指纹。 VersionX 金鑰指紋是32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F。 APT 檢查簽署的儲存庫元資料及其包含的套件摘要；鍵的範圍是signed-by。更新為sudo apt update && sudo apt upgrade ash;刪除與sudo apt remove ash。

Fedora 和 RHEL 相容系統：DNF

先修條件：x86_64 或 aarch64、管理員存取權限、DNF/RPM、curl,gpg和 CA 憑證。安裝您的發行版中缺少的工具。在导入之前检查密钥并比较上面的指纹：

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

RPM 檔案沒有單獨簽名。repo_gpgcheck=1驗證包含其校驗和的儲存庫元資料；gpgcheck=0反映了缺少的每個包簽名，而不是禁用的存儲庫驗證。如果您的策略需要已簽署的 RPM 有效負載，則此儲存庫不符合它。更新為sudo dnf upgrade ash;刪除與sudo dnf remove ash。

Arch Linux：吃豆人

先決條件：x86_64、管理員存取權限、Pacman 及其金鑰環已初始化、curl， 和gpg。在信任之前，请验证显示的密钥指纹与上面的指纹是否匹配。添加存储库一次，而不是每次更新时添加：

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman 驗證套件和資料庫簽章。保持 Arch 同步sudo pacman -Syu，不是部分升級；消除ash和sudo pacman -R ash。

其他Linux安裝方法

已經在使用Linux 上的自製程式？這相同的點擊指令支援amd64和arm64； Brew 擁有這些文件，而不是 APT/DNF。否則，請使用經過驗證的腳本/存檔安裝或匹配的.deb/.rpm 下載。安裝經過驗證的 .debsudo apt install ./PACKAGE.deb，或 .rpm 與sudo dnf install ./PACKAGE.rpm（替換檔名）。直接套件仍然由套件管理器擁有，但不會添加儲存庫或自動訂閱未來版本。當前 RPM 有效負載是無符號的；遵循您的發行版的策略而不是停用簽名檢查。

FreeBSD

先決條件：amd64、Bash（即使您的互動式 shell 是 zsh 或 Fish）、下載/驗證工具以及可寫入的安裝目錄。使用 FreeBSD 的本機管理器安裝 Bash：

sudo pkg install bash

FreeBSD 的pkg管理先決條件，而不是ash: 目前沒有ash.pkg 儲存庫，沒有 arm64 發布存檔。使用已驗證的腳本， 或者驗證 FreeBSD amd64 tarball，將其解壓縮到臨時目錄中，然後安裝其版本控制ash二進制為~/.local/bin/ash旁邊ash-broker。將其原生插件複製到$XDG_DATA_HOME/ash/plugins(預設~/.local/share/ash/plugins）， 然後初始化。您擁有這些文件；pkg delete不會刪除它們。使用發布自我更新在預設位置或手動取代已驗證的工件。

初始化并验证

安装二进制文件后，以普通用户身份交互式运行安装程序。如果您不想集成 shell，则可以仅安装 Ash。這可能不是您想要的。 ash的真正价值是下面的shell集成。仅资产设置使您的启动文件保持不变：

ash install

您可能想要使用的安裝涉及 shell 整合。這將更改您的 .bashrc（或 shell 的等效項）以包含 Ash。要啟用 command-not-found 集成，請為您使用的 shell 選擇一個命令：

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

魚

ash install --shell fish --shell-integration

bash 使用~/.bashrc,zsh 使用~/.zshrc，和魚使用$XDG_CONFIG_HOME/fish/config.fish(預設~/.config/fish/config.fish）。之後開啟一個新的shell；現有的 shell 保留其正在執行的代理程式。整合前置~/.local/binto PATH：在選擇系統包之前刪除舊的使用者本機副本。

如果缺少提供者設置，安裝程式會偵測現有的提供者金鑰或正在執行的本機伺服器；否則，它會提供提供者選單並提示輸入憑證。選擇一個可用的支援工具的模型。現有的有效設定將被保留，因此重新運行安裝程序不是提供程序切換命令。

設定儲存在$XDG_CONFIG_HOME/ash/.ash_env(預設~/.config/ash/.ash_env，私有檔案權限）​​。託管集成加載它們。如果沒有集成，Bash/zsh 用戶可以在正常啟動配置中獲取該文件；釣魚用戶應設置相應的ASH_AI_*使用 Fish 語法的變量，而不是 Bash 格式檔案的來源。保護任何包含令牌的文件，並且永遠不要提交它。

對於不帶整合的用戶本地安裝，請將其實際目錄新增至 PATH。 bash/zsh：export PATH="$HOME/.local/bin:$PATH"。魚：fish_add_path "$HOME/.local/bin"。使用 shell 的啟動配置來保持這一點；如果適用，請取代您的自訂安裝目錄。

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

第一個命令應解析為您選擇的安裝。提示需要正在運行的伺服器或有效的雲端憑證；安裝 ash 不會安裝模型。

本地 Ollama：無需雲端帳戶

您不需要有本地人工智慧即可使用ash。但是，如果您想在本機上運行模型而不依賴雲端供應商，則可以設定本機 Ollama 伺服器。

Ollama 還提供用於遠端運行模型的雲端服務，但本地使用不需要該服務ash。雲端伺服器包括免費方案和 Google 的 Gemma 4 31b 雲端模式（gemma4-31b：雲）可以很好地配合ash。這是專案用來產生發行說明和執行 DevOps 任務的模型。

使用其安裝 Ollama官方作業系統說明。启动 Ollama 应用程序/服务，或运行ollama serve如果伺服器尚未運行，則在單獨的終端中。在 FreeBSD 上，ash的支援並不意味著本機 Ollama 安裝程式：如果需要，請在另一個受支援的主機上使用可存取的伺服器。

下載適合您的硬體的具有工具功能的模型；llama3.1:8b是一個例子，不是最低要求。檢查目前工具目錄對於替代方案：

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

如果尚未設定雲端金鑰，安裝程式可以偵測本機伺服器並提供下載的模型。如果已配置另一個提供程序，請手動變更端點/模型。 Bash/zsh 範例：

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

魚當量：

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

這些變更僅影響目前 shell。將它們保留在您的受保護的ash環境檔案或適當的 shell 配置，取代任何舊的提供者覆蓋。本地 Ollama 不需要令牌。保持伺服器處於環回狀態，除非您刻意保護存取安全；遠端伺服器接收您的提示和工具輸出。

可選：設定OLLAMA_KEEP_ALIVE=30m在奧拉馬伺服器環境並重新啟動伺服器以使模型保持溫暖。-1讓它們無限期地加載，但會在請求之間消耗內存。僅在ash客戶端不會重新配置已經執行的伺服器。

本地推理沒有提供者 API 帳單，但使用您的硬體/儲存/電力。奧拉馬雲是一項具有身份驗證和計劃限制的獨立服務；它與本地設定不一樣。

腳本安裝：替代方案，而不是首選

偏好 Homebrew、APT、DNF 或 Pacman：它們追蹤擁有的文件，使用其信任配置驗證下載，並提供熟悉的更新/刪除。他们仍然需要信任的发布者和软件包安装操作。

網站腳本使用您帳戶的權限來執行程式碼。 受感染的網站、發布者或更改腳本可以讀取機密、更改檔案或安裝其他軟體。 HTTPS 保護傳輸，而不是該程式碼的意圖。將 URL 直接透過管道傳輸到 shell 會在您查看它之前執行它。腳本的存檔簽章檢查不會驗證腳本本身。切勿使用 sudo 運行它或禁用其驗證。

先決條件：支援的作業系統/架構，$SHELL識別 Bash/zsh/Fish，Sigstore聯名,tar,uname,install、標準 shell 實用程式、SHA-256 指令（sha256sum,shasum， 或者sha256）和一個下載器（curl,wget，或Python）。該範例使用了curl。 FreeBSD 還需要 Bash。您的主/安裝目錄必須是可寫入的。

下載到本機文件，使用編輯器檢查它，並且僅在您信任其來源和行為時才執行。檢查並不能保證安全；不要盲目執行以下步驟：

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

檢查後，以一般使用者身分執行已儲存的副本：

sh ./ash-install.sh
rm ./ash-install.sh

install.sh下載最新版本，驗證其 Sigstore 簽署的校驗和清單和存檔摘要，然後安裝ash/ash-broker在~/.local/bin。原生插件消失了$XDG_DATA_HOME/ash/plugins。它運行每個用戶設定並在啟用 shell 整合之前進行詢問。如果沒有互動式終端，可能會跳過提供者/整合提示：運行ash install之後進行互動。

您可以設定ASH_INSTALL_DIR在運行腳本之前選擇另一個目的地。自己將該目的地加入 PATH 中。僅在以下情況下支援自我更新~/.local/bin;自訂目的地需要手動替換。該腳本沒有 Beta/Nightly 選擇器。

驗證直接包或存檔

先修條件：共同簽署和 SHA-256 實用程式。從同一已發布的版本中，下載您的套件/存檔，SHA256SUMS， 和SHA256SUMS.sigstore.json。在新目录中工作。代替vX.Y.Z具有確切的標籤，包括預發布後綴（如果適用）：

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

只有在成功之後，才可以使用以下命令計算文件的摘要shasum -a 256 PACKAGE在 macOS 上，sha256sum PACKAGE在 Linux 上，或者sha256 -q PACKAGE在 FreeBSD 上。代替PACKAGE與下載的檔案名稱並將其與已驗證清單中該檔案名稱的條目進行精確比較。當缺少條目或任何不符時停止。在文件旁邊下載的未簽名校驗和並不等同於經過驗證的發布者元資料。

更新與三個頻道

  • 發布（推薦）：穩定的已發布版本，例如vX.Y.Z;存儲庫配置調用此stable。
  • 測試版：預發布測試，已標記vX.Y.Z-beta.N;期待變化和回歸。
  • 每晚：最近的預設分支更改，已標記vX.Y.Z-nightly.YYYYMMDD.N;回歸風險最高。建置已計劃，但在沒有任何變更或發布失敗時可能會被跳過。

已發布的版本更新了對應的 Homebrew 公式或簽署的 Linux 儲存庫。當您執行所屬管理員的升級命令（或您自己的作業系統更新策略）時，您會收到它。發布、儲存庫更新和網站部署可能會相互滯後；在更改頻道之前檢查可用性。 ash 不會靜默安裝背景二進位更新。

Homebrew：安裝或切換公式

對於全新 Beta/Nightly 安裝，請使用上面 brew install 中對應的完整公式名稱。切換時，首先卸載目前安裝的公式：所有三個都提供相同的二進位檔案。範例，發布測試版：

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

使用ash-nightly每晚或ash用於安裝/升級命令中的發布。卸載舊頻道的實際公式，並不總是ash。保留用户设置；切换后打开一个新的shell。

Linux：選擇一個儲存庫通道

易於：使用APT 設定恰好具有表中的一種分佈。若要切換現有安裝，請編輯/etc/apt/sources.list.d/versionx.list, 替換stable和beta或者nightly（或回到stable）， 然後：

sudo apt update
sudo apt install --allow-downgrades ash

地下城與勇士:使用DNF設定與選定的基本網址。對於現有安裝，替換baseurl在/etc/yum.repos.d/versionx.repo，保留其簽名設置，然後：

sudo dnf --refresh distro-sync ash

吃豆人：使用吃豆人設置與選定的伺服器 URL。保留部分名稱[versionx]：每個頻道都會發布一個資料庫，名為versionx.db。更改该部分中的服务器，而不是添加不同名称的数据库。切換（包括降級）：

sudo pacman -Syuu ash

審查提議的交易：返回Release可能會降級ash，Pacman的雙重u也可以降級其他軟體包。切換前備份配置。然後使用作業系統部分的普通 APT/DNF/Pacman 升級命令；不要啟用多個 ash 通道來源。

用戶本地版本更新

ash update

僅當活動時，這才會驗證並安裝穩定版本ash可執行檔位於~/.local/bin。它還更新捆綁的資產/插件，並提供自訂文件的選擇。ash update --version vX.Y.Z選擇穩定的標籤，而不是通道；它不是降級命令。沒有--channel選項。套件管理器安裝、macOS .pkg 安裝和自訂腳本目標必須使用其所屬的管理器/安裝程式。 FreeBSD Beta/Nightly 使用手動驗證的存檔，而不是自我更新程式訂閱。更新後開啟新的shell。

卸載而不刪除無關檔案

1.首先停用 shell 整合

在刪除二進位檔案之前，為啟用整合的每個 shell 執行指令：

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

魚

ash install --shell fish --disable-shell-integration

如果ash已經遺失，請編輯相關的啟動文件初始化並僅刪除之間的區塊# >>> ash install >>>和# <<< ash install <<<。刪除任何ash- 您手动添加的特定路径/环境行，而不是不相关的 shell 配置。關閉ash- 隨後啟用 shell，以便其 shell 擁有的經紀人退出。

2. 讓所屬套件管理器刪除其文件

自製軟體（發布）

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

吃豆人

sudo pacman -R ash

僅選擇您的安裝方法；用於 Homebrew Beta/夜間使用ash-beta/ash-nightly。 APT/DNF/Pacman 刪除套件擁有的二進位檔案、外掛程式和手冊頁，而不是您的主目錄設定/歷史記錄。不要手动删除包拥有的文件。

可選的儲存庫清理：刪除ash原始檔/etc/apt/sources.list.d/versionx.list及其專用的/etc/apt/keyrings/versionx-keyring.gpg，或ash儲存庫文件/etc/yum.repos.d/versionx.repo，或ash [versionx]部分來自/etc/pacman.conf。首先檢查沒有其他包裝使用它們。僅在確認其指紋且沒有其他相依性後才刪除匯入的 RPM/Pacman 信任金鑰；切勿刪除發行版的共用金鑰環。

3a.手動刪除 macOS .pkg

macOS 安裝程式記錄了收據，但沒有ash卸載程序。確認這是一個 .pkg 安裝，而不是 Homebrew，並檢查其確切的有效負載：

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

使用該收據作為庫存，僅刪除其ash- 擁有的文件：/usr/local/bin/ash,/usr/local/bin/ash-broker，文件在/usr/local/lib/ash/plugins,/usr/local/share/man/man1/ash.1，列出的本地化ash.1頁面和通知/usr/local/share/licenses/ash。需要管理員權限。如果其他安裝程式隨後替換了這些文件，請檢查所有權；不要刪除其副本。刪除空白ash- 僅限目錄，不共享/usr/local,bin，或 man 目錄。

刪除有效負載後，可以選擇刪除收據：

sudo pkgutil --forget dev.ash.cli

忘記收據不會刪除任何已安裝的檔案。保留它，直到檢查有效負載為止。

3b.手動移除使用者本機/Linux/FreeBSD存檔

找到活動副本command -v ash和command -v ash-broker。對於預設腳本安裝，停用掛鉤後，刪除這兩個特定檔案：

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

為了ASH_INSTALL_DIR或手動提取的存檔，僅刪除實際安裝的ash/經紀人路徑。刪除您使用原始文件清單安裝的存檔外掛程式/手冊頁/通知；腳本外掛程式位於ash使用者資料目錄。如果文件位於/usr/bin，先檢查所有權dpkg -S /usr/bin/ash,rpm -qf /usr/bin/ash， 或者pacman -Qo /usr/bin/ash視情況而定。套件擁有的副本必須透過該管理員刪除，即使是透過獨立下載安裝的。

4. 選用：刪除本機設定、工具和歷史記錄

備份您想要保留的任何內容。 這個單獨的步驟可以刪除提供者設定/令牌、自訂工具/外掛程式、對話歷史記錄和暫存檔案。卸載二進位檔案並不意味著同意刪除它們。

  • 配置：$XDG_CONFIG_HOME/ash, 預設~/.config/ash。
  • 數據、插件與Python環境：$XDG_DATA_HOME/ash, 預設~/.local/share/ash。
  • 歷史和狀態：$XDG_STATE_HOME/ash, 預設~/.local/state/ash。
  • 快取:$XDG_CACHE_HOME/ash, 預設~/.cache/ash。
  • 經紀商運行時間：$XDG_RUNTIME_DIR/ash， 或者$XDG_STATE_HOME/ash/runtime當沒有可用的運行時根。

在僅刪除這些 ash 子目錄之前檢查您的實際絕對 XDG 覆蓋；切勿刪除 XDG 根目錄或您的主目錄。關閉所有啟用 ash 的 shell 後，根據需要刪除剩餘的 ash 運行時檔案。 MCP OAuth 憑證也可能保留在作業系統憑證管理員中：刪除其中的 ash 特定條目並撤銷 MCP 提供者的存取權。撤銷其提供者帳戶中未使用的 AI 金鑰；刪除本機檔案不會撤銷金鑰。請勿在 ash 刪除過程中卸載 Ollama/models、Python 或共用相依性。

快速故障排除

未找到指令或版本錯誤
檢查路徑和command -v ash/command -v ash-broker。一個老~/.local/bin副本可以隱藏包。一次使用一個擁有者/頻道並開啟一個新 shell。
提供者選單未出現
跑步ash install從互動式終端。保留現有的有效設定；使用手動配置更換提供者。如果不進行集成，請確保將設定匯出到 CLI 環境中。
沒有模型或連線被拒絕
對於 Ollama，確認其伺服器正在運行並且ollama list包括您選擇的型號。對於雲端服務，檢查端點、模型資格、HTTPS、令牌和帳戶配額；切勿共用帶有令牌的日誌。
儲存庫或通道不可用
檢查架構和已發布的版本/儲存庫。出版可能會滯後；不要停用簽名驗證來解決不可用的儲存庫問題。
Python 工具設定失敗
使用 venv/ensurepip 安裝 Python 並允許依賴項下載，然後重新執行ash install。基本的ash沒有這些工具仍然可以使用。
