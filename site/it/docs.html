Pratico assistente shell per flussi di lavoro con comandi non trovati. Questa pagina è la versione web della ash(1) pagina man installabile.

Sinossi

ash [text ...]
ash install [--shell bash|zsh] [--dry-run] [--overwrite]
ash mcp add <url> [--no-browser]
ash snooze [duration|off]
ash update [--version vX.Y.Z] [--yes|--skip-customized]

Descrizione

ash invia il testo del prompt all'endpoint AI configurato e stampa la risposta dell'assistente. Quando non viene fornito alcun testo posizionale, ash legge il testo del prompt dall'input standard non interattivo.

Il sottocomando install aggiunge un blocco di integrazione gestita ai file di avvio della shell. Bash utilizza ~/.bashrc e zsh utilizza ~/.zshrc.

Le connessioni al provider AI sono condivise tramite un broker locale. Il fallimento del broker ricorre all'HTTPS diretto.

L'intelligenza artificiale può utilizzare systemd per pianificare attività in background. Questi possono essere lavori ricorrenti o una tantum. I processi pianificati utilizzano HTTPS diretto per impostazione predefinita.

ash mantiene uno spazio di lavoro temporaneo con ambito sessione in ~/.ash/scratch/<session-id>/. Le directory scratch obsolete e inattive vengono rimosse automaticamente dopo la finestra di conservazione configurata. I registri della cronologia sono archiviati in ~/.ash/history/. I vecchi file della cronologia vengono automaticamente ripuliti in base ai criteri di conservazione.

Strumenti, script, file, reindirizzamenti e output secondari sono dati non attendibili e non devono sovrascrivere le istruzioni del sistema o dell'utente. La funzionalità di esecuzione dello strumento non è una sandbox quando è abilitata l'esecuzione arbitraria di Python o shell. Per impostazione predefinita Python è abilitato, quindi fai attenzione.

Server MCP remoti

I server MCP (Model Context Protocol) forniscono strumenti che un modello AI può chiamare. Ash supporta server MCP HTTP Streamable remoti e mantiene le sessioni client in ash-broker attraverso le invocazioni Ash nella stessa shell.

Registra un server aggiungendo il suo URL, da solo, a ~/.ash/.ash_allow, o esegui ash mcp add <url> da un'applicazione interattiva Ash conchiglia. Il comando connette e registra il server solo dopo una connessione riuscita:

https://mcpplaygroundonline.com/mcp-complex-server

L'autorizzazione OAuth si apre nel browser desktop quando è disponibile una GUI. Se non è possibile aprire il browser, Ash stampa un URL di autorizzazione copiabile e attende nel terminale. Utilizza ash mcp add <url> --no-browser per utilizzare sempre questo flusso terminale. L'autorizzazione manuale dell'URL richiede ancora un browser sullo stesso host; non è un flusso OAuth senza browser.

Le righe URL che iniziano con http:// o https:// sono registrazioni MCP, non comandi shell. Gli schemi vengono riconosciuti senza distinzione tra maiuscole e minuscole. Ash deriva il nome locale del server dai primi 8 caratteri esadecimali minuscoli di SHA-256 sul testo dell'URL tagliato. È richiesto HTTPS tranne che per lo sviluppo di localhost; Gli URL con credenziali, stringhe di query o frammenti incorporati vengono rifiutati. Per le connessioni OAuth dirette, il rilevamento consente indirizzi IP non pubblici solo per l'esatta autorità MCP registrata; gli altri host OAuth rimangono soggetti al blocco degli indirizzi non pubblici. Un proxy di uscita configurato è responsabile del filtraggio dei propri indirizzi di destinazione. Le modifiche vengono lette alla successiva richiesta Ash.

Le registrazioni MCP rimangono abilitate con ASH_STRICT=1. L'output restituito dallo strumento viene comunque trattato come prova non attendibile. Registra solo i server di cui ti fidi: i loro strumenti potrebbero eseguire azioni per tuo conto. Per i server protetti da OAuth, Ash apre il browser quando è disponibile una GUI mentre il broker gestisce il callback e i token. Le credenziali utilizzano il gestore credenziali del sistema operativo quando disponibile o un file crittografato protetto da un ASH_MCP_CREDENTIAL_KEY di 32 byte casuali fornito dall'utente. I file ~/.ash/mcp.json esistenti non vengono più letti; sposta gli URL del server in .ash_allow.

Se l'inizializzazione MCP fallisce, Ash continua la richiesta senza strumenti MCP remoti. Le corse interattive stampano un avviso; le esecuzioni non interattive falliscono silenziosamente. I processi pianificati non dispongono del broker per shell interattiva e pertanto non possono utilizzare strumenti MCP remoti. Un prompt pianificato che dipende da MCP può comunque essere eseguito ma può terminare senza l'azione o i dati MCP richiesti. Non pianificare richieste che richiedono MCP.

Consulta le FAQ MCP per una rapida panoramica e note di configurazione.

Comandi

ash [--attach path]... [text ...]
Esegui una singola richiesta di assistente. --attach allega alla richiesta un file (immagine o documento); ripetibile. Dimensioni limitate da ASH_ATTACHMENT_MAX_BYTES e attualmente inviato in rete solo a provider compatibili con OpenAI.
ash mcp add <url> [--no-browser]
Connetti e registra un server MCP remoto nell'attuale .ash_allow. Apre l'autorizzazione OAuth in un browser desktop quando disponibile; ritorna a un URL copiabile nel terminale. --no-browser utilizza sempre il flusso del terminale.
ash install [--shell bash|zsh] [--dry-run]
Installa o aggiorna l'integrazione della shell. Quando --shell viene omesso, quando possibile viene utilizzata la shell corrente. --dry-run visualizza in anteprima le modifiche senza scrivere. Quando è interattivo, l'installazione si configura automaticamente anche AI_ENDPOINT, AI_MODEL e AI_AUTH_TOKEN: preferisce una chiave API del provider cloud già impostata (OpenAI, Anthropic, Google Gemini, Azure OpenAI, Mistral, Cohere, Groq, xAI, DeepSeek, Together AI, OpenRouter o HuggingFace), quindi un server di inferenza locale in esecuzione (Ollama, LM Studio, llama.cpp/MLX/LocalAI, vLLM, text- generation-webui, Jan o GPT4All) e in caso contrario richiede un menu del provider numerato. Il modello viene scelto dall'elenco dei modelli dell'endpoint quando disponibile.
ash snooze [duration|off]
Interrompe l'elaborazione automatica del prompt della shell. Il valore predefinito è cinque minuti. Le durate utilizzano la sintassi Go come 30s, 5m o 1h. Utilizza off per riprendere immediatamente.
ash update [--version vX.Y.Z] [--yes|--skip-customized]
Scarica e installa l'ultima versione stabile di macOS, Linux o FreeBSD per l'architettura corrente in ~/.local/bin/ash. Le versioni richiedono la verifica Sigstore e la verifica SHA-256.

Ambiente

AI_AUTH_TOKEN
Token al portatore opzionale. Se impostato, viene inviato come autenticazione della portante ed è richiesto per gli endpoint cloud. Gli indirizzi privati/LAN (RFC1918 IPv4, IPv6 ULA) e i nomi host mDNS .local vengono trattati come non cloud (come localhost) a meno che non sia impostato ASH_STRICT=1.
AI_CACHE
Attivazione/disattivazione cache nativa del provider opzionale. Abilitato per impostazione predefinita quando supportato; utilizzare off o false per disabilitare.
AI_ENDPOINT
URL di base richiesto per l'endpoint API della chat.
AI_MODEL
Nome del modello richiesto inviato al endpoint.
AI_PROVIDER
Override opzionale del provider: anthropic, bedrock, cohere, gemini, google, ollama o openai. Quando non impostato, ash rileva il provider dall'endpoint.
AI_TIMEOUT
Timeout della richiesta facoltativo. Impostazione predefinita: 3m.
ASH_ALWAYS_OPENAI_API
Attiva/disattiva test facoltativo. In modalità true-like, instrada il provider ollama attraverso l'adattatore SDK compatibile con OpenAI invece della sua implementazione manuale. Impostazione predefinita: attiva.
ASH_ATTACHMENT_MAX_BYTES
Dimensione massima opzionale in byte per un file passato tramite --attach. Impostazione predefinita: 10485760 (10 MiB).
ASH_HISTORY_MAX
Messaggi storici massimi opzionali per chiave. Impostazione predefinita: 40.
ASH_LOG_FILE
Percorso del registro di debug facoltativo quando la registrazione dettagliata è abilitata.
ASH_LOG_MAX_BYTES
Dimensione massima del registro facoltativa prima della rotazione. Predefinito: 1048576.
ASH_MAX_AGENTS
Numero massimo di agenti secondari facoltativi generati da un processo principale. Impostazione predefinita: 6.
ASH_MAX_TOOL_ITERS
Iterazioni massime facoltative del loop di chiamate allo strumento AI. Impostazione predefinita: 16.
ASH_RELEVANCE_WINDOW
Osservazioni recenti facoltative dello strumento incluse nello stato di esecuzione. Impostazione predefinita: 4.
ASH_RETRY_BASE_DELAY
Ritardo base backoff tra tentativi facoltativo. Impostazione predefinita: 250ms.
ASH_RETRY_MAX_ATTEMPTS
Tentativi di richiesta riproducibili facoltativi. Impostazione predefinita: 3.
ASH_SCHEDULED_TASK
Flag di pianificazione interno utilizzato dalle invocazioni gestite da ash.
ASH_STREAM
Attivazione/disattivazione facoltativa. In modalità true-like, trasmette la risposta dai provider il cui adattatore la supporta (attualmente solo OpenAI). Impostazione predefinita: attivato.
ASH_TASK_MAX
Limite facoltativo sulle attività di esecuzione derivate da una richiesta. Predefinito: 6.
ASH_TASK_STALL_ROUNDS
L'assistente opzionale fa un giro di stallo prima di fermarsi. Impostazione predefinita: 2.
ASH_ALLOW
Lista consentita facoltativa di eseguibili separati da virgole per run_unix_command. Altrimenti ~/.ash/.ash_allow viene utilizzato quando presente; questa sostituzione non espande i token Ash interni.
ASH_DENY
Lista negata facoltativa separata da virgole per bloccare esplicitamente comandi, strumenti e plug-in. Altrimenti ~/.ash/.ash_deny viene utilizzato quando presente.
ASH_TOOL_OUTPUT_MAX
Uscita massima opzionale dello strumento catturato in byte. Impostazione predefinita: 8192.
ASH_TOOL_TIMEOUT
Timeout comando strumento locale opzionale. Impostazione predefinita: 15s.
ASH_VERBOSE
Registrazione debug ed esecuzione dashboard facoltativi. Valori come 1, true, on e debug lo abilitano.
SESSION_ID
Identificatore di sessione per cronologia persistente e denominazione dei registri. Generato automaticamente per le corse interattive in caso di mancanza.

File

  • ~/.ash/.ash_system: prompt del sistema canonico. $TOOLS_DIR_LIST, $PLUGINS_DIR_LIST e $IF_PYTHON_AVAILABLE sono sostituzioni interne Ash, mai variabili di ambiente.
  • ~/.ash/.ash_allow — comando canonico, strumento e lista consentita dei plugin. Le sue direttive autonome $TOOLS_DIR_LIST e $PLUGINS_DIR_LIST consentono script gestiti regolari e plugin nativi; sostituire con nomi letterali per una policy restrittiva.
  • ~/.ash/.ash_deny — file canonico di lista negata per bloccare comandi, strumenti o plugin specifici.
  • ~/.ash/plugins/ — directory dei plugin binari nativi.
  • ~/.ash/history/ — file di cronologia delle conversazioni.
  • ~/.ash/scratch/ — scratch con ambito sessione file.
  • ~/.ash/.ash_snooze_until: scadenza posticipazione automatica del prompt.

Stato di uscita

ash restituisce 0 in caso di successo. Restituisce un valore diverso da zero quando la configurazione, le richieste di rete o l'esecuzione dello strumento falliscono.

Esempi

echo "summarize this directory" | ash
ash install --shell bash
ash install --shell zsh --dry-run
