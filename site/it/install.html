Prima di iniziare

  1. Sistema e shell supportati: macOS o Linux su amd64/x86_64 o arm64/aarch64, oppure FreeBSD su amd64. Usa Bash, zsh o Fish. I pacchetti Arch sono solo x86_64. Non esiste un installer nativo Windows/PowerShell.
  2. Accesso ai download: connessione Internet funzionante e accesso HTTPS affidabile a GitHub, al repository scelto e al fornitore del modello. Anche l’inferenza locale richiede un download iniziale del modello.
  3. Permessi: directory personale scrivibile per i file utente. I pacchetti di sistema Linux e .pkg macOS richiedono amministrazione; esegui Homebrew e ash install come utente normale.
  4. Un modello: server locale con modello scaricato oppure account cloud/chiave API. Scegli un modello con chiamate agli strumenti, non solo immagini/audio. RAM, disco e GPU locali dipendono dal modello.

I pacchetti ash precompilati non richiedono Go, Rust, Node.js o strumenti Xcode. Il gestore può avere propri prerequisiti; segui prima la sua configurazione ufficiale.

Facoltativo: strumenti Python inclusi

L’uso base non richiede Python. Gli strumenti inclusi richiedono Python 3 con venv e ensurepip e accesso alle dipendenze da scaricare. Su Debian/Ubuntu installa python3 e python3-venv; Python Homebrew include venv. Su FreeBSD usa pip corrispondente alla versione Python. Riesegui ash install. Viene creato un ambiente isolato in $XDG_DATA_HOME/ash/venv (predefinito ~/.local/share/ash/venv); un errore disattiva gli strumenti, non ash base.

macOS

Consigliato: Homebrew

Prerequisiti: Homebrew, ambiente macOS supportato e comando brew funzionante. Il tap sceglie automaticamente l’archivio Intel o Apple Silicon. Installa Release senza sudo:

brew install Jonconradt/ash/ash
ash version

Homebrew gestisce binari, plugin nativi, manuali e avvisi di licenza nel proprio prefisso (normalmente /opt/homebrew su Apple Silicon o /usr/local su Intel). Verifica l’archivio con lo SHA-256 della formula. Non configura fornitore o avvio della shell: continua con l’inizializzazione utente. Aggiorna con brew upgrade ash, rimuovi Release con brew uninstall ash; vedi formule dei canali per Beta/Nightly.

Alternativa: .pkg nativo

Scarica darwin-arm64.pkg per Apple Silicon o darwin-amd64.pkg per Intel da una versione pubblicata. Verifica il manifesto firmato delle somme di controllo prima di aprire l’installer. Servono privilegi amministrativi.

Il pacchetto macOS non è firmato né notarizzato. Il manifesto verifica separatamente editore/somme, non è notarizzazione Apple. Non disattivare Gatekeeper né aggirare avvisi per installare ash; preferisci Homebrew se richiesto dalla politica di sicurezza.

Il pacchetto scrive ash e ash-broker in /usr/local/bin, plugin in /usr/local/lib/ash/plugins, manuali in /usr/local/share/man, avvisi in /usr/local/share/licenses/ash. La ricevuta è dev.ash.cli. Non inizializza l’utente né iscrive agli aggiornamenti: inizializza dopo, aggiorna sostituendo con un .pkg più recente verificato e usa la rimozione manuale per disinstallare. Non sovrascrivere una copia Homebrew.

Linux

Usa il gestore della distribuzione quando possibile. I pacchetti gestiscono /usr/bin/ash, /usr/bin/ash-broker, /usr/lib/ash/plugins, manuali in /usr/share/man e avvisi di licenza. Impostazioni del fornitore e hook della shell spettano all’inizializzazione utente.

Debian e Ubuntu: APT

Prerequisiti: amd64 o arm64, amministrazione, APT, curl, gpg e certificati CA. Installa dalla distribuzione gli strumenti download/chiavi mancanti prima del repository. Release si chiama stable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Prima di importare chiavi verifica l’impronta con una fonte affidabile dell’editore. L’impronta VersionX è 32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. APT verifica metadati firmati e digest dei pacchetti inclusi; signed-by limita l’ambito della chiave. Aggiorna con sudo apt update && sudo apt upgrade ash; rimuovi con sudo apt remove ash.

Fedora e sistemi compatibili RHEL: DNF

Prerequisiti: x86_64 o aarch64, amministrazione, DNF/RPM, curl, gpg e certificati CA. Installa gli strumenti mancanti dalla distribuzione. Ispeziona la chiave e confronta l’impronta sopra prima dell’importazione:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

I RPM non sono firmati singolarmente. repo_gpgcheck=1 verifica i metadati con le loro somme; gpgcheck=0 riflette l’assenza di firme per pacchetto, non la disattivazione della verifica repository. Se la tua politica richiede contenuti RPM firmati, questo repository non basta. Aggiorna con sudo dnf upgrade ash; rimuovi con sudo dnf remove ash.

Arch Linux: Pacman

Prerequisiti: x86_64, amministrazione, Pacman con portachiavi inizializzato, curl e gpg. Verifica che l’impronta mostrata corrisponda alla precedente prima di fidarti. Aggiungi il repository una volta, non a ogni aggiornamento:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman verifica firme dei pacchetti e del database. Sincronizza Arch con sudo pacman -Syu, evitando aggiornamenti parziali; rimuovi ash con sudo pacman -R ash.

Altri metodi Linux

Usi già Homebrew su Linux? Le stesse istruzioni tap supportano amd64 e arm64; i file sono gestiti da Brew, non APT/DNF. Altrimenti usa script/archivio verificato o un download .deb/.rpm adatto. Installa un .deb verificato con sudo apt install ./PACKAGE.deb, un .rpm con sudo dnf install ./PACKAGE.rpm (sostituisci i nomi). Il pacchetto resta gestito, ma non aggiunge repository né iscrizione automatica a versioni future. Il RPM attuale non è firmato; segui la politica della distribuzione invece di disattivare verifiche.

FreeBSD

Prerequisiti: amd64, Bash (anche se usi zsh o Fish interattivamente), strumenti download/verifica e directory scrivibile. Installa Bash con il gestore nativo FreeBSD:

sudo pkg install bash

Il pkg FreeBSD gestisce prerequisiti, non ash: non esistono attualmente repository ash .pkg o archivio arm64. Usa lo script verificato, oppure verifica un tarball FreeBSD amd64, estrailo in una directory temporanea e installa il binario ash versionato come ~/.local/bin/ash, accanto a ash-broker. Copia plugin nativi in $XDG_DATA_HOME/ash/plugins (predefinito ~/.local/share/ash/plugins), poi inizializza. Gestisci tu questi file; pkg delete non li rimuove. Usa autoaggiornamenti Release nel percorso predefinito o sostituisci file verificati manualmente.

Inizializzare e verificare

Dopo i binari configura interattivamente come utente normale. La sola configurazione dei file non modifica l’avvio:

ash install

Per integrare anche comandi non trovati, scegli esattamente un comando per la tua shell:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Fish

ash install --shell fish --shell-integration

Bash usa ~/.bashrc, zsh ~/.zshrc, Fish $XDG_CONFIG_HOME/fish/config.fish (predefinito ~/.config/fish/config.fish). Apri poi una nuova shell; quelle esistenti mantengono il broker. L’integrazione antepone ~/.local/bin al PATH: rimuovi copie locali vecchie prima di aspettarti un pacchetto di sistema.

Se mancano impostazioni, vengono rilevate chiavi esistenti o server locale attivo; altrimenti si propone il menu fornitori e si chiedono credenziali. Scegli un modello disponibile con strumenti. Impostazioni valide restano: rieseguire non cambia fornitore.

Le impostazioni sono in $XDG_CONFIG_HOME/ash/.ash_env (predefinito ~/.config/ash/.ash_env, permessi privati). L’integrazione le carica. Senza integrazione, Bash/zsh possono caricare il file nell’avvio; Fish deve impostare le variabili ASH_AI_* nella propria sintassi, senza caricare il file Bash. Proteggi file con token e non committarli mai.

Per installazioni locali senza integrazione aggiungi il percorso effettivo al PATH. Bash/zsh: export PATH="$HOME/.local/bin:$PATH". Fish: fish_add_path "$HOME/.local/bin". Rendilo permanente nell’avvio; sostituisci il percorso personalizzato quando necessario.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

I primi comandi devono trovare l’installazione scelta. La richiesta necessita di server attivo o credenziali cloud valide; installare ash non installa un modello.

Ollama locale: nessun account cloud

Installa Ollama con le istruzioni ufficiali del sistema. Avvia app/servizio o ollama serve in un altro terminale se manca un server. Il supporto ash FreeBSD non implica un installer Ollama nativo: usa un server raggiungibile su altro host supportato se necessario.

Scarica un modello con strumenti adatto all’hardware; llama3.1:8b è un esempio, non un requisito minimo. Consulta il catalogo attuale con strumenti per alternative:

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

Senza chiavi cloud già definite, si può rilevare il server locale e proporre il modello scaricato. Se c’è già un altro fornitore, cambia manualmente endpoint/modello. Esempio Bash/zsh:

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Equivalente Fish:

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Queste modifiche valgono solo nella shell attuale. Salvale nel file ambiente ash protetto o nella configurazione adatta, sostituendo vecchie impostazioni. Ollama locale non richiede token. Mantieni il server su loopback salvo accesso deliberatamente protetto; server remoti ricevono richieste e risultati degli strumenti.

Facoltativo: imposta OLLAMA_KEEP_ALIVE=30m nell’ambiente del server Ollama e riavvialo per mantenere modelli caricati. -1 li mantiene indefinitamente ma consuma memoria tra richieste. Impostarlo solo nel terminale client ash non riconfigura server già attivi.

L’inferenza locale non fattura API ma usa hardware/spazio/energia. Ollama cloud è un servizio separato con autenticazione e limiti del piano, non questa configurazione locale.

Piani cloud gratuiti

Gratuito non significa illimitato o privato. Account, regioni, quote, modelli e politiche dati variano e cambiano. Richieste e risultati pertinenti lasciano la macchina. Controlla limiti e condizioni; abilita fatturazione a pagamento solo se vuoi pagare.

Crea una chiave dai link, esegui ash install interattivamente e scegli il fornitore. Vengono richiesti token ed elencati modelli dove supportato. Scegli un modello testuale gratuito con strumenti attualmente disponibile; essere elencato non garantisce gratuità per il tuo account.

Configurazione manuale o cambio fornitore

Sostituisci l’endpoint seguente con quello della tabella e MODEL_ID con un modello verificato nel tuo account. Se la chiave è già esportata come GROQ_API_KEY, questo esempio Bash/zsh la riusa senza digitare il segreto:

export ASH_AI_ENDPOINT="https://api.groq.com/openai/v1"
export ASH_AI_MODEL="MODEL_ID"
export ASH_AI_AUTH_TOKEN="$GROQ_API_KEY"

Equivalente Fish:

set -gx ASH_AI_ENDPOINT https://api.groq.com/openai/v1
set -gx ASH_AI_MODEL MODEL_ID
set -gx ASH_AI_AUTH_TOKEN "$GROQ_API_KEY"

Per Gemini/OpenRouter usa i rispettivi endpoint e variabili riconosciute. Salva le impostazioni in sicurezza per future shell. Il cloud richiede HTTPS e token; HTTP locale non è una scorciatoia cloud. Vedi riferimento ambiente e altri fornitori supportati per servizi a pagamento e configurazioni avanzate.

Script d’installazione: alternativa, non prima scelta

Preferisci Homebrew, APT, DNF o Pacman: tracciano file gestiti, verificano download con la propria fiducia e offrono aggiornamento/rimozione familiari. Richiedono comunque fiducia in editori e azioni d’installazione.

Uno script web esegue codice con i permessi del tuo account. Un sito/editore compromesso o script modificato può leggere segreti, alterare file o installare software. HTTPS protegge il trasporto, non le intenzioni. Inviare una URL direttamente alla shell esegue prima dell’esame. Le firme degli archivi non autenticano lo script. Mai eseguirlo con sudo o disabilitarne la verifica.

Prerequisiti: sistema/architettura supportati, $SHELL indicante Bash/zsh/Fish, Sigstore cosign, tar, uname, install, utilità standard, comando SHA-256 (sha256sum, shasum o sha256) e downloader (curl, wget o Python). L’esempio usa curl. FreeBSD richiede anche Bash. La directory personale/d’installazione deve essere scrivibile.

Scarica un file locale, esaminalo in un editor ed eseguilo solo se ti fidi di fonte e comportamento. L’esame non garantisce sicurezza; non seguire questi passaggi alla cieca:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

Dopo l’esame esegui la copia salvata come utente normale:

sh ./ash-install.sh
rm ./ash-install.sh

install.sh scarica l’ultimo Release, verifica manifesto firmato Sigstore e digest archivio e installa ash/ash-broker in ~/.local/bin. I plugin vanno in $XDG_DATA_HOME/ash/plugins. Configura l’utente e chiede prima dell’integrazione shell. Senza terminale interattivo può saltare domande fornitore/integrazione: esegui poi ash install interattivamente.

Imposta ASH_INSTALL_DIR prima dello script per un’altra destinazione. Aggiungila al PATH autonomamente. L’autoaggiornamento supporta solo ~/.local/bin; destinazioni personalizzate richiedono sostituzione manuale. Lo script non seleziona Beta/Nightly.

Verificare un pacchetto o archivio diretto

Prerequisiti: cosign e utilità SHA-256. Scarica pacchetto/archivio, SHA256SUMS e SHA256SUMS.sigstore.json dalla stessa versione pubblicata. Lavora in una directory nuova. Sostituisci vX.Y.Z con il tag esatto, incluso suffisso preliminare se applicabile:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Solo dopo successo calcola il digest con shasum -a 256 PACKAGE su macOS, sha256sum PACKAGE su Linux o sha256 -q PACKAGE su FreeBSD. Sostituisci PACKAGE con il nome scaricato e confrontalo esattamente alla sua voce nel manifesto verificato. Fermati se manca o differisce. Una somma non firmata accanto al file non equivale a metadati verificati dell’editore.

Aggiornamenti e tre canali

  • Release (consigliato): versioni stabili come vX.Y.Z; il repository lo chiama stable.
  • Beta: test preliminari con tag vX.Y.Z-beta.N; aspettati modifiche e regressioni.
  • Nightly: modifiche recenti del ramo predefinito, tag vX.Y.Z-nightly.YYYYMMDD.N; massimo rischio di regressione. Build programmate possono essere saltate senza modifiche o se fallisce la pubblicazione.

Una pubblicazione aggiorna formula Homebrew o repository Linux firmato corrispondente. La ricevi con l’aggiornamento del gestore responsabile o secondo la politica del sistema. Pubblicazione, repository e sito possono essere sfalsati; verifica disponibilità prima di cambiare canale. ash non installa binari silenziosamente in background.

Homebrew: installare o cambiare formule

Per nuove installazioni Beta/Nightly usa il nome completo sopra in brew install. Per cambiare disinstalla prima la formula attuale: tutte forniscono gli stessi binari. Esempio Release a Beta:

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

Usa ash-nightly per Nightly o ash per Release nei comandi installazione/aggiornamento. Rimuovi la vera formula del vecchio canale, non sempre ash. I dati utente restano; apri poi una nuova shell.

Linux: scegliere un canale repository

APT: usa la configurazione APT con esattamente una distribuzione della tabella. Per cambiare modifica /etc/apt/sources.list.d/versionx.list, sostituendo stable con beta o nightly (o ritorna a stable), poi:

sudo apt update
sudo apt install --allow-downgrades ash

DNF: usa la configurazione DNF con baseurl scelta. Per installazioni esistenti sostituisci baseurl in /etc/yum.repos.d/versionx.repo, mantenendo firme, poi:

sudo dnf --refresh distro-sync ash

Pacman: usa la configurazione Pacman con URL Server scelta. Mantieni la sezione [versionx]: ogni canale pubblica il database versionx.db. Cambia Server in quella sezione, senza aggiungere database con altro nome. Per cambiare, incluso downgrade:

sudo pacman -Syuu ash

Esamina la transazione: tornare a Release può retrocedere ash, e il doppio u Pacman anche altri pacchetti. Salva configurazione prima. Poi usa aggiornamenti normali APT/DNF/Pacman delle sezioni sistema; non lasciare più fonti di canali ash attive.

Aggiornamenti Release locali all’utente

ash update

Verifica e installa una versione stabile solo se l’ash attivo è in ~/.local/bin. Aggiorna anche file/plugin inclusi, con scelte per personalizzati. ash update --version vX.Y.Z sceglie tag stabile, non canale; non è un downgrade. Non esiste --channel. Pacchetti gestiti, .pkg macOS e script in percorsi personalizzati usano gestore/installer originario. FreeBSD Beta/Nightly usa archivi verificati manuali, non iscrizione all’autoaggiornatore. Apri poi una nuova shell.

Disinstallare senza cancellare file estranei

1. Disattivare prima integrazione shell

Prima di rimuovere binari, esegui il comando per ogni shell con integrazione:

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Fish

ash install --shell fish --disable-shell-integration

Se ash manca già, modifica l’avvio indicato in inizializzazione e rimuovi solo il blocco tra # >>> ash install >>> e # <<< ash install <<<. Rimuovi righe PATH/ambiente ash aggiunte manualmente, non altro. Chiudi poi shell ash per terminare i broker.

2. Lasciare rimuovere i file al gestore responsabile

Homebrew (Release)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

Scegli solo il tuo metodo; per Homebrew Beta/Nightly usa ash-beta/ash-nightly. APT/DNF/Pacman rimuovono binari, plugin e manuali propri, non configurazione/cronologia personali. Non cancellare manualmente file gestiti.

Pulizia repository facoltativa: rimuovi la fonte ash /etc/apt/sources.list.d/versionx.list e la chiave dedicata /etc/apt/keyrings/versionx-keyring.gpg, il repository /etc/yum.repos.d/versionx.repo, oppure sezione ash [versionx] da /etc/pacman.conf. Controlla prima che altri pacchetti non li usino. Rimuovi chiavi RPM/Pacman solo verificando impronta e assenza d’altri dipendenti; mai il portachiavi condiviso della distribuzione.

3a. Rimozione manuale .pkg macOS

macOS Installer registra una ricevuta ma non ha disinstallatore ash. Conferma installazione .pkg, non Homebrew, ed esamina il contenuto esatto:

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

Usando la ricevuta come inventario, rimuovi solo file ash: /usr/local/bin/ash, /usr/local/bin/ash-broker, file in /usr/local/lib/ash/plugins, /usr/local/share/man/man1/ash.1, pagine ash.1 tradotte elencate e avvisi in /usr/local/share/licenses/ash. Servono privilegi amministrativi. Verifica proprietà se un altro installer li ha sostituiti; non rimuovere la sua copia. Rimuovi directory vuote esclusive, non condivise /usr/local, bin o manuali.

Dopo i file, rimuovi facoltativamente la ricevuta:

sudo pkgutil --forget dev.ash.cli

Dimenticare una ricevuta non elimina file installati. Conservala fino alla fine della verifica del contenuto.

3b. Rimozione manuale locale / Linux / FreeBSD

Trova la copia attiva con command -v ash e command -v ash-broker. Per lo script predefinito, dopo aver disabilitato hook, rimuovi esattamente questi due file:

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

Per ASH_INSTALL_DIR o archivio estratto manualmente, rimuovi solo percorsi reali ash/broker. Elimina plugin/manuali/avvisi installati secondo l’inventario originale; i plugin dello script sono nei dati utente ash. In /usr/bin controlla proprietà con dpkg -S /usr/bin/ash, rpm -qf /usr/bin/ash o pacman -Qo /usr/bin/ash. Una copia gestita va rimossa dal gestore anche se scaricata singolarmente.

4. Facoltativo: cancellare impostazioni, strumenti e cronologia

Salva ciò che vuoi conservare. Questo passo separato può cancellare impostazioni/token, strumenti/plugin personalizzati, conversazioni e file di lavoro. Disinstallare binari non implica consenso a cancellarli.

  • Configurazione: $XDG_CONFIG_HOME/ash, predefinito ~/.config/ash.
  • Dati, plugin e ambiente Python: $XDG_DATA_HOME/ash, predefinito ~/.local/share/ash.
  • Cronologia e stato: $XDG_STATE_HOME/ash, predefinito ~/.local/state/ash.
  • Cache: $XDG_CACHE_HOME/ash, predefinito ~/.cache/ash.
  • Runtime broker: $XDG_RUNTIME_DIR/ash, oppure $XDG_STATE_HOME/ash/runtime senza radice runtime disponibile.

Esamina i veri percorsi XDG assoluti prima di cancellare solo sottodirectory ash; mai radice XDG o directory personale. Dopo aver chiuso tutte le shell ash, rimuovi residui runtime se serve. Credenziali MCP OAuth possono restare nel gestore del sistema: rimuovi voci ash e revoca accesso presso MCP. Revoca chiavi IA inutilizzate nei rispettivi account; cancellare file non revoca chiavi. Non disinstallare Ollama/modelli, Python o dipendenze condivise rimuovendo ash.

Risoluzione rapida dei problemi

Comando assente o versione errata
Controlla PATH e command -v ash/command -v ash-broker. Una vecchia copia in ~/.local/bin può nascondere pacchetti. Usa un solo responsabile/canale e apri una nuova shell.
Menu fornitori assente
Esegui ash install interattivamente. Impostazioni valide restano; usa configurazione manuale per cambiare. Senza integrazione esporta impostazioni nell’ambiente CLI.
Modello assente o connessione rifiutata
Per Ollama verifica server attivo e modello in ollama list. Nel cloud verifica endpoint, idoneità, HTTPS, token e quota; non condividere log con token.
Repository o canale indisponibile
Verifica architettura e versione/repository pubblicati. Pubblicare può tardare; non disattivare firme per aggirare indisponibilità.
Configurazione Python fallita
Installa Python con venv/ensurepip, consenti download dipendenze e riesegui ash install. ash base resta utilizzabile senza questi strumenti.
