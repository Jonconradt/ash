Prima di iniziare

  1. Un sistema e una shell supportati: macOS o Linux su amd64/x86_64 o arm64/aarch64 o FreeBSD su amd64. Usa Bash, zsh o Fish. I pacchetti Arch sono solo x86_64. Non esiste un programma di installazione nativo di Windows/PowerShell.
  2. Accesso per il download: una connessione Internet funzionante e un accesso HTTPS affidabile a GitHub, al repository di pacchetti selezionato e al provider del modello. L'inferenza locale richiede ancora il download iniziale del modello.
  3. Autorizzazioni: una directory home scrivibile per le risorse per utente. I pacchetti del sistema Linux e macOS .pkg necessitano dell'accesso come amministratore; esegui Homebrew e ash install come utente normale.
  4. Un modello: un server di inferenza locale con un modello scaricato o un account cloud/chiave API. Scegli un modello che supporti la chiamata degli strumenti, non un modello solo immagine/audio. Le esigenze di RAM locale, disco e GPU dipendono dal modello.

I pacchetti ash predefiniti non richiedono gli strumenti di creazione Go, Rust, Node.js o Xcode. Un gestore di pacchetti può avere i propri prerequisiti; segui prima le istruzioni di configurazione ufficiali.

Opzionale: strumenti Python in bundle

Di baseashl'uso non richiede Python. Gli strumenti Python in bundle richiedono Python 3venvEensurepip, oltre all'accesso per scaricare le relative dipendenze. Su Debian/Ubuntu, installapython3Epython3-venv; Homebrew Python include il supporto venv. Su FreeBSD, usa il pacchetto pip corrispondente alla tua versione Python. Quindi rieseguireash install. L'installazione crea un ambiente isolato sotto$XDG_DATA_HOME/ash/venv(predefinito~/.local/share/ash/venv); un errore disabilita quegli strumenti, non quelli di baseash.

Debian e Ubuntu: APT

Prerequisiti: amd64 o arm64, accesso amministratore, APT,curl,gpge certificati CA. Installa gli strumenti di download/chiave mancanti utilizzando la tua distribuzione prima di aggiungere il repository. La versione è nominatastable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Prima di importare qualsiasi chiave del repository, verifica la sua impronta digitale rispetto a una fonte di editore attendibile. L'impronta digitale della chiave VersionX è32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. APT controlla i metadati del repository firmato e il pacchetto digest che contiene; l'ambito della chiave è compresosigned-by. Aggiorna consudo apt update && sudo apt upgrade ash; rimuovere consudo apt remove ash.

Sistemi compatibili con Fedora e RHEL: DNF

Prerequisiti: x86_64 o aarch64, accesso amministratore, DNF/RPM,curl,gpge certificati CA. Installa gli strumenti mancanti dalla tua distribuzione. Ispeziona la chiave e confronta l'impronta digitale sopra prima di importarla:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

I file RPM non sono firmati individualmente.repo_gpgcheck=1verifica i metadati del repository che coprono i loro checksum;gpgcheck=0riflette le firme per pacchetto assenti, non la verifica del repository disabilitata. Se la tua policy richiede payload RPM firmati, questo repository non li soddisfa. Aggiorna consudo dnf upgrade ash; rimuovere consudo dnf remove ash.

ArchLinux: Pacman

Prerequisiti: x86_64, accesso amministratore, Pacman con il suo portachiavi inizializzato,curl, Egpg. Verificare che l'impronta digitale della chiave visualizzata corrisponda a quella sopra prima di fidarsi. Aggiungi il repository una volta, non a ogni aggiornamento:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman verifica sia le firme dei pacchetti che quelle del database. Mantieni Arch sincronizzato consudo pacman -Syu, non un aggiornamento parziale; rimuovereashconsudo pacman -R ash.

Inizializza e verifica

Dopo aver installato i file binari, esegui il setup in modo interattivo come utente normale. Se non desideri l'integrazione della shell, puoi installare solo Ash. Probabilmente non è quello che vuoi. Il vero valore di ash è l'integrazione della shell di seguito. La configurazione delle sole risorse lascia invariati i file di avvio:

ash install

L'installazione che probabilmente desideri utilizzare prevede l'integrazione della shell. Questo cambierà il tuo .bashrc (o l'equivalente per la tua shell) per includere Ash. Per abilitare l'integrazione dei comandi non trovati, scegli esattamente un comando per la shell che utilizzi:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Pesce

ash install --shell fish --shell-integration

Bash utilizza~/.bashrc, usa zsh~/.zshrce usi del pesce$XDG_CONFIG_HOME/fish/config.fish(predefinito~/.config/fish/config.fish). Successivamente apri una nuova shell; le shell esistenti mantengono il loro broker in esecuzione. L'integrazione è anteposta~/.local/binal PERCORSO: rimuove una vecchia copia locale dell'utente prima di aspettarsi che venga selezionato un pacchetto di sistema.

Se mancano le impostazioni del provider, la configurazione rileva le chiavi del provider esistenti o un server locale in esecuzione; altrimenti offre un menu del provider e richiede le credenziali. Scegli un modello compatibile con strumenti disponibile. Le impostazioni valide esistenti vengono conservate, quindi la riesecuzione della configurazione non è un comando di cambio provider.

Le impostazioni sono memorizzate in$XDG_CONFIG_HOME/ash/.ash_env(predefinito~/.config/ash/.ash_env, autorizzazioni per file privati). L'integrazione gestita li carica. Senza integrazione, gli utenti Bash/zsh possono procurarsi quel file nella normale configurazione di avvio; Gli utenti Fish dovrebbero impostare il corrispondenteASH_AI_*variabili che utilizzano la sintassi Fish, non originano il file in formato Bash. Proteggi qualsiasi file contenente token e non eseguirne mai il commit.

Per un'installazione locale dell'utente senza integrazione, aggiungere la directory effettiva a PATH. Bash/zsh:export PATH="$HOME/.local/bin:$PATH". Pescare:fish_add_path "$HOME/.local/bin". Mantienilo utilizzando la configurazione di avvio della tua shell; sostituire la directory di installazione personalizzata quando applicabile.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

I primi comandi dovrebbero risolvere l'installazione che hai scelto. La richiesta richiede un server in esecuzione o credenziali cloud valide; l'installazione di ash non installa un modello.

Installazione di script: un'alternativa, non la prima scelta

Preferisci Homebrew, APT, DNF o Pacman: tengono traccia dei file di proprietà, verificano i download utilizzando la loro configurazione di attendibilità e forniscono aggiornamenti/rimozioni familiari. Richiedono comunque la fiducia degli editori e le azioni di installazione dei pacchetti.

Uno script di un sito web esegue il codice con le autorizzazioni del tuo account. Un sito web, un editore o uno script modificato compromesso può leggere segreti, alterare file o installare altro software. HTTPS protegge il trasporto, non le intenzioni di quel codice. Inviando un URL direttamente a una shell lo si esegue prima che tu possa rivederlo. I controlli della firma dell'archivio dello script non autenticano lo script stesso. Non eseguirlo mai con sudo né disabilitarne la verifica.

Prerequisiti: un sistema operativo/architettura supportato,$SHELLidentificare Bash/zsh/Fish,Firma Sigstore,tar,uname,install, utilità della shell standard, un comando SHA-256 (sha256sum,shasum, Osha256) e un downloader (curl,wgeto Python). L'esempio utilizza curl. Anche FreeBSD ha bisogno di Bash. La tua directory home/installazione deve essere scrivibile.

Scaricalo in un file locale, esaminalo con un editor ed eseguilo solo se ti fidi della sua origine e del suo comportamento. L'ispezione non è una garanzia di sicurezza; non eseguire questi passaggi alla cieca:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

Dopo l'ispezione, esegui la copia salvata come utente normale:

sh ./ash-install.sh
rm ./ash-install.sh

install.shscarica la versione più recente, verifica il manifest del checksum firmato Sigstore e il digest dell'archivio, quindi installaash/ash-brokerIn~/.local/bin. I plugin nativi vanno in rovina$XDG_DATA_HOME/ash/plugins. Esegue la configurazione per utente e chiede prima di abilitare l'integrazione della shell. Senza un terminale interattivo, le richieste del provider/integrazione potrebbero essere saltate: eseguiash installin modo interattivo in seguito.

Puoi impostareASH_INSTALL_DIRprima di eseguire lo script per scegliere un'altra destinazione. Aggiungi tu stesso quella destinazione a PATH.L'aggiornamento automatico è supportato solo in~/.local/bin; le destinazioni personalizzate richiedono la sostituzione manuale. Lo script non ha un selettore Beta/Notturno.

Verificare un pacchetto o un archivio diretto

Prerequisiti: cosign e un'utilità SHA-256. Dalla stessa versione pubblicata, scarica il tuo pacchetto/archivio,SHA256SUMS, ESHA256SUMS.sigstore.json. Lavora in una nuova directory. SostituirevX.Y.Zcon il tag esatto, incluso un suffisso prerelease, se applicabile:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Solo dopo che ciò ha esito positivo, calcola il digest del tuo file conshasum -a 256 PACKAGEsu macOS,sha256sum PACKAGEsu Linux, osha256 -q PACKAGEsu FreeBSD. SostituirePACKAGEcon il nome file scaricato e confrontalo esattamente con la voce di quel nome file nel manifest verificato. Interrompi su una voce mancante o su qualsiasi mancata corrispondenza. Un checksum non firmato scaricato accanto a un file non equivale ai metadati dell'editore verificati.

Aggiornamenti e i tre canali

  • Rilascio (consigliato):versioni pubblicate stabili comevX.Y.Z; la configurazione del repository lo chiamastable.
  • Beta:test pre-release, taggatovX.Y.Z-beta.N; aspettarsi cambiamenti e regressioni.
  • Notturno:recenti modifiche al ramo predefinito, contrassegnate con tagvX.Y.Z-nightly.YYYYMMDD.N; il più alto rischio di regressione. Le build sono pianificate ma potrebbero essere saltate se non cambia nulla o la pubblicazione non riesce.

Una versione pubblicata aggiorna la corrispondente formula Homebrew o il repository Linux firmato. Lo ricevi quando esegui il comando di aggiornamento del gestore proprietario (o lo fa la tua politica di aggiornamento del sistema operativo). La pubblicazione, gli aggiornamenti del repository e la distribuzione del sito Web possono ritardare a vicenda; verificare la disponibilità prima di cambiare canale. ash non installa silenziosamente gli aggiornamenti binari in background.

4. Facoltativo: cancella le impostazioni locali, gli strumenti e la cronologia

Esegui il backup di tutto ciò che desideri conservare. Questo passaggio separato può cancellare le impostazioni/token del provider, gli strumenti/plug-in personalizzati, la cronologia delle conversazioni e i file di lavoro. La disinstallazione dei file binari non implica il consenso a cancellarli.

  • Configurazione:$XDG_CONFIG_HOME/ash, predefinito~/.config/ash.
  • Dati, plugin e ambiente Python:$XDG_DATA_HOME/ash, predefinito~/.local/share/ash.
  • Storia e stato:$XDG_STATE_HOME/ash, predefinito~/.local/state/ash.
  • Cache:$XDG_CACHE_HOME/ash, predefinito~/.cache/ash.
  • Durata del broker:$XDG_RUNTIME_DIR/ash, O$XDG_STATE_HOME/ash/runtimequando non è disponibile alcuna root di runtime.

Controlla le tue effettive sostituzioni XDG assolute prima di eliminare solo queste sottodirectory ash; non eliminare mai una root XDG o la tua home directory. Dopo che tutte le shell abilitate per ash sono state chiuse, rimuovere i file di runtime ash rimanenti, se necessario. Revocare le chiavi AI non utilizzate negli account del fornitore; l'eliminazione di un file locale non revoca una chiave. Non disinstallare Ollama/models, Python o le dipendenze condivise come parte della rimozione di ash.

Risoluzione rapida dei problemi

Comando non trovato o versione errata
Controlla PERCORSO ecommand -v ash/command -v ash-broker. Un vecchio~/.local/binla copia può eseguire l'ombreggiatura di un pacchetto. Utilizza un proprietario/canale alla volta e apri una nuova shell.
Il menu del fornitore non è stato visualizzato
Correreash installda un terminale interattivo. Le impostazioni valide esistenti vengono conservate; utilizzoconfigurazione manualeper cambiare fornitore. Senza integrazione, assicurati che le impostazioni vengano esportate nell'ambiente della CLI.
Nessun modello o connessione rifiutata
Per Ollama, conferma che il suo server è in esecuzione eollama listinclude il modello scelto. Per i servizi cloud, controlla l'endpoint, l'idoneità del modello, HTTPS, il token e la quota dell'account; non condividere mai log contenenti token.
Repository o canale non disponibile
Controllare l'architettura e la versione/repository pubblicato. La pubblicazione può subire ritardi; non disabilitare la verifica della firma per aggirare un repository non disponibile.
La configurazione dello strumento Python non è riuscita
Installa Python con venv/ensurepip e consenti i download delle dipendenze, quindi esegui nuovamenteash install. Di baseashrimane utilizzabile senza questi strumenti.
