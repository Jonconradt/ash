Ier Dir ufänkt

  1. Ënnerstëtzte System a Shell: macOS oder Linux op amd64/x86_64 oder arm64/aarch64, oder FreeBSD op amd64. Benotzt Bash, zsh oder Fish. Arch-Pakete sinn nëmmen x86_64. Et gëtt keen nativen Windows-/PowerShell-Installer.
  2. Download-Zougang: funktionéierenden Internet a vertrauenswürdegen HTTPS-Zougang op GitHub, de gewielte Repository an de Modellubidder. Lokal Inferenz brauch och en éischte Modelldownload.
  3. Rechter: beschreiwbaren Heemverzeechnes fir Benotzerdateien. Linux-Systempaketen a macOS-.pkg brauchen Administratioun; féiert Homebrew an ash install als normale Benotzer aus.
  4. E Modell: lokalen Inferenzserver mat erofgeluedenem Modell oder Cloud-Konto/API-Schlëssel. Wielt e Modell mat Tool-Opriff, net nëmme Bild/Audio. Lokal RAM-, Späicher- a GPU-Bedierfnesser hänke vum Modell of.

Fäerdeg ash-Pakete brauchen net Go, Rust, Node.js oder Xcode-Buildtools. Package-Managere kënnen eege Viraussetzungen hunn; befollegt fir d’éischt hir offiziell Ariichtung.

Optional: matgeliwwert Python-Tools

Basisgebrauch brauch kee Python. Matgeliwwert Tools brauche Python 3 mat venv an ensurepip an Zougang fir Ofhängegkeeten erofzelueden. Op Debian/Ubuntu installéiert python3 an python3-venv; Homebrew-Python enthält venv. Op FreeBSD benotzt de pip-Package passend zur Python-Versioun. Widderhuelt ash install. Eng isoléiert Ëmwelt entsteet ënner $XDG_DATA_HOME/ash/venv (Standard ~/.local/share/ash/venv); e Feeler deaktivéiert dës Tools, net ash selwer.

macOS

Recommandéiert: Homebrew

Viraussetzungen: Homebrew, ënnerstëtzte macOS-Ëmwelt a funktionéierende brew-Befeel. Den Tap wielt automatesch Intel- oder Apple-Silicon-Archiv. Installéiert Release ouni sudo:

brew install Jonconradt/ash/ash
ash version

Homebrew verwalt Binären, native Plugins, Man-Säiten a Lizenzhiweiser am eegene Präfix (normalerweis /opt/homebrew op Apple Silicon oder /usr/local op Intel). Et kontrolléiert d’Archiv mam SHA-256 vun der Formel. Ubidder a Shell-Startdatei ginn net konfiguréiert: fuert mat der Initialiséierung pro Benotzer virun. Aktualiséiert mat brew upgrade ash, läscht Release mat brew uninstall ash; fir Beta/Nightly kuckt Kanalformelen.

Alternativ: nativen .pkg

Luet darwin-arm64.pkg fir Apple Silicon oder darwin-amd64.pkg fir Intel vun enger publizéierter Versioun. Verifizéiert dat ënnerschriwwent Prüfsummemanifest, ier Dir den Installer opmaacht. Administratiounsrechter sinn néideg.

De macOS-Package ass net ënnerschriwwen oder notariséiert. D’Manifest bitt separat Ubidder-/Prüfsummeverifikatioun, keng Apple-Notarisatioun. Deaktivéiert net Gatekeeper a ëmgoot keng Warnunge just fir ash; benotzt Homebrew wann Är Sécherheetspolitik et verlaangt.

De Package schreift ash an ash-broker op /usr/local/bin, Plugins op /usr/local/lib/ash/plugins, Man-Säiten op /usr/local/share/man, Hiweiser op /usr/local/share/licenses/ash. D’Quittung ass dev.ash.cli. Et initialiséiert kee Benotzer an abonnéiert keng Updates: initialiséiert duerno, ersetzt mat engem méi neie verifizéierte .pkg fir Updates a benotzt manuellt Ewechhuelen fir d’Deinstallatioun. Net iwwer eng Homebrew-Kopie installéieren.

Linux

Benotzt wa méiglech de Manager vun Ärer Distributioun. Dës Pakete verwalten /usr/bin/ash, /usr/bin/ash-broker, /usr/lib/ash/plugins, Man-Säiten ënner /usr/share/man a Lizenzhiweiser. Ubidderastellungen a Shell-Hooks bleiwe fir d’Initialiséierung pro Benotzer.

Debian an Ubuntu: APT

Viraussetzungen: amd64/arm64, Administratioun, APT, curl, gpg, CA-Zertifikater. Installéiert feelend Download-/Schlësseltools aus der Distributioun virum Repository. Release heescht stable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Virum Schlësselimport kontrolléiert de Fangerofdrock mat enger vertrauenswürdeger Ubidderquell. VersionX huet 32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. APT kontrolléiert ënnerschriwwe Metadaten an enthale Package-Prüfsummen; signed-by limitéiert de Schlësselberäich. Aktualiséieren: sudo apt update && sudo apt upgrade ash; läschen: sudo apt remove ash.

Fedora a RHEL-kompatibel Systemer: DNF

Viraussetzungen: x86_64/aarch64, Administratioun, DNF/RPM, curl, gpg, CA-Zertifikater. Installéiert feelend Tools aus der Distributioun. Kontrolléiert Schlëssel a Fangerofdrock uewen virum Import:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

RPM-Dateie sinn net eenzel ënnerschriwwen. repo_gpgcheck=1 verifizéiert Metadate mat hire Prüfsummen; gpgcheck=0 entsprécht feelende Packagesignaturen, net ausgeschalter Repository-Verifikatioun. Wann Är Politik ënnerschriwwe RPM-Inhalter verlaangt, geet dëse Repository net duer. Aktualiséieren: sudo dnf upgrade ash; läschen: sudo dnf remove ash.

Arch Linux: Pacman

Viraussetzungen: x86_64, Administratioun, Pacman mat initialiséiertem Schlësselbund, curl, gpg. Vertraut eréischt wann den ugewisene Fangerofdrock dem uewen entsprécht. Füügt de Repository eemol derbäi, net bei all Update:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman verifizéiert Package- an Datebanksignaturen. Synchroniséiert Arch mat sudo pacman -Syu, keng partiell Updates; läscht ash mat sudo pacman -R ash.

Aner Linux-Methoden

Benotzt Dir schonn Homebrew op Linux? Déi selwecht Tap-Instruktiounen ënnerstëtzen amd64/arm64; Brew verwalt d’Dateien, net APT/DNF. Soss benotzt eng verifizéiert Skript-/Archivinstallatioun oder passende .deb-/.rpm-Download. Installéiert verifizéiert .deb mat sudo apt install ./PACKAGE.deb, .rpm mat sudo dnf install ./PACKAGE.rpm (Dateinimm ersetzen). Direkt Pakete bleiwen verwalt, addéieren awer kee Repository oder automatescht Abonnement op spéider Versiounen. Aktuelle RPM ass net ënnerschriwwen; befollegt d’Politik amplaz Kontrollen auszeschalten.

FreeBSD

Viraussetzungen: amd64, Bash (och mat interaktivem zsh/Fish), Download-/Verifikatiounstools a beschreiwbaren Installatiounsdossier. Installéiert Bash mam native FreeBSD-Manager:

sudo pkg install bash

FreeBSD säin pkg verwalt Viraussetzungen, net ash: aktuell gëtt et keen ash-.pkg-Repository oder arm64-Archiv. Benotzt de verifizéierte Skript, oder verifizéiert en FreeBSD-amd64-Tarball, entpaakt an en temporären Dossier a setzt säi versionéierten ash-Binär als ~/.local/bin/ash nieft ash-broker. Kopéiert native Plugins op $XDG_DATA_HOME/ash/plugins (Standard ~/.local/share/ash/plugins), dann initialiséiert. Dir verwalt dës Dateien; pkg delete läscht se net. Benotzt Release-Selbstupdates um Standarduert oder ersetzt verifizéiert Artefakte manuell.

Initialiséieren a kontrolléieren

No de Binäre féiert d’Ariichtung interaktiv als normale Benotzer aus. Nëmmen Assets ariichten ännert keng Startdateien:

ash install

Fir onbekannt Befehler z’integréieren, wielt genee ee Befeel fir Är Shell:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Fish

ash install --shell fish --shell-integration

Bash benotzt ~/.bashrc, zsh ~/.zshrc, Fish $XDG_CONFIG_HOME/fish/config.fish (Standard ~/.config/fish/config.fish). Maacht duerno eng nei Shell op; bestoend behalen hire Broker. Integratioun stellt ~/.local/bin virum PATH: läscht al lokal Kopien ier Dir e Systempackage erwaart.

Feelen Ubidderastellungen, erkennt d’Ariichtung bestoend Schlësselen oder e lokale Server; soss bitt se e Menü a freet Zougangsdaten. Wielt e verfügbare Modell mat Tools. Gëlteg Astellunge bleiwen; nees ariichten wiesselt net den Ubidder.

Astellunge leien an $XDG_CONFIG_HOME/ash/.ash_env (Standard ~/.config/ash/.ash_env, privat Dateirechter). Integratioun luet se. Ouni kënnen Bash/zsh d’Datei am normale Startup lueden; Fish muss ASH_AI_*-Variabele mat Fish-Syntax setzen, net d’Bash-Datei lueden. Schützt Token-Dateien a committéiert se ni.

Ouni Integratioun füügt de richtege lokale Verzeechnes an de PATH. Bash/zsh: export PATH="$HOME/.local/bin:$PATH". Fish: fish_add_path "$HOME/.local/bin". Späichert et an der Startkonfiguratioun; ersetzt duerch Ären eegene Verzeechnes wann néideg.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

Déi éischt Befehler mussen déi gewielten Installatioun fannen. D’Ufro brauch e lafende Server oder gëlteg Cloud-Zougangsdaten; ash installéiere setzt kee Modell op.

Lokalen Ollama: kee Cloud-Konto néideg

Installéiert Ollama no den offiziellen OS-Instruktiounen. Start App/Déngscht oder ollama serve an engem aneren Terminal wann nach kee Server leeft. ash op FreeBSD heescht keen nativen Ollama-Installer: benotzt wann néideg e bereikbare Server op engem aneren ënnerstëtzten Host.

Luet e Modell mat Tools passend zu Ärer Hardware; llama3.1:8b ass e Beispill, kee Minimum. Alternativen am aktuelle Tool-Katalog:

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

Ouni gesate Cloud-Schlësselen erkennt d’Ariichtung de lokale Server a bitt de geluedene Modell. Ass en aneren Ubidder konfiguréiert, ännert Endpoint/Modell manuell. Bash/zsh-Beispill:

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Fish-Entspriechung:

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Dës Ännerunge gëllen nëmme fir déi aktuell Shell. Späichert se an der geschützter ash-Ëmweltdatei oder Shell-Konfiguratioun an ersetzt al Ubidderastellungen. Lokalen Ollama brauch keen Token. Halt de Server op Loopback ausser Dir séchert Zougang bewosst; remote Servere kréien Ufroen an Tool-Ausgaben.

Optional: setzt OLLAMA_KEEP_ALIVE=30m an der Ëmwelt vum Ollama-Server a start nei fir Modeller gelueden ze halen. -1 hält se onbegrenzten, verbraucht awer Späicher tëscht Ufroen. Nëmmen am ash-Clientterminal gesat konfiguréiert et kee lafende Server nei.

Lokal Inferenz huet keng API-Rechnung, benotzt awer Hardware/Späicher/Stroum. Ollama Cloud ass e separate Service mat Authentifikatioun an Tarifgrenzen, net dës lokal Ariichtung.

Gratis Cloud-Offeren

Gratis heescht net onlimitéiert oder privat. Konten, Regiounen, Quoten, Modeller an Datepolitike variéieren a kënnen änneren. Ufroen a relevant Tool-Ausgabe verloossen Äre Rechner. Liest aktuell Grenzen/Konditiounen; aktivéiert Bezuelen nëmme wann Dir bezuele wëllt.

Erstellt e Schlëssel iwwer d’Links, start ash install interaktiv a wielt den Ubidder. Token gëtt gefrot, Modeller ginn opgelëscht wa méiglech. Wielt en aktuelle gratis Textmodell mat Tool-Opriff; opgelëscht heescht net garantéiert gratis fir Äre Konto.

Manuell Konfiguratioun oder Ubidderwiessel

Ersetzt den Endpoint hei ënnen duerch den Tabellenwäert an MODEL_ID duerch e Modell kontrolléiert am Konto. Ass de Schlëssel schonn als GROQ_API_KEY exportéiert, benotzt dëst Bash/zsh-Beispill en ouni Geheimnis ze tippen:

Skriptinstallatioun: Alternativ, net éischt Wiel

Bevirzucht Homebrew, APT, DNF oder Pacman: si verfollegen Dateien, verifizéieren Downloads no hirer Vertrauenskonfiguratioun a bidden bekannt Updates/Entfernung. Vertrauen an Ubidder an Installatiounsaktioune bleift néideg.

E Website-Skript féiert Code mat Äre Kontorechter aus. Eng kompromittéiert Säit/Ubidder oder verännert Skript ka Geheimnisser liesen, Dateien änneren oder Software installéieren. HTTPS schützt Transport, net Code-Intentioun. URL direkt an eng Shell leeden exekutéiert virum Iwwerpréiwen. Archivsignature verifizéieren net de Skript selwer. Ni mat sudo ausféieren oder Verifikatioun auszeschalten.

Viraussetzungen: ënnerstëtzten OS/Architektur, $SHELL mat Bash/zsh/Fish, Sigstore cosign, tar, uname, install, Standard-Shelltools, SHA-256-Befeel (sha256sum, shasum oder sha256), Downloader (curl, wget oder Python). Beispill benotzt curl. FreeBSD brauch och Bash. Heem-/Installatiounsdossier muss beschreiwbar sinn.

Luet eng lokal Datei, kontrolléiert am Editor, féiert nëmmen aus wann Dir Quell a Verhalen vertraut. Kontroll garantéiert keng Sécherheet; net blann ausféieren:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

No der Kontroll féiert déi gespäichert Kopie als normale Benotzer aus:

sh ./ash-install.sh
rm ./ash-install.sh

install.sh luet leschte Release, kontrolléiert Sigstore-Manifest an Archivdigest, installéiert ash/ash-broker an ~/.local/bin. Plugins ginn op $XDG_DATA_HOME/ash/plugins. Ariichtung pro Benotzer freet virun Shell-Integratioun. Ouni interaktiven Terminal kënnen Ubidder-/Integratiounsfroen ausfalen: start ash install duerno interaktiv.

Setzt ASH_INSTALL_DIR virum Skript fir en anert Zil. Füügt selwer an de PATH. Selbstupdate gëtt nëmmen ënner ~/.local/bin ënnerstëtzt; aner Ziler brauchen manuellt Ersetzen. De Skript huet kee Beta-/Nightly-Selector.

Direkte Package oder Archiv verifizéieren

Viraussetzungen: cosign a SHA-256-Tool. Luet Package/Archiv, SHA256SUMS an SHA256SUMS.sigstore.json vun derselwechter Versioun. Schafft an engem neien Dossier. Ersetzt vX.Y.Z mam geneeën Tag, inklusive Virversiounssuffix:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Eréischt nom Succès berechent de Digest mat shasum -a 256 PACKAGE op macOS, sha256sum PACKAGE op Linux oder sha256 -q PACKAGE op FreeBSD. Ersetzt PACKAGE mam Downloadnumm a vergläicht genee mam Eintrag am verifizéierte Manifest. Bei feelendem Eintrag oder Ënnerscheed stoppen. Onënnerschriwwe Prüfsumm nieft der Datei ass keng verifizéiert Ubiddermetadaten.

Aktualiséierungen an dräi Kanäl

  • Release (recommandéiert): stabil Versioune wéi vX.Y.Z; am Repository stable genannt.
  • Beta: Virversiounstester, Tag vX.Y.Z-beta.N; Ännerungen a Regressiounen erwaarden.
  • Nightly: rezent Standardbranch-Ännerungen, Tag vX.Y.Z-nightly.YYYYMMDD.N; héchst Regressiounsgefor. Geplangte Builds kënnen ouni Ännerung oder bei Publikatiounsfeeler ausfalen.

Eng Publikatioun aktualiséiert déi passend Homebrew-Formel oder ënnerschriwwent Linux-Repository. Dir kritt se mam Upgrade vum zoustännege Manager oder OS-Politik. Publikatioun, Repository a Website kënnen zäitlech versat sinn; kontrolléiert Disponibilitéit virum Kanalwiessel. ash installéiert keng heemlech Hannergrond-Binärupdates.

Homebrew: Formelen installéieren oder wiesselen

Fir nei Beta/Nightly benotzt komplette Formelnumm uewen an brew install. Beim Wiessel läscht déi aktuell Formel fir d’éischt: all dräi liwweren déiselwecht Binären. Beispill Release op Beta:

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

Benotzt ash-nightly fir Nightly oder ash fir Release an Installatioun/Upgrade. Läscht déi richteg al Kanalformel, net ëmmer ash. Benotzerastellunge bleiwen; maacht eng nei Shell op.

Linux: ee Repository-Kanal wielen

APT: benotzt APT-Ariichtung mat genee enger Tabellendistributioun. Fir ze wiesselen ännert /etc/apt/sources.list.d/versionx.list, ersetzt stable duerch beta oder nightly (oder zeréck stable), dann:

sudo apt update
sudo apt install --allow-downgrades ash

DNF: benotzt DNF-Ariichtung mat gewielter baseurl. Bei bestoender Installatioun ersetzt baseurl an /etc/yum.repos.d/versionx.repo, behält Signaturastellungen, dann:

sudo dnf --refresh distro-sync ash

Pacman: benotzt Pacman-Ariichtung mat gewielter Server-URL. Behält Abschnitt [versionx]: all Kanal publizéiert Datebank versionx.db. Ännert Server do amplaz eng anescht benannten Datebank. Fir Wiessel inklusiv Downgrade:

sudo pacman -Syuu ash

Kontrolléiert Transaktioun: zeréck op Release ka ash erofsetzen, Pacman säin duebelt u och aner Pakete. Séchert Konfiguratioun virum Wiessel. Duerno normal APT/DNF/Pacman-Upgrades aus OS-Abschnëtter; net méi ash-Kanalquellen aktiv loossen.

Benotzerlokal Release-Updates

Verifizéiert an installéiert stabil nëmme wann aktiven ash ënner ~/.local/bin läit. Package-Manager, macOS-.pkg an eegene Skriptzil brauchen zoustännege Manager/Installer. FreeBSD Beta/Nightly benotzt manuell verifizéiert Archiver, kee Selbstupdate-Abonnement. Duerno nei Shell.

Deinstalléieren ouni friem Dateien ze läschen

1. Als éischt Shell-Integratioun deaktivéieren

Virum Binärläsche féiert de Befeel fir all Shell mat Integratioun aus:

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Fish

ash install --shell fish --disable-shell-integration

Feelt ash schonn, ännert Startdatei aus Initialiséierung a läscht nëmmen de Block tëscht # >>> ash install >>> an # <<< ash install <<<. Läsche manuell ash-PATH-/Ëmweltzeilen, net aner Konfiguratioun. Duerno ash-Shells zoumaache fir Broker ze stoppen.

2. De zoustännege Manager läscht seng Dateien

Homebrew (Release)

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Wielt nëmmen Är Method; Homebrew Beta/Nightly benotzt ash-beta/ash-nightly. APT/DNF/Pacman läschen eege Binären, Plugins, Man-Säiten, net perséinlech Konfiguratioun/Historik. Keng Package-Dateien manuell läschen.

Optional Repository-Botzen: ash-Quell /etc/apt/sources.list.d/versionx.list a spezifesche /etc/apt/keyrings/versionx-keyring.gpg, Repository /etc/yum.repos.d/versionx.repo, oder ash-Abschnitt [versionx] aus /etc/pacman.conf läschen. 3a. macOS-.pkg manuell läschen
