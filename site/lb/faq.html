Wat brauch ech ier ech ash benotzen kann?

Dir braucht deashausführbar, en AI Endpunkt an e Modellnumm. Lafenash installautomatesch konfiguréiert dës: et benotzt e scho gesate Cloud Provider API Schlëssel oder e lafende lokalen Inferenzserver wann se fonnt ginn, soss weist et e nummeréiert Providermenü a freet no engem API Schlëssel, da léisst Dir e Modell aus der Modelllëscht vum Endpunkt wielen. E lokalen Endpunkt wéi Ollama ka benotzenhttp://localhost:11434, an e LAN Host wéihttp://brain.local:11434oder eng privat IP gëtt och als lokal behandelt (ausserASH_STRICT=1); Cloud Endpunkte mussen HTTPS benotzen an och erfuerderenAI_AUTH_TOKEN. Wou installéiert ash, a wéi kontrolléieren ech datt meng Shell et fanne kann?

De verifizéierte Installateur setzt ash an~/.local/bin/ash,an anash installfüügt dee Verzeichnis op ÄrPATHduerch d'geréiert~/.ash/.ash_envFichier. Öffnen en neien Terminal, da lafencommand -v ashze bestätegen. De Self-Updater installéiert seng Ersatzbinär op d'selwecht~/.local/bin/ashStanduert.

Wéi aktualiséieren ech ash op déi lescht Verëffentlechungsversioun?

Net-ënnerstëtzt Notzlaascht ginn iwwersprangen, an net-interaktiv Lafen refuséieren dës Ausnahmen. Benotztash update --version vX.Y.Zfir eng spezifesch Versioun; benotzen--yesnëmmen wann Dir personaliséiert verwaltete Dateien ersat wëllt.

Ech sinn gelafash install. Firwat ännert sech näischt an dësem Terminal?

Öffnen en neien Terminal, oder lued d'Datei fir Är Shell nei:source ~/.bashrcfir Bash,source ~/.zshrcfir zsh,osource ~/.config/fish/config.fishfir Fësch ausser Dir e Benotzerdefinéiert benotztXDG_CONFIG_HOME.

Wat sinn MCP Serveren, a wéi addéieren ech een?

MCP (Model Context Protocol) Serveren weisen Tools aus, déi en AI Modell kann nennen, sou wéi Sich, Analyse oder Servicespezifesch Aktiounen. Fir e Fern Streamable HTTP MCP Server derbäi ze setzen, setzt seng URL op seng eege Linn an~/.ash/.ash_allow, da lafen ash erëm. Zum Beispill:https://mcpplaygroundonline.com/mcp-complex-server. Ash verbënnt duerch säi Broker a bitt de Server Tools un de Modell. Benotzt nëmmen Serveren déi Dir vertraut: hir Tools kënnen Handlungen aus Ärem Numm maachen. HTTPS ass erfuerderlech ausser fir localhost Entwécklungsserver. Bestehend~/.ash/mcp.jsonDateien ginn net méi gelies; réckelen hir URLen an.ash_allow. Wann d'MCP Initialiséierung feelt, geet ash weider ouni Remote MCP Tools: et warnt an interaktiven Sessiounen a bleift roueg an net-interaktiven Sessiounen.

Kann geplangten Aarbechtsplaze MCP Server benotzen?

Nee Geplangte an aner net-interaktiv Aarbechtsplazen ierwen keen interaktiven Shell Broker, sou datt Remote MCP Tools net verfügbar sinn. Ash leeft nach ëmmer d'Prompt ouni MCP Tools an ënnerdréckt dësen erwaarten Initialiséierungsfehler. Eng Ufro, déi op MCP hänkt, kann also fäerdeg sinn ouni déi ugefrote Donnéeën oder Handlungen. Zäitplang keng Ufroen déi MCP erfuerderen.

Wéi funktionnéiert MCP OAuth, a wou ginn Umeldungsinformatiounen gespäichert?

Fir en OAuth-geschützte Server mécht Ash d'Autorisatiounssäit am Desktop-Browser op wann e GUI verfügbar ass; wann et e Browser net kann opmaachen, dréckt et eng URL fir manuell an engem Browser op deemselwechte Host ze autoriséieren. Benotztash mcp add <url> --no-browserfir ëmmer den Terminalflow ze benotzen. Fir direkt OAuth Verbindungen erlaabt Entdeckung Net-ëffentlech IP Adressen nëmme fir déi exakt registréiert MCP Autoritéit; aner OAuth-Host bleiwen ënner net-ëffentlech-Adress-Blockéierung. E konfiguréierten Egress Proxy ass verantwortlech fir seng Destinatiounsadressen ze filteren. De Broker handhabt den Callback, Tokenaustausch, Erfrëschung a persistent MCP Sessioun. Umeldungsinformatiounen ginn am Betribssystem Umeldungsmanager gespäichert wann verfügbar. Wann et net verfügbar ass, konfiguréiert de verschlësselte Dateifallback mat engem zoufälleg 32-ByteASH_MCP_CREDENTIAL_KEY; Ash späichert ni de Schlëssel selwer.

Schafen e Schlëssel an Ärem Provider Kont, wéiOpenAI,Anthropesch,Google AI Studio,Azure OpenAI,Mistral,Zesummenhang,Groq,xAI,DeepSeek,Zesummen AI,Open Router,HuggingFace, oderOllama, exportéiert se dann als Ëmfeldvariabel vum Provider (oderAI_AUTH_TOKENdirekt).ash installautomatesch erkennt déi meescht vun dëse Provider-spezifesche Ëmweltvariablen. Cloud Endpunkte mussen HTTPS benotzen an en Token erfuerderen; privat / LAN Adressen an.localHostnumm ginn net als Cloud Endpunkte behandelt ausserASH_STRICT=1gesat ass.

Sécherheet a Kontroll

Wéi spären ech ash fir méi sécher ze sinn, a wat sinn d'Implikatiounen?

Halt déi ausführbar Erlaabneslëscht schmuel, favoriséiert nëmme liest Tools, a füügt keng privilegiéiert oder zerstéierend Kommandoen derbäi. SetztASH_STRICT=1fir unerkannt Prompt-Injektiounsmuster vun onvertrauenswürdege Tool, Datei, Skript, Pipeline a Kand-Agent Output ze blockéieren. Dëst kann och legitimen Text verstoppen, deen op eng Injektiounsversuch gläicht. D'Erlaabneslëscht ass eng Ausféierungsgrenz, net eng Sandkëscht: ash an erlaabt Tools lafen nach ëmmer wéi Dir.

Kann ash zerstéierende Kommandoen lafen wéirm?

Wéi änneren ech d'Befehle ash ass erlaabt auszeféieren?

Edit~/.ash/.ash_allowa lëschten ausführbaren Nimm, eng pro Zeil oder Komma-getrennt. Seng eegestänneg$TOOLS_DIR_LISTan$PLUGINS_DIR_LISTDirektiven erlaben berechtegt verwaltete Scripten an gebierteg Plugins; ersetzen se mat wuertwiertlech Nimm fir eng restriktiv Politik. Usproch Scripten a Plugins si regelméisseg Dateien an~/.ash/tools/oder~/.ash/plugins/mat liesen an ausféieren Bits. Dir kënnt och explizit Kommandoen ofleenen andeems Dir se derbäigesat~/.ash/.ash_deny. Alternativ setzenASH_ALLOWoderASH_DENYop eng komma-getrennt Lëscht. Ännerungen ginn op déi nächst ash Ufro gelies.

Ënner wéi engem Benotzer leeft ash?

ash an all erlaabt Tool lafen als de Benotzer deen ash ufänkt. Et erhéicht keng Privilegien. Déi geréiert~/.ashAarbechtsberäich ass Erlaabnis-gehärt, awer säin Inhalt bleift zougänglech fir Äre Benotzer an all Prozess deen Dir explizit erlaabt.

Vertrauen ash Text, deen iwwer Päif kritt gëtt, d'selwecht wéi de Benotzertext? Wéi eng Protectiounen existéiere fir béiswëlleg Donnéeën?

Jo. Wann ash keng Kommandozeilargumenter kritt an de Standardinput gëtt gepäift, behandelt et dësen Input als de Benotzerprompt. Gitt net ontrauen Websäiten, Logbicher oder generéierten Text direkt op ash, ausser Dir wëllt et als Ufro autoriséieren. Dëst ënnerscheet sech vum ash-verwalte Tool, Datei, Skript, Pipeline, a Kand-Agent Output: ash markéiert dës Resultater als net zouverléissege Beweiser an instruéiert de Modell ni Instruktioune vun hinnen ze verfollegen. SetztASH_STRICT=1fir zousätzlech unerkannt Prompt-Injektiounssätz an ontrauen Beweiser ze ersetzen. D'Erlaabneslëscht an d'direkt-argv Ausféierungsregele gëllen nach ëmmer fir d'Ausféierung vum Tool.

Sinn meng ash Dateien privat vun anere Benotzer op dësem Computer?

Während Installatioun, ash härden der~/.ashVerzeechnes fir Besëtzer-nëmmen Permissiounen a geréiert Dateien op Besëtzer liesbar a Besëtzer schreiwen Permissiounen. Sessiounen a Späicheren
