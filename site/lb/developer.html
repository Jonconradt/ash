Fräisetzung Builder an artifacts

No de Qualitéitskontrolle leeft make release-artifacts op Linux. Een Ubuntu-Job baut d'macOS-Archive fir Intel an Apple Silicon fir Homebrew, ouni macOS-Runner oder .pkg-Installateuren. macOS-Ziler schléissen all Rust-Plugins aus, och flip_a_coin a lokal Builds. Linux a FreeBSD behalen d'Rust-Plugins.

CI kontrolléiert den Inhalt vun de macOS-Archiven an d'Mach-O-Architekturen, féiert d'Binärdateien awer net aus. Linux a FreeBSD behalen d'Lafzäittester vun den ausgepaakten Archiven; Packagen a Shell-Integratioune ginn net installéiert. Fir macOS op Linux ze bauen: make release-artifacts RELEASE_TARGET_OSES=darwin RELEASE_TARGET_ARCHES="amd64 arm64" RELEASE_MACOS_PKG=0 RELEASE_VERSION=v1.2.3. make release erstellt nach ëmmer e lokale .pkg op macOS, ouni lokal Binärdateien un CI ze schécken.

Fir lokal Artefakt Builds, spezifizéiert d'Zil OS, d'Architektur an d'Versioun explizit:

make release-artifacts \
  RELEASE_TARGET_OSES=linux \
  RELEASE_TARGET_ARCHES="arm64 amd64" \
  RELEASE_VERSION=v1.2.3

release-artifactsbaut a validéiert d'Formater déi fir dat Zil ënnerstëtzt ginn. D'Defaults sinn Host OS (auto) a béidamd64 arm64; FreeBSD Verëffentlechung ass limitéiert opamd64. Artefakte ginn ënnerdist/release. Fir eng eenzeg binär / Plugin bauen, benotzenmake release-build-one RELEASE_GOOS=linux RELEASE_ARCH=arm64 RELEASE_VERSION=v1.2.3.

make versionleeft d'Verëffentlechungskontrollen a baut Artefakte ouni se ze publizéieren. Am Géigesaz,make releaseass e Verëffentlechungs-Workflow: et erfuerdert macOS, e propperen Aarbechtsbaum a konfiguréiert Git Identitéit, generéiert Verëffentlechungsnotizen, erstellt / dréckt Verëffentlechungsreferenzen, a kuckt de GitHub Workflow. Säi Standardkanal ass Beta; wielt stabil oder Nightly matCHANNEL=stableoderCHANNEL=nightly. Generéiert Verëffentlechungsnotizen erfuerderlechASH_AI_ENDPOINTanASH_AI_MODEL, ausser Notizen sinn mat geliwwertRELEASE_NOTES_INPUT.

Verbose Runtime Logbuch

ASH_VERBOSEaktivéiert strukturéiert JSON Debug Logging a dréckt en Ausféierungsdashboard virAsherausgoen. Akzeptéiert Wäerter sinn1,y,yes,true,on,an andebug, case-onsensibel. D'Dashboard resüméiert d'Bühn Timings, Tool-Call Zuel, Tokentotalen wann verfügbar, a Gesamt Echtzäit.

ASH_VERBOSE=1 \
ASH_LOG_FILE="$HOME/.local/state/ash/debug.jsonl" \
ASH_LOG_MAX_BYTES=10485760 \
ash "investigate this error"

WéiniASH_LOG_FILEgesat ass, verbose JSON Log records ginn op dee Wee geschriwwe; den Elterenverzeichnis gëtt erstallt wéi néideg.ASH_LOG_MAX_BYTESkontrolléiert Rotatioun an Default op1048576bytes (1 MiB). Ouni eng explizit Logdatei benotzt Debug-Output de Prozessdiagnostesche Schrëftsteller. Halt d'Logbicher privat a iwwerpréift se ier Dir deelt.

Dëst ass ënnerscheet vu Make'sV=1: benotzenV=1ze gesinn bauen / Test Kommando Ausgang anASH_VERBOSE=1ze diagnostizéieren anAshRuntime Opruff.

Fuert e Package Test

Automatiséierte Modus ass de Standard an läscht de VM nom Test. D'Standardplattform follegt dem Host: macOS wieltmacos, Linux wieltubuntu. Wielt eng aner ënnerstëtzt Plattform a Modus explizit. De Package Kanal ass Standard opbeta; benotzen--channel nightly,--channel beta, oder--channel releasefir een ze wielen.--channel stableass en Alias ​​​​firrelease.

scripts/vm.sh --platform macos --mode interactive
scripts/vm.sh --platform ubuntu --channel nightly --mode automated
scripts/vm.sh --platform debian --mode interactive
scripts/vm.sh --platform fedora --mode automated
scripts/vm.sh --platform rocky --mode interactive

Interaktive Modus léisst den installéierten VM fir manuell Testen lafen. Op macOS, fuert de gedréckte tart exec -it Kommando an engem Terminal fir eng Gaascht Shell opzemaachen. Ausgaang vun dëser Shell léisst de VM lafen; de Gaascht zoumaachen oder et vum Host stoppen. Fir en erhale Tart VM ze stoppen an ze läschen, benotzt:

tart stop VM_NAME && tart delete VM_NAME

Op Linux dréckt de Skript en SSH Kommando an e Stop Kommando; Stop de VM a läscht säin Zoustand mat:

scripts/vm.sh --stop VM_NAME

Automatiséierte Modus fiert d'Installatioun an d'Shell-Setup Rauchkontrollen, stoppt dann an läscht de VM. Erofgelueden Basisbiller bleiwen am cache. Tart Biller kënne geännert ginn matASH_TEST_VM_IMAGE; Linux Cloud-Bild URLen kënnen iwwerschriwwe ginnASH_TEST_QEMU_IMAGE. Linux Biller sinn ënner cache${XDG_CACHE_HOME:-~/.cache}/ash/vm-images, an interaktiv VM Disken an SSH Schlësselen ginn ënner gehal${XDG_STATE_HOME:-~/.local/state}/ash/vm. SetztASH_TEST_VM_CACHE_DIRoderASH_TEST_VM_STATE_DIRdës Plazen z'änneren.

Fir de Gaascht mam selwechten AI Service wéi den Host ze verbannen, exportéiert déi néidegASH_AI_*Variabelen ier Dir de Skript leeft, zum BeispillASH_AI_ENDPOINT,ASH_AI_MODELan, wann néideg,ASH_AI_AUTH_TOKEN. Exportéiert Wäerter ginn un de Gaascht weidergeleet; onexportéiert Shell Variablen sinn net. Interaktiv VMs behalen dës Umeldungsinformatiounen am Gaaschtprofil mat Modus0600; Linux VM Disks sinn net verschlësselte, also schützt de Staatsverzeichnis a stoppt / läscht de VM wann et fäerdeg ass.
