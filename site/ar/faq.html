البدء

ماذا أحتاج قبل أن أتمكن من استخدام ash؟

أنت بحاجة إلى ash القابل للتنفيذ، ونقطة نهاية الذكاء الاصطناعي، واسم النموذج. يؤدي تشغيل ash install إلى تكوين ما يلي تلقائيًا: فهو يستخدم مفتاح API لموفر السحابة الذي تم تعيينه بالفعل أو خادم استدلال محلي قيد التشغيل عند العثور عليه، وإلا فإنه يعرض قائمة موفر مرقمة ويطالب بمفتاح API، ثم يتيح لك اختيار نموذج من قائمة نماذج نقطة النهاية. يمكنك أيضًا ضبط AI_ENDPOINT وAI_MODEL يدويًا. يمكن لنقطة النهاية المحلية مثل Ollama استخدام http://localhost:11434، ويتم أيضًا التعامل مع مضيف LAN مثل http://brain.local:11434 أو عنوان IP الخاص على أنه محلي (ما لم ASH_STRICT=1)؛ يجب أن تستخدم نقاط النهاية السحابية HTTPS وتتطلب أيضًا AI_AUTH_TOKEN. يعد تكامل Shell اختياريًا: يمكنك دائمًا تشغيل ash "your question" مباشرةً.

أين يتم تثبيت ash، وكيف أتحقق من إمكانية العثور على Shell الخاص بي؟

يضع المثبت الذي تم التحقق منه ash في ~/.local/bin/ash، ويضيف ash install هذا الدليل إلى ملفك PATH من خلال الملف ~/.ash/.ash_env المُدار. افتح محطة جديدة، ثم قم بتشغيل command -v ash للتأكيد. يقوم المُحدِّث الذاتي بتثبيت الثنائي البديل على نفس الموقع ~/.local/bin/ash.

كيف يمكنني استخدام ash دون تغيير الصدفة الخاصة بي؟

مرر موجه مقتبس مباشرة: ash "how do I find large files?". بدون أي وسيطات، يقبل ash أيضًا مطالبة إدخال قياسية غير تفاعلية، مثل git diff | ash. الاستخدام المباشر هو الخيار الأقل إثارة للدهشة عندما تتعلم ash أو تكتب برنامجًا نصيًا.

لماذا يقول ash أن تكوين الذكاء الاصطناعي الخاص بي غير مكتمل؟

تأكد من أن AI_ENDPOINT وAI_MODEL غير فارغين في البيئة التي يتم فيها تشغيل ash. بالنسبة لاسم المضيف السحابي، قم أيضًا بتعيين AI_AUTH_TOKEN. قم بتشغيل printf '%s\n' "$AI_ENDPOINT" "$AI_MODEL" للتأكد من وجود القيمتين الأوليين، ولكن لا تطبع رمز المصادقة المميز في تسجيل طرفي أو سجل مشترك.

التثبيت والتحديث

هل يعمل ash على نظام التشغيل Windows 11؟

ليس محليًا. ash يدعم bash وzsh وFish على أنظمة التشغيل macOS وLinux وFreeBSD؛ لا يوجد هدف تثبيت PowerShell. استخدم WSL لتجربة Linux المدعومة.

كيف أقوم بتثبيت ash في نظام Windows الفرعي لنظام Linux (WSL)؟

قم بتثبيته داخل توزيع WSL الخاص بك مثل Linux: curl -fsSL https://jonconradt.github.io/ash/install.sh | sh. ثم قم بتكوين AI_ENDPOINT وAI_MODEL، وتشغيل ash install للواجهة التي تعمل داخل WSL.

كيف يمكنني تحديث ash إلى أحدث إصدار؟

تشغيل ash update على macOS أو Linux أو FreeBSD. يقوم بتنزيل أحدث أرشيف مطابق ثابت، ويتحقق من بيان الإصدار باستخدام حزمة Sigstore وملخص SHA-256، ثم يتم التثبيت على ~/.local/bin/ash. إذا فشل التحقق من التوقيع أو كان الأرشيف يحتوي على إدخالات غير مدعومة، فيجب الحصول على تأكيد تفاعلي؛ لا توافق على التوقيع الفاشل إلا إذا كنت تثق بشكل مستقل في مصدر الإصدار. يتم تخطي الحمولات غير المدعومة، وترفض عمليات التشغيل غير التفاعلية هذه الاستثناءات. استخدم ash update --version vX.Y.Z لإصدار محدد؛ استخدم --yes فقط عندما تريد استبدال الملفات المُدارة المخصصة.

لقد قمت بتشغيل ash install. لماذا لا يتغير شيء في هذه المحطة؟

يقوم التثبيت بتحديث ملف بدء التشغيل؛ ولا يعيد كتابة عملية الصدفة الجارية بالفعل. افتح محطة طرفية جديدة، أو أعد تحميل الملف لـ Shell الخاص بك: source ~/.bashrc لـ Bash، source ~/.zshrc لـ zsh، أو source ~/.config/fish/config.fish لـ Fish إلا إذا كنت تستخدم XDG_CONFIG_HOME مخصص.

لا تزال الأوامر غير المعروفة تقول "لم يتم العثور عليه". كيف يمكنني استكشاف أخطاء تكامل Shell وإصلاحها؟

التشغيل الأول command -v ash; لا يمكن للمجمّع استدعاء ملف ثنائي لا يمكن لصدفتك العثور عليه. ثم أعد تحميل الصدفة أو أعد تشغيلها وتأكد من أن ملف بدء التشغيل الخاص بها يحتوي على الكتلة المُدارة >>> ash install >>>. أخيرًا قم بتشغيل ash snooze off، لأن التأجيل يترك أوامر غير معروفة عمدًا كحالات فشل عادية "لم يتم العثور عليها".

ما هي الملفات التي يتغير ash install، وهل يمكنني معاينتها؟

يضيف أو يحدّث كتلة واحدة تحمل علامة ash في ملف بدء تشغيل Shell المحدد ويدير الملفات ضمن ~/.ash، بما في ذلك التكوين، الأغلفة، والأدوات المجمعة. قم بتشغيل ash install --shell bash --dry-run لمعاينة تغيير ملف بدء التشغيل دون كتابته. إعادة تشغيل التثبيت غير فعالة؛ استخدم --overwrite فقط عندما تريد تحديث ملفات التمهيد المُدارة.

هل يدعم ash السمك؟

نعم. تشغيل ash install --shell fish. يضيف ash كتلة مُدارة إلى $XDG_CONFIG_HOME/fish/config.fish، أو ~/.config/fish/config.fish عندما لا يتم تعيين XDG_CONFIG_HOME. يستخدم السمك fish_command_not_found، لذلك يصل الأمر الذي لم يتم حله إلى ash بوسائطه الأصلية.

لماذا لا يتم استخدام الأحرف الصغيرة test وtype في Fish؟

يحتفظ Fish بتلك الأسماء الصغيرة باعتبارها عناصر أساسية ولا يسمح لوظيفة باستبدالها. استخدم Test ... أو Type ... للتعبير عن ash نية، أو استدعاء ash "..." مباشرة. تظل أغلفة التصادم المتوافقة الأخرى متاحة.

ماذا عن ksh93؟

ksh93 غير مدعوم لتكامل الصدفة. يمكن لسلوكه FPATH فقط تحميل ملف يحمل اسم أمر غير معروف؛ فهو لا يحتوي على رد اتصال عام لم يتم العثور على أمر يمكنه تنفيذ ash التوجيه الفوري أو دورة حياة الوسيط بأمان.

الذكاء الاصطناعي والاتصالات

هل يتضمن ash الذكاء الاصطناعي؟

لا. ash هو عميل لنقطة نهاية الذكاء الاصطناعي التي تقوم بتكوينها. اضبط AI_ENDPOINT و AI_MODEL؛ ash يدعم Ollama المحلي والخوادم المحلية الأخرى المتوافقة مع OpenAI (LM Studio، llama.cpp، MLX، LocalAI، vLLM، text-generation-webui، Jan، GPT4All)، ويكتشف محولات موفر السحابة المدعومة من نقطة النهاية، مع تجاوز AI_PROVIDER اختياري.

ما هي خوادم MCP، وكيف يمكنني ذلك هل تريد إضافة واحدة؟

تكشف خوادم MCP (بروتوكول سياق النموذج) عن الأدوات التي يمكن لنموذج الذكاء الاصطناعي استدعاءها، مثل البحث أو التحليل أو الإجراءات الخاصة بالخدمة. لإضافة خادم HTTP MCP قابل للبث عن بعد، ضع عنوان URL الخاص به على السطر الخاص به في ~/.ash/.ash_allow، ثم قم بتشغيل ash مرة أخرى. على سبيل المثال: https://mcpplaygroundonline.com/mcp-complex-server. Ash يتصل عبر وسيطه ويقدم أدوات الخادم للنموذج. استخدم فقط الخوادم التي تثق بها: قد تؤدي أدواتها إجراءات نيابة عنك. HTTPS مطلوب باستثناء خوادم تطوير المضيف المحلي. لم تعد ملفات ~/.ash/mcp.json الموجودة قابلة للقراءة؛ انقل عناوين URL الخاصة بهم إلى .ash_allow. في حالة فشل تهيئة MCP، يستمر ash بدون أدوات MCP عن بعد: فهو يحذر في الجلسات التفاعلية ويظل صامتًا في الجلسات غير التفاعلية.

هل يمكن للمهام المجدولة استخدام خوادم MCP؟

لا. لا ترث المهام المجدولة وغيرها من المهام غير التفاعلية وسيط Shell التفاعلي، لذا لا تتوفر أدوات MCP عن بعد. Ash لا يزال يقوم بتشغيل الموجه بدون أدوات MCP ويمنع هذا الفشل المتوقع في التهيئة. وبالتالي قد تنتهي المطالبة التي تعتمد على MCP دون البيانات أو الإجراء المطلوب. لا تقم بجدولة المطالبات التي تتطلب MCP.

هل يعمل MCP عندما ASH_STRICT=1؟

نعم. يقوم سطر عنوان URL الخاص بـ HTTP(S) بتسجيل خادم MCP بشكل صريح ولا يتم التعامل معه على أنه shell قابل للتنفيذ. لا يؤدي الوضع الصارم إلى تعطيل خوادم MCP التي تم تكوينها. ولا يزال يطبق حماية المخرجات غير الموثوق بها Ash على محتوى الأداة التي تم إرجاعها.

كيف يعمل MCP OAuth، وأين يتم تخزين بيانات الاعتماد؟

بالنسبة لخادم محمي بـ OAuth، يفتح Ash صفحة التفويض في متصفح سطح المكتب عندما تكون واجهة المستخدم الرسومية متاحة؛ إذا لم يتمكن من فتح المتصفح، فإنه يطبع عنوان URL للتفويض يدويًا في متصفح على نفس المضيف. استخدم ash mcp add <url> --no-browser لاستخدام التدفق الطرفي دائمًا. بالنسبة لاتصالات OAuth المباشرة، يسمح الاكتشاف بعناوين IP غير العامة فقط لسلطة MCP المسجلة بالضبط؛ يظل مضيفو OAuth الآخرون خاضعين لحظر العناوين غير العامة. وكيل الخروج الذي تم تكوينه مسؤول عن تصفية عناوين الوجهة الخاصة به. يتعامل الوسيط مع رد الاتصال وتبادل الرموز والتحديث وجلسة MCP المستمرة. يتم تخزين بيانات الاعتماد في مدير بيانات اعتماد نظام التشغيل عند توفرها. إذا لم يكن متاحًا، فقم بتكوين الإجراء الاحتياطي للملف المشفر باستخدام ASH_MCP_CREDENTIAL_KEY عشوائي بحجم 32 بايت؛ Ash لا يقوم أبدًا بتخزين المفتاح نفسه.

أين يمكنني العثور على AUTH_KEY لموفري الذكاء الاصطناعي السحابي الأكثر شهرة؟

ash يطلق على هذه القيمة AI_AUTH_TOKEN; ولا يقوم بإنشاء أو توزيع مفاتيح الموفر. أنشئ مفتاحًا في حساب مقدم الخدمة، مثل OpenAI، وAnthropic، وGoogle AI Studio، وAzure OpenAI، Mistral، Cohere، Groq، xAI، DeepSeek، Together AI، OpenRouter، HuggingFace، أو Ollama، ثم قم بتصديره كمتغير بيئة الموفر (أو AI_AUTH_TOKEN مباشرة). ash install يكتشف تلقائيًا معظم متغيرات البيئة الخاصة بالموفر. يجب أن تستخدم نقاط النهاية السحابية HTTPS وتتطلب رمزًا مميزًا؛ لا يتم التعامل مع عناوين LAN الخاصة/LAN وأسماء المضيفين .local كنقاط نهاية سحابية ما لم يتم تعيين ASH_STRICT=1.

هل يفتح ash اتصالاً جديدًا في كل مرة؟

ليس للاستخدام التفاعلي العادي لـ Unix Shell. يبدأ Bash وzsh وFish وسيطًا واحدًا لكل جلسة Shell، ويتواصلون معه من خلال مقبس Unix خاص، ويعيدون استخدام تجمع اتصال HTTP المحدود الخاص به. يخرج الوسيط بعد عدم النشاط؛ تستخدم المهام المجدولة الطلبات المباشرة بدلاً من وسيط شل مستمر.

هل يستخدم فيش الوسيط؟

نعم. يبدأ برنامج Fish Wrapper ويعيد استخدام نفس الوسيط لكل جلسة مثل bash وzsh، ويقوم بتحديث عقد الإيجار فورًا قبل طلب ash، ويحافظ على هدوء إعداد الوسيط.

ماذا يحدث إذا كان الطلب بطيئًا، أو غير متاح، أو غيرت رأيي؟

اضغط على Ctrl-C لإلغاء طلب على متن الطائرة. المهلة الافتراضية لطلب الذكاء الاصطناعي هي ثلاث دقائق؛ اضبط AI_TIMEOUT مثلاً AI_TIMEOUT=90s لتغييره. ash إعادة المحاولة في حالات فشل الذكاء الاصطناعي القابلة لإعادة المحاولة حتى ثلاث مرات افتراضيًا مع تراجع قصير المدى؛ اضبط هذا السلوك باستخدام ASH_RETRY_MAX_ATTEMPTS وASH_RETRY_BASE_DELAY وASH_RETRY_MAX_DELAY.

السلامة والتحكم

كيف يمكنني تأمين ash لكي أكون أكثر أمانًا، وما هي الآثار المترتبة على ذلك؟

احرص على إبقاء القائمة المسموح بها القابلة للتنفيذ ضيقة، وتفضيل الأدوات المخصصة للقراءة فقط، وعدم إضافة أوامر مميزة أو مدمرة. قم بتعيين ASH_STRICT=1 لحظر أنماط الحقن الفوري المعترف بها من الأدوات والملفات والبرامج النصية وخط الأنابيب ومخرجات الوكيل الفرعي غير الموثوق بها. يمكن أن يؤدي هذا أيضًا إلى إخفاء النص الشرعي الذي يشبه محاولة الحقن. القائمة المسموح بها هي حد تنفيذ، وليست وضع حماية: ash وستظل الأدوات المسموح بها تعمل مثلك.

هل يمكن ash تشغيل أوامر مدمرة مثل rm؟

ليس مع القائمة المسموح بها الافتراضية المثبتة. ينصح صراحةً ضد rm، mv، dd، chmod، chown، kill، وsudo. إذا قمت بإضافة واحد منهم، ash يمكن أن يطلب ذلك مع أذوناتك؛ راجع هذا القرار بعناية.

كيف يمكنني تغيير الأوامر المسموح بتنفيذها ash؟

تحرير ~/.ash/.ash_allow وإدراج الأسماء القابلة للتنفيذ فقط، واحد في كل سطر أو مفصولة بفاصلات. تسمح التوجيهات المستقلة $TOOLS_DIR_LIST و$PLUGINS_DIR_LIST بالبرامج النصية المُدارة المؤهلة والمكونات الإضافية الأصلية؛ استبدلها بأسماء حرفية للسياسة المقيدة. البرامج النصية والمكونات الإضافية المؤهلة هي ملفات عادية في ~/.ash/tools/ أو ~/.ash/plugins/ مع وحدات البت للقراءة والتنفيذ. يمكنك أيضًا رفض الأوامر بشكل صريح عن طريق إضافتها إلى ~/.ash/.ash_deny. بدلاً من ذلك، قم بتعيين ASH_ALLOW أو ASH_DENY إلى قائمة مفصولة بفواصل. تتم قراءة التغييرات عند طلب ash التالي.

ما هو المستخدم الذي يعمل تحته ash؟

ash ويتم تشغيل كل أداة مسموح بها كمستخدم يبدأ ash. ولا يرفع الامتيازات. مساحة العمل ~/.ash المُدارة متشددة من حيث الأذونات، ولكن محتوياتها تظل في متناول المستخدم الخاص بك ولأي عملية تسمح بها صراحةً.

هل يثق ash في النص المستلم عبر توجيه الإخراج مثل نص المستخدم؟ ما هي وسائل الحماية المتوفرة للبيانات الضارة؟

نعم. عندما لا يتلقى ash أي وسائط سطر أوامر ويتم إرسال الإدخال القياسي، فإنه يعامل هذا الإدخال كمطالبة للمستخدم. لا تقم بإرسال صفحات الويب أو السجلات أو النصوص التي تم إنشاؤها غير الموثوق بها مباشرةً إلى ash إلا إذا كنت تنوي السماح بذلك كمطالبة. وهذا يختلف عن الأداة المُدارة ash، والملف، والبرنامج النصي، وخطوط الأنابيب، ومخرجات الوكيل الفرعي: ash تُصنف هذه النتائج على أنها أدلة غير موثوقة وتُوجه النموذج بعدم اتباع التعليمات الصادرة منها مطلقًا. قم بتعيين ASH_STRICT=1 لاستبدال عبارات الحقن السريع المعترف بها في الأدلة غير الموثوق بها. لا تزال قواعد القائمة المسموح بها وتنفيذ argv المباشر تنطبق على تنفيذ الأداة.

هل ملفات ash الخاصة بي خاصة عن المستخدمين الآخرين على هذا الكمبيوتر؟

أثناء التثبيت، ash يربط دليل ~/.ash بأذونات المالك فقط والملفات المُدارة إلى أذونات يمكن للمالك قراءتها وأذونات قابلة للكتابة من قبل المالك. وهذا يحمي من الحسابات المحلية الأخرى بموجب أذونات Unix العادية، ولكن ليس ضد حسابك الخاص، أو المسؤولين، أو النسخ الاحتياطية، أو البرامج التي تختار تشغيلها مع الوصول إلى الدليل الرئيسي الخاص بك.

الأدوات وسير العمل

هل يدعم ash الأنابيب وتقاليد Unix الأخرى؟

نعم. يمكنك توجيه النص إلى ash كمطالبة، على سبيل المثال git diff | ash. بالنسبة إلى مسارات الأدوات المطلوبة بواسطة الذكاء الاصطناعي، يدعم ash ما بين اثنين إلى ستة عشر ملفًا تنفيذيًا مدرجًا في القائمة المسموح بها ومتصلًا مباشرةً بدون غلاف، مثل ls | grep pattern | pbcopy. يتم حظر أنماط التحكم في Shell في وسيطات الأداة، ويجب إدراج كل ملف قابل للتنفيذ في خط الأنابيب المُدار بواسطة ash في القائمة المسموح بها.

هل سيقوم ash بإعادة تفسير الأوامر داخل نصوص الصدفة الخاصة بي، أو أوامر SSH، أو وظائف cron؟

لا. تعود أغلفة التكامل Bash وzsh فورًا في الأصداف غير التفاعلية، لذا تحافظ البرامج النصية ووظائف CI وأوامر SSH وأوامر cron على السلوك العادي للأوامر غير الموجودة. استخدم استدعاء صريحًا مثل ash "summarize this log" أو some-command | ash عندما يجب أن تستدعي الأتمتة ash.

كيف يمكنني إيقاف ash من تفسير أوامري لبضع دقائق؟

قم بتشغيل ash snooze لمدة خمس دقائق افتراضية، أو حدد مدة مثل: ash snooze 30s أو ash snooze 1h. قم بتشغيل ash snooze off للاستئناف فورًا. يقوم الغفوة بإيقاف التوجيه التلقائي للأوامر غير الموجودة والتوجيه المجمّع مؤقتًا؛ لا تزال أوامر ash ... الصريحة تعمل.

كيف يمكنني تصحيح أخطاء ash والاطلاع على مزيد من المعلومات حول ما تفعله؟

اضبط ASH_VERBOSE=1 قبل تشغيل ash لتمكين إخراج تصحيح الأخطاء المنظم ولوحة معلومات التنفيذ الطرفي. اضبط ASH_LOG_FILE لكتابة تصحيح JSON إلى ملف؛ يتحكم ASH_LOG_MAX_BYTES في التدوير والإعدادات الافتراضية إلى 1 ميجا بايت عند تكوين ملف سجل.

ما هي الحدود المطبقة عند تشغيل ash الأدوات؟

افتراضيًا، يكون لكل استدعاء أداة مهلة مدتها 15 ثانية ويلتقط ما يصل إلى 8192 بايت من الإخراج. قد يقوم طلب الذكاء الاصطناعي بإجراء ما يصل إلى 16 تكرارًا لحلقة الأدوات، ويحتوي خط الأنابيب المُدار ash على مرحلتين إلى ستة عشر مرحلة. اضبط مهلة الأداة وحد الإخراج باستخدام ASH_TOOL_TIMEOUT وASH_TOOL_OUTPUT_MAX؛ حافظ على تركيز المخرجات باستخدام أوامر مثل head أو tail أو grep.

أين موجه النظام الافتراضي؟

ملف المطالبة الأساسي هو ~/.ash/.ash_system، ويتم تثبيته من الملف الافتراضي المجمع عند تشغيل ash install. ash يقرأ هذا الملف أولاً. إذا كان غائبًا، يعود ash إلى .ash_system في دليل العمل الحالي ثم ~/.ash_system. يتم توسيع قيم $VARIABLE العادية من البيئة، ولكن $TOOLS_DIR_LIST و$PLUGINS_DIR_LIST و$IF_PYTHON_AVAILABLE هي بدائل Ash داخلية محجوزة وليست مشتقة من البيئة أبدًا.

أين أضع البرامج النصية الخاصة بي والمكونات الإضافية الأصلية لـ ash للاتصال كأدوات؟

ضع نصوص Python في ~/.ash/tools/ وقم بتجميع المكونات الإضافية الثنائية الأصلية في ~/.ash/plugins/. تأكد من أنها قابلة للتنفيذ، وأضف الاسم القابل للتنفيذ إلى ~/.ash/.ash_allow (أو اعتمد على $TOOLS_DIR_LIST / $PLUGINS_DIR_LIST). ash لا يستدعي shell لأوامر Unix والمكونات الإضافية المسموح بها.

ما هي أفضل الممارسات لأداة أو مكون إضافي حتى يفهم الذكاء الاصطناعي الغرض منه واستخدامه؟

اتبع نمط الأداة/البرنامج الإضافي القياسي: اكشف عن الخيارات التي يمكن التنبؤ بها باستخدام وسيطات واجهة سطر الأوامر (CLI)؛ وقم بتنفيذ خيار --ai-docs الذي يشرح القدرات، وكل وسيطة وافتراضية، ومخطط الإخراج، وحالات الفشل، ومتى يجب على الذكاء الاصطناعي استخدام الأداة. قم بإصدار JSON مدمج ومنظم بحقل status وتفاصيل خطأ قابلة للتنفيذ بدلاً من النثر الممزوج بالبيانات. حافظ على تحديد المخرجات، والتحقق من صحة المدخلات، وتعيين مهلات الشبكة، والتعامل مع حالات الفشل المتوقعة، وجعل الأداة آمنة للاتصال بشكل متكرر. أضف اسم الملف العاري إلى ~/.ash/.ash_allow; يمكن لـ ash تنفيذه فقط عندما يكون مدرجًا في القائمة المسموح بها وغير مدرج في ~/.ash/.ash_deny.

ما هي البرامج النصية للأداة المتوفرة والمكونات الإضافية الأصلية؟

البرامج النصية لـ bootstrap Python المثبتة هي headlines.py وwikipedia.py وyfinance.py في ~/.ash/tools/. المكونات الإضافية الأصلية المتوفرة هي what_time_is_it (Go) وflip_a_coin (Rust) وcalculator (TypeScript) في ~/.ash/plugins/.

هل يمكن ash الاتصال بالوكلاء الفرعيين؟

نعم. يمكن للوكيل الأصلي استخدام run_sub_agent لمهمة واحدة مركزة ومستقلة. يرث الطفل دليل العمل والتكوين والأدوات وأذونات نظام التشغيل، ويعيد نتيجة محددة، ولا يمكنه إنشاء طفل آخر. الحد الأقصى الافتراضي هو ستة وكلاء فرعيين لكل تشغيل رئيسي ويمكن تغييره باستخدام ASH_MAX_AGENTS.

هل يمكن ash إنشاء ملفات ذاكرة لتتبع المهام المعقدة وما تعلمته في الجلسة؟

نعم. يمكنه كتابة ملفات مساحة العمل المستمرة ضمن ~/.ash، والتي يتم تعقبها في ~/.ash/inventory.md، وملفات التسويد على نطاق الجلسة ضمن ~/.ash/scratch/<session-id>/. استخدم ملفات مساحة العمل الدائمة للحصول على المعلومات التي تنوي الاحتفاظ بها؛ استخدام الملفات المؤقتة للخطط المؤقتة والملاحظات والعناصر المساعدة.

هل يمكن ash جدولة العمل لوقت لاحق؟

نعم، من خلال أدوات الذكاء الاصطناعي الخاصة به. في نظام التشغيل macOS، تستخدم الجدولة لمرة واحدة launchd LaunchAgent لكل مستخدم وتتطلب launchctl. في Linux، يتم دعم الجداول المتكررة من خلال المستخدم الخاص بك crontab؛ ash يدير فقط الإدخالات المميزة الخاصة به. لا يتوفر برنامج الجدولة launchd لمرة واحدة على Linux، لذا استخدم إدخال cron أو برنامج جدولة Linux آخر لمهمة Linux لمرة واحدة. تتلقى عمليات التشغيل المجدولة بيئة محدودة وتستخدم HTTPS المباشر بدلاً من وسيط الصدفة التفاعلي، لذا تأكد من توفر تكوين الذكاء الاصطناعي المطلوب للمهمة المجدولة. لا يمكنهم استخدام أدوات MCP عن بعد؛ Ash يعمل بدونها ولا يحذر في الجلسات غير التفاعلية. لا تقم بجدولة المطالبات التي تتطلب MCP.

الجلسات والتخزين

أين توجد ملفات السجل أو السجل لـ ash؟

يتم تخزين سجل المحادثات بتنسيق JSON في ~/.ash/history/<SESSION_ID>.json; استخدم عمليات التشغيل المجدولة task_<SESSION_ID>.json. عند تمكين تسجيل التصحيح المجدول، يكون موقع السجل الافتراضي هو ~/.ash/logs/task_<SESSION_ID>.log. يمكنك اختيار مسار آخر لسجل تصحيح الأخطاء باستخدام ASH_LOG_FILE.

ما هي مدة الاحتفاظ بملفات السجل؟

ash يزيل ملفات السجل JSON الأقدم من 14 يومًا أثناء التنظيف العادي للتطبيق، بميزانية تنظيف تبلغ 300 مللي ثانية حتى لا يتأخر الخروج. نافذة الرسائل الأخيرة منفصلة: فهي تحتفظ بما يصل إلى 40 رسالة لكل محادثة افتراضيًا ويمكن تغييرها باستخدام ASH_HISTORY_MAX.

كيف يمكنني مسح محادثة أو البدء من جديد؟

يتم فصل السجل عن طريق معرف الجلسة ومفتاح نموذج/نقطة نهاية الذكاء الاصطناعي. ابدأ جلسة طرفية جديدة لمعرف جلسة جديد، أو قم بإزالة ملف JSON ذي الصلة ضمن ~/.ash/history/ عندما تريد عمدًا تجاهل سجل المحادثة المحلي هذا. لا تؤدي إزالة ملف السجل إلى إلغاء مفتاح الموفر أو حذف البيانات من جانب الموفر؛ قم بإدارة هذه العناصر بشكل منفصل مع الموفر.

ما هو SESSION_ID وأين يتم إنشاؤه؟

إنه معرف كل جلسة يُستخدم لفصل السجل والمساحة المؤقتة ومآخذ الوسيط وأسماء السجل المجدولة. تنشئ بيئة الصدفة المُدارة قيمة أبجدية رقمية عشوائية مكونة من 16 حرفًا من /dev/urandom عند بدء الصدفة؛ ash ينشئ واحدًا أيضًا عندما لا يكون للاستدعاء التفاعلي أي قيمة.

هل يمكنني استبدال تنفيذ منشئ SESSION_ID؟

يمكنك توفير SESSION_ID الخاص بك قبل البدء ash أو تخصيص ملف البيئة المُدارة محليًا، ولكن ash يتحقق من صحته. تتكون المعرفات الصالحة من 128 حرفًا على الأكثر وتستخدم الحروف والأرقام والشرطات السفلية والواصلات، مع لاحقة نقطة اختيارية واحدة للجلسة التابعة. لا تستخدم قيمًا مشتركة أو غير موثوقة: تجمع التصادمات بين سجل الجلسة وحالة وقت التشغيل.
