في هذه الصفحة قبل البدء macOS Linux FreeBSD التهيئة والتحقق Ollama محلي الخطط السحابية المجانية التثبيت بالسكربت التحقق من التنزيل التحديثات والقنوات الإزالة استكشاف المشكلات

قبل البدء

  1. نظام وصدفة مدعومان: macOS أو Linux على amd64/x86_64 أو arm64/aarch64، أو FreeBSD على amd64. استخدم Bash أو zsh أو Fish. حزم Arch تدعم x86_64 فقط. لا مثبّت أصليًا لـ Windows/PowerShell.
  2. الوصول للتنزيل: اتصال إنترنت يعمل ووصول HTTPS موثوق إلى GitHub ومستودع الحزم المختار ومزوّد النموذج. حتى الاستدلال المحلي يتطلب تنزيل النموذج أولًا.
  3. الصلاحيات: مجلد منزل قابل للكتابة لملفات المستخدم. حزم Linux النظامية و.pkg على macOS تتطلب صلاحيات مسؤول؛ شغّل Homebrew وash install كمستخدم عادي.
  4. نموذج: خادم استدلال محلي بنموذج منزّل أو حساب سحابي/مفتاح API. اختر نموذجًا يدعم استدعاء الأدوات، لا نموذج صور/صوت فقط. احتياجات الذاكرة والقرص وGPU محليًا تعتمد عليه.

الحزم الجاهزة لا تحتاج Go أو Rust أو Node.js أو أدوات بناء Xcode. لمدير الحزم متطلبات خاصة محتملة؛ اتبع إعداداته الرسمية أولًا.

اختياري: أدوات Python المرفقة

الاستخدام الأساسي لا يتطلب Python. الأدوات المرفقة تحتاج Python 3 مع venv وensurepip وإمكانية تنزيل اعتمادياتها. على Debian/Ubuntu ثبّت python3 وpython3-venv؛ Python من Homebrew يتضمن venv. على FreeBSD استخدم حزمة pip الموافقة لإصدار Python. أعد ash install. ينشئ الإعداد بيئة معزولة في $XDG_DATA_HOME/ash/venv (الافتراضي ~/.local/share/ash/venv)؛ الفشل يعطّل الأدوات لا ash الأساسي.

macOS

الموصى به: Homebrew

المتطلبات: Homebrew وبيئة macOS مدعومة وأمر brew يعمل. يختار tap تلقائيًا أرشيف Intel أو Apple Silicon. ثبّت Release دون sudo:

brew install Jonconradt/ash/ash
ash version

يدير Homebrew الملفات التنفيذية والإضافات الأصلية وصفحات الدليل وإشعارات الترخيص في بادئته (عادة /opt/homebrew على Apple Silicon أو /usr/local على Intel). يفحص الأرشيف مقابل SHA-256 للصيغة. لا يضبط المزوّد أو ملف بدء الصدفة: تابع إلى تهيئة المستخدم. حدّث بـ brew upgrade ash وأزل Release بـ brew uninstall ash؛ راجع صيغ القنوات لـ Beta/Nightly.

بديل: .pkg أصلي

نزّل darwin-arm64.pkg لـ Apple Silicon أو darwin-amd64.pkg لـ Intel من إصدار منشور. تحقق من بيان المجاميع الموقّع قبل فتح المثبّت. تحتاج صلاحيات مسؤول.

حزمة macOS غير موقّعة وغير موثّقة لدى Apple. البيان يتحقق مستقلًا من الناشر والمجاميع، لا يقدّم توثيق Apple. لا تعطّل Gatekeeper أو تتجاوز تحذيرًا لمجرد التثبيت؛ فضّل Homebrew إن تطلبت سياسة الأمان ذلك.

تكتب الحزمة ash وash-broker في /usr/local/bin والإضافات في /usr/local/lib/ash/plugins والأدلة في /usr/local/share/man والإشعارات في /usr/local/share/licenses/ash. الإيصال هو dev.ash.cli. لا تهيئ المستخدم أو تشترك بالتحديثات: هيّئ بعد التثبيت، واستبدلها بـ .pkg أحدث موثّق للتحديث، واتبع الإزالة اليدوية للحذف. لا تثبّتها فوق نسخة يديرها Homebrew.

Linux

استخدم مدير توزيعتك متى أمكن. تدير الحزم /usr/bin/ash و/usr/bin/ash-broker و/usr/lib/ash/plugins والأدلة تحت /usr/share/man وإشعارات الترخيص. تترك إعدادات المزوّد وخطافات الصدفة لـ تهيئة المستخدم.

Debian وUbuntu: APT

المتطلبات: amd64 أو arm64، مسؤول، APT وcurl وgpg وشهادات CA. ثبّت أدوات التنزيل/المفاتيح الناقصة من توزيعتك قبل إضافة المستودع. تسمى Release هنا stable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

قبل استيراد مفتاح، تحقق من بصمته بمصدر موثوق للناشر. بصمة VersionX هي 32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. يفحص APT البيانات الوصفية الموقّعة ومجاميع الحزم فيها؛ يقيّد signed-by نطاق المفتاح. حدّث بـ sudo apt update && sudo apt upgrade ash؛ أزل بـ sudo apt remove ash.

Fedora والأنظمة المتوافقة مع RHEL: DNF

المتطلبات: x86_64 أو aarch64، مسؤول، DNF/RPM وcurl وgpg وشهادات CA. ثبّت الأدوات الناقصة من التوزيعة. افحص المفتاح وقارن البصمة أعلاه قبل الاستيراد:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

ملفات RPM ليست موقّعة منفردة. يتحقق repo_gpgcheck=1 من البيانات الوصفية المغطية لمجاميعها؛ يعكس gpgcheck=0 غياب توقيع كل حزمة، لا تعطيل تحقق المستودع. إن تطلبت سياستك محتويات RPM موقّعة فلا يفي بها المستودع. حدّث بـ sudo dnf upgrade ash؛ أزل بـ sudo dnf remove ash.

Arch Linux: Pacman

المتطلبات: x86_64، مسؤول، Pacman بحلقة مفاتيح مهيّأة وcurl وgpg. طابق البصمة المعروضة بأعلاه قبل الوثوق. أضف المستودع مرة واحدة لا بكل تحديث:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

يتحقق Pacman من توقيعات الحزم وقاعدة البيانات. زامن Arch بـ sudo pacman -Syu دون تحديث جزئي؛ أزل ash بـ sudo pacman -R ash.

طرق Linux الأخرى

تستخدم Homebrew على Linux بالفعل؟ تدعم تعليمات tap نفسها amd64 وarm64؛ يدير Brew الملفات لا APT/DNF. وإلا استخدم تثبيت سكربت/أرشيف موثّق أو تنزيل .deb/.rpm مناسب. ثبّت .deb موثّقًا بـ sudo apt install ./PACKAGE.deb أو .rpm بـ sudo dnf install ./PACKAGE.rpm (استبدل الأسماء). تبقى الحزمة تحت إدارة مديرها لكنها لا تضيف مستودعًا أو اشتراكًا بالإصدارات المستقبلية. محتوى RPM الحالي غير موقّع؛ اتبع سياسة التوزيعة بدل تعطيل الفحص.

FreeBSD

المتطلبات: amd64 وBash (حتى لو كانت الصدفة التفاعلية zsh أو Fish)، أدوات تنزيل/تحقق ومجلد تثبيت قابل للكتابة. ثبّت Bash بمدير FreeBSD الأصلي:

sudo pkg install bash

يدير pkg في FreeBSD المتطلبات لا ash: لا مستودع ash .pkg أو أرشيف arm64 حاليًا. استخدم السكربت الموثّق، أو تحقق من tarball لـ FreeBSD amd64، وفكّه بمجلد مؤقت وثبّت تنفيذية ash ذات الإصدار باسم ~/.local/bin/ash بجوار ash-broker. انسخ الإضافات الأصلية إلى $XDG_DATA_HOME/ash/plugins (افتراضيًا ~/.local/share/ash/plugins) ثم هيّئ. أنت تدير الملفات؛ لن يزيلها pkg delete. استخدم تحديثات Release الذاتية بالموقع الافتراضي أو استبدل القطع الموثّقة يدويًا.

التهيئة والتحقق

بعد التنفيذيات شغّل الإعداد تفاعليًا كمستخدم عادي. إعداد الملفات فقط يبقي ملفات البدء دون تغيير:

ash install

لدمج الأوامر غير الموجودة أيضًا، اختر أمرًا واحدًا مطابقًا لصدفتك:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Fish

ash install --shell fish --shell-integration

يستخدم Bash ~/.bashrc وzsh ~/.zshrc وFish $XDG_CONFIG_HOME/fish/config.fish (الافتراضي ~/.config/fish/config.fish). افتح صدفة جديدة؛ الموجودة تحتفظ بالوسيط الجاري. يقدّم الدمج ~/.local/bin في PATH: أزل النسخة المحلية القديمة قبل توقع اختيار حزمة النظام.

عند غياب الإعدادات يكشف الإعداد مفاتيح موجودة أو خادمًا محليًا جاريًا؛ وإلا يعرض قائمة المزوّدين ويطلب الاعتمادات. اختر نموذجًا متاحًا يدعم الأدوات. الإعدادات الصالحة محفوظة؛ إعادة الإعداد لا تغيّر المزوّد.

تحفظ الإعدادات في $XDG_CONFIG_HOME/ash/.ash_env (الافتراضي ~/.config/ash/.ash_env، أذونات خاصة). يحملها الدمج المدار. دون دمج يمكن لـ Bash/zsh تحميل الملف في بدء التشغيل؛ على Fish ضبط متغيرات ASH_AI_* بصيغته لا تحميل ملف Bash. احمِ ملفات الرموز ولا تودعها بالمستودع.

للتثبيت المحلي بلا دمج أضف المجلد الفعلي إلى PATH. Bash/zsh: export PATH="$HOME/.local/bin:$PATH". Fish: fish_add_path "$HOME/.local/bin". احفظ ذلك في بدء الصدفة؛ استبدل بمجلدك المخصص عند الحاجة.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

يجب أن تجد الأوامر الأولى التثبيت المختار. الطلب يحتاج خادمًا جاريًا أو اعتمادات سحابية صالحة؛ تثبيت ash لا يثبّت نموذجًا.

Ollama محلي: لا حساب سحابي مطلوب

ثبّت Ollama باتباع تعليمات النظام الرسمية. شغّل التطبيق/الخدمة أو ollama serve بطرفية أخرى إن لم يكن الخادم جاريًا. دعم ash لـ FreeBSD لا يعني مثبّت Ollama أصليًا: استخدم خادمًا متاحًا بمضيف مدعوم آخر عند الحاجة.

نزّل نموذج أدوات يناسب عتادك؛ llama3.1:8b مثال لا حد أدنى. راجع كتالوج الأدوات الحالي لبدائل:

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

بلا مفاتيح سحابية مضبوطة يمكن كشف الخادم المحلي وعرض النموذج المنزّل. إن ضُبط مزوّد آخر فغيّر نقطة الاتصال/النموذج يدويًا. مثال Bash/zsh:

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

المكافئ في Fish:

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

تؤثر التغييرات على الصدفة الحالية فقط. احفظها بملف بيئة ash المحمي أو إعداد الصدفة المناسب، مستبدلًا تجاوزات المزوّد القديمة. Ollama المحلي لا يحتاج رمزًا. أبقِ الخادم على loopback إلا إن أمّنت الوصول عمدًا؛ البعيد يستقبل طلباتك ونتائج الأدوات.

اختياري: اضبط OLLAMA_KEEP_ALIVE=30m في بيئة خادم Ollama وأعد تشغيله لإبقاء النماذج محمّلة. يبقيها -1 بلا حد لكنه يستهلك الذاكرة بين الطلبات. ضبطه في طرفية عميل ash فقط لا يعيد ضبط خادم جارٍ.

الاستدلال المحلي لا يفوتر API لكنه يستهلك العتاد/التخزين/الكهرباء. Ollama السحابي خدمة منفصلة بمصادقة وحدود خطة، ليست الإعداد المحلي.

الخطط السحابية المجانية

مجاني لا يعني غير محدود أو خاصًا. الحسابات والمناطق والحصص والنماذج وسياسات البيانات تختلف وتتغير. الطلبات ونتائج الأدوات ذات الصلة تغادر جهازك. راجع الحدود والشروط؛ لا تفعّل الفوترة المدفوعة دون نية الدفع.

أنشئ مفتاحًا بالروابط، شغّل ash install تفاعليًا واختر المزوّد. يُطلب الرمز وتُعرض النماذج حيث يدعمها. اختر نموذج نص مجانيًا يستدعي الأدوات متاحًا حاليًا؛ ظهوره لا يضمن المجانية لحسابك.

تصدّر مفتاحًا معروفًا بالفعل؟ يكشفه الإعداد؛ مع عدة مفاتيح يطلب اختيارًا. لا تلصق مفاتيح حقيقية بتاريخ الأوامر أو التسجيلات أو المصدر. ملف الإعداد يحتوي سرًا لا خزنة مشفرة.

إعداد يدوي أو تغيير المزوّد

استبدل نقطة الاتصال أدناه بقيمة الجدول وMODEL_ID بنموذج متحقق منه بحسابك. إن صُدّر المفتاح باسم GROQ_API_KEY يعيد مثال Bash/zsh استخدامه دون كتابة السر:

export ASH_AI_ENDPOINT="https://api.groq.com/openai/v1"
export ASH_AI_MODEL="MODEL_ID"
export ASH_AI_AUTH_TOKEN="$GROQ_API_KEY"

المكافئ في Fish:

set -gx ASH_AI_ENDPOINT https://api.groq.com/openai/v1
set -gx ASH_AI_MODEL MODEL_ID
set -gx ASH_AI_AUTH_TOKEN "$GROQ_API_KEY"

لـ Gemini/OpenRouter استخدم نقطة الاتصال ومتغير المفتاح الخاصين بهما. احفظ بأمان للصدفات المقبلة. السحابة تحتاج HTTPS ورمزًا؛ HTTP محلي ليس اختصارًا سحابيًا. راجع مرجع البيئة والمزوّدين الآخرين المدعومين للخدمات المدفوعة والتجاوزات المتقدمة.

التثبيت بالسكربت: بديل لا الخيار الأول

فضّل Homebrew وAPT وDNF وPacman: تتتبع الملفات وتتحقق من التنزيلات بإعداد الثقة وتوفر تحديثًا/إزالة مألوفين. تظل الثقة بالناشر وأفعال التثبيت مطلوبة.

سكربت الموقع ينفّذ كودًا بصلاحيات حسابك. موقع/ناشر مخترق أو سكربت متغير قد يقرأ أسرارًا ويعدل ملفات أو يثبّت برامج. HTTPS يحمي النقل لا نية الكود. تمرير URL مباشرة للصدفة ينفّذ قبل الفحص. توقيعات الأرشيف لا توثّق السكربت نفسه. لا تستخدم sudo أو تعطّل التحقق أبدًا.

المتطلبات: نظام/معمارية مدعومان، $SHELL يحدد Bash/zsh/Fish، Sigstore cosign وtar وuname وinstall وأدوات صدفة قياسية وأمر SHA-256 (sha256sum أو shasum أو sha256) ومنزّل (curl أو wget أو Python). المثال يستخدم curl. FreeBSD يحتاج Bash أيضًا. مجلد المنزل/التثبيت قابل للكتابة.

نزّل ملفًا محليًا، افحصه بمحرر ونفّذ فقط إن وثقت بالمصدر والسلوك. الفحص لا يضمن الأمان؛ لا تتبع الخطوات عميانًا:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

بعد الفحص شغّل النسخة المحفوظة كمستخدم عادي:

sh ./ash-install.sh
rm ./ash-install.sh

ينزّل install.sh آخر Release ويتحقق من بيان Sigstore الموقّع وملخص الأرشيف ويثبّت ash/ash-broker في ~/.local/bin. الإضافات في $XDG_DATA_HOME/ash/plugins. يُجري إعداد المستخدم ويسأل قبل دمج الصدفة. بلا طرفية تفاعلية قد تتخطى أسئلة المزوّد/الدمج: شغّل ash install تفاعليًا بعده.

اضبط ASH_INSTALL_DIR قبل السكربت لاختيار وجهة أخرى. أضفها بنفسك لـ PATH. التحديث الذاتي مدعوم تحت ~/.local/bin فقط؛ الوجهات الخاصة تتطلب استبدالًا يدويًا. لا محدد Beta/Nightly بالسكربت.

التحقق من حزمة أو أرشيف مباشر

المتطلبات: cosign وأداة SHA-256. نزّل الحزمة/الأرشيف وSHA256SUMS وSHA256SUMS.sigstore.json من الإصدار نفسه. اعمل بمجلد جديد. استبدل vX.Y.Z بالوسم الدقيق مع لاحقة ما قبل الإصدار إن وجدت:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

بعد النجاح فقط احسب الملخص بـ shasum -a 256 PACKAGE على macOS أو sha256sum PACKAGE على Linux أو sha256 -q PACKAGE على FreeBSD. استبدل PACKAGE باسم الملف وطابقه تمامًا بإدخاله في البيان المتحقق. توقف عند غياب الإدخال أو الاختلاف. مجموع غير موقّع بجوار الملف لا يعادل بيانات ناشر موثّقة.

التحديثات والقنوات الثلاث

  • Release (موصى به): إصدارات مستقرة مثل vX.Y.Z؛ يسميها إعداد المستودع stable.
  • Beta: اختبارات ما قبل الإصدار، الوسم vX.Y.Z-beta.N؛ توقع تغييرات وتراجعات.
  • Nightly: تغييرات حديثة للفرع الافتراضي، الوسم vX.Y.Z-nightly.YYYYMMDD.N؛ أعلى خطر تراجع. البناء مجدول لكنه قد يُتخطى دون تغييرات أو عند فشل النشر.

يحدّث الإصدار المنشور صيغة Homebrew أو مستودع Linux الموقّع الموافق. تتلقاه بأمر تحديث المدير المسؤول أو سياسة نظامك. النشر والمستودعات والموقع قد تتأخر بعضها عن بعض؛ تحقق من التوفر قبل تغيير القناة. لا يثبّت ash تحديثات تنفيذية خلفية بصمت.

Homebrew: تثبيت الصيغ أو تبديلها

لتثبيت Beta/Nightly جديد استخدم الاسم الكامل أعلاه في brew install. عند التبديل أزل الصيغة الحالية أولًا: الثلاث توفر التنفيذيات نفسها. مثال Release إلى Beta:

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

استخدم ash-nightly لـ Nightly أو ash لـ Release بالتثبيت/التحديث. أزل الصيغة الفعلية للقناة القديمة، لا ash دائمًا. تُحفظ الإعدادات؛ افتح صدفة جديدة.

Linux: اختيار قناة مستودع واحدة

APT: اتبع إعداد APT بتوزيعة واحدة من الجدول. للتبديل عدّل /etc/apt/sources.list.d/versionx.list مستبدلًا stable بـ beta أو nightly (أو عُد لـ stable) ثم:

sudo apt update
sudo apt install --allow-downgrades ash

DNF: اتبع إعداد DNF بـ baseurl المختارة. بالتثبيت الموجود استبدل baseurl في /etc/yum.repos.d/versionx.repo محافظًا على التوقيع، ثم:

sudo dnf --refresh distro-sync ash

Pacman: اتبع إعداد Pacman بـ URL Server المختار. أبقِ القسم [versionx]: كل قناة تنشر قاعدة versionx.db. غيّر Server فيه لا تضف قاعدة باسم آخر. للتبديل بما فيه الرجوع:

sudo pacman -Syuu ash

راجع المعاملة: العودة لـ Release قد تخفض ash، وu المزدوج بـ Pacman قد يخفض حزمًا أخرى. انسخ الإعداد احتياطيًا أولًا. بعدها استخدم التحديثات العادية من أقسام النظام؛ لا تترك مصادر قنوات ash متعددة فعّالة.

تحديثات Release المحلية للمستخدم

ash update

يتحقق ويثبّت المستقر فقط إن كانت تنفيذية ash النشطة تحت ~/.local/bin. يحدّث الملفات/الإضافات أيضًا مع خيارات للمخصصة. يختار ash update --version vX.Y.Z وسمًا مستقرًا لا قناة؛ ليس أمر خفض إصدار. لا خيار --channel. تثبيت المدير و.pkg والوجهات الخاصة تحتاج مديرها/مثبّتها. FreeBSD Beta/Nightly يستخدم أرشيفات موثّقة يدويًا لا اشتراك المحدث الذاتي. افتح صدفة جديدة.

الإزالة دون حذف ملفات غير مرتبطة

1. عطّل دمج الصدفة أولًا

قبل حذف التنفيذيات نفّذ الأمر لكل صدفة فعّلت دمجها:

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Fish

ash install --shell fish --disable-shell-integration

إن غاب ash عدّل ملف البدء من التهيئة واحذف فقط الكتلة بين # >>> ash install >>> و# <<< ash install <<<. احذف أسطر PATH/بيئة ash المضافة يدويًا لا إعدادات غير مرتبطة. أغلق صدفات ash لإنهاء وسطاءها.

2. دع مدير الحزم المسؤول يحذف ملفاته

Homebrew (Release)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

اختر طريقتك فقط؛ لـ Homebrew Beta/Nightly استخدم ash-beta/ash-nightly. APT/DNF/Pacman يزيل الملفات التنفيذية والإضافات والأدلة المملوكة لا إعدادات/تاريخ المنزل. لا تحذف ملفات الحزم يدويًا.

تنظيف مستودع اختياري: احذف مصدر ash /etc/apt/sources.list.d/versionx.list ومفتاحه الخاص /etc/apt/keyrings/versionx-keyring.gpg أو مستودع /etc/yum.repos.d/versionx.repo أو قسم ash [versionx] من /etc/pacman.conf. تأكد أن لا حزم أخرى تستخدمها. أزل مفتاح RPM/Pacman بعد تأكيد البصمة وعدم اعتماد غيره؛ لا تحذف حلقة مفاتيح التوزيعة المشتركة.

3أ. إزالة .pkg macOS يدويًا

يسجل macOS Installer إيصالًا بلا مزيل ash. تأكد أنه .pkg لا Homebrew وافحص المحتوى الدقيق:

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

بالإيصال كجرد احذف فقط ملفات ash: /usr/local/bin/ash و/usr/local/bin/ash-broker وملفات /usr/local/lib/ash/plugins و/usr/local/share/man/man1/ash.1 وصفحات ash.1 المترجمة المسردة وإشعارات /usr/local/share/licenses/ash. تحتاج مسؤولًا. إن استبدلها مثبّت آخر افحص الملكية ولا تحذف نسخته. احذف مجلدات ash الفارغة فقط لا المشتركة /usr/local وbin أو الأدلة.

بعد الملفات يمكنك حذف الإيصال اختياريًا:

sudo pkgutil --forget dev.ash.cli

نسيان الإيصال لا يحذف أي ملفات مثبتة. احتفظ به حتى اكتمال فحص المحتوى.

3ب. إزالة الأرشيف المحلي / Linux / FreeBSD يدويًا

حدد النسخة النشطة بـ command -v ash وcommand -v ash-broker. بالسكربت الافتراضي بعد تعطيل الخطافات احذف هذين الملفين فقط:

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

لـ ASH_INSTALL_DIR أو الأرشيف اليدوي احذف مسارات ash/الوسيط الفعلية فقط. أزل الإضافات/الأدلة/الإشعارات بجردك الأصلي؛ إضافات السكربت ببيانات المستخدم. تحت /usr/bin افحص الملكية أولًا بـ dpkg -S /usr/bin/ash أو rpm -qf /usr/bin/ash أو pacman -Qo /usr/bin/ash. أزل النسخة المدارة بمديرها حتى لو نزّلت منفردة.

4. اختياري: حذف إعدادات وأدوات وتاريخ محلي

انسخ ما تريد حفظه احتياطيًا. الخطوة المنفصلة قد تحذف الإعدادات/الرموز والأدوات/الإضافات المخصصة والتاريخ وملفات العمل. إزالة التنفيذيات لا تعني الموافقة على محوها.

  • الإعداد: $XDG_CONFIG_HOME/ash، الافتراضي ~/.config/ash.
  • البيانات والإضافات وبيئة Python: $XDG_DATA_HOME/ash، الافتراضي ~/.local/share/ash.
  • التاريخ والحالة: $XDG_STATE_HOME/ash، الافتراضي ~/.local/state/ash.
  • الذاكرة المؤقتة: $XDG_CACHE_HOME/ash، الافتراضي ~/.cache/ash.
  • تشغيل الوسيط: $XDG_RUNTIME_DIR/ash، أو $XDG_STATE_HOME/ash/runtime عند غياب جذر تشغيل.

افحص تجاوزات XDG المطلقة الفعلية قبل حذف مجلدات ash الفرعية فقط؛ لا تحذف جذر XDG أو المنزل. بعد إغلاق كل صدفات ash احذف بقايا التشغيل إن لزم. قد تبقى اعتمادات MCP OAuth بمدير النظام: احذف إدخالات ash وألغ الوصول عند مزوّد MCP. ألغ مفاتيح AI غير المستخدمة من حساباتها؛ حذف ملف لا يلغي مفتاحًا. لا تزل Ollama/النماذج أو Python أو الاعتماديات المشتركة مع ash.

حل المشكلات سريعًا

أمر مفقود أو إصدار خاطئ
افحص PATH وcommand -v ash/command -v ash-broker. نسخة قديمة في ~/.local/bin قد تحجب حزمة. استخدم مسؤولًا/قناة واحدة وافتح صدفة جديدة.
لم تظهر قائمة المزوّدين
شغّل ash install تفاعليًا. تُحفظ الإعدادات الصالحة؛ استخدم الإعداد اليدوي للتبديل. بلا دمج صدّر الإعدادات لبيئة CLI.
نموذج مفقود أو اتصال مرفوض
لـ Ollama تأكد من الخادم ووجود النموذج في ollama list. للسحابة افحص نقطة الاتصال والأهلية وHTTPS والرمز والحصة؛ لا تشارك سجلات برموز.
المستودع أو القناة غير متاح
افحص المعمارية والإصدار/المستودع المنشور. النشر قد يتأخر؛ لا تعطّل التوقيع للتجاوز.
فشل إعداد أدوات Python
ثبّت Python مع venv/ensurepip واسمح بتنزيل الاعتماديات ثم أعد ash install. يبقى ash الأساسي صالحًا بلا الأدوات.
