Résumé

ash [text ...]
ash install [--shell bash|zsh] [--dry-run] [--overwrite]
ash mcp add <url> [--no-browser]
ash snooze [duration|off]
ash update [--version vX.Y.Z] [--yes|--skip-customized]

Description

ash envoie un texte d'invite au point de terminaison IA configuré et imprime la réponse de l'assistant. Lorsqu'aucun texte de position n'est fourni, ash lit le texte d'invite à partir d'une entrée standard non interactive.

La sous-commande install ajoute un bloc d'intégration géré aux fichiers de démarrage du shell. Bash utilise ~/.bashrc et zsh utilise ~/.zshrc.

Les connexions au fournisseur d'IA sont partagées via un courtier local. L’échec du courtier revient au HTTPS direct.

L'IA peut utiliser systemd pour planifier des tâches en arrière-plan. Il peut s’agir de tâches récurrentes ou ponctuelles. Les tâches planifiées utilisent HTTPS direct par défaut.

ash maintient un espace de travail de travail à l'échelle de la session sous ~/.ash/scratch/<session-id>/. Les répertoires de travail obsolètes et inactifs sont automatiquement supprimés après la fenêtre de rétention configurée. Les journaux d'historique sont stockés sous ~/.ash/history/. Les anciens fichiers d'historique sont automatiquement nettoyés conformément à la politique de conservation.

Les sorties des outils, scripts, fichiers, canalisations et enfants ne sont pas des données fiables et ne doivent pas remplacer les instructions du système ou de l'utilisateur. La fonctionnalité d'exécution d'outil n'est pas un bac à sable lorsque l'exécution arbitraire de Python ou de shell est activée. Par défaut, Python est activé, alors méfiez-vous.

Serveurs MCP distants

Les serveurs MCP (Model Context Protocol) fournissent des outils qu'un modèle d'IA peut appeler. Ash prend en charge les serveurs HTTP MCP streamables distants et conserve leurs sessions client dans ash-broker lors des invocations Ash dans le même shell.

Enregistrez un serveur en ajoutant son URL, par lui-même, à ~/.ash/.ash_allow, ou exécutez ash mcp add <url> à partir d'un serveur interactif. Coque Ash. La commande connecte et enregistre le serveur uniquement après une connexion réussie :

https://mcpplaygroundonline.com/mcp-complex-server

L'autorisation OAuth s'ouvre dans le navigateur de bureau lorsqu'une interface graphique est disponible. Si le navigateur ne peut pas être ouvert, Ash imprime une URL d'autorisation copiable et attend dans le terminal. Utilisez ash mcp add <url> --no-browser pour toujours utiliser ce flux de terminal. L'autorisation manuelle d'URL nécessite toujours un navigateur sur le même hôte ; il ne s'agit pas d'un flux OAuth sans navigateur.

Les lignes d'URL commençant par http:// ou https:// sont des enregistrements MCP, pas des commandes shell. Les schémas sont reconnus sans tenir compte de la casse. Ash dérive le nom local du serveur à partir des 8 premiers caractères hexadécimaux minuscules de SHA-256 sur le texte de l'URL découpé. HTTPS est requis sauf pour le développement localhost ; Les URL contenant des informations d'identification intégrées, des chaînes de requête ou des fragments sont rejetées. Pour les connexions OAuth directes, la découverte autorise les adresses IP non publiques uniquement pour l'autorité MCP enregistrée exacte ; les autres hôtes OAuth restent soumis au blocage des adresses non publiques. Un proxy de sortie configuré est chargé de filtrer ses adresses de destination. Les modifications sont lues lors de la prochaine requête Ash.

Les enregistrements MCP restent activés avec ASH_STRICT=1. Les résultats de l'outil renvoyés sont toujours traités comme des preuves non fiables. Enregistrez uniquement les serveurs en qui vous avez confiance : leurs outils peuvent effectuer des actions en votre nom. Pour les serveurs protégés par OAuth, Ash ouvre le navigateur lorsqu'une interface graphique est disponible pendant que le courtier gère le rappel et les jetons. Les informations d'identification utilisent le gestionnaire d'informations d'identification du système d'exploitation lorsqu'il est disponible, ou un fichier crypté protégé par un ASH_MCP_CREDENTIAL_KEY aléatoire de 32 octets fourni par l'utilisateur. Les fichiers ~/.ash/mcp.json existants ne sont plus lus ; déplacez les URL du serveur dans .ash_allow.

Si l'initialisation MCP échoue, Ash continue la requête sans outils MCP distants. Les exécutions interactives impriment un avertissement ; les exécutions non interactives échouent silencieusement. Les tâches planifiées ne disposent pas du courtier per-interactive-shell et ne peuvent donc pas utiliser les outils MCP distants. Une invite planifiée qui dépend de MCP peut toujours s'exécuter mais peut se terminer sans l'action ou les données MCP demandées. Ne planifiez pas d'invites nécessitant MCP.

Consultez la FAQ MCP pour un aperçu rapide et des notes de configuration.

Commandes

ash [--attach path]... [text ...]
Exécuter une seule requête d'assistant. --attach joint un fichier (image ou document) à la demande ; reproductible. Taille limitée par ASH_ATTACHMENT_MAX_BYTES et actuellement envoyé sur le réseau uniquement aux fournisseurs compatibles OpenAI.
ash mcp add <url> [--no-browser]
Connectez et enregistrez un serveur MCP distant dans le .ash_allow effectif. Ouvre l'autorisation OAuth dans un navigateur de bureau lorsqu'elle est disponible ; revient à une URL copiable dans le terminal. --no-browser utilise toujours le flux du terminal.
ash install [--shell bash|zsh] [--dry-run]
Installer ou mettre à jour l'intégration du shell. Lorsque --shell est omis, le shell actuel est utilisé lorsque cela est possible. --dry-run prévisualise les modifications sans écrire. Lorsqu'elle est interactive, l'installation configure également automatiquement AI_ENDPOINT, AI_MODEL et AI_AUTH_TOKEN : elle préfère une clé API de fournisseur de cloud déjà définie (OpenAI, Anthropic, Google Gemini, Azure OpenAI, Mistral, Cohere, Groq, xAI, DeepSeek, Together AI, OpenRouter ou HuggingFace), puis un serveur d'inférence local en cours d'exécution. (Ollama, LM Studio, llama.cpp/MLX/LocalAI, vLLM, text-generation-webui, Jan ou GPT4All), et autrement vous invite avec un menu de fournisseur numéroté. Le modèle est choisi dans la liste des modèles du point de terminaison lorsqu'il est disponible.
ash snooze [duration|off]
Suspendre le traitement automatique des invites du shell. La valeur par défaut est de cinq minutes. Les durées utilisent la syntaxe Go telle que 30s, 5m ou 1h. Utilisez off pour reprendre immédiatement.
ash update [--version vX.Y.Z] [--yes|--skip-customized]
Téléchargez et installez la dernière version stable de macOS, Linux ou FreeBSD pour l'architecture actuelle dans ~/.local/bin/ash. Les versions nécessitent une vérification Sigstore et une vérification SHA-256.

Environnement

AI_AUTH_TOKEN
Jeton de porteur facultatif. Lorsqu'il est défini, il est envoyé comme authentification du porteur et est requis pour les points de terminaison du cloud. Les adresses privées/LAN (RFC1918 IPv4, IPv6 ULA) et les noms d'hôtes mDNS .local sont traités comme des noms d'hôtes non cloud (comme localhost) à moins que ASH_STRICT=1 ne soit défini.
AI_CACHE
Bascule facultative du cache natif du fournisseur. Activé par défaut lorsqu'il est pris en charge ; utilisez off ou false pour désactiver.
AI_ENDPOINT
URL de base requise pour le point de terminaison de l'API de chat.
AI_MODEL
Nom du modèle requis envoyé au point de terminaison.
AI_PROVIDER
Remplacement facultatif du fournisseur : anthropic, bedrock, cohere, gemini, google, ollama ou openai. Lorsqu'il n'est pas défini, ash détecte le fournisseur à partir du point de terminaison.
AI_TIMEOUT
Délai d'expiration de la demande facultatif. Par défaut : 3m.
ASH_ALWAYS_OPENAI_API
Bascule de test facultative. Lorsqu'il est vrai, achemine le fournisseur ollama via l'adaptateur SDK compatible OpenAI au lieu de son implémentation manuelle. Par défaut : activé.
ASH_ATTACHMENT_MAX_BYTES
Taille maximale facultative en octets pour un fichier transmis via --attach. Par défaut : 10485760 (10 Mio).
ASH_HISTORY_MAX
Messages d'historique maximum facultatifs par clé. Par défaut : 40.
ASH_LOG_FILE
Chemin du journal de débogage facultatif lorsque la journalisation détaillée est activée.
ASH_LOG_MAX_BYTES
Taille maximale facultative du journal avant la rotation. Par défaut : 1048576.
ASH_MAX_AGENTS
Sous-agents maximum facultatifs générés par un processus parent. Par défaut : 6.
ASH_MAX_TOOL_ITERS
Itérations de boucle d'appel d'outil IA maximales facultatives. Par défaut : 16.
ASH_RELEVANCE_WINDOW
Observations récentes facultatives de l'outil incluses dans l'état d'exécution. Par défaut : 4.
ASH_RETRY_BASE_DELAY
Délai de base d'attente de nouvelle tentative facultatif. Par défaut : 250ms.
ASH_RETRY_MAX_ATTEMPTS
Tentatives de requête facultatives réessayables. Par défaut : 3.
ASH_SCHEDULED_TASK
Drapeau du planificateur interne utilisé par les invocations gérées par ash.
ASH_STREAM
Bascule facultative. Lorsqu'il est vrai, diffuse la réponse des fournisseurs dont l'adaptateur la prend en charge (actuellement OpenAI uniquement). Par défaut : activé.
ASH_TASK_MAX
Limitation facultative des tâches d'exécution dérivées d'une requête. Par défaut : 6.
ASH_TASK_STALL_ROUNDS
L'assistant facultatif décroche les tours avant de s'arrêter. Par défaut : 2.
ASH_ALLOW
Liste autorisée facultative d'exécutables séparés par des virgules pour run_unix_command. Sinon, ~/.ash/.ash_allow est utilisé lorsqu'il est présent ; ce remplacement n'étend pas les jetons Ash internes.
ASH_DENY
Liste de refus facultative séparée par des virgules pour bloquer explicitement les commandes, les outils et les plugins. Sinon, ~/.ash/.ash_deny est utilisé lorsqu'il est présent.
ASH_TOOL_OUTPUT_MAX
Sortie maximale facultative de l'outil capturé en octets. Par défaut : 8192.
ASH_TOOL_TIMEOUT
Délai d'expiration facultatif de la commande d'outil local. Par défaut : 15s.
ASH_VERBOSE
Tableau de bord facultatif de journalisation et d'exécution du débogage. Des valeurs telles que 1, true, on et debug l'activent.
SESSION_ID
Identifiant de session pour l'historique persistant et la dénomination des journaux. Généré automatiquement pour les exécutions interactives en cas d'absence.

Fichiers

  • ~/.ash/.ash_system — invite système canonique. $TOOLS_DIR_LIST, $PLUGINS_DIR_LIST et $IF_PYTHON_AVAILABLE sont des substitutions internes de Ash, jamais des variables d'environnement.
  • ~/.ash/.ash_allow — liste blanche de commandes, d'outils et de plugins canoniques. Ses directives autonomes $TOOLS_DIR_LIST et $PLUGINS_DIR_LIST autorisent les scripts gérés réguliers et les plugins natifs ; remplacer par des noms littéraux pour une politique restrictive.
  • ~/.ash/.ash_deny — fichier de liste de refus canonique pour bloquer des commandes, des outils ou des plugins spécifiques.
  • ~/.ash/plugins/ — répertoire de plugins binaires natifs.
  • ~/.ash/history/ — fichiers d'historique de conversation.
  • ~/.ash/scratch/ — scratch à l'échelle de la session fichiers.
  • ~/.ash/.ash_snooze_until — expiration automatique de la répétition de l'invite.

Statut de sortie

ash renvoie 0 en cas de succès. Il renvoie une valeur différente de zéro lorsque la configuration, les requêtes réseau ou l'exécution de l'outil échouent.

Exemples

echo "summarize this directory" | ash
ash install --shell bash
ash install --shell zsh --dry-run
