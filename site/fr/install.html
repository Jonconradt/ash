Avant de commencer

  1. Un système et un shell pris en charge : macOS ou Linux sur amd64/x86_64 ou arm64/aarch64, ou FreeBSD sur amd64. Utilisez Bash, zsh ou Fish. Les packages Arch sont uniquement x86_64. Il n'existe pas d'installateur natif Windows/PowerShell.
  2. Accès au téléchargement : une connexion Internet fonctionnelle et un accès HTTPS fiable à GitHub, au référentiel de packages sélectionné et à votre fournisseur de modèles. L'inférence locale nécessite toujours un téléchargement initial du modèle.
  3. Autorisations : un répertoire personnel accessible en écriture pour les ressources de chaque utilisateur. Les packages système Linux et macOS .pkg nécessitent un accès administrateur ; exécutez Homebrew et ash install en tant qu'utilisateur normal.
  4. Un modèle : soit un serveur d'inférence local avec un modèle téléchargé, soit un compte cloud/une clé API. Choisissez un modèle qui prend en charge l’appel d’outils, et non un modèle image/audio uniquement. Les besoins locaux en RAM, disque et GPU dépendent de ce modèle.

Les packages ash prédéfinis ne nécessitent pas d'outils de build Go, Rust, Node.js ou Xcode. Un gestionnaire de packages peut avoir ses propres prérequis ; suivez d'abord ses instructions de configuration officielles.

Facultatif : outils Python fournis

Basiqueashl'utilisation ne nécessite pas Python. Les outils Python fournis nécessitent Python 3 avecvenvetensurepip, ainsi qu'un accès pour télécharger leurs dépendances. Sur Debian/Ubuntu, installezpython3etpython3-venv; Homebrew Python inclut le support venv. Sur FreeBSD, utilisez le package pip correspondant à votre version de Python. Puis relancezash install. Le programme d'installation crée un environnement isolé sous$XDG_DATA_HOME/ash/venv(défaut~/.local/share/ash/venv); un échec désactive ces outils, pas de baseash.

macOS

Recommandé : Homebrew

Prérequis :Homebrew, son environnement macOS pris en charge et un système fonctionnelbrewcommande. Le robinet sélectionne automatiquement l'archive Intel ou Apple Silicon. Homebrew 6 ne fait pas implicitement confiance à ce robinet tiers. Si Homebrew refuse de charger la formule comme étant non fiable, vérifiez l'éditeur et la formule, puis faites confiance uniquement à cette formule (pas à l'intégralité du robinet) :

brew trust --formula jonconradt/ash/ash
brew install Jonconradt/ash/ash
ash version

Homebrew se souvient de cette décision de confiance locale. Le robinet ne peut pas activer la confiance en votre nom ; faire confiance à tout le robinet avecbrew trust jonconradt/ashest plus large et permet également de charger ses autres formules. Pour faire plutôt confiance à Beta ou Nightly, utilisez le nom de la formule correspondante,jonconradt/ash/ash-betaoujonconradt/ash/ash-nightly. Homebrew possède les binaires, les plugins natifs fournis, les pages de manuel et les avis de licence dans son préfixe (normalement/opt/homebrewsur Apple Silicon ou/usr/localsur Intel). Il vérifie l'archive par rapport à la somme de contrôle SHA-256 de la formule. Il ne configure pas votre fournisseur et ne modifie pas votre fichier de démarrage shell : continuez versinitialisation par utilisateur. Utiliserbrew upgrade ashpour les mises à jour etbrew uninstall ashpour supprimer Release ; voirformules de canalpour la version bêta/nuit.

Alternative : .pkg natif

Téléchargez ledarwin-arm64.pkgactif pour Apple Silicon oudarwin-amd64.pkgpour Intel d'unversion publiée.Vérifier son manifeste de somme de contrôle signéavant d'ouvrir le programme d'installation. L'accès administrateur est requis.

Le package macOS n'est ni signé ni notarié. Le manifeste de version fournit une vérification distincte de l'éditeur/de la somme de contrôle, et non une notarisation Apple. Ne désactivez pas Gatekeeper et ne contournez pas un avertissement de sécurité simplement pour installer ash ; préférez Homebrew si votre politique de sécurité l'exige.

Le paquet écritashetash-brokerà/usr/local/bin, des plugins pour/usr/local/lib/ash/plugins, pages de manuel vers/usr/local/share/man, et des avis à/usr/local/share/licenses/ash. Le reçu estdev.ash.cli. Il n'exécute pas d'initialisation par utilisateur et ne s'abonne pas aux mises à jour :initialiseraprès l'installation, remplacez-le par un fichier .pkg plus récent et vérifié à mettre à jour et utilisez leprocédure de suppression manuelleà désinstaller. Ne l'installez pas sur une copie appartenant à Homebrew.

Debian et Ubuntu : APT

Prérequis : amd64 ou arm64, accès administrateur, APT,curl,gpget les certificats CA. Installez les outils de téléchargement/clés manquants à l'aide de votre distribution avant d'ajouter le référentiel. La version est nomméestable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Avant d'importer une clé de référentiel, vérifiez son empreinte digitale par rapport à une source d'éditeur fiable. L'empreinte digitale de la clé VersionX est32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. APT vérifie les métadonnées signées du référentiel et les résumés de packages qu'il contient ; la clé est limitée àsigned-by. Mettre à jour avecsudo apt update && sudo apt upgrade ash; supprimer avecsudo apt remove ash.

Systèmes compatibles Fedora et RHEL : DNF

Prérequis : x86_64 ou aarch64, accès administrateur, DNF/RPM,curl,gpget les certificats CA. Installez les outils manquants de votre distribution. Inspectez la clé et comparez l’empreinte digitale ci-dessus avant de l’importer :

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

Les fichiers RPM ne sont pas signés individuellement.repo_gpgcheck=1vérifie les métadonnées du référentiel couvrant leurs sommes de contrôle ;gpgcheck=0reflète les signatures absentes par package, et non la vérification du référentiel désactivée. Si votre politique nécessite des charges utiles RPM signées, ce référentiel ne la respecte pas. Mettre à jour avecsudo dnf upgrade ash; supprimer avecsudo dnf remove ash.

Arch Linux : Pacman

Prérequis : x86_64, accès administrateur, Pacman avec son trousseau initialisé,curl, etgpg. Vérifiez que l'empreinte digitale de la clé affichée correspond à celle ci-dessus avant de lui faire confiance. Ajoutez le référentiel une fois, pas à chaque mise à jour :

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman vérifie les signatures des packages et de la base de données. Gardez Arch synchronisé avecsudo pacman -Syu, pas une mise à niveau partielle ; retirerashavecsudo pacman -R ash.

Initialisez et vérifiez

Après avoir installé les binaires, exécutez l'installation de manière interactive en tant qu'utilisateur normal. Si vous ne souhaitez pas d'intégration shell, vous pouvez installer uniquement Ash. Ce n'est probablement pas ce que vous voulez. La vraie valeur de ash est l'intégration shell ci-dessous. La configuration des ressources uniquement laisse vos fichiers de démarrage inchangés :

ash install

L'installation que vous souhaiterez probablement utiliser implique une intégration shell. Cela modifiera votre .bashrc (ou l'équivalent pour votre shell) pour inclure Ash. Pour activer l'intégration des commandes introuvables, choisissez exactement une commande pour le shell que vous utilisez :

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Poisson

ash install --shell fish --shell-integration

Bash utilise~/.bashrc, zsh utilise~/.zshrc, et le poisson utilise$XDG_CONFIG_HOME/fish/config.fish(défaut~/.config/fish/config.fish). Ouvrez ensuite un nouveau shell ; les shells existants conservent leur courtier en cours d'exécution. Préfixes d'intégration~/.local/binvers PATH : supprimez une ancienne copie locale de l'utilisateur avant de vous attendre à ce qu'un package système soit sélectionné.

Si les paramètres du fournisseur sont manquants, le programme d'installation détecte les clés de fournisseur existantes ou un serveur local en cours d'exécution ; sinon, il propose un menu de fournisseur et demande des informations d'identification. Choisissez un modèle disponible compatible avec les outils. Les paramètres valides existants sont conservés, donc la réexécution de l’installation n’est pas une commande de changement de fournisseur.

Les paramètres sont stockés dans$XDG_CONFIG_HOME/ash/.ash_env(défaut~/.config/ash/.ash_env, autorisations de fichiers privés). L'intégration gérée les charge. Sans intégration, les utilisateurs de Bash/zsh peuvent rechercher ce fichier dans leur configuration de démarrage normale ; Les utilisateurs de poissons doivent définir le paramètre correspondantASH_AI_*variables utilisant la syntaxe Fish, et non la source du fichier au format Bash. Protégez tout fichier contenant des jetons et ne le validez jamais.

Pour une installation utilisateur locale sans intégration, ajoutez son répertoire réel à PATH. Bash/zsh :export PATH="$HOME/.local/bin:$PATH". Poisson:fish_add_path "$HOME/.local/bin". Conservez cela en utilisant la configuration de démarrage de votre shell ; remplacez votre répertoire d'installation personnalisé le cas échéant.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

Les premières commandes devraient résoudre l'installation que vous avez choisie. L'invite nécessite un serveur en cours d'exécution ou des informations d'identification cloud valides ; l'installation de ash n'installe pas de modèle.

Ollama local : aucun compte cloud requis

Vous n'avez pas besoin d'avoir une IA locale pour l'utiliserash. Toutefois, si vous souhaitez exécuter des modèles localement sans recourir à un fournisseur de cloud, vous pouvez configurer un serveur Ollama local.

Ollama propose également un service cloud pour exécuter des modèles à distance, mais cela n'est pas requis pour une utilisation locale avecash. Le serveur cloud comprend un niveau gratuit et le modèle cloud Gemma 4 31b de Google (gemma4-31b:nuage) fonctionne très bien avecash. Il s'agit du modèle utilisé par le projet pour générer des notes de version et effectuer des tâches de développement.

Installez Ollama en utilisant soninstructions officielles du système d'exploitation. Téléchargez un modèle compatible avec les outils et adapté à votre matériel ;llama3.1:8best un exemple et non une exigence minimale. Vérifiez lecatalogue d'outils actuelpour les alternatives :

En l'absence de clé cloud déjà définie, le programme d'installation peut détecter le serveur local et proposer le modèle téléchargé. Si un autre fournisseur est déjà configuré, modifiez manuellement le point de terminaison/modèle. Exemple Bash/zsh :

Gardez le serveur en boucle, sauf si vous sécurisez délibérément l'accès ; un serveur distant reçoit vos invites et les résultats de l'outil.

Installation de script : une alternative, pas le premier choix

Préférez Homebrew, APT, DNF ou Pacman : ils suivent les fichiers détenus, vérifient les téléchargements à l'aide de leur configuration de confiance et fournissent des mises à jour/suppressions familières. Ils nécessitent toujours des éditeurs de confiance et des actions d'installation de packages.

Un script de site Web exécute du code avec les autorisations de votre compte. Un site Web, un éditeur ou un script modifié compromis peut lire des secrets, modifier des fichiers ou installer d'autres logiciels. HTTPS protège le transport, pas les intentions de ce code. Le transfert d'une URL directement vers un shell l'exécute avant que vous puissiez la consulter. Les vérifications de signature d'archive du script n'authentifient pas le script lui-même. Ne l'exécutez jamais avec sudo et ne désactivez jamais sa vérification.

Prérequis : un OS/architecture supporté,$SHELLidentifier Bash/zsh/Fish,Cosignature Sigstore,tar,uname,install, des utilitaires shell standard, une commande SHA-256 (sha256sum,shasum, ousha256), et un téléchargeur (curl,wget, ou Python). L'exemple utilise curl. FreeBSD a également besoin de Bash. Votre répertoire home/installation doit être accessible en écriture.

Téléchargez dans un fichier local, inspectez-le avec un éditeur et exécutez-le uniquement si vous faites confiance à sa source et à son comportement. L'inspection n'est pas une garantie de sécurité ; n'exécutez pas ces étapes aveuglément :

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

Après inspection, exécutez la copie enregistrée en tant qu'utilisateur normal :

sh ./ash-install.sh
rm ./ash-install.sh

install.shtélécharge la dernière version, vérifie son manifeste de somme de contrôle et son résumé d'archive signés Sigstore, et installeash/ash-brokerdans~/.local/bin. Les plugins natifs disparaissent$XDG_DATA_HOME/ash/plugins. Il exécute la configuration par utilisateur et demande avant d'activer l'intégration du shell. Sans terminal interactif, les invites du fournisseur/intégration peuvent être ignorées : exécuterash installde manière interactive par la suite.

Vous pouvez définirASH_INSTALL_DIRavant d'exécuter le script pour choisir une autre destination. Ajoutez vous-même cette destination à PATH.La mise à jour automatique est prise en charge uniquement sous~/.local/bin; les destinations personnalisées nécessitent un remplacement manuel. Le script n'a pas de sélecteur Beta/Nightly.

Vérifier un package direct ou une archive

Prérequis : cosignature et un utilitaire SHA-256. À partir de la même version publiée, téléchargez votre package/archive,SHA256SUMS, etSHA256SUMS.sigstore.json. Travaillez dans un nouveau répertoire. RemplacervX.Y.Zavec la balise exacte, y compris un suffixe de préversion le cas échéant :

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Seulement après que cela réussisse, calculez le résumé de votre fichier avecshasum -a 256 PACKAGEsur macOS,sha256sum PACKAGEsous Linux, ousha256 -q PACKAGEsur FreeBSD. RemplacerPACKAGEavec le nom de fichier téléchargé et comparez-le exactement avec l'entrée de ce nom de fichier dans le manifeste vérifié. Arrêtez-vous sur une entrée manquante ou toute incohérence. Une somme de contrôle non signée téléchargée à côté d'un fichier n'est pas équivalente aux métadonnées vérifiées de l'éditeur.

Mises à jour et les trois chaînes

  • Sortie (recommandée) :versions publiées stables telles quevX.Y.Z; la configuration du référentiel appelle cecistable.
  • Bêta:tests préliminaires, taguévX.Y.Z-beta.N; attendez-vous à des changements et des régressions.
  • Chaque nuit:modifications récentes de la branche par défaut, étiquetéesvX.Y.Z-nightly.YYYYMMDD.N; le risque de régression le plus élevé. Les builds sont planifiées mais peuvent être ignorées lorsque rien ne change ou que la publication échoue.

Une version publiée met à jour la formule Homebrew correspondante ou le référentiel Linux signé. Vous le recevez lorsque vous exécutez la commande de mise à niveau du gestionnaire propriétaire (ou votre propre politique de mise à jour du système d'exploitation le fait). La publication, les mises à jour du référentiel et le déploiement du site Web peuvent être en retard ; vérifiez la disponibilité avant de changer de chaîne. ash n'installe pas silencieusement les mises à jour binaires en arrière-plan.

Pour une nouvelle installation bêta/nuit, utilisez le nom complet de la formule correspondante ci-dessus dans brew install. Lors du changement, désinstallez d'abord la formule actuellement installée : toutes les trois fournissent les mêmes binaires. Exemple de version bêta :

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

Utiliserash-nightlypour la nuit ouashpour Release dans les commandes d’installation/mise à niveau. Désinstallez la formule actuelle de l'ancienne chaîne, pas toujoursash. Les paramètres utilisateur sont conservés ; ouvrez un nouveau shell après le changement.

Pacman :utiliser leConfiguration de Pacmanavec l'URL du serveur sélectionné. Conserver le nom de la section[versionx]: chaque chaîne publie une base de données nomméeversionx.db. Modifiez le serveur dans cette section plutôt que d'ajouter une base de données nommée différemment. Pour changer, y compris un déclassement :

sudo pacman -Syuu ash

Examinez la transaction proposée : le retour à Release peut rétrograder ash, et le double de Pacman u peut également rétrograder d'autres packages. Sauvegardez la configuration avant de changer. Ensuite, utilisez les commandes de mise à niveau APT/DNF/Pacman normales à partir des sections du système d'exploitation ; ne laissez pas plusieurs sources de canaux ash activées.

Désinstaller sans supprimer les fichiers sans rapport

1. Désactivez d'abord l'intégration du shell

Avant de supprimer les binaires, exécutez la commande pour chaque shell sur lequel vous avez activé l'intégration :

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Poisson

ash install --shell fish --disable-shell-integration

Siashest déjà manquant, modifiez le fichier de démarrage correspondant à partir deinitialisationet supprimez uniquement le bloc entre# >>> ash install >>>et# <<< ash install <<<. Supprimez toutash-lignes PATH/environnement spécifiques que vous avez ajoutées manuellement, et non sans rapport avec la configuration du shell. Fermerash- a ensuite activé les shells afin que leurs courtiers appartenant à des shells quittent.

2. Laissez le gestionnaire de packages propriétaire supprimer ses fichiers

Homebrew (version)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

Choisissez uniquement votre méthode d'installation ; pour Homebrew Beta/utilisation nocturneash-beta/ash-nightly. APT/DNF/Pacman supprime les binaires, plugins et pages de manuel appartenant au package, et non la configuration/l'historique de votre répertoire personnel. Ne supprimez pas manuellement les fichiers appartenant au package.

Nettoyage du référentiel facultatif : supprimez leashfichier source/etc/apt/sources.list.d/versionx.listet son dédié/etc/apt/keyrings/versionx-keyring.gpg, ou leashfichier de référentiel/etc/yum.repos.d/versionx.repo, ou leash [versionx]section de/etc/pacman.conf. Vérifiez d’abord qu’aucun autre package ne les utilise. Supprimez une clé de confiance RPM/Pacman importée uniquement après avoir confirmé son empreinte digitale et que rien d'autre ne dépend d'elle ; ne supprimez jamais le trousseau partagé d’une distribution.

3a. Suppression manuelle de macOS .pkg

Le programme d'installation de macOS enregistre un reçu mais n'en a aucunashprogramme de désinstallation. Confirmez qu'il s'agit d'une installation .pkg, et non d'Homebrew, et inspectez sa charge utile exacte :

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

En utilisant ce reçu comme inventaire, supprimez uniquement sonash-fichiers appartenant :/usr/local/bin/ash,/usr/local/bin/ash-broker, les fichiers dans/usr/local/lib/ash/plugins,/usr/local/share/man/man1/ash.1, la liste localiséeash.1pages et avis dans/usr/local/share/licenses/ash. Des privilèges d'administrateur sont nécessaires. Vérifiez la propriété si un autre installateur a ensuite remplacé ces fichiers ; ne supprimez pas sa copie. Supprimer videash-uniquement les répertoires, non partagés/usr/local,bin, ou des répertoires man.

Après avoir supprimé la charge utile, supprimez éventuellement le reçu :

sudo pkgutil --forget dev.ash.cli

Oublier un reçu ne supprime aucun fichier installé.Conservez-le jusqu'à ce que vous ayez fini de vérifier la charge utile.

4. Facultatif : effacez les paramètres locaux, les outils et l'historique

Sauvegardez tout ce que vous souhaitez conserver. Cette étape distincte peut effacer les paramètres/jetons du fournisseur, les outils/plugins personnalisés, l'historique des conversations et les fichiers de travail. La désinstallation des fichiers binaires n'implique pas le consentement à leur effacement.

  • Configuration:$XDG_CONFIG_HOME/ash, défaut~/.config/ash.
  • Données, plugins et environnement Python :$XDG_DATA_HOME/ash, défaut~/.local/share/ash.
  • Histoire et état :$XDG_STATE_HOME/ash, défaut~/.local/state/ash.
  • Cache :$XDG_CACHE_HOME/ash, défaut~/.cache/ash.
  • Durée d'exécution du courtier :$XDG_RUNTIME_DIR/ash, ou$XDG_STATE_HOME/ash/runtimelorsqu'aucune racine d'exécution n'est disponible.

Inspectez vos remplacements XDG absolus réels avant de supprimer uniquement ces sous-répertoires ash ; ne supprimez jamais une racine XDG ou votre répertoire personnel. Une fois tous les shells compatibles ash fermés, supprimez les fichiers d'exécution ash restants si nécessaire. Les informations d'identification MCP OAuth peuvent également rester dans le gestionnaire d'informations d'identification du système d'exploitation : supprimez-y les entrées spécifiques à ash et révoquez l'accès au fournisseur MCP. Révoquer les clés AI inutilisées dans leurs comptes fournisseurs ; la suppression d'un fichier local ne révoque pas une clé. Ne désinstallez pas Ollama/models, Python ou les dépendances partagées dans le cadre de la suppression de ash.

Dépannage rapide

Commande introuvable ou mauvaise version
Vérifiez CHEMIN etcommand -v ash/command -v ash-broker. Un vieux~/.local/binla copie peut observer un package. Utilisez un propriétaire/canal à la fois et ouvrez un nouveau shell.
Le menu du fournisseur n'apparaît pas
Courirash installdepuis une borne interactive. Les paramètres valides existants sont conservés ; utiliserconfiguration manuellepour changer de fournisseur. Sans intégration, assurez-vous que les paramètres sont exportés dans l'environnement de la CLI.
Aucun modèle ni connexion refusé
Pour Ollama, confirmez que son serveur est en cours d'exécution etollama listcomprend le modèle choisi. Pour les services cloud, vérifiez le point de terminaison, l'éligibilité du modèle, HTTPS, le jeton et le quota de compte ; ne partagez jamais de journaux contenant des jetons.
Dépôt ou canal indisponible
Vérifiez l'architecture et la version/référentiel publié. La publication peut prendre du retard ; ne désactivez pas la vérification de signature pour contourner un référentiel indisponible.
La configuration de l'outil Python a échoué
Installez Python avec venv/ensurepip et autorisez les téléchargements de dépendances, puis réexécutezash install. Basiqueashreste utilisable sans ces outils.
