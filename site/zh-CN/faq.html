入门

使用 ash 之前我需要什么？

你需要ash可执行文件、AI 端点和模型名称。跑步ash install自动配置这些：它使用已设置的云提供商 API 密钥或找到时正在运行的本地推理服务器，否则它会显示编号的提供商菜单并提示输入 API 密钥，然后让您从端点的模型列表中选择模型。您还可以设置AI_ENDPOINT和AI_MODEL手动。本地端点（例如 Ollama）可以使用http://localhost:11434，以及 LAN 主机，例如http://brain.local:11434或者私有 IP 也被视为本地 IP（除非ASH_STRICT=1）；云端点必须使用 HTTPS，并且还要求AI_AUTH_TOKEN。 Shell 集成是可选的：您可以随时运行ash "your question"直接地。

ash 安装在哪里，如何检查我的 shell 是否可以找到它？

经过验证的安装程序将 ash 放入~/.local/bin/ash， 和ash install将该目录添加到您的PATH通过托管的~/.ash/.ash_env文件。打开一个新终端，然后运行command -v ash确认。自更新程序将其替换二进制文件安装到相同的~/.local/bin/ash地点。

如何在不更改 shell 的情况下使用 ash？

直接传递引用的提示：ash "how do I find large files?"。如果没有参数，ash 也接受非交互式标准输入提示，例如git diff | ash。当您学习 ash 或编写脚本时，直接使用是最不令人惊讶的选择。

为什么ash说我的AI配置不完整？

检查一下AI_ENDPOINT和AI_MODEL在 ash 运行的环境中非空。对于云主机名，还设置AI_AUTH_TOKEN。跑步printf '%s\n' "$AI_ENDPOINT" "$AI_MODEL"确认前两个值存在，但不将身份验证令牌打印到终端记录或共享日志中。

安装和更新

ash 在 Windows 11 上运行吗？

不是原生的。 ash 支持 macOS、Linux 和 FreeBSD 上的 bash、zsh 和 Fish；没有 PowerShell 安装目标。使用 WSL 获得受支持的 Linux 体验。

如何在适用于 Linux 的 Windows 子系统 (WSL) 中安装 ash？

将其作为 Linux 安装在 WSL 发行版中：curl -fsSL https://jonconradt.github.io/ash/install.sh | sh。然后配置AI_ENDPOINT和AI_MODEL，然后运行ash install对于在 WSL 内运行的 shell。

如何将 ash 更新到最新发布版本？

跑步ash update在 macOS、Linux 或 FreeBSD 上。它下载最新的稳定匹配存档，使用其 Sigstore 捆绑包和 SHA-256 摘要验证发布清单，然后安装到~/.local/bin/ash。如果签名验证失败或者存档包含不支持的条目，则需要交互式确认；除非您独立信任发布源，否则不要批准失败的签名。跳过不支持的有效负载，非交互式运行拒绝这些异常。使用ash update --version vX.Y.Z对于特定版本；使用--yes仅当您想要替换自定义托管文件时。

我跑了ash install。为什么这个终端没有任何变化？

安装更新启动文件；它不会重写已经运行的 shell 进程。打开一个新终端，或为您的 shell 重新加载文件：source ~/.bashrc对于巴什来说，source ~/.zshrc对于 zsh，或者source ~/.config/fish/config.fish对于鱼，除非您使用自定义XDG_CONFIG_HOME。

未知命令仍然显示“未找到”。如何解决 shell 集成问题？

第一次运行command -v ash;包装器无法调用 shell 找不到的二进制文件。然后重新加载或重新启动 shell 并检查其启动文件是否包含>>> ash install >>>管理块。终于跑了ash snooze off，因为暂停会故意将未知命令留下为正常的“未找到”失败。

文件有什么作用ash install更改，我可以预览吗？

它在选定的 shell 启动文件中添加或更新一个标记为 ash 的块，并管理下面的文件~/.ash，包括配置、包装器和捆绑工具。跑步ash install --shell bash --dry-run预览启动文件更改而不写入它。重新运行安装是幂等的；使用--overwrite仅当您想要刷新托管引导程序文件时。

ash支持鱼吗？

是的。跑步ash install --shell fish。 ash 添加一个托管块到$XDG_CONFIG_HOME/fish/config.fish， 或者~/.config/fish/config.fish当 XDG_CONFIG_HOME 未设置时。鱼类用途fish_command_not_found，因此未解析的命令及其原始参数到达 ash。

为什么不小写test和type在鱼？

Fish 将这些小写名称保留为基本内置函数，并且不允许函数替换它们。使用Test ...或者Type ...表达 ash 意图，或调用ash "..."直接地。其他兼容的碰撞包装器仍然可用。

ksh93呢？

shell 集成不支持 ksh93。它是FPATH行为只能加载以未知命令命名的文件；它没有可以安全地实现 ash 提示路由或代理生命周期的通用命令未找到回调。

人工智能与连接

ash 包含 AI 吗？

否。ash 是您配置的 AI 端点的客户端。放AI_ENDPOINT和AI_MODEL; ash 支持本地 Ollama 和其他本地 OpenAI 兼容服务器（LM Studio、llama.cpp、MLX、LocalAI、vLLM、text- Generation-webui、Jan、GPT4All），并从端点检测支持的云提供商适配器，并带有可选的AI_PROVIDER覆盖。

什么是 MCP 服务器？如何添加？

MCP（模型上下文协议）服务器公开 AI 模型可以调用的工具，例如搜索、分析或特定于服务的操作。要添加远程 Streamable HTTP MCP 服务器，请将其 URL 放在单独的行中~/.ash/.ash_allow，然后再次运行ash。例如：https://mcpplaygroundonline.com/mcp-complex-server。 Ash 通过其代理进行连接并向模型提供服务器工具。仅使用您信任的服务器：他们的工具可能代表您执行操作。除本地主机开发服务器外，都需要 HTTPS。现存的~/.ash/mcp.json文件不再被读取；将他们的 URL 移至.ash_allow。如果 MCP 初始化失败，ash 会在没有远程 MCP 工具的情况下继续：它在交互式会话中发出警告，并在非交互式会话中保持静默。

计划作业可以使用 MCP 服务器吗？

不可以。计划作业和其他非交互式作业不会继承交互式 shell 的代理，因此远程 MCP 工具不可用。 Ash 仍然在没有 MCP 工具的情况下运行提示并抑制这种预期的初始化失败。因此，依赖 MCP 的提示可能会在没有请求的数据或操作的情况下完成。不要安排需要 MCP 的提示。

MCP 何时工作ASH_STRICT=1？

是的。 HTTP(S) URL 行显式注册 MCP 服务器，并且不被视为 shell 可执行文件。严格模式不会禁用已配置的 MCP 服务器。它仍然将 Ash 的不受信任输出保护应用于返回的工具内容。

MCP OAuth 如何工作以及凭据存储在哪里？

对于受 OAuth 保护的服务器，当 GUI 可用时，Ash 在桌面浏览器中打开授权页面；如果无法打开浏览器，则会打印 URL 以在同一主机上的浏览器中手动授权。使用ash mcp add <url> --no-browser始终使用终端流。对于直接 OAuth 连接，发现仅允许确切注册的 MCP 机构使用非公共 IP 地址；其他 OAuth 主机仍然受到非公共地址阻止。配置的出口代理负责过滤其目标地址。代理处理回调、令牌交换、刷新和持久 MCP 会话。凭据可用时存储在操作系统凭据管理器中。如果不可用，请使用随机 32 字节配置加密文件后备ASH_MCP_CREDENTIAL_KEY; Ash 从不存储密钥本身。

在哪里可以找到最流行的云 AI 提供商的 AUTH_KEY？

ash调用该值AI_AUTH_TOKEN;它不创建或分发提供商密钥。在您的提供商帐户中创建密钥，例如开放人工智能,人择,谷歌人工智能工作室,Azure 开放人工智能,米斯特拉尔,连贯,格罗克,人工智能,深度搜索,一起人工智能,开放路由器,抱脸， 或者奥拉马，然后将其导出为提供者的环境变量（或AI_AUTH_TOKEN直接地）。ash install自动检测大多数特定于提供程序的环境变量。云端点必须使用 HTTPS 并需要令牌；私有/LAN 地址和.local主机名不被视为云端点，除非ASH_STRICT=1已设置。

ash每次都会打开一个新连接吗？

不适用于正常的交互式 Unix shell 使用。 Bash、zsh 和 Fish 为每个 shell 会话启动一个代理，通过私有 Unix 套接字与其通信，并重用其有限的 HTTP 连接池。经纪商在不活动后退出；计划作业使用直接请求而不是持久的 shell 代理。

Fish 使用经纪人吗？

是的。 Fish 包装器启动并重用与 bash 和 zsh 相同的每会话代理，在 ash 请求之前刷新其租约，并保持代理设置安静。

如果请求速度缓慢、不可用或者我改变了主意，会发生什么情况？

按Ctrl-C取消飞行中的请求。默认AI请求超时时间为三分钟；放AI_TIMEOUT， 例如AI_TIMEOUT=90s，更改它。 ash 默认情况下重试可重试的 AI 故障最多 3 次，并具有短的有界退避；调整该行为ASH_RETRY_MAX_ATTEMPTS,ASH_RETRY_BASE_DELAY， 和ASH_RETRY_MAX_DELAY。

安全与控制

如何锁定 ash 才能更安全，这会产生什么影响？

缩小可执行白名单的范围，支持只读工具，并且不要添加特权或破坏性命令。放ASH_STRICT=1阻止来自不受信任的工具、文件、脚本、管道和子代理输出的已识别提示注入模式。这还可以隐藏类似于注入尝试的合法文本。允许名单是一个执行边界，而不是沙箱：ash，允许的工具仍然可以像您一样运行。

ash 可以运行破坏性命令，例如rm？

不适用于已安装的默认白名单。它明确建议反对rm,mv,dd,chmod,chown,kill， 和sudo。如果您添加其中之一，ash可以在您的权限下请求；仔细审查该决定。

如何更改允许执行的命令ash？

编辑~/.ash/.ash_allow并列出裸露的可执行文件名称，每行一个或以逗号分隔。它是独立的$TOOLS_DIR_LIST和$PLUGINS_DIR_LIST指令允许合格的托管脚本和本机插件；将它们替换为限制性策略的字面名称。合格的脚本和插件是常规文件~/.ash/tools/或者~/.ash/plugins/具有读取和执行位。您还可以通过将命令添加到显式拒绝命令~/.ash/.ash_deny。或者设置ASH_ALLOW或者ASH_DENY到以逗号分隔的列表。更改将在下一个 ash 请求时读取。

ash 在什么用户下运行？

ash 以及每个允许的工具以启动 ash 的用户身份运行。它不会提升特权。所管理的~/.ash工作区经过权限强化，但您的用户和您明确允许的任何进程仍然可以访问其内容。

ash 信任通过管道接收的文本与用户文本相同吗？针对恶意数据有哪些保护措施？

是的。当 ash 未接收到命令行参数并且通过管道传输标准输入时，它将将该输入视为用户提示符。请勿将不受信任的网页、日志或生成的文本直接传送到 ash，除非您打算将其授权为提示。这与 ash 管理的工具、文件、脚本、管道和子代理输出不同：ash 将这些结果标记为不受信任的证据，并指示模型永远不要遵循它们的指令。放ASH_STRICT=1另外替换不可信证据中公认的提示注入短语。白名单和 direct-argv 执行规则仍然适用于工具执行。

我的 ash 文件对这台计算机上的其他用户来说是私有的吗？

在安装过程中，ash 会强化~/.ash将目录授予仅所有者权限，将托管文件授予所有者可读和所有者可写权限。这可以防止正常 Unix 权限下的其他本地帐户，但不能防止您自己的帐户、管理员、备份或您选择运行的具有主目录访问权限的软件。

工具和工作流程

ash 支持管道和其他 Unix 传统吗？

是的。例如，您可以通过管道将文本输入 ash 作为提示git diff | ash。对于 AI 请求的工具管道，ash 支持 2 到 16 个允许的可执行文件直接连接而无需 shell，例如ls | grep pattern | pbcopy。工具参数中的 Shell 控制模式被阻止，并且 ash 管理的管道中的每个可执行文件都必须列入白名单。

ash 会重新解释我的 shell 脚本、SSH 命令或 cron 作业中的命令吗？

不会。Bash 和 zsh 集成包装器会立即在非交互式 shell 中返回，因此脚本、CI 作业、SSH 单行命令和 cron 命令会保持正常的命令未找到行为。使用显式调用，例如ash "summarize this log"或者some-command | ash当自动化应调用 ash 时。

如何阻止 ash 解释我的命令几分钟？

跑步ash snooze默认为五分钟，或指定持续时间，例如ash snooze 30s或者ash snooze 1h。跑步ash snooze off立即恢复。 Snooze 暂停自动未找到命令和包装器路由；明确的ash ...命令仍然有效。

如何调试 ash 并查看有关其正在执行的操作的更多信息？

放ASH_VERBOSE=1在运行 ash 以启用结构化调试输出和终端执行仪表板之前。放ASH_LOG_FILE将调试 JSON 写入文件；ASH_LOG_MAX_BYTES控制旋转，配置日志文件时默认为 1 MiB。

ash 运行工具时有哪些限制？

默认情况下，每个工具调用都有 15 秒的超时时间，并捕获最多 8192 字节的输出。一个 AI 请求最多可以进行 16 次工具循环迭代，并且 ash 管理的管道有 2 到 16 个阶段。调整工具超时和输出限制ASH_TOOL_TIMEOUT和ASH_TOOL_OUTPUT_MAX;使用以下命令保持输出集中head,tail， 或者grep。

默认的系统提示符在哪里？

规范的提示文件是~/.ash/.ash_system，运行时从捆绑的默认安装ash install。 ash 首先读取该文件。如果不存在，ash 会回退到.ash_system在当前工作目录中，然后~/.ash_system。普通的$VARIABLE价值观是从环境中扩展出来的，但是$TOOLS_DIR_LIST,$PLUGINS_DIR_LIST， 和$IF_PYTHON_AVAILABLE是保留的内部 Ash 替换，并且绝不是环境派生的。

我应该在哪里放置我自己的脚本和本机插件以供 ash 作为工具调用？

将Python脚本放入~/.ash/tools/并编译了本机二进制插件~/.ash/plugins/。确保它们是可执行的，并将裸可执行名称添加到~/.ash/.ash_allow（或依赖$TOOLS_DIR_LIST/$PLUGINS_DIR_LIST）。 ash 不会为允许的 Unix 命令和插件调用 shell。

工具或插件的最佳实践是什么，以便人工智能了解其目的和用途？

遵循标准工具/插件模式：使用 CLI 参数公开可预测的选项；并实施--ai-docs解释功能、每个参数和默认值、输出模式、故障状态以及人工智能何时应使用该工具的选项。发出紧凑的结构化 JSONstatus字段和可操作的错误详细信息，而不是与数据混合的散文。保持输出有限，验证输入，设置网络超时，处理预期故障，并使工具可以安全地重复调用。将其裸文件名添加到~/.ash/.ash_allow; ash只有在白名单中且不在列表中时才能执行~/.ash/.ash_deny。

提供的工具脚本和原生插件有哪些？

安装的引导Python脚本是headlines.py,wikipedia.py， 和yfinance.py在~/.ash/tools/。提供的本机插件是what_time_is_it（去），flip_a_coin（铁锈），以及calculator（打字稿）在~/.ash/plugins/。

ash可以呼叫子代理吗？

是的。父代理可以使用run_sub_agent完成一项专注的、独立的任务。子级继承工作目录、配置、工具和操作系统权限，返回有界结果，并且无法创建另一个子级。默认最大值是每个父运行六个子代理，可以使用以下命令进行更改ASH_MAX_AGENTS。

ash 能否生成内存文件来跟踪复杂的任务以及它在会话中学到的内容？

是的。它可以在下面写入持久工作区文件~/.ash，其中被跟踪~/.ash/inventory.md，以及会话范围的临时文件~/.ash/scratch/<session-id>/。使用持久工作区文件来保存您想要保留的信息；将临时文件用于临时计划、注释和辅助工件。

ash可以安排稍后工作吗？

是的，通过其人工智能工具。在 macOS 上，一次性调度使用每用户launchd启动代理并需要launchctl。在 Linux 上，您的用户支持循环计划crontab; ash 仅管理其自己的标记条目。一次性的launchd调度程序在 Linux 上不可用，因此请使用 cron 条目或其他 Linux 调度程序来执行一次性 Linux 作业。计划运行接收有限的环境并使用直接 HTTPS 而不是交互式 shell 代理，因此请确保所需的 AI 配置可用于计划作业。他们无法使用远程 MCP 工具； Ash 在没有它们的情况下运行，并且不会在非交互式会话中发出警告。不要安排需要 MCP 的提示。

会话和存储

ash 的历史记录或日志文件在哪里？

对话历史记录以 JSON 形式存储在~/.ash/history/<SESSION_ID>.json;计划运行使用task_<SESSION_ID>.json。启用计划调试日志记录后，其默认日志位置是~/.ash/logs/task_<SESSION_ID>.log。您可以选择另一个调试日志路径ASH_LOG_FILE。

历史文件保留多长时间？

ash 在正常应用程序清理期间删除超过 14 天的历史 JSON 文件，清理预算为 300 毫秒，因此退出不会延迟。最近消息窗口是独立的：默认情况下每个对话最多保留 40 条消息，并且可以使用以下命令进行更改ASH_HISTORY_MAX。

如何清理对话或重新开始？

历史记录由会话 ID 和 AI 端点/模型密钥分隔。为新的会话 ID 启动新的终端会话，或删除下面的相关 JSON 文件~/.ash/history/当您故意想要丢弃本地对话历史记录时。删除历史文件不会撤销提供商密钥或删除提供商端数据；与提供商单独管理这些内容。

什么是SESSION_ID它是在哪里生成的？

它是每个会话的标识符，用于分隔历史记录、暂存空间、代理套接字和计划日志名称。托管 shell 环境生成一个随机的 16 个字符的字母数字值/dev/urandom当外壳启动时；当交互式调用没有值时，ash 也会创建一个。

我可以替换的实施吗SESSION_ID发电机？

您可以自己提供SESSION_ID在启动 ash 或自定义本地托管环境文件之前，但 ash 会对其进行验证。有效 ID 最多 128 个字符，并使用字母、数字、下划线、连字符以及一个可选的子会话点后缀。不要使用不受信任或共享的值：冲突结合了会话历史记录和运行时状态。
