开始之前

  1. 受支持的系统和 shell：amd64/x86_64 或 arm64/aarch64 上的 macOS 或 Linux，或 amd64 上的 FreeBSD。使用 Bash、zsh 或 Fish。 Arch 软件包仅限 x86_64。没有本机 Windows/PowerShell 安装程序。
  2. 下载访问：有效的互联网连接以及对 GitHub、所选包存储库和模型提供程序的可信 HTTPS 访问。本地推理仍然需要初始模型下载。
  3. 权限：每个用户资产的可写主目录。 Linux系统包和macOS .pkg需要管理员权限；以普通用户身份运行 Homebrew 和 ash install。
  4. 模型：包含下载模型的本地推理服务器或云帐户/API 密钥。选择支持工具调用的模型，而不是仅图像/音频的模型。本地 RAM、磁盘和 GPU 需求取决于该型号。

预构建的 ash 包不需要 Go、Rust、Node.js 或 Xcode 构建工具。包管理器可能有其自己的先决条件；首先按照其官方设置说明进行操作。

可选：捆绑的 Python 工具

基本的ash使用不需要Python。捆绑的 Python 工具需要 Python 3venv和ensurepip，以及下载其依赖项的权限。在 Debian/Ubuntu 上，安装python3和python3-venv; Homebrew Python 包含 venv 支持。在 FreeBSD 上，使用与您的 Python 版本匹配的 pip 包。然后重新运行ash install。安装程序在下面创建一个隔离环境$XDG_DATA_HOME/ash/venv（默认~/.local/share/ash/venv）；失败会禁用这些工具，而不是基本工具ash。

macOS

推荐：自制

先决条件：自制、其支持的 macOS 环境以及工作brew命令。点击会自动选择 Intel 或 Apple Silicon 存档。 Homebrew 6 并不隐式信任此第三方水龙头。如果 Homebrew 拒绝将公式加载为不受信任，请检查发布者和公式，然后仅信任此公式（而不是整个水龙头）：

brew trust --formula jonconradt/ash/ash
brew install Jonconradt/ash/ash
ash version

Homebrew 会记住这个本地信任决定。水龙头无法代表您启用信任；相信整个水龙头brew trust jonconradt/ash更广泛，也允许加载其他公式。要信任 Beta 或 Nightly，请使用相应的公式名称，jonconradt/ash/ash-beta或者jonconradt/ash/ash-nightly。 Homebrew 拥有其前缀中的二进制文件、捆绑的本机插件、手册页和许可证声明（通常/opt/homebrew在 Apple Silicon 上或/usr/local英特尔）。它根据公式的 SHA-256 校验和检查存档。它不会配置您的提供程序或编辑您的 shell 启动文件：继续每个用户初始化。使用brew upgrade ash用于更新和brew uninstall ash删除发布；看渠道公式对于测试版/每晚。

替代方案：本机 .pkg

下载darwin-arm64.pkgApple Silicon 的资产或darwin-amd64.pkg对于英特尔来说已发布的版本。验证其签名的校验和清单在打开安装程序之前。需要管理员访问权限。

ma​​cOS 软件包未签名且未经公证。发布清单提供单独的发布者/校验和验证，而不是 Apple 公证。不要仅仅为了安装 ash 而禁用 Gatekeeper 或绕过安全警告；如果您的安全策略需要，则首选 Homebrew。

包里写着ash和ash-broker到/usr/local/bin, 插件/usr/local/lib/ash/plugins，手册页到/usr/local/share/man，并通知/usr/local/share/licenses/ash。收据是dev.ash.cli。它不运行每用户初始化或订阅更新：初始化安装后，将其替换为经过验证的较新的.pkg进行更新，并使用手动移除程序卸载。不要将其安装在 Homebrew 拥有的副本上。

Linux

尽可能使用您的发行版的包管理器。这些包拥有/usr/bin/ash,/usr/bin/ash-broker,/usr/lib/ash/plugins，手册页下/usr/share/man和许可通知。他们将提供程序设置和 shell 挂钩留给每个用户初始化。

Debian 和 Ubuntu：APT

先决条件：amd64 或 arm64、管理员访问权限、APT、curl,gpg和 CA 证书。在添加存储库之前，使用您的发行版安装缺少的下载/密钥工具。发布被命名为stable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

在导入任何存储库密钥之前，请根据受信任的发布者源验证其指纹。 VersionX 密钥指纹是32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F。 APT 检查签名的存储库元数据及其包含的包摘要；键的范围是signed-by。更新为sudo apt update && sudo apt upgrade ash;删除与sudo apt remove ash。

Fedora 和 RHEL 兼容系统：DNF

先决条件：x86_64 或 aarch64、管理员访问权限、DNF/RPM、curl,gpg和 CA 证书。安装您的发行版中缺少的工具。在导入之前检查密钥并比较上面的指纹：

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

RPM 文件没有单独签名。repo_gpgcheck=1验证包含其校验和的存储库元数据；gpgcheck=0反映了缺少的每个包签名，而不是禁用的存储库验证。如果您的策略需要签名的 RPM 有效负载，则此存储库不满足它。更新为sudo dnf upgrade ash;删除与sudo dnf remove ash。

Arch Linux：吃豆人

先决条件：x86_64、管理员访问权限、Pacman 及其密钥环已初始化、curl， 和gpg。在信任之前，请验证显示的密钥指纹与上面的指纹是否匹配。添加存储库一次，而不是每次更新时添加：

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman 验证包和数据库签名。保持 Arch 同步sudo pacman -Syu，不是部分升级；消除ash和sudo pacman -R ash。

其他Linux安装方法

已经在使用Linux 上的自制程序？这相同的点击指令支持amd64和arm64； Brew 拥有这些文件，而不是 APT/DNF。否则，请使用经过验证的脚本/存档安装或匹配的.deb/.rpm 下载。安装经过验证的 .debsudo apt install ./PACKAGE.deb，或 .rpm 与sudo dnf install ./PACKAGE.rpm（替换文件名）。直接包仍然由包管理器拥有，但不会添加存储库或自动订阅未来版本。当前 RPM 有效负载是无符号的；遵循您的发行版的策略而不是禁用签名检查。

FreeBSD

先决条件：amd64、Bash（即使您的交互式 shell 是 zsh 或 Fish）、下载/验证工具以及可写的安装目录。使用 FreeBSD 的本机管理器安装 Bash：

sudo pkg install bash

FreeBSD 的pkg管理先决条件，而不是ash: 目前没有ash.pkg 存储库，没有 arm64 发布存档。使用已验证的脚本， 或者验证 FreeBSD amd64 tarball，将其解压到临时目录中，然后安装其版本控制ash二进制为~/.local/bin/ash旁边ash-broker。将其原生插件复制到$XDG_DATA_HOME/ash/plugins（默认~/.local/share/ash/plugins）， 然后初始化。您拥有这些文件；pkg delete不会删除它们。使用发布自我更新在默认位置或手动替换已验证的工件。

初始化并验证

安装二进制文件后，以普通用户身份交互式运行安装程序。如果您不想集成 shell，则可以仅安装 Ash。这可能不是您想要的。 ash的真正价值是下面的shell集成。仅资产设置使您的启动文件保持不变：

ash install

您可能想要使用的安装涉及 shell 集成。这将更改您的 .bashrc（或 shell 的等效项）以包含 Ash。要启用 command-not-found 集成，请为您使用的 shell 选择一个命令：

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

鱼

ash install --shell fish --shell-integration

bash 使用~/.bashrc,zsh 使用~/.zshrc，和鱼使用$XDG_CONFIG_HOME/fish/config.fish（默认~/.config/fish/config.fish）。之后打开一个新的shell；现有的 shell 保留其正在运行的代理。集成前置~/.local/binto PATH：在选择系统包之前删除旧的用户本地副本。

如果缺少提供程序设置，安装程序会检测现有的提供程序密钥或正在运行的本地服务器；否则，它会提供提供者菜单并提示输入凭据。选择一个可用的支持工具的模型。现有的有效设置将被保留，因此重新运行安装程序不是提供程序切换命令。

设置存储在$XDG_CONFIG_HOME/ash/.ash_env（默认~/.config/ash/.ash_env，私有文件权限）。托管集成加载它们。如果没有集成，Bash/zsh 用户可以在正常启动配置中获取该文件；钓鱼用户应设置相应的ASH_AI_*使用 Fish 语法的变量，而不是 Bash 格式文件的源。保护任何包含令牌的文件，并且永远不要提交它。

对于不带集成的用户本地安装，请将其实际目录添加到 PATH。 bash/zsh：export PATH="$HOME/.local/bin:$PATH"。鱼：fish_add_path "$HOME/.local/bin"。使用 shell 的启动配置来保持这一点；如果适用，请替换您的自定义安装目录。

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

第一个命令应解析为您选择的安装。提示需要正在运行的服务器或有效的云凭据；安装 ash 不会安装模型。

本地 Ollama：无需云帐户

您不需要有本地人工智能即可使用ash。但是，如果您想在本地运行模型而不依赖云提供商，则可以设置本地 Ollama 服务器。

Ollama 还提供用于远程运行模型的云服务，但本地使用不需要该服务ash。云服务器包括免费套餐和 Google 的 Gemma 4 31b 云模型（gemma4-31b：云）可以很好地配合ash。这是项目用来生成发行说明和执行 DevOps 任务的模型。

使用其安装 Ollama官方操作系统说明。启动 Ollama 应用程序/服务，或运行ollama serve如果服务器尚未运行，则在单独的终端中。在 FreeBSD 上，ash的支持并不意味着本机 Ollama 安装程序：如果需要，请在另一个受支持的主机上使用可访问的服务器。

下载适合您的硬件的具有工具功能的模型；llama3.1:8b是一个例子，不是最低要求。检查当前工具目录对于替代方案：

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

如果尚未设置云密钥，安装程序可以检测本地服务器并提供下载的模型。如果已配置另一个提供程序，请手动更改端点/模型。 Bash/zsh 示例：

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

鱼当量：

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

这些更改仅影响当前 shell。将它们保留在您的受保护的ash环境文件或适当的 shell 配置，替换任何旧的提供程序覆盖。本地 Ollama 不需要令牌。保持服务器处于环回状态，除非您刻意保护访问安全；远程服务器接收您的提示和工具输出。

可选：设置OLLAMA_KEEP_ALIVE=30m在奥拉马服务器环境并重新启动服务器以使模型保持温暖。-1让它们无限期地加载，但会在请求之间消耗内存。仅在ash客户端不会重新配置已经运行的服务器。

本地推理没有提供商 API 账单，但使用您的硬件/存储/电力。奥拉马云是一项具有身份验证和计划限制的独立服务；它与本地设置不一样。

手动配置或切换提供商

将下面的端点替换为表的值并MODEL_ID使用您的提供商帐户中验证的模型。如果您的密钥已导出为GROQ_API_KEY，这个 Bash/zsh 示例重用了它而无需输入密钥：

export ASH_AI_ENDPOINT="https://api.groq.com/openai/v1"
export ASH_AI_MODEL="MODEL_ID"
export ASH_AI_AUTH_TOKEN="$GROQ_API_KEY"

鱼当量：

set -gx ASH_AI_ENDPOINT https://api.groq.com/openai/v1
set -gx ASH_AI_MODEL MODEL_ID
set -gx ASH_AI_AUTH_TOKEN "$GROQ_API_KEY"

对于 Gemini 或 OpenRouter，请使用它们的端点和识别的键变量。安全地保存所选设置以供将来的 shell 使用。云端点需要 HTTPS 和令牌；本地 HTTP 不是云服务的快捷方式。看环境参考和其他支持的提供商用于付费服务和高级覆盖。

脚本安装：替代方案，而不是首选

更喜欢 Homebrew、APT、DNF 或 Pacman：它们跟踪拥有的文件，使用其信任配置验证下载，并提供熟悉的更新/删除。他们仍然需要信任的发布者和软件包安装操作。

网站脚本使用您帐户的权限运行代码。受感染的网站、发布者或更改脚本可以读取机密、更改文件或安装其他软件。 HTTPS 保护传输，而不是该代码的意图。将 URL 直接通过管道传输到 shell 会在您查看它之前执行它。脚本的存档签名检查不会验证脚本本身。切勿使用 sudo 运行它或禁用其验证。

先决条件：受支持的操作系统/架构，$SHELL识别 Bash/zsh/Fish，Sigstore联名,tar,uname,install、标准 shell 实用程序、SHA-256 命令（sha256sum,shasum， 或者sha256）和一个下载器（curl,wget，或Python）。该示例使用了curl。 FreeBSD 还需要 Bash。您的主/安装目录必须是可写的。

下载到本地文件，使用编辑器检查它，并且仅在您信任其来源和行为时才执行。检查并不能保证安全；不要盲目执行以下步骤：

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

检查后，以普通用户身份运行保存的副本：

sh ./ash-install.sh
rm ./ash-install.sh

install.sh下载最新版本，验证其 Sigstore 签名的校验和清单和存档摘要，然后安装ash/ash-broker在~/.local/bin。原生插件消失了$XDG_DATA_HOME/ash/plugins。它运行每用户设置并在启用 shell 集成之前进行询问。如果没有交互式终端，可能会跳过提供程序/集成提示：运行ash install之后进行互动。

您可以设置ASH_INSTALL_DIR在运行脚本之前选择另一个目的地。自己将该目的地添加到 PATH 中。仅在以下情况下支持自我更新~/.local/bin;自定义目的地需要手动替换。该脚本没有 Beta/Nightly 选择器。

验证直接包或存档

先决条件：共同签名和 SHA-256 实用程序。从同一已发布的版本中，下载您的包/存档，SHA256SUMS， 和SHA256SUMS.sigstore.json。在新目录中工作。代替vX.Y.Z具有确切的标签，包括预发布后缀（如果适用）：

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

只有在成功之后，才可以使用以下命令计算文件的摘要shasum -a 256 PACKAGE在 macOS 上，sha256sum PACKAGE在 Linux 上，或者sha256 -q PACKAGE在 FreeBSD 上。代替PACKAGE与下载的文件名并将其与已验证清单中该文件名的条目进行精确比较。当缺少条目或任何不匹配时停止。在文件旁边下载的未签名校验和并不等同于经过验证的发布者元数据。

更新和三个渠道

  • 发布（推荐）：稳定的已发布版本，例如vX.Y.Z;存储库配置调用此stable。
  • 测试版：预发布测试，已标记vX.Y.Z-beta.N;期待变化和回归。
  • 每晚：最近的默认分支更改，已标记vX.Y.Z-nightly.YYYYMMDD.N;回归风险最高。构建已计划，但在没有任何更改或发布失败时可能会被跳过。

已发布的版本更新了相应的 Homebrew 公式或签名的 Linux 存储库。当您运行所属管理器的升级命令（或您自己的操作系统更新策略）时，您会收到它。发布、存储库更新和网站部署可能会相互滞后；在更改频道之前检查可用性。 ash 不会静默安装后台二进制更新。

Homebrew：安装或切换公式

对于全新 Beta/Nightly 安装，请使用上面 brew install 中相应的完整公式名称。切换时，首先卸载当前安装的公式：所有三个都提供相同的二进制文件。示例，发布测试版：

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

使用ash-nightly每晚或ash用于安装/升级命令中的发布。卸载旧频道的实际公式，并不总是ash。保留用户设置；切换后打开一个新的shell。

Linux：选择一个存储库通道

易于：使用APT 设置恰好具有表中的一种分布。要切换现有安装，请编辑/etc/apt/sources.list.d/versionx.list, 替换stable和beta或者nightly（或回到stable）， 然后：

sudo apt update
sudo apt install --allow-downgrades ash

地下城与勇士:使用DNF设置与选定的基本网址。对于现有安装，替换baseurl在/etc/yum.repos.d/versionx.repo，保留其签名设置，然后：

sudo dnf --refresh distro-sync ash

吃豆人：使用吃豆人设置与选定的服务器 URL。保留部分名称[versionx]：每个频道都会发布一个数据库，名为versionx.db。更改该部分中的服务器，而不是添加不同名称的数据库。切换（包括降级）：

sudo pacman -Syuu ash

审查提议的交易：返回Release可能会降级ash，Pacman的双重u也可以降级其他软件包。切换前备份配置。然后使用操作系统部分的普通 APT/DNF/Pacman 升级命令；不要启用多个 ash 通道源。

用户本地版本更新

ash update

仅当活动时，这才会验证并安装稳定版本ash可执行文件位于~/.local/bin。它还更新捆绑的资产/插件，并提供自定义文件的选择。ash update --version vX.Y.Z选择稳定的标签，而不是通道；它不是降级命令。没有--channel选项。包管理器安装、macOS .pkg 安装和自定义脚本目标必须使用其所属的管理器/安装程序。 FreeBSD Beta/Nightly 使用手动验证的存档，而不是自我更新程序订阅。更新后打开新的shell。

卸载而不删除无关文件

1.首先禁用 shell 集成

在删除二进制文件之前，为启用集成的每个 shell 运行命令：

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

鱼

ash install --shell fish --disable-shell-integration

如果ash已经丢失，请编辑相关的启动文件初始化并仅删除之间的块# >>> ash install >>>和# <<< ash install <<<。删除任何ash- 您手动添加的特定路径/环境行，而不是不相关的 shell 配置。关闭ash- 随后启用 shell，以便其 shell 拥有的经纪人退出。

2. 让所属包管理器删除其文件

自制软件（发布）

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

吃豆人

sudo pacman -R ash

仅选择您的安装方法；用于 Homebrew Beta/夜间使用ash-beta/ash-nightly。 APT/DNF/Pacman 删除包拥有的二进制文件、插件和手册页，而不是您的主目录配置/历史记录。不要手动删除包拥有的文件。

可选的存储库清理：删除ash源文件/etc/apt/sources.list.d/versionx.list及其专用的/etc/apt/keyrings/versionx-keyring.gpg，或ash存储库文件/etc/yum.repos.d/versionx.repo，或ash [versionx]部分来自/etc/pacman.conf。首先检查没有其他包使用它们。仅在确认其指纹且没有其他依赖项后才删除导入的 RPM/Pacman 信任密钥；切勿删除发行版的共享密钥环。

3a.手动删除 macOS .pkg

macOS 安装程序记录了收据，但没有ash卸载程序。确认这是一个 .pkg 安装，而不是 Homebrew，并检查其确切的有效负载：

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

使用该收据作为库存，仅删除其ash- 拥有的文件：/usr/local/bin/ash,/usr/local/bin/ash-broker，文件在/usr/local/lib/ash/plugins,/usr/local/share/man/man1/ash.1，列出的本地化ash.1页面和通知/usr/local/share/licenses/ash。需要管理员权限。如果其他安装程序随后替换了这些文件，请检查所有权；不要删除其副本。删除空ash- 仅限目录，不共享/usr/local,bin，或 man 目录。

删除有效负载后，可以选择删除收据：

sudo pkgutil --forget dev.ash.cli

忘记收据不会删除任何已安装的文件。保留它，直到检查完有效负载为止。

3b.手动删除用户本地/Linux/FreeBSD存档

找到活动副本command -v ash和command -v ash-broker。对于默认脚本安装，禁用挂钩后，删除这两个特定文件：

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

为了ASH_INSTALL_DIR或手动提取的存档，仅删除实际安装的ash/经纪人路径。删除您使用原始文件清单安装的存档插件/手册页/通知；脚本插件位于ash用户数据目录。如果文件位于/usr/bin，首先检查所有权dpkg -S /usr/bin/ash,rpm -qf /usr/bin/ash， 或者pacman -Qo /usr/bin/ash视情况而定。包拥有的副本必须通过该管理器删除，即使是通过独立下载安装的。

4. 可选：删除本地设置、工具和历史记录

备份您想要保留的任何内容。这个单独的步骤可以删除提供商设置/令牌、自定义工具/插件、对话历史记录和暂存文件。卸载二进制文件并不意味着同意删除它们。

  • 配置：$XDG_CONFIG_HOME/ash， 默认~/.config/ash。
  • 数据、插件和Python环境：$XDG_DATA_HOME/ash， 默认~/.local/share/ash。
  • 历史和状态：$XDG_STATE_HOME/ash， 默认~/.local/state/ash。
  • 缓存：$XDG_CACHE_HOME/ash， 默认~/.cache/ash。
  • 经纪商运行时间：$XDG_RUNTIME_DIR/ash， 或者$XDG_STATE_HOME/ash/runtime当没有可用的运行时根时。

在仅删除这些 ash 子目录之前检查您的实际绝对 XDG 覆盖；切勿删除 XDG 根目录或您的主目录。关闭所有启用 ash 的 shell 后，根据需要删除剩余的 ash 运行时文件。 MCP OAuth 凭据也可能保留在操作系统凭据管理器中：删除其中的 ash 特定条目并撤销 MCP 提供程序的访问权限。撤销其提供商帐户中未使用的 AI 密钥；删除本地文件不会撤销密钥。请勿在 ash 删除过程中卸载 Ollama/models、Python 或共享依赖项。

快速故障排除

未找到命令或版本错误
检查路径和command -v ash/command -v ash-broker。一个老~/.local/bin副本可以隐藏包。一次使用一个所有者/频道并打开一个新 shell。
提供商菜单未出现
跑步ash install从交互式终端。保留现有的有效设置；使用手动配置更换提供商。如果不进行集成，请确保将设置导出到 CLI 环境中。
没有模型或连接被拒绝
对于 Ollama，确认其服务器正在运行并且ollama list包括您选择的型号。对于云服务，检查端点、模型资格、HTTPS、令牌和帐户配额；切勿共享带有令牌的日志。
存储库或通道不可用
检查架构和已发布的版本/存储库。出版可能会滞后；不要禁用签名验证来解决不可用的存储库问题。
Python 工具设置失败
使用 venv/ensurepip 安装 Python 并允许依赖项下载，然后重新运行ash install。基本的ash没有这些工具仍然可以使用。
