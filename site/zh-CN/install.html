开始之前

  1. 受支持的系统和 shell：amd64/x86_64 或 arm64/aarch64 上的 macOS、Linux，或 amd64 上的 FreeBSD。使用 Bash、zsh 或 Fish。Arch 包仅支持 x86_64。没有原生 Windows/PowerShell 安装程序。
  2. 下载访问：可用的互联网连接，以及对 GitHub、选定软件仓库和模型提供商的可信 HTTPS 访问。本地推理也需要先下载模型。
  3. 权限：主目录须可写，以保存用户文件。Linux 系统包和 macOS .pkg 需要管理员权限；Homebrew 和 ash install 应以普通用户运行。
  4. 模型：已下载模型的本地推理服务器，或云端账户/API 密钥。选择支持工具调用的模型，而非仅图像/音频模型。本地内存、磁盘和 GPU 需求取决于模型。

预编译 ash 包不需要 Go、Rust、Node.js 或 Xcode 构建工具。包管理器可能有自己的要求；请先遵循其官方设置说明。

可选：内置 Python 工具

基本使用无需 Python。内置 Python 工具需要带 venv 和 ensurepip 的 Python 3，并能下载依赖。在 Debian/Ubuntu 安装 python3 和 python3-venv；Homebrew Python 包含 venv 支持。FreeBSD 请使用与 Python 版本匹配的 pip 包。然后重新运行 ash install。设置会在 $XDG_DATA_HOME/ash/venv（默认 ~/.local/share/ash/venv）创建隔离环境；失败只禁用这些工具，不影响基本功能。

macOS

推荐：Homebrew

前提：Homebrew、受支持的 macOS 环境和可用的 brew 命令。tap 自动选择 Intel 或 Apple Silicon 压缩包。安装 Release 无需 sudo：

brew install Jonconradt/ash/ash
ash version

Homebrew 管理其前缀内的二进制、原生插件、手册页和许可声明（Apple Silicon 通常为 /opt/homebrew，Intel 为 /usr/local）。它按配方的 SHA-256 校验压缩包。不配置提供商，也不修改 shell 启动文件：请继续用户初始化。用 brew upgrade ash 更新，用 brew uninstall ash 移除 Release；Beta/Nightly 见渠道配方。

替代方案：原生 .pkg

从已发布版本下载 Apple Silicon 的 darwin-arm64.pkg 或 Intel 的 darwin-amd64.pkg。打开安装程序前，验证其签名校验和清单。需要管理员权限。

macOS 包未经签名或公证。发布清单提供独立的发布者/校验和验证，不是 Apple 公证。不要仅为安装 ash 而禁用 Gatekeeper 或绕过安全警告；如安全政策有要求，请优先使用 Homebrew。

包将 ash 和 ash-broker 写入 /usr/local/bin，插件写入 /usr/local/lib/ash/plugins，手册写入 /usr/local/share/man，声明写入 /usr/local/share/licenses/ash。收据为 dev.ash.cli。不执行用户初始化或订阅更新：安装后初始化，更新时替换为已验证的新版 .pkg，卸载时遵循手动移除步骤。不要覆盖 Homebrew 管理的版本。

Linux

尽量使用发行版的包管理器。这些包管理 /usr/bin/ash、/usr/bin/ash-broker、/usr/lib/ash/plugins、/usr/share/man 下的手册及许可声明。提供商设置和 shell 钩子留给用户初始化。

Debian 和 Ubuntu：APT

前提：amd64 或 arm64、管理员权限、APT、curl、gpg 和 CA 证书。添加仓库前，通过发行版安装缺失的下载/密钥工具。Release 名为 stable：

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

导入任何仓库密钥前，使用可信发布者来源核对指纹。VersionX 指纹为 32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F。APT 验证已签名仓库元数据及其中的包摘要；signed-by 限制密钥适用范围。用 sudo apt update && sudo apt upgrade ash 更新；用 sudo apt remove ash 移除。

Fedora 和兼容 RHEL 的系统：DNF

前提：x86_64 或 aarch64、管理员权限、DNF/RPM、curl、gpg 和 CA 证书。从发行版安装缺失工具。导入前查看密钥并核对上述指纹：

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

RPM 文件未单独签名。repo_gpgcheck=1 验证覆盖其校验和的仓库元数据；gpgcheck=0 表示没有单包签名，不是禁用仓库验证。如政策要求已签名 RPM 内容，此仓库不符合要求。用 sudo dnf upgrade ash 更新；用 sudo dnf remove ash 移除。

Arch Linux：Pacman

前提：x86_64、管理员权限、已初始化密钥环的 Pacman、curl 和 gpg。信任前核对显示的指纹与上述一致。只添加一次仓库，不要每次更新都添加：

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman 验证包和数据库签名。用 sudo pacman -Syu 保持 Arch 同步，不要部分升级；用 sudo pacman -R ash 移除 ash。

其他 Linux 安装方式

已使用 Linux 上的 Homebrew？相同 tap 说明支持 amd64 和 arm64；文件由 Brew 管理，不是 APT/DNF。否则使用已验证的脚本/压缩包安装，或匹配的 .deb/.rpm 下载。用 sudo apt install ./PACKAGE.deb 安装已验证的 .deb，或用 sudo dnf install ./PACKAGE.rpm 安装 .rpm（替换文件名）。直接包仍由包管理器管理，但不添加仓库或自动订阅未来版本。当前 RPM 内容未签名；遵循发行版政策，不要禁用签名检查。

FreeBSD

前提：amd64、Bash（即使交互 shell 为 zsh/Fish）、下载/验证工具和可写安装目录。使用 FreeBSD 原生管理器安装 Bash：

sudo pkg install bash

FreeBSD 的 pkg 管理前提组件，不管理 ash：目前没有 ash .pkg 仓库或 arm64 发布压缩包。使用已验证脚本，或验证 FreeBSD amd64 tarball，解压到临时目录，将版本化 ash 二进制安装为 ~/.local/bin/ash，与 ash-broker 放在一起。复制原生插件到 $XDG_DATA_HOME/ash/plugins（默认 ~/.local/share/ash/plugins），然后初始化。这些文件由您管理，pkg delete 不会移除它们。在默认位置使用 Release 自更新，或手动替换已验证文件。

初始化与验证

安装二进制后，以普通用户交互运行设置。仅设置用户文件不会改动启动文件：

ash install

如要启用“命令未找到”集成，请按所用 shell 选择且仅选择一条命令：

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Fish

ash install --shell fish --shell-integration

Bash 使用 ~/.bashrc，zsh 使用 ~/.zshrc，Fish 使用 $XDG_CONFIG_HOME/fish/config.fish（默认 ~/.config/fish/config.fish）。随后打开新 shell；已有 shell 保留运行中的 broker。集成将 ~/.local/bin 加到 PATH 前面：要让系统包被选中，先删除旧的用户本地版本。

若缺少提供商设置，会检测现有密钥或运行中的本地服务器；否则显示提供商菜单并要求凭据。选择可用、支持工具调用的模型。有效设置会保留，所以重新设置不是切换提供商命令。

设置保存于 $XDG_CONFIG_HOME/ash/.ash_env（默认 ~/.config/ash/.ash_env，私有文件权限）。托管集成会加载它。无集成时，Bash/zsh 可在正常启动配置中加载此文件；Fish 应使用 Fish 语法设置对应 ASH_AI_* 变量，不要加载 Bash 格式文件。保护含令牌的文件，切勿提交到仓库。

本地安装不启用集成时，将实际目录加入 PATH。Bash/zsh：export PATH="$HOME/.local/bin:$PATH"。Fish：fish_add_path "$HOME/.local/bin"。在启动配置中持久保存；如适用，请替换为自定义安装目录。

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

前几条命令应指向选定安装。提问需要运行中的服务器或有效云端凭据；安装 ash 不会安装模型。

本地 Ollama：无需云端账户

按 官方操作系统说明安装 Ollama。启动应用/服务；如果服务器未运行，可在另一个终端运行 ollama serve。ash 支持 FreeBSD 不代表有原生 Ollama 安装程序：必要时使用其他受支持主机上的可达服务器。

下载适合硬件、支持工具调用的模型；llama3.1:8b 是示例，不是最低要求。其他选择见当前工具模型目录：

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

若未设置云端密钥，设置可检测本地服务器并提供已下载模型。如果已配置其他提供商，请手动更改端点/模型。Bash/zsh 示例：

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Fish 等效命令：

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

这些更改仅影响当前 shell。在受保护的 ash 环境文件或适当 shell 配置中保存，替换旧提供商覆盖设置。本地 Ollama 不需令牌。除非有意保护远程访问，否则将服务器保持在 loopback；远程服务器会收到提问及工具输出。

可选：在 Ollama 服务器环境中设置 OLLAMA_KEEP_ALIVE=30m 并重启服务器，保持模型加载。-1 无限保持加载，但请求间仍占用内存。仅在 ash 客户端终端设置，不会重配已运行服务器。

本地推理没有提供商 API 账单，但消耗硬件/存储/电力。Ollama 云服务是独立服务，有身份验证和套餐限制，不等同于本地设置。

免费不代表无限或私密。账户、地区、额度、模型和数据政策不同，也可能变化。提问及相关工具输出会离开设备。查阅最新限制和条款；除非准备付费，否则不要启用付费计费。

手动配置或切换提供商

将以下端点替换为表中值，将 MODEL_ID 替换为在提供商账户核实的模型。若密钥已导出为 GROQ_API_KEY，此 Bash/zsh 示例无需输入秘密即可复用：

export ASH_AI_ENDPOINT="https://api.groq.com/openai/v1"
export ASH_AI_MODEL="MODEL_ID"
export ASH_AI_AUTH_TOKEN="$GROQ_API_KEY"

Fish 等效命令：

set -gx ASH_AI_ENDPOINT https://api.groq.com/openai/v1
set -gx ASH_AI_MODEL MODEL_ID
set -gx ASH_AI_AUTH_TOKEN "$GROQ_API_KEY"

Gemini/OpenRouter 请使用各自端点与密钥变量。安全保存设置供后续 shell 使用。云端要求 HTTPS 和令牌；本地 HTTP 不是访问云服务的捷径。付费服务和高级覆盖设置见环境参考及其他支持提供商。

脚本安装：替代方案，非首选

优先选择 Homebrew、APT、DNF 或 Pacman：它们跟踪所属文件，根据其信任配置验证下载，并提供熟悉的更新/移除功能。但仍需信任发布者及包安装行为。

网站脚本会以您的账户权限执行代码。被攻破的网站/发布者或变化的脚本可读取秘密、修改文件或安装其他软件。HTTPS 保护传输，不保护代码意图。直接将 URL 管道传给 shell，会在检查前执行。压缩包签名验证不能认证脚本自身。切勿以 sudo 运行或禁用验证。

前提：受支持系统/架构、标识 Bash/zsh/Fish 的 $SHELL、Sigstore cosign、tar、uname、install、标准 shell 工具、SHA-256 命令（sha256sum、shasum 或 sha256）及下载器（curl、wget 或 Python）。示例使用 curl。FreeBSD 还需要 Bash。主目录/安装目录必须可写。

下载到本地文件，用编辑器检查，仅当信任来源及行为时运行。检查不保证安全；不要盲目执行：

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

检查后，以普通用户运行保存的副本：

sh ./ash-install.sh
rm ./ash-install.sh

install.sh 下载最新 Release，验证 Sigstore 签名清单及压缩包摘要，将 ash/ash-broker 安装到 ~/.local/bin。原生插件放到 $XDG_DATA_HOME/ash/plugins。它执行用户设置并在启用集成前询问。无交互终端时可能跳过提供商/集成提示：随后交互运行 ash install。

运行脚本前可设置 ASH_INSTALL_DIR 选择其他目录。自行加入 PATH。自更新仅支持 ~/.local/bin；自定义目录需手动替换。脚本无 Beta/Nightly 选择器。

验证直接下载的包或压缩包

前提：cosign 和 SHA-256 工具。从同一发布版本下载包/压缩包、SHA256SUMS 和 SHA256SUMS.sigstore.json。在新目录中操作。将 vX.Y.Z 替换为精确标签，必要时包含预发布后缀：

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

仅在验证成功后，用 macOS 的 shasum -a 256 PACKAGE、Linux 的 sha256sum PACKAGE 或 FreeBSD 的 sha256 -q PACKAGE 计算摘要。将 PACKAGE 替换为下载文件名，与已验证清单中该文件的条目精确比较。缺条目或任何不匹配应停止。随文件下载的未签名校验和不等于已验证的发布者元数据。

更新与三个渠道

  • Release（推荐）：如 vX.Y.Z 的稳定发布；仓库配置称为 stable。
  • Beta：预发布测试，标签 vX.Y.Z-beta.N；可能有变化和回归。
  • Nightly：默认分支最新变动，标签 vX.Y.Z-nightly.YYYYMMDD.N；回归风险最高。构建按计划运行，但无变化或发布失败时可能跳过。

发布版本会更新对应 Homebrew 配方或签名 Linux 仓库。运行所属管理器的升级命令（或由系统更新政策执行）才会收到更新。发布、仓库更新和网站部署可能不同步；切换前检查可用性。ash 不会静默安装后台二进制更新。

Homebrew：安装或切换配方

新装 Beta/Nightly 时，在 brew install 中使用上表完整配方名称。切换时先卸载当前配方：三个配方提供相同二进制。Release 转 Beta 示例：

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

安装/升级命令中，Nightly 用 ash-nightly，Release 用 ash。卸载旧渠道的实际配方，不总是 ash。用户设置保留；切换后打开新 shell。

Linux：选择一个仓库渠道

APT：按APT 设置使用表中且仅一个发行渠道。切换现有安装时编辑 /etc/apt/sources.list.d/versionx.list，将 stable 替换为 beta 或 nightly（或改回 stable），然后：

sudo apt update
sudo apt install --allow-downgrades ash

DNF：按DNF 设置使用选定 baseurl。现有安装中替换 /etc/yum.repos.d/versionx.repo 内的 baseurl，保留签名设置，然后：

sudo dnf --refresh distro-sync ash

Pacman：按Pacman 设置使用选定 Server URL。保留节名 [versionx]：每个渠道都发布名为 versionx.db 的数据库。更改同一节的 Server，而非添加异名数据库。切换（包含降级）：

sudo pacman -Syuu ash

检查拟议事务：回到 Release 可能降级 ash，Pacman 双 u 也可能降级其他包。切换前备份配置。随后按系统章节使用常规 APT/DNF/Pacman 升级；不要同时启用多个 ash 渠道源。

用户本地 Release 更新

ash update

仅在当前 ash 执行文件位于 ~/.local/bin 时验证并安装稳定版。还会更新内置文件/插件，并对自定义文件提供选项。ash update --version vX.Y.Z 选择稳定标签，不选择渠道；不是降级命令。没有 --channel 选项。包管理器、macOS .pkg 和自定义脚本目录安装须使用所属管理器/安装程序。FreeBSD Beta/Nightly 使用手动验证的压缩包，非自更新订阅。更新后打开新 shell。

卸载而不删除无关文件

1. 先禁用 shell 集成

删除二进制前，对每个启用集成的 shell 执行相应命令：

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Fish

ash install --shell fish --disable-shell-integration

若 ash 已不存在，按初始化说明编辑对应启动文件，仅删除 # >>> ash install >>> 与 # <<< ash install <<< 之间的块。移除手动添加的 ash 专用 PATH/环境行，不要删除无关配置。随后关闭启用 ash 的 shell，使其管理的 broker 退出。

2. 让所属包管理器移除其文件

Homebrew (Release)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

只选择实际安装方式；Homebrew Beta/Nightly 用 ash-beta/ash-nightly。APT/DNF/Pacman 移除包所属二进制、插件和手册，不删除主目录配置/历史。不要手动删包文件。

可选仓库清理：移除 ash 源文件 /etc/apt/sources.list.d/versionx.list 及其专用 /etc/apt/keyrings/versionx-keyring.gpg，或仓库文件 /etc/yum.repos.d/versionx.repo，或 /etc/pacman.conf 内的 ash [versionx] 节。先检查没有其他包使用。确认指纹且无其他依赖后才能移除 RPM/Pacman 信任密钥；切勿删除发行版共享密钥环。

3a. 手动移除 macOS .pkg

macOS Installer 记录收据，但无 ash 卸载程序。确认这是 .pkg 而非 Homebrew 安装，并检查其精确内容：

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

按收据清单仅删除 ash 文件：/usr/local/bin/ash、/usr/local/bin/ash-broker、/usr/local/lib/ash/plugins 内文件、/usr/local/share/man/man1/ash.1、列出的本地化 ash.1 页及 /usr/local/share/licenses/ash 内声明。需要管理员权限。若另一安装程序已替换文件，先查归属，不要删除其副本。仅删除空的 ash 专用目录，不删除共享 /usr/local、bin 或手册目录。

删除内容后，可选移除收据：

sudo pkgutil --forget dev.ash.cli

遗忘收据不会删除任何已安装文件。在完成内容检查前保留它。

3b. 手动移除用户本地 / Linux / FreeBSD 压缩包

用 command -v ash 和 command -v ash-broker 找到当前版本。默认脚本安装禁用钩子后，仅删除这两个文件：

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

对 ASH_INSTALL_DIR 或手动解压版本，仅删除实际 ash/broker 路径。按原始清单移除自行安装的插件/手册/声明；脚本插件在 ash 用户数据目录。如文件在 /usr/bin，先用相应 dpkg -S /usr/bin/ash、rpm -qf /usr/bin/ash 或 pacman -Qo /usr/bin/ash 查归属。包所属版本即使来自独立下载，也必须通过管理器移除。

4. 可选：清除本地设置、工具与历史

备份所有要保留的内容。此独立步骤会删除提供商设置/令牌、自定义工具/插件、会话历史及工作文件。卸载二进制不等于同意清除它们。

  • 配置：$XDG_CONFIG_HOME/ash，默认 ~/.config/ash。
  • 数据、插件和 Python 环境：$XDG_DATA_HOME/ash，默认 ~/.local/share/ash。
  • 历史与状态：$XDG_STATE_HOME/ash，默认 ~/.local/state/ash。
  • 缓存：$XDG_CACHE_HOME/ash，默认 ~/.cache/ash。
  • Broker 运行数据：$XDG_RUNTIME_DIR/ash；无运行根目录时为 $XDG_STATE_HOME/ash/runtime。

检查实际绝对 XDG 覆盖路径后，仅删除 ash 子目录；切勿删除 XDG 根或主目录。关闭所有 ash shell 后，按需清理运行残留。MCP OAuth 凭据可能仍在系统凭据管理器：删除 ash 专属项并在 MCP 提供商撤销访问。在账户撤销不再使用的 AI 密钥；删本地文件不撤销密钥。移除 ash 时不要卸载 Ollama/模型、Python 或共享依赖。

快速故障排查

命令不存在或版本错误
检查 PATH 及 command -v ash/command -v ash-broker。~/.local/bin 中旧版可能遮蔽包。一次只使用一个管理方/渠道，并打开新 shell。
没有出现提供商菜单
从交互终端运行 ash install。有效设置会保留；使用手动配置切换提供商。无集成时，确保设置已导出到 CLI 环境。
没有模型或连接被拒绝
Ollama 请确认服务器运行且 ollama list 包含所选模型。云服务请检查端点、模型资格、HTTPS、令牌与额度；不要分享含令牌日志。
仓库或渠道不可用
检查架构及发布版本/仓库。发布可能滞后；不要禁用签名验证绕过不可用仓库。
Python 工具设置失败
安装支持 venv/ensurepip 的 Python，允许下载依赖，再运行 ash install。没有这些工具仍可使用基本 ash。
