Memulai

Apa yang saya perlukan sebelum saya dapat menggunakan ash?

Anda memerlukan ash yang dapat dieksekusi, titik akhir AI, dan nama model. Menjalankan ash install akan mengonfigurasikan ini secara otomatis: ia menggunakan kunci API penyedia cloud yang telah ditetapkan atau server inferensi lokal yang sedang berjalan ketika ditemukan, jika tidak maka akan menampilkan menu penyedia bernomor dan meminta kunci API, lalu memungkinkan Anda memilih model dari daftar model titik akhir. Anda juga dapat mengatur AI_ENDPOINT dan AI_MODEL secara manual. Titik akhir lokal seperti Ollama dapat menggunakan http://localhost:11434, dan host LAN seperti http://brain.local:11434 atau IP pribadi juga diperlakukan sebagai lokal (kecuali ASH_STRICT=1); titik akhir cloud harus menggunakan HTTPS dan juga memerlukan AI_AUTH_TOKEN. Integrasi shell bersifat opsional: Anda selalu dapat menjalankan ash "your question" secara langsung.

Di mana ash diinstal, dan bagaimana cara memeriksa apakah shell saya dapat menemukannya?

Penginstal terverifikasi menempatkan ash di ~/.local/bin/ash, dan ash install menambahkan direktori tersebut ke direktori Anda PATH melalui file ~/.ash/.ash_env yang dikelola. Buka terminal baru, lalu jalankan command -v ash untuk konfirmasi. Pembaru mandiri menginstal biner penggantinya ke lokasi ~/.local/bin/ash yang sama.

Bagaimana cara menggunakan ash tanpa mengubah shell saya?

Lewati perintah yang dikutip secara langsung: ash "how do I find large files?". Tanpa argumen, ash juga menerima perintah input standar non-interaktif, seperti git diff | ash. Penggunaan langsung adalah opsi yang paling tidak mengejutkan saat Anda mempelajari ash atau menulis skrip.

Mengapa ash mengatakan konfigurasi AI saya tidak lengkap?

Periksa apakah AI_ENDPOINT dan AI_MODEL tidak kosong di lingkungan tempat ash dijalankan. Untuk nama host cloud, atur juga AI_AUTH_TOKEN. Jalankan printf '%s\n' "$AI_ENDPOINT" "$AI_MODEL" untuk mengonfirmasi bahwa dua nilai pertama ada, tetapi jangan mencetak token autentikasi ke dalam rekaman terminal atau log bersama.

Menginstal dan Memperbarui

Apakah ash berfungsi di Windows 11?

Tidak secara bawaan. ash mendukung bash, zsh, dan Fish di macOS, Linux, dan FreeBSD; tidak ada target pemasangan PowerShell. Gunakan WSL untuk pengalaman Linux yang didukung.

Bagaimana cara menginstal ash di Subsistem Windows untuk Linux (WSL)?

Menginstalnya di dalam distribusi WSL Anda sebagai Linux: curl -fsSL https://jonconradt.github.io/ash/install.sh | sh. Kemudian konfigurasikan AI_ENDPOINT dan AI_MODEL, dan jalankan ash install untuk shell yang berjalan di dalam WSL.

Bagaimana cara memperbarui ash ke versi rilis terbaru?

Jalankan ash update di macOS, Linux, atau FreeBSD. Ia mengunduh arsip pencocokan stabil terbaru, memverifikasi manifes rilis dengan bundel Sigstore dan intisari SHA-256, lalu menginstal ke ~/.local/bin/ash. Jika verifikasi tanda tangan gagal atau arsip berisi entri yang tidak didukung, diperlukan konfirmasi interaktif; jangan menyetujui tanda tangan yang gagal kecuali Anda memercayai sumber rilis secara independen. Payload yang tidak didukung akan dilewati, dan proses non-interaktif menolak pengecualian ini. Gunakan ash update --version vX.Y.Z untuk versi tertentu; gunakan --yes hanya jika Anda ingin file terkelola khusus diganti.

Saya menjalankan ash install. Mengapa tidak ada perubahan di terminal ini?

Instalasi memperbarui file startup; itu tidak menulis ulang proses shell yang sudah berjalan. Buka terminal baru, atau muat ulang file untuk shell Anda: source ~/.bashrc untuk Bash, source ~/.zshrc untuk zsh, atau source ~/.config/fish/config.fish untuk Fish kecuali Anda menggunakan XDG_CONFIG_HOME khusus.

Perintah yang tidak dikenal masih mengatakan “tidak ditemukan.” Bagaimana cara memecahkan masalah integrasi shell?

Pertama jalankan command -v ash; pembungkusnya tidak dapat memanggil biner yang tidak dapat ditemukan oleh shell Anda. Kemudian muat ulang atau mulai ulang shell dan periksa apakah file startupnya berisi blok terkelola >>> ash install >>>. Terakhir, jalankan ash snooze off, karena penundaan dengan sengaja meninggalkan perintah yang tidak diketahui sebagai kegagalan normal “tidak ditemukan”.

File apa yang diubah ash install, dan dapatkah saya mempratinjaunya?

File ini menambah atau memperbarui blok bertanda ash di file startup shell yang dipilih dan mengelola file di bawah ~/.ash, termasuk konfigurasi, pembungkus, dan alat yang dibundel. Jalankan ash install --shell bash --dry-run untuk melihat pratinjau perubahan file startup tanpa menulisnya. Menginstal ulang instalasi adalah idempoten; gunakan --overwrite hanya jika Anda ingin file bootstrap terkelola disegarkan.

Apakah ash mendukung Fish?

Ya. Jalankan ash install --shell fish. ash menambahkan blok terkelola ke $XDG_CONFIG_HOME/fish/config.fish, atau ~/.config/fish/config.fish ketika XDG_CONFIG_HOME tidak disetel. Fish menggunakan fish_command_not_found, sehingga perintah yang belum terselesaikan mencapai ash dengan argumen aslinya.

Mengapa tidak menggunakan huruf kecil test dan type di Fish?

Fish menyimpan nama huruf kecil tersebut sebagai bawaan penting dan tidak mengizinkan fungsi untuk menggantikannya. Gunakan Test ... atau Type ... untuk menyatakan maksud ash, atau panggil ash "..." secara langsung. Wrapper tabrakan lain yang kompatibel tetap tersedia.

Bagaimana dengan ksh93?

ksh93 tidak didukung untuk integrasi shell. Perilaku FPATH-nya hanya dapat memuat file yang diberi nama berdasarkan perintah yang tidak diketahui; ia tidak memiliki callback command-not-found umum yang dapat dengan aman mengimplementasikan perutean cepat atau siklus hidup broker ash.

AI dan Koneksi

Apakah ash termasuk AI?

Tidak. ash adalah klien untuk titik akhir AI yang Anda konfigurasi. Tetapkan AI_ENDPOINT dan AI_MODEL; ash mendukung Ollama lokal dan server lokal lain yang kompatibel dengan OpenAI (LM Studio, llama.cpp, MLX, LocalAI, vLLM, text-generasi-webui, Jan, GPT4All), dan mendeteksi adaptor penyedia cloud yang didukung dari titik akhir, dengan opsi override AI_PROVIDER.

Apa itu server MCP, dan bagaimana cara menambahkannya satu?

Server MCP (Model Context Protocol) mengekspos alat yang dapat dipanggil oleh model AI, seperti penelusuran, analisis, atau tindakan khusus layanan. Untuk menambahkan server HTTP MCP Streamable jarak jauh, masukkan URL-nya pada barisnya sendiri di ~/.ash/.ash_allow, lalu jalankan ash lagi. Misalnya: https://mcpplaygroundonline.com/mcp-complex-server. Ash terhubung melalui brokernya dan menawarkan alat server ke model. Gunakan hanya server yang Anda percayai: alat mereka mungkin melakukan tindakan atas nama Anda. HTTPS diperlukan kecuali untuk server pengembangan localhost. File ~/.ash/mcp.json yang ada tidak lagi dibaca; pindahkan URL mereka ke .ash_allow. Jika inisialisasi MCP gagal, ash dilanjutkan tanpa alat MCP jarak jauh: alat ini memperingatkan dalam sesi interaktif dan tetap diam dalam sesi non-interaktif.

Dapatkah pekerjaan terjadwal menggunakan server MCP?

Tidak. Pekerjaan terjadwal dan pekerjaan non-interaktif lainnya tidak mewarisi broker shell interaktif, sehingga alat MCP jarak jauh tidak tersedia. Ash masih menjalankan prompt tanpa alat MCP dan menekan kegagalan inisialisasi yang diharapkan. Oleh karena itu, perintah yang bergantung pada MCP mungkin selesai tanpa data atau tindakan yang diminta. Jangan jadwalkan perintah yang memerlukan MCP.

Apakah MCP berfungsi saat ASH_STRICT=1?

Ya. Baris URL HTTP(S) secara eksplisit mendaftarkan server MCP dan tidak diperlakukan sebagai shell yang dapat dieksekusi. Mode ketat tidak menonaktifkan server MCP yang dikonfigurasi. Ini masih menerapkan perlindungan keluaran tidak tepercaya Ash pada konten alat yang dikembalikan.

Bagaimana cara kerja MCP OAuth, dan di mana kredensial disimpan?

Untuk server yang dilindungi OAuth, Ash membuka halaman otorisasi di browser desktop ketika GUI tersedia; jika tidak dapat membuka browser, ia akan mencetak URL untuk diotorisasi secara manual di browser pada host yang sama. Gunakan ash mcp add <url> --no-browser untuk selalu menggunakan aliran terminal. Untuk koneksi OAuth langsung, penemuan mengizinkan alamat IP non-publik hanya untuk otoritas MCP yang terdaftar; host OAuth lainnya tetap tunduk pada pemblokiran alamat non-publik. Proksi jalan keluar yang dikonfigurasi bertanggung jawab untuk memfilter alamat tujuannya. Broker menangani panggilan balik, pertukaran token, penyegaran, dan sesi MCP yang persisten. Kredensial disimpan di manajer kredensial sistem operasi bila tersedia. Jika tidak tersedia, konfigurasikan fallback file terenkripsi menggunakan ASH_MCP_CREDENTIAL_KEY 32-byte acak; Ash tidak pernah menyimpan kunci itu sendiri.

Di mana saya dapat menemukan AUTH_KEY untuk penyedia cloud AI paling populer?

ash menyebut nilai ini AI_AUTH_TOKEN; itu tidak membuat atau mendistribusikan kunci penyedia. Buat kunci di akun penyedia Anda, seperti OpenAI, Anthropic, Google AI Studio, Azure OpenAI, Mistral, Cohere, Groq, xAI, DeepSeek, Bersama AI, OpenRouter, HuggingFace, atau Ollama, lalu ekspor sebagai variabel lingkungan penyedia (atau AI_AUTH_TOKEN secara langsung). ash install mendeteksi secara otomatis sebagian besar variabel lingkungan khusus penyedia ini. Titik akhir cloud harus menggunakan HTTPS dan memerlukan token; alamat pribadi/LAN dan nama host .local tidak diperlakukan sebagai titik akhir cloud kecuali ASH_STRICT=1 disetel.

Apakah ash membuka koneksi baru setiap kali?

Tidak untuk penggunaan shell Unix interaktif normal. Bash, zsh, dan Fish memulai satu broker per sesi shell, berkomunikasi dengannya melalui soket Unix pribadi, dan menggunakan kembali kumpulan koneksi HTTP yang dibatasi. Broker keluar setelah tidak aktif; pekerjaan terjadwal menggunakan permintaan langsung, bukan broker shell persisten.

Apakah Fish menggunakan broker tersebut?

Ya. Fish wrapper memulai dan menggunakan kembali broker per sesi yang sama seperti bash dan zsh, menyegarkan sewanya segera sebelum permintaan ash, dan membuat pengaturan broker tetap tenang.

Apa yang terjadi jika permintaan lambat, tidak tersedia, atau saya berubah pikiran?

Tekan Ctrl-C untuk membatalkan permintaan dalam penerbangan. Batas waktu permintaan AI default adalah tiga menit; atur AI_TIMEOUT, misalnya AI_TIMEOUT=90s, untuk mengubahnya. ash mencoba ulang kegagalan AI yang dapat dicoba hingga tiga kali secara default dengan batas waktu yang singkat; sesuaikan perilaku tersebut dengan ASH_RETRY_MAX_ATTEMPTS, ASH_RETRY_BASE_DELAY, dan ASH_RETRY_MAX_DELAY.

Keamanan dan Kontrol

Bagaimana cara mengunci ash agar lebih aman, dan apa implikasinya?

Jaga agar daftar eksekusi yang diizinkan tetap sempit, pilih alat hanya-baca, dan jangan tambahkan perintah istimewa atau destruktif. Setel ASH_STRICT=1 untuk memblokir pola injeksi cepat yang dikenali dari alat, file, skrip, saluran pipa, dan keluaran agen anak yang tidak tepercaya. Ini juga dapat menyembunyikan teks sah yang menyerupai upaya penyuntikan. Daftar yang diizinkan adalah batas eksekusi, bukan kotak pasir: ash dan alat yang diizinkan masih berjalan sesuai keinginan Anda.

Dapatkah ash menjalankan perintah destruktif seperti rm?

Tidak dengan daftar izin default yang terpasang. Ini secara eksplisit menyarankan agar rm, mv, dd, chmod, chown, kill, dan sudo. Jika Anda menambahkan salah satunya, ash dapat memintanya dengan izin Anda; tinjau keputusan itu dengan hati-hati.

Bagaimana cara mengubah perintah ash yang boleh dijalankan?

Edit ~/.ash/.ash_allow dan daftarkan nama-nama yang dapat dieksekusi, satu per baris atau dipisahkan koma. Perintah $TOOLS_DIR_LIST dan $PLUGINS_DIR_LIST yang berdiri sendiri mengizinkan skrip terkelola dan plugin asli yang memenuhi syarat; gantilah dengan nama literal untuk kebijakan yang membatasi. Skrip dan plugin yang memenuhi syarat adalah file biasa dalam ~/.ash/tools/ atau ~/.ash/plugins/ dengan bit baca dan eksekusi. Anda juga dapat menolak perintah secara eksplisit dengan menambahkannya ke ~/.ash/.ash_deny. Atau atur ASH_ALLOW atau ASH_DENY ke daftar yang dipisahkan koma. Perubahan dibaca pada permintaan ash berikutnya.

Pengguna apa yang menjalankan ash?

ash dan setiap alat yang diizinkan dijalankan sebagai pengguna yang memulai ash. Itu tidak meningkatkan hak istimewa. Ruang kerja ~/.ash yang dikelola telah diperketat izinnya, namun kontennya tetap dapat diakses oleh pengguna Anda dan proses apa pun yang Anda izinkan secara eksplisit.

Apakah teks kepercayaan ash yang diterima melalui pipa sama dengan teks pengguna? Perlindungan apa saja yang tersedia untuk data berbahaya?

Ya. Ketika ash tidak menerima argumen baris perintah dan masukan standar disalurkan, masukan tersebut akan diperlakukan sebagai perintah pengguna. Jangan menyalurkan halaman web, log, atau teks yang tidak tepercaya secara langsung ke ash kecuali Anda ingin mengotorisasinya sebagai perintah. Hal ini berbeda dengan keluaran alat, file, skrip, pipeline, dan agen turunan yang dikelola ash: ash memberi label pada hasil tersebut sebagai bukti yang tidak tepercaya dan menginstruksikan model untuk tidak pernah mengikuti instruksi dari bukti tersebut. Setel ASH_STRICT=1 untuk menggantikan frasa injeksi cepat yang dikenali dalam bukti yang tidak tepercaya. Aturan eksekusi daftar yang diizinkan dan direct-argv masih berlaku untuk eksekusi alat.

Apakah file ash saya bersifat pribadi dari pengguna lain di komputer ini?

Selama instalasi, ash mengeraskan direktori ~/.ash menjadi izin hanya pemilik dan file terkelola menjadi izin yang dapat dibaca dan ditulis oleh pemilik. Ini melindungi terhadap akun lokal lain dengan izin Unix normal, namun tidak terhadap akun Anda sendiri, administrator, cadangan, atau perangkat lunak yang Anda pilih untuk dijalankan dengan akses ke direktori beranda Anda.

Alat dan Alur Kerja

Apakah ash mendukung pipa dan tradisi Unix lainnya?

Ya. Anda dapat menyalurkan teks ke ash sebagai perintah, misalnya git diff | ash. Untuk pipeline alat yang diminta AI, ash mendukung dua hingga enam belas executable yang diizinkan dan terhubung langsung tanpa shell, seperti ls | grep pattern | pbcopy. Pola kontrol shell dalam argumen alat diblokir, dan setiap eksekusi dalam pipeline yang dikelola ash harus diizinkan.

Akankah ash menafsirkan ulang perintah di dalam skrip shell, perintah SSH, atau tugas cron saya?

Tidak. Pembungkus integrasi Bash dan zsh segera kembali dalam shell non-interaktif, sehingga skrip, tugas CI, satu baris SSH, dan perintah cron mempertahankan perilaku normal command-not-found. Gunakan pemanggilan eksplisit seperti ash "summarize this log" atau some-command | ash ketika automasi memanggil ash.

Bagaimana cara menghentikan ash menafsirkan perintah saya selama beberapa menit?

Jalankan ash snooze selama lima menit default, atau tentukan durasi seperti ash snooze 30s atau ash snooze 1h. Jalankan ash snooze off untuk segera melanjutkan. Tunda menjeda perutean perintah-tidak-ditemukan dan pembungkus otomatis; perintah eksplisit ash ... masih berfungsi.

Bagaimana cara men-debug ash dan melihat informasi selengkapnya tentang apa yang dilakukannya?

Setel ASH_VERBOSE=1 sebelum menjalankan ash untuk mengaktifkan keluaran debug terstruktur dan dasbor eksekusi terminal. Setel ASH_LOG_FILE untuk menulis debug JSON ke file; ASH_LOG_MAX_BYTES mengontrol rotasi dan default ke 1 MiB saat file log dikonfigurasi.

Batasan apa yang berlaku saat ash menjalankan alat?

Secara default, setiap panggilan alat memiliki batas waktu 15 detik dan menangkap output hingga 8192 byte. Permintaan AI dapat menghasilkan hingga 16 iterasi perulangan alat, dan pipeline yang dikelola ash memiliki dua hingga enam belas tahap. Sesuaikan batas waktu habis alat dan batas keluaran dengan ASH_TOOL_TIMEOUT dan ASH_TOOL_OUTPUT_MAX; menjaga keluaran tetap fokus dengan perintah seperti head, tail, atau grep.

Di mana perintah sistem default?

File prompt kanonik adalah ~/.ash/.ash_system, diinstal dari paket default saat Anda menjalankan ash install. ash membaca file itu terlebih dahulu. Jika tidak ada, ash kembali ke .ash_system di direktori kerja saat ini dan kemudian ~/.ash_system. Nilai $VARIABLE biasa diperluas dari lingkungan, tetapi $TOOLS_DIR_LIST, $PLUGINS_DIR_LIST, dan $IF_PYTHON_AVAILABLE dicadangkan sebagai pengganti Ash internal dan tidak pernah berasal dari lingkungan.

Di mana saya dapat meletakkan skrip dan plugin asli saya sendiri ash untuk dipanggil sebagai alat?

Masukkan skrip Python di ~/.ash/tools/ dan kompilasi plugin biner asli di ~/.ash/plugins/. Pastikan mereka dapat dieksekusi, dan tambahkan nama kosong yang dapat dieksekusi ke ~/.ash/.ash_allow (atau andalkan $TOOLS_DIR_LIST / $PLUGINS_DIR_LIST). ash tidak memanggil shell untuk perintah dan plugin Unix yang diizinkan.

Apa praktik terbaik untuk alat atau plugin sehingga AI memahami tujuan dan penggunaannya?

Ikuti pola alat/plugin standar: tampilkan opsi yang dapat diprediksi dengan argumen CLI; dan menerapkan opsi --ai-docs yang menjelaskan kemampuan, setiap argumen dan default, skema keluaran, status kegagalan, dan kapan AI harus menggunakan alat tersebut. Memancarkan JSON terstruktur ringkas dengan bidang status dan detail kesalahan yang dapat ditindaklanjuti, bukan prosa yang dicampur dengan data. Pertahankan batas keluaran, validasi masukan, tetapkan batas waktu jaringan, tangani kegagalan yang diperkirakan, dan jadikan alat aman untuk dipanggil berulang kali. Tambahkan nama file aslinya ke ~/.ash/.ash_allow; ash dapat menjalankannya hanya jika diizinkan dan tidak tercantum dalam ~/.ash/.ash_deny.

Apa saja skrip alat dan plugin asli yang disediakan?

Skrip bootstrap Python yang diinstal adalah headlines.py, wikipedia.py, dan yfinance.py di ~/.ash/tools/. Plugin asli yang disediakan adalah what_time_is_it (Go), flip_a_coin (Rust), dan calculator (TypeScript) di ~/.ash/plugins/.

Dapatkah ash menghubungi sub-agen?

Ya. Agen orang tua dapat menggunakan run_sub_agent untuk satu tugas yang terfokus dan independen. Seorang anak mewarisi direktori kerja, konfigurasi, alat, dan izin OS, mengembalikan hasil yang dibatasi, dan tidak dapat membuat anak lain. Maksimum default adalah enam sub-agen per proses induk dan dapat diubah dengan ASH_MAX_AGENTS.

Dapatkah ash menghasilkan file memori untuk melacak tugas-tugas kompleks dan apa yang telah dipelajari dalam sesi ini?

Ya. Itu dapat menulis file ruang kerja persisten di bawah ~/.ash, yang dilacak di ~/.ash/inventory.md, dan file awal cakupan sesi di bawah ~/.ash/scratch/<session-id>/. Gunakan file ruang kerja persisten untuk informasi yang ingin Anda simpan; menggunakan file awal untuk rencana sementara, catatan, dan artefak pembantu.

Dapatkah ash menjadwalkan pekerjaan untuk nanti?

Ya, melalui alat AI-nya. Di macOS, penjadwalan satu kali menggunakan launchd LaunchAgent per pengguna dan memerlukan launchctl. Di Linux, jadwal berulang didukung melalui pengguna Anda crontab; ash hanya mengelola entri yang ditandainya sendiri. Penjadwal launchd satu kali tidak tersedia di Linux, jadi gunakan entri cron atau penjadwal Linux lainnya untuk pekerjaan Linux satu kali. Proses terjadwal menerima lingkungan terbatas dan menggunakan HTTPS langsung, bukan broker shell interaktif, jadi pastikan konfigurasi AI yang diperlukan tersedia untuk pekerjaan terjadwal. Mereka tidak dapat menggunakan alat MCP jarak jauh; Ash berjalan tanpa mereka dan tidak memperingatkan dalam sesi non-interaktif. Jangan jadwalkan perintah yang memerlukan MCP.

Sesi dan Penyimpanan

Di mana riwayat atau file log untuk ash?

Riwayat percakapan disimpan sebagai JSON di ~/.ash/history/<SESSION_ID>.json; proses terjadwal gunakan task_<SESSION_ID>.json. Jika pencatatan debug terjadwal diaktifkan, lokasi log defaultnya adalah ~/.ash/logs/task_<SESSION_ID>.log. Anda dapat memilih jalur log debug lainnya dengan ASH_LOG_FILE.

Berapa lama file riwayat disimpan?

ash menghapus file JSON riwayat yang lebih lama dari 14 hari selama pembersihan aplikasi normal, dengan anggaran pembersihan 300 ms sehingga keluar tidak tertunda. Jendela pesan terbaru terpisah: jendela ini menyimpan hingga 40 pesan per percakapan secara default dan dapat diubah dengan ASH_HISTORY_MAX.

Bagaimana cara menghapus percakapan atau memulai percakapan baru?

Riwayat dipisahkan oleh ID sesi dan titik akhir/kunci model AI. Mulai sesi terminal baru untuk ID sesi baru, atau hapus file JSON yang relevan di bawah ~/.ash/history/ ketika Anda dengan sengaja ingin membuang riwayat percakapan lokal tersebut. Menghapus file riwayat tidak mencabut kunci penyedia atau menghapus data sisi penyedia; kelola secara terpisah dengan penyedia.

Apa itu SESSION_ID dan di mana pembuatannya?

Ini adalah pengidentifikasi per sesi yang digunakan untuk memisahkan riwayat, ruang awal, soket broker, dan nama log terjadwal. Lingkungan shell yang dikelola menghasilkan nilai alfanumerik 16 karakter acak dari /dev/urandom saat shell dimulai; ash juga membuatnya ketika pemanggilan interaktif tidak memiliki nilai.

Dapatkah saya mengganti implementasi generator SESSION_ID?

Anda dapat menyediakan SESSION_ID Anda sendiri sebelum memulai ash atau menyesuaikan file lingkungan terkelola lokal Anda, tetapi ash memvalidasinya. ID yang valid terdiri dari maksimal 128 karakter dan menggunakan huruf, angka, garis bawah, tanda hubung, dengan satu akhiran titik sesi anak opsional. Jangan gunakan nilai yang tidak dipercaya atau dibagikan: tabrakan menggabungkan riwayat sesi dan status waktu proses.

Dukungan dan Komunitas

Bagaimana cara melaporkan bug?

Buka masalah di github.com/Jonconradt/ash/issues dengan versi atau komit ash, sistem operasi dan shell Anda, konfigurasi yang relevan dengan masalah rahasia dihapus, langkah-langkah yang dapat direproduksi, dan hasil yang diamati. Untuk kerentanan keamanan, jangan membuka isu publik; laporkan secara pribadi melalui email atau penasihat keamanan GitHub.

Apakah ada papan diskusi di proyek ash?

Ya. Gunakan Diskusi GitHub untuk pertanyaan dan ide, dan Masalah GitHub untuk bug yang dapat direproduksi dan pekerjaan yang dilacak.
