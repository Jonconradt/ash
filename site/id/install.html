Sebelum memulai

  1. Sistem dan shell didukung: macOS/Linux pada amd64/x86_64 atau arm64/aarch64, atau FreeBSD pada amd64. Gunakan Bash, zsh, atau Fish. Paket Arch hanya x86_64. Tidak ada pemasang Windows/PowerShell native.
  2. Akses unduhan: koneksi Internet berfungsi dan akses HTTPS tepercaya ke GitHub, repositori terpilih, serta penyedia model. Inferensi lokal tetap memerlukan unduhan model awal.
  3. Izin: direktori rumah dapat ditulis untuk aset pengguna. Paket sistem Linux dan .pkg macOS membutuhkan administrator; jalankan Homebrew dan ash install sebagai pengguna biasa.
  4. Model: server inferensi lokal dengan model terunduh atau akun cloud/kunci API. Pilih model dengan pemanggilan alat, bukan khusus gambar/audio. Kebutuhan RAM, disk, GPU lokal bergantung model.

Paket ash siap pakai tidak memerlukan Go, Rust, Node.js, atau alat build Xcode. Pengelola paket mungkin punya prasyarat sendiri; ikuti petunjuk resminya dahulu.

Opsional: alat Python bawaan

Penggunaan dasar tidak membutuhkan Python. Alat bawaan perlu Python 3 dengan venv dan ensurepip serta akses unduhan dependensi. Pada Debian/Ubuntu pasang python3 dan python3-venv; Python Homebrew mencakup venv. Pada FreeBSD gunakan paket pip sesuai versi Python. Ulangi ash install. Penyiapan membuat lingkungan terisolasi di $XDG_DATA_HOME/ash/venv (default ~/.local/share/ash/venv); kegagalan menonaktifkan alat itu, bukan ash dasar.

macOS

Disarankan: Homebrew

Prasyarat: Homebrew, lingkungan macOS didukung, dan perintah brew berfungsi. Tap otomatis memilih arsip Intel/Apple Silicon. Pasang Release tanpa sudo:

brew install Jonconradt/ash/ash
ash version

Homebrew mengelola biner, plugin native, halaman manual, dan pemberitahuan lisensi dalam prefiksnya (biasanya /opt/homebrew pada Apple Silicon atau /usr/local pada Intel). Arsip diperiksa terhadap SHA-256 formula. Tidak mengatur penyedia atau startup shell: lanjutkan inisialisasi per pengguna. Perbarui dengan brew upgrade ash, hapus Release dengan brew uninstall ash; lihat formula kanal untuk Beta/Nightly.

Alternatif: .pkg native

Unduh darwin-arm64.pkg untuk Apple Silicon atau darwin-amd64.pkg untuk Intel dari rilis terpublikasi. Verifikasi manifes checksum bertanda tangan sebelum membuka pemasang. Memerlukan administrator.

Paket macOS tidak ditandatangani atau dinotarisasi. Manifes memberi verifikasi penerbit/checksum terpisah, bukan notarisasi Apple. Jangan nonaktifkan Gatekeeper atau lewati peringatan demi memasang ash; gunakan Homebrew jika kebijakan keamanan mengharuskan.

Paket menulis ash dan ash-broker ke /usr/local/bin, plugin ke /usr/local/lib/ash/plugins, manual ke /usr/local/share/man, pemberitahuan ke /usr/local/share/licenses/ash. Tanda terimanya dev.ash.cli. Tidak menginisialisasi pengguna atau berlangganan pembaruan: inisialisasi setelah pemasangan, ganti dengan .pkg terbaru terverifikasi untuk pembaruan, dan gunakan penghapusan manual untuk melepas. Jangan timpa salinan milik Homebrew.

Linux

Gunakan pengelola distribusi bila memungkinkan. Paket ini mengelola /usr/bin/ash, /usr/bin/ash-broker, /usr/lib/ash/plugins, manual di /usr/share/man, dan pemberitahuan lisensi. Pengaturan penyedia dan hook shell diserahkan ke inisialisasi per pengguna.

Debian dan Ubuntu: APT

Prasyarat: amd64/arm64, administrator, APT, curl, gpg, sertifikat CA. Pasang alat unduhan/kunci yang belum ada melalui distribusi sebelum repositori. Release dinamai stable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Sebelum mengimpor kunci, cocokkan sidik jari dengan sumber penerbit tepercaya. Sidik jari VersionX adalah 32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. APT memeriksa metadata repositori bertanda tangan dan digest paket di dalamnya; signed-by membatasi cakupan kunci. Perbarui: sudo apt update && sudo apt upgrade ash; hapus: sudo apt remove ash.

Fedora dan sistem kompatibel RHEL: DNF

Prasyarat: x86_64/aarch64, administrator, DNF/RPM, curl, gpg, sertifikat CA. Pasang alat yang kurang melalui distribusi. Periksa kunci dan cocokkan sidik jari di atas sebelum impor:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

RPM tidak ditandatangani satu per satu. repo_gpgcheck=1 memverifikasi metadata yang mencakup checksum; gpgcheck=0 mencerminkan tidak adanya tanda tangan per paket, bukan mematikan verifikasi repositori. Bila kebijakan mewajibkan muatan RPM bertanda tangan, repositori ini tidak memenuhi. Perbarui: sudo dnf upgrade ash; hapus: sudo dnf remove ash.

Arch Linux: Pacman

Prasyarat: x86_64, administrator, Pacman dengan keyring diinisialisasi, curl, gpg. Cocokkan sidik jari yang tampil dengan di atas sebelum mempercayai. Tambahkan repositori sekali, bukan setiap pembaruan:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman memverifikasi tanda tangan paket dan basis data. Sinkronkan Arch dengan sudo pacman -Syu, bukan pembaruan parsial; hapus ash dengan sudo pacman -R ash.

Metode Linux lainnya

Sudah memakai Homebrew di Linux? Petunjuk tap yang sama mendukung amd64/arm64; Brew mengelola berkas, bukan APT/DNF. Jika tidak, gunakan skrip/arsip terverifikasi atau unduhan .deb/.rpm sesuai. Pasang .deb terverifikasi dengan sudo apt install ./PACKAGE.deb, .rpm dengan sudo dnf install ./PACKAGE.rpm (ganti nama berkas). Paket langsung tetap dikelola, tetapi tidak menambahkan repositori atau langganan rilis berikutnya. RPM saat ini tidak bertanda tangan; patuhi kebijakan distribusi, jangan matikan pemeriksaan.

FreeBSD

Prasyarat: amd64, Bash (walau shell interaktif zsh/Fish), alat unduh/verifikasi, direktori pemasangan dapat ditulis. Pasang Bash melalui pengelola native FreeBSD:

sudo pkg install bash

pkg FreeBSD mengelola prasyarat, bukan ash: belum ada repositori ash .pkg atau arsip arm64. Gunakan skrip terverifikasi, atau verifikasi tarball FreeBSD amd64, ekstrak ke direktori sementara dan pasang biner ash berversi sebagai ~/.local/bin/ash di samping ash-broker. Salin plugin native ke $XDG_DATA_HOME/ash/plugins (default ~/.local/share/ash/plugins), lalu inisialisasi. Anda mengelola berkas ini; pkg delete tidak menghapusnya. Gunakan pembaruan mandiri Release di lokasi default atau ganti artefak terverifikasi manual.

Inisialisasi dan periksa

Setelah biner terpasang, jalankan penyiapan interaktif sebagai pengguna biasa. Penyiapan hanya aset membiarkan startup tetap:

ash install

Untuk integrasi perintah tidak ditemukan, pilih tepat satu perintah sesuai shell:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Fish

ash install --shell fish --shell-integration

Bash memakai ~/.bashrc, zsh ~/.zshrc, Fish $XDG_CONFIG_HOME/fish/config.fish (default ~/.config/fish/config.fish). Buka shell baru; shell lama mempertahankan broker aktif. Integrasi menambahkan ~/.local/bin di depan PATH: hapus salinan lokal lama sebelum mengharapkan paket sistem terpilih.

Jika pengaturan belum ada, penyiapan mendeteksi kunci atau server lokal aktif; jika tidak, menawarkan menu penyedia dan meminta kredensial. Pilih model tersedia dengan alat. Pengaturan valid dipertahankan; mengulang penyiapan tidak mengganti penyedia.

Pengaturan di $XDG_CONFIG_HOME/ash/.ash_env (default ~/.config/ash/.ash_env, izin privat). Integrasi terkelola memuatnya. Tanpa integrasi, Bash/zsh dapat memuat berkas di startup biasa; Fish harus menetapkan variabel ASH_AI_* dalam sintaks Fish, bukan memuat format Bash. Lindungi berkas token dan jangan commit.

Tanpa integrasi, tambahkan direktori pemasangan lokal sebenarnya ke PATH. Bash/zsh: export PATH="$HOME/.local/bin:$PATH". Fish: fish_add_path "$HOME/.local/bin". Simpan dalam startup shell; ganti dengan direktori khusus bila perlu.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

Perintah awal harus menunjuk pemasangan terpilih. Permintaan memerlukan server aktif atau kredensial cloud valid; memasang ash tidak memasang model.

Ollama lokal: tanpa akun cloud

Pasang Ollama mengikuti petunjuk OS resmi. Mulai aplikasi/layanan atau jalankan ollama serve di terminal lain jika server belum aktif. Dukungan FreeBSD ash tidak berarti pemasang Ollama native: gunakan server terjangkau pada host lain yang didukung bila perlu.

Unduh model dengan alat sesuai hardware; llama3.1:8b adalah contoh, bukan minimum. Lihat katalog alat terkini untuk pilihan lain:

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

Tanpa kunci cloud sudah ditetapkan, server lokal dapat dideteksi dan model terunduh ditawarkan. Jika penyedia lain sudah dikonfigurasi, ubah endpoint/model manual. Contoh Bash/zsh:

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Padanan Fish:

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Perubahan hanya berlaku di shell saat ini. Simpan di berkas lingkungan ash terlindungi atau konfigurasi shell sesuai, mengganti pengaturan penyedia lama. Ollama lokal tidak perlu token. Biarkan server pada loopback kecuali akses diamankan sengaja; server remote menerima permintaan dan keluaran alat.

Opsional: tetapkan OLLAMA_KEEP_ALIVE=30m di lingkungan server Ollama lalu mulai ulang agar model tetap termuat. -1 mempertahankan selamanya tetapi memakai memori di antara permintaan. Menetapkan hanya di terminal klien ash tidak mengatur ulang server aktif.

Inferensi lokal tidak menagih API, tetapi memakai hardware/penyimpanan/listrik. Ollama cloud adalah layanan terpisah dengan autentikasi dan batas paket, bukan penyiapan lokal ini.

Paket cloud gratis

Gratis bukan berarti tanpa batas atau privat. Akun, wilayah, kuota, model, kebijakan data berbeda dan berubah. Permintaan dan keluaran relevan keluar dari mesin. Tinjau batas/syarat terkini; aktifkan penagihan berbayar hanya jika berniat membayar.

Buat kunci lewat tautan, jalankan ash install interaktif dan pilih penyedia. Token diminta, model didaftar bila didukung. Pilih model teks gratis dengan pemanggilan alat yang tersedia; tercantum tidak menjamin gratis bagi akun Anda.

Konfigurasi manual atau mengganti penyedia

Ganti endpoint berikut dengan tabel dan MODEL_ID dengan model terverifikasi di akun. Bila kunci sudah diekspor sebagai GROQ_API_KEY, contoh Bash/zsh memakai ulang tanpa mengetik rahasia:

export ASH_AI_ENDPOINT="https://api.groq.com/openai/v1"
export ASH_AI_MODEL="MODEL_ID"
export ASH_AI_AUTH_TOKEN="$GROQ_API_KEY"

Padanan Fish:

set -gx ASH_AI_ENDPOINT https://api.groq.com/openai/v1
set -gx ASH_AI_MODEL MODEL_ID
set -gx ASH_AI_AUTH_TOKEN "$GROQ_API_KEY"

Untuk Gemini/OpenRouter gunakan endpoint dan variabel kunci masing-masing. Simpan aman untuk shell berikutnya. Cloud perlu HTTPS dan token; HTTP lokal bukan jalan pintas cloud. Lihat referensi lingkungan dan penyedia lain didukung untuk layanan berbayar dan pengaturan lanjutan.

Pemasangan skrip: alternatif, bukan pilihan pertama

Utamakan Homebrew, APT, DNF, Pacman: melacak berkas, memverifikasi unduhan sesuai kepercayaannya dan menawarkan pembaruan/penghapusan familiar. Tetap perlu mempercayai penerbit dan tindakan pemasangan.

Skrip situs menjalankan kode dengan izin akun Anda. Situs/penerbit diretas atau skrip berubah dapat membaca rahasia, mengubah berkas, memasang software lain. HTTPS melindungi transport, bukan niat kode. Mengalirkan URL langsung ke shell mengeksekusi sebelum ditinjau. Tanda tangan arsip tidak mengautentikasi skrip sendiri. Jangan jalankan dengan sudo atau matikan verifikasinya.

Prasyarat: OS/arsitektur didukung, $SHELL menunjukkan Bash/zsh/Fish, Sigstore cosign, tar, uname, install, utilitas shell standar, perintah SHA-256 (sha256sum, shasum, atau sha256), downloader (curl, wget, atau Python). Contoh memakai curl. FreeBSD perlu Bash juga. Direktori rumah/pemasangan harus dapat ditulis.

Unduh ke berkas lokal, tinjau dengan editor, jalankan hanya jika percaya sumber dan perilakunya. Tinjauan tidak menjamin aman; jangan ikuti langkah secara buta:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

Setelah ditinjau, jalankan salinan sebagai pengguna biasa:

sh ./ash-install.sh
rm ./ash-install.sh

install.sh mengunduh Release terbaru, memverifikasi manifes bertanda tangan Sigstore dan digest arsip, memasang ash/ash-broker di ~/.local/bin. Plugin native di $XDG_DATA_HOME/ash/plugins. Menyiapkan pengguna dan bertanya sebelum integrasi shell. Tanpa terminal interaktif pertanyaan dapat dilewati: jalankan ash install interaktif sesudahnya.

Tetapkan ASH_INSTALL_DIR sebelum skrip untuk lokasi lain. Tambahkan sendiri ke PATH. Pembaruan mandiri hanya mendukung ~/.local/bin; lokasi khusus perlu penggantian manual. Tidak ada pemilih Beta/Nightly.

Verifikasi paket atau arsip langsung

Prasyarat: cosign dan utilitas SHA-256. Unduh paket/arsip, SHA256SUMS, SHA256SUMS.sigstore.json dari rilis sama. Gunakan direktori baru. Ganti vX.Y.Z dengan tag tepat termasuk akhiran prarilis bila ada:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Hanya setelah berhasil hitung digest dengan shasum -a 256 PACKAGE di macOS, sha256sum PACKAGE di Linux, sha256 -q PACKAGE di FreeBSD. Ganti PACKAGE dengan nama unduhan dan cocokkan persis dengan entrinya dalam manifes terverifikasi. Berhenti bila hilang atau berbeda. Checksum tanpa tanda tangan di samping berkas bukan metadata penerbit terverifikasi.

Pembaruan dan tiga kanal

  • Release (disarankan): versi stabil seperti vX.Y.Z; konfigurasi repositori menyebut stable.
  • Beta: pengujian prarilis, tag vX.Y.Z-beta.N; antisipasi perubahan dan regresi.
  • Nightly: perubahan baru cabang default, tag vX.Y.Z-nightly.YYYYMMDD.N; risiko regresi tertinggi. Build terjadwal bisa dilewati tanpa perubahan atau saat publikasi gagal.

Rilis terpublikasi memperbarui formula Homebrew atau repositori Linux bertanda tangan terkait. Diterima saat menjalankan upgrade pengelola pemilik atau kebijakan OS. Publikasi, repositori, situs bisa tertinggal satu sama lain; periksa sebelum pindah kanal. ash tidak diam-diam memasang pembaruan biner latar belakang.

Homebrew: memasang atau mengganti formula

Untuk pemasangan Beta/Nightly baru, gunakan nama formula lengkap di atas dalam brew install. Saat pindah, hapus formula lama dahulu: ketiganya memberi biner sama. Contoh Release ke Beta:

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

Gunakan ash-nightly untuk Nightly atau ash untuk Release dalam pemasangan/upgrade. Hapus formula kanal lama sebenarnya, tidak selalu ash. Pengaturan pengguna tetap; buka shell baru sesudahnya.

Linux: pilih satu kanal repositori

APT: gunakan penyiapan APT dengan tepat satu distribusi tabel. Untuk pindah ubah /etc/apt/sources.list.d/versionx.list, ganti stable dengan beta atau nightly (atau kembali stable), lalu:

sudo apt update
sudo apt install --allow-downgrades ash

DNF: gunakan penyiapan DNF dengan baseurl dipilih. Pada pemasangan lama ganti baseurl di /etc/yum.repos.d/versionx.repo, pertahankan pengaturan tanda tangan, lalu:

sudo dnf --refresh distro-sync ash

Pacman: gunakan penyiapan Pacman dengan URL Server dipilih. Pertahankan bagian [versionx]: setiap kanal menerbitkan database versionx.db. Ganti Server di bagian itu, bukan menambah database berbeda nama. Untuk pindah, termasuk downgrade:

sudo pacman -Syuu ash

Tinjau transaksi: kembali Release dapat menurunkan ash, dan u ganda Pacman juga paket lain. Cadangkan konfigurasi dahulu. Lalu gunakan upgrade normal APT/DNF/Pacman pada bagian OS; jangan aktifkan banyak sumber kanal ash.

Pembaruan Release lokal pengguna

ash update

Memverifikasi dan memasang stabil hanya jika ash aktif di ~/.local/bin. Aset/plugin diperbarui juga, dengan pilihan untuk berkas khusus. ash update --version vX.Y.Z memilih tag stabil, bukan kanal; bukan perintah downgrade. Tidak ada --channel. Paket terkelola, .pkg, tujuan skrip khusus harus memakai pengelola/pemasangnya. FreeBSD Beta/Nightly memakai arsip terverifikasi manual, bukan langganan updater. Buka shell baru sesudahnya.

Menghapus tanpa berkas tak terkait

1. Nonaktifkan integrasi shell dahulu

Sebelum biner dihapus, jalankan perintah untuk setiap shell dengan integrasi:

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Fish

ash install --shell fish --disable-shell-integration

Jika ash sudah hilang, ubah startup dari inisialisasi dan hapus hanya blok antara # >>> ash install >>> dan # <<< ash install <<<. Hapus baris PATH/lingkungan ash yang ditambah manual, bukan konfigurasi lain. Tutup shell ash agar brokernya keluar.

2. Biarkan pengelola pemilik menghapus berkasnya

Homebrew (Release)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

Pilih hanya metode Anda; Homebrew Beta/Nightly gunakan ash-beta/ash-nightly. APT/DNF/Pacman menghapus biner, plugin, manual sendiri, bukan konfigurasi/riwayat rumah. Jangan hapus berkas paket manual.

Pembersihan opsional: hapus sumber ash /etc/apt/sources.list.d/versionx.list dan kunci khusus /etc/apt/keyrings/versionx-keyring.gpg, repositori /etc/yum.repos.d/versionx.repo, atau bagian ash [versionx] dari /etc/pacman.conf. Pastikan paket lain tidak memakainya. Hapus kunci RPM/Pacman setelah sidik jari dan tiadanya ketergantungan dipastikan; jangan hapus keyring bersama distribusi.

3a. Penghapusan .pkg macOS manual

macOS Installer mencatat tanda terima tetapi tidak punya penghapus ash. Pastikan .pkg, bukan Homebrew, dan periksa muatan tepatnya:

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

Dengan tanda terima sebagai inventaris, hapus hanya milik ash: /usr/local/bin/ash, /usr/local/bin/ash-broker, berkas di /usr/local/lib/ash/plugins, /usr/local/share/man/man1/ash.1, halaman terlokalisasi ash.1 tercantum, pemberitahuan di /usr/local/share/licenses/ash. Perlu administrator. Periksa pemilik jika pemasang lain telah mengganti; jangan hapus salinannya. Hapus direktori kosong khusus ash, bukan bersama /usr/local, bin, manual.

Setelah muatan dihapus, opsional hapus tanda terima:

sudo pkgutil --forget dev.ash.cli

Melupakan tanda terima tidak menghapus berkas terpasang. Simpan hingga pemeriksaan selesai.

3b. Penghapusan arsip lokal / Linux / FreeBSD manual

Temukan salinan aktif dengan command -v ash dan command -v ash-broker. Pada skrip default, setelah hook mati, hapus tepat dua berkas:

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

Untuk ASH_INSTALL_DIR atau arsip manual hapus hanya jalur ash/broker nyata. Hapus plugin/manual/pemberitahuan menurut inventaris asli; plugin skrip di data pengguna ash. Di /usr/bin periksa pemilik dahulu dengan dpkg -S /usr/bin/ash, rpm -qf /usr/bin/ash, atau pacman -Qo /usr/bin/ash. Salinan terkelola wajib dihapus lewat pengelola meski unduhan mandiri.

4. Opsional: hapus pengaturan, alat, riwayat lokal

Cadangkan yang ingin disimpan. Langkah terpisah ini bisa menghapus pengaturan/token, alat/plugin khusus, percakapan, berkas kerja. Menghapus biner bukan persetujuan untuk itu.

  • Konfigurasi: $XDG_CONFIG_HOME/ash, default ~/.config/ash.
  • Data, plugin, lingkungan Python: $XDG_DATA_HOME/ash, default ~/.local/share/ash.
  • Riwayat dan status: $XDG_STATE_HOME/ash, default ~/.local/state/ash.
  • Cache: $XDG_CACHE_HOME/ash, default ~/.cache/ash.
  • Runtime broker: $XDG_RUNTIME_DIR/ash, atau $XDG_STATE_HOME/ash/runtime jika akar runtime tidak tersedia.

Periksa override XDG absolut nyata sebelum menghapus hanya subdirektori ash; jangan akar XDG atau rumah. Setelah semua shell ash ditutup, hapus sisa runtime bila perlu. Kredensial MCP OAuth dapat tertinggal di pengelola OS: hapus entri ash dan cabut akses pada penyedia MCP. Cabut kunci AI tak terpakai di akun penyedia; menghapus berkas tidak mencabut kunci. Jangan hapus Ollama/model, Python, atau dependensi bersama saat melepas ash.

Pemecahan masalah singkat

Perintah hilang atau versi salah
Periksa PATH dan command -v ash/command -v ash-broker. Salinan lama di ~/.local/bin dapat menutupi paket. Gunakan satu pemilik/kanal dan buka shell baru.
Menu penyedia tidak tampil
Jalankan ash install interaktif. Pengaturan valid tetap; gunakan konfigurasi manual untuk pindah. Tanpa integrasi pastikan pengaturan diekspor ke lingkungan CLI.
Tidak ada model atau koneksi ditolak
Untuk Ollama pastikan server aktif dan model ada di ollama list. Cloud: periksa endpoint, kelayakan, HTTPS, token, kuota; jangan bagikan log bertoken.
Repositori atau kanal tak tersedia
Periksa arsitektur serta rilis/repositori terpublikasi. Publikasi dapat terlambat; jangan matikan verifikasi tanda tangan untuk mengatasi.
Penyiapan Python gagal
Pasang Python dengan venv/ensurepip, izinkan unduhan dependensi, ulangi ash install. ash dasar tetap dapat dipakai tanpa alat itu.
