Sebelum Anda memulai

  1. Sistem dan shell yang didukung: macOS atau Linux di amd64/x86_64 atau arm64/aarch64, atau FreeBSD di amd64. Gunakan Bash, zsh, atau Fish. Paket Arch hanya x86_64. Tidak ada penginstal Windows/PowerShell asli.
  2. Akses unduhan: koneksi internet yang berfungsi dan akses HTTPS tepercaya ke GitHub, repositori paket yang dipilih, dan penyedia model Anda. Inferensi lokal masih memerlukan pengunduhan model awal.
  3. Izin: direktori beranda yang dapat ditulis untuk aset per pengguna. Paket sistem Linux dan macOS .pkg memerlukan akses administrator; jalankan Homebrew dan ash install sebagai pengguna normal Anda.
  4. Model: server inferensi lokal dengan model yang diunduh atau akun cloud/kunci API. Pilih model yang mendukung pemanggilan alat, bukan model gambar/audio saja. Kebutuhan RAM, disk, dan GPU lokal bergantung pada model tersebut.

Paket ash bawaan tidak memerlukan alat pembuatan Go, Rust, Node.js, atau Xcode. Manajer paket mungkin memiliki prasyaratnya sendiri; ikuti petunjuk penyiapan resminya terlebih dahulu.

Debian dan Ubuntu: APT

Prasyarat: amd64 atau arm64, akses administrator, APT,curl,gpg, dan sertifikat CA. Instal alat unduhan/kunci yang hilang menggunakan distribusi Anda sebelum menambahkan repositori. Rilis diberi namastable:

sudo apt update
sudo apt install ca-certificates curl gnupg
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://www.versionx.ai/apt/gpg.key -o versionx-apt.asc
gpg --show-keys --with-fingerprint versionx-apt.asc
sudo gpg --dearmor --batch --yes -o /etc/apt/keyrings/versionx-keyring.gpg versionx-apt.asc
sudo chmod 0644 /etc/apt/keyrings/versionx-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/versionx-keyring.gpg] https://www.versionx.ai/apt stable main" |
  sudo tee /etc/apt/sources.list.d/versionx.list
sudo apt update
sudo apt install ash
rm versionx-apt.asc

Sebelum mengimpor kunci repositori apa pun, verifikasi sidik jarinya terhadap sumber penerbit tepercaya. Sidik jari kunci VersionX adalah32C6 C11D 2F86 BFE4 6EB7 7FFC 5257 FEA6 1368 919F. APT memeriksa metadata repositori yang ditandatangani dan intisari paket yang dikandungnya; kuncinya dicakup dengansigned-by. Perbarui dengansudo apt update && sudo apt upgrade ash; hapus dengansudo apt remove ash.

Sistem yang kompatibel dengan Fedora dan RHEL: DNF

Prasyarat: x86_64 atau aarch64, akses administrator, DNF/RPM,curl,gpg, dan sertifikat CA. Instal alat yang hilang dari distribusi Anda. Periksa kunci dan bandingkan sidik jari di atas sebelum mengimpornya:

curl -fsSL https://www.versionx.ai/rpm/gpg.key -o versionx-rpm.asc
gpg --show-keys --with-fingerprint versionx-rpm.asc
sudo rpm --import versionx-rpm.asc
sudo tee /etc/yum.repos.d/versionx.repo >/dev/null <<'EOF'
[versionx]
name=VersionX ash repository
baseurl=https://www.versionx.ai/rpm/
enabled=1
gpgcheck=0
repo_gpgcheck=1
gpgkey=https://www.versionx.ai/rpm/gpg.key
EOF
sudo dnf install ash
rm versionx-rpm.asc

File RPM tidak ditandatangani secara individual.repo_gpgcheck=1memverifikasi metadata repositori yang mencakup checksumnya;gpgcheck=0mencerminkan tidak adanya tanda tangan per paket, bukan verifikasi repositori yang dinonaktifkan. Jika kebijakan Anda memerlukan payload RPM yang ditandatangani, repositori ini tidak memenuhinya. Perbarui dengansudo dnf upgrade ash; hapus dengansudo dnf remove ash.

Lengkungan Linux: Pacman

Prasyarat: x86_64, akses administrator, Pacman dengan keyringnya diinisialisasi,curl, Dangpg. Verifikasi sidik jari kunci yang ditampilkan cocok dengan yang di atas sebelum mempercayainya. Tambahkan repositori satu kali, bukan pada setiap pembaruan:

curl -fsSL https://www.versionx.ai/pacman/gpg.key -o versionx-pacman.asc
gpg --show-keys --with-fingerprint versionx-pacman.asc
sudo pacman-key --add versionx-pacman.asc
sudo pacman-key --lsign-key 32C6C11D2F86BFE46EB77FFC5257FEA61368919F
sudo tee -a /etc/pacman.conf >/dev/null <<'EOF'
[versionx]
Server = https://www.versionx.ai/pacman/$arch
SigLevel = Required DatabaseRequired
EOF
sudo pacman -Syu ash
rm versionx-pacman.asc

Pacman memverifikasi tanda tangan paket dan database. Jaga agar Arch tetap tersinkronisasi dengansudo pacman -Syu, bukan peningkatan sebagian; menghapusashdengansudo pacman -R ash.

Inisialisasi dan verifikasi

Setelah memasang binari, jalankan penyiapan secara interaktif sebagai pengguna biasa. Jika Anda tidak ingin integrasi shell, Anda hanya dapat menginstal Ash. Ini mungkin bukan yang Anda inginkan. Nilai sebenarnya dari ash adalah integrasi shell di bawah ini. Penyiapan khusus aset membuat file startup Anda tidak berubah:

ash install

Instalasi yang mungkin ingin Anda gunakan melibatkan integrasi shell. Ini akan mengubah .bashrc Anda (atau setara dengan shell Anda) untuk menyertakan Ash. Untuk mengaktifkan integrasi command-not-found, pilih satu perintah untuk shell yang Anda gunakan:

Bash

ash install --shell bash --shell-integration

zsh

ash install --shell zsh --shell-integration

Ikan

ash install --shell fish --shell-integration

Bash menggunakan~/.bashrc, zsh menggunakan~/.zshrc, dan penggunaan Ikan$XDG_CONFIG_HOME/fish/config.fish(bawaan~/.config/fish/config.fish). Buka shell baru sesudahnya; shell yang ada mempertahankan broker yang sedang berjalan. Integrasi mendahului~/.local/binke PATH: hapus salinan lokal pengguna lama sebelum mengharapkan paket sistem dipilih.

Jika pengaturan penyedia tidak ada, pengaturan mendeteksi kunci penyedia yang ada atau server lokal yang sedang berjalan; jika tidak, ia menawarkan menu penyedia dan meminta kredensial. Pilih model berkemampuan alat yang tersedia. Pengaturan valid yang ada dipertahankan, jadi menjalankan kembali pengaturan bukanlah perintah peralihan penyedia.

Pengaturan disimpan di$XDG_CONFIG_HOME/ash/.ash_env(bawaan~/.config/ash/.ash_env, izin file pribadi). Integrasi terkelola memuatnya. Tanpa integrasi, pengguna Bash/zsh dapat mengambil file tersebut dalam konfigurasi startup normal mereka; Pengguna ikan harus mengatur yang sesuaiASH_AI_*variabel menggunakan sintaksis Fish, bukan sumber file format Bash. Lindungi file apa pun yang berisi token dan jangan pernah mengkomitnya.

Untuk instalasi pengguna lokal tanpa integrasi, tambahkan direktori sebenarnya ke PATH. pesta/zsh:export PATH="$HOME/.local/bin:$PATH". Ikan:fish_add_path "$HOME/.local/bin". Pertahankan ini menggunakan konfigurasi startup shell Anda; gantikan direktori instalasi khusus Anda bila memungkinkan.

command -v ash
command -v ash-broker
ash version
ash "Say hello in one sentence"

Perintah pertama harus sesuai dengan instalasi yang Anda pilih. Prompt memerlukan server yang berjalan atau kredensial cloud yang valid; menginstal ash tidak menginstal model.

Ollama Lokal: tidak diperlukan akun cloud

Anda tidak perlu memiliki AI lokal untuk menggunakannyaash. Namun, jika Anda ingin menjalankan model secara lokal tanpa bergantung pada penyedia cloud, Anda dapat menyiapkan server Ollama lokal.

Ollama juga menawarkan layanan cloud untuk menjalankan model dari jarak jauh, tetapi itu tidak diperlukan untuk penggunaan lokalash. Server cloud mencakup tingkat gratis dan model cloud Gemma 4 31b Google (gemma4-31b:awan) bekerja sangat baik denganash. Ini adalah model yang digunakan oleh proyek untuk menghasilkan catatan rilis dan melakukan tugas devops.

Instal Ollama menggunakaninstruksi OS resmi. Mulai aplikasi/layanan Ollama, atau jalankanollama servedi terminal terpisah jika server belum berjalan. Di FreeBSD,ashDukungan tidak berarti penginstal Ollama asli: gunakan server yang dapat dijangkau pada host lain yang didukung jika diperlukan.

Unduh model berkemampuan alat yang sesuai dengan perangkat keras Anda;llama3.1:8badalah contoh, bukan persyaratan minimum. Periksakatalog alat terkiniuntuk alternatif:

ollama pull llama3.1:8b
ollama list
curl -fsS http://localhost:11434/api/tags
ash install

Jika kunci cloud belum disetel, penyiapan dapat mendeteksi server lokal dan menawarkan model yang diunduh. Jika penyedia lain sudah dikonfigurasi, ubah titik akhir/model secara manual. Contoh Bash/zsh:

export ASH_AI_ENDPOINT="http://localhost:11434"
export ASH_AI_MODEL="llama3.1:8b"
unset ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Setara dengan ikan:

set -gx ASH_AI_ENDPOINT http://localhost:11434
set -gx ASH_AI_MODEL llama3.1:8b
set -e ASH_AI_AUTH_TOKEN
ash "Say hello in one sentence"

Perubahan ini hanya mempengaruhi shell saat ini. Pertahankan mereka dalam perlindungan Andaashfile lingkungan atau konfigurasi shell yang sesuai, menggantikan penggantian penyedia lama. Ollama lokal tidak memerlukan token. Pertahankan server dalam keadaan loopback kecuali Anda dengan sengaja mengamankan akses; server jarak jauh menerima perintah dan keluaran alat Anda.

Opsional: aturOLLAMA_KEEP_ALIVE=30mdiServer Ollamalingkungan dan mulai ulang server untuk menjaga model tetap hangat.-1membuatnya tetap dimuat tanpa batas waktu tetapi menghabiskan memori di antara permintaan. Pengaturan ini hanya diashterminal klien tidak mengkonfigurasi ulang server yang sudah berjalan.

Inferensi lokal tidak memiliki tagihan API penyedia, tetapi menggunakan perangkat keras/penyimpanan/listrik Anda.Awan Ollamaadalah layanan terpisah dengan batas otentikasi dan paket; ini tidak sama dengan pengaturan lokal ini.

Pemasangan skrip: alternatif, bukan pilihan pertama

Lebih memilih Homebrew, APT, DNF, atau Pacman: mereka melacak file yang dimiliki, memverifikasi unduhan menggunakan konfigurasi kepercayaannya, dan memberikan pembaruan/penghapusan yang sudah dikenal. Hal ini tetap memerlukan penerbit yang dapat dipercaya dan tindakan pemasangan paket.

Skrip situs web menjalankan kode dengan izin akun Anda. Situs web yang disusupi, penerbit, atau skrip yang diubah dapat membaca rahasia, mengubah file, atau memasang perangkat lunak lain. HTTPS melindungi transportasi, bukan maksud dari kode itu. Mengirimkan URL langsung ke shell akan mengeksekusinya sebelum Anda dapat meninjaunya. Pemeriksaan tanda tangan arsip skrip tidak mengautentikasi skrip itu sendiri. Jangan pernah menjalankannya dengan sudo atau menonaktifkan verifikasinya.

Prasyarat: OS/arsitektur yang didukung,$SHELLmengidentifikasi Bash/zsh/Fish,tanda tangan toko tanda tangan,tar,uname,install, utilitas shell standar, perintah SHA-256 (sha256sum,shasum, atausha256), dan pengunduh (curl,wget, atau Piton). Contohnya menggunakan curl. FreeBSD juga membutuhkan Bash. Direktori home/instalasi Anda harus dapat ditulis.

Unduh ke file lokal, periksa dengan editor, dan jalankan hanya jika Anda memercayai sumber dan perilakunya. Inspeksi bukanlah jaminan keselamatan; jangan menjalankan langkah-langkah ini secara membabi buta:

curl -fsSL https://jonconradt.github.io/ash/install.sh -o ash-install.sh
less ash-install.sh

Setelah pemeriksaan, jalankan salinan yang disimpan sebagai pengguna biasa:

sh ./ash-install.sh
rm ./ash-install.sh

install.shmengunduh Rilis terbaru, memverifikasi manifes checksum dan intisari arsip yang ditandatangani Sigstore, dan memasangash/ash-brokerdi dalam~/.local/bin. Plugin asli berada di bawah$XDG_DATA_HOME/ash/plugins. Ini menjalankan pengaturan per pengguna dan bertanya sebelum mengaktifkan integrasi shell. Tanpa terminal interaktif, perintah penyedia/integrasi mungkin dilewati: jalankanash installsecara interaktif setelahnya.

Anda dapat mengaturASH_INSTALL_DIRsebelum menjalankan skrip untuk memilih tujuan lain. Tambahkan sendiri tujuan itu ke PATH.Pembaruan mandiri hanya didukung di bawah~/.local/bin; tujuan khusus memerlukan penggantian manual. Skrip tidak memiliki pemilih Beta/Malam.

Verifikasi paket atau arsip langsung

Prasyarat: cosign dan utilitas SHA-256. Dari rilis terbitan yang sama, unduh paket/arsip Anda,SHA256SUMS, DanSHA256SUMS.sigstore.json. Bekerja di direktori baru. MenggantivX.Y.Zdengan tag persisnya, termasuk akhiran prarilis jika ada:

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Jonconradt/ash/.github/workflows/release.yml@refs/tags/vX.Y.Z" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"

Baru setelah itu berhasil, hitung intisari file Anda denganshasum -a 256 PACKAGEdi macOS,sha256sum PACKAGEdi Linux, atausha256 -q PACKAGEdi FreeBSD. MenggantiPACKAGEdengan nama file yang diunduh dan bandingkan persis dengan entri nama file tersebut di manifes terverifikasi. Berhenti pada entri yang hilang atau ketidakcocokan apa pun. Checksum tak bertanda tangan yang diunduh di samping file tidak setara dengan metadata penerbit terverifikasi.

Pembaruan dan tiga saluran

  • Rilis (disarankan):versi terbitan stabil sepertivX.Y.Z; konfigurasi repositori memanggil inistable.
  • Beta:pengujian prarilis, diberi tagvX.Y.Z-beta.N; mengharapkan perubahan dan kemunduran.
  • Malam:perubahan cabang default terkini, diberi tagvX.Y.Z-nightly.YYYYMMDD.N; risiko regresi tertinggi. Pembuatan dijadwalkan tetapi dapat dilewati jika tidak ada perubahan atau penerbitan gagal.

Rilis yang diterbitkan memperbarui formula Homebrew yang sesuai atau repositori Linux yang ditandatangani. Anda menerimanya ketika Anda menjalankan perintah pemutakhiran manajer pemilik (atau kebijakan pembaruan OS Anda sendiri yang menjalankannya). Publikasi, pembaruan repositori, dan penerapan situs web dapat berjalan lambat satu sama lain; periksa ketersediaan sebelum mengganti saluran. ash tidak menginstal pembaruan biner latar belakang secara diam-diam.

Homebrew: menginstal atau mengganti formula

Untuk instalasi Beta/Nightly baru, gunakan nama formula lengkap yang sesuai di atas di brew install. Saat beralih, hapus dulu formula yang saat ini diinstal: ketiganya menyediakan binari yang sama. Contoh, Rilis ke Beta:

brew uninstall ash
brew install Jonconradt/ash/ash-beta
brew update
brew upgrade ash-beta

Menggunakanash-nightlyuntuk Nightly atauashuntuk Rilis dalam perintah instal/peningkatan. Copot pemasangan formula saluran lama yang sebenarnya, tidak selaluash. Pengaturan pengguna dipertahankan; buka shell baru setelah beralih.

Linux: pilih satu saluran repositori

TEPAT:gunakanpengaturan APTdengan tepat satu distribusi dari tabel. Untuk mengganti instalasi yang sudah ada, edit/etc/apt/sources.list.d/versionx.list, menggantikanstabledenganbetaataunightly(atau kembali kestable), Kemudian:

sudo apt update
sudo apt install --allow-downgrades ash

DNF:gunakanpengaturan DNFdengan baseurl yang dipilih. Untuk instalasi yang sudah ada, gantibaseurldi dalam/etc/yum.repos.d/versionx.repo, mempertahankan pengaturan tanda tangannya, lalu:

sudo dnf --refresh distro-sync ash

Pacman:gunakanPengaturan Pacmandengan URL Server yang dipilih. Simpan nama bagiannya[versionx]: setiap saluran menerbitkan database bernamaversionx.db. Ubah Server di satu bagian itu daripada menambahkan database dengan nama berbeda. Untuk beralih, termasuk downgrade:

sudo pacman -Syuu ash

Tinjau transaksi yang diusulkan: kembali ke Rilis dapat menurunkan versi ash, dan dobel Pacman u dapat menurunkan versi paket lainnya juga. Cadangkan konfigurasi sebelum beralih. Setelah itu gunakan perintah pemutakhiran APT/DNF/Pacman normal dari bagian OS; jangan biarkan beberapa sumber saluran ash aktif.

Copot pemasangan tanpa menghapus file yang tidak terkait

1. Nonaktifkan integrasi shell terlebih dahulu

Sebelum menghapus biner, jalankan perintah untuk setiap shell tempat Anda mengaktifkan integrasi:

Bash

ash install --shell bash --disable-shell-integration

zsh

ash install --shell zsh --disable-shell-integration

Ikan

ash install --shell fish --disable-shell-integration

Jikaashsudah hilang, edit file startup yang relevan dariinisialisasidan hapus hanya blok di antaranya# >>> ash install >>>Dan# <<< ash install <<<. Hapus apa punash-baris PATH/lingkungan khusus yang Anda tambahkan secara manual, bukan konfigurasi shell yang tidak terkait. Menutupash-mengaktifkan shell setelahnya sehingga broker milik shell mereka keluar.

2. Biarkan manajer paket pemilik menghapus filenya

Minuman Rumahan (Rilis)

brew uninstall ash

APT

sudo apt remove ash

DNF

sudo dnf remove ash

Pacman

sudo pacman -R ash

Pilih hanya metode instalasi Anda; untuk Homebrew Beta/penggunaan malam hariash-beta/ash-nightly. APT/DNF/Pacman menghapus binari, plugin, dan halaman manual milik paket, bukan konfigurasi/riwayat direktori home Anda. Jangan menghapus file milik paket secara manual.

Pembersihan repositori opsional: hapusashberkas sumber/etc/apt/sources.list.d/versionx.listdan berdedikasi/etc/apt/keyrings/versionx-keyring.gpg, atau ituashberkas repositori/etc/yum.repos.d/versionx.repo, atau ituash [versionx]bagian dari/etc/pacman.conf. Pertama periksa apakah tidak ada paket lain yang menggunakannya. Hapus kunci kepercayaan RPM/Pacman yang diimpor hanya setelah mengonfirmasi sidik jarinya dan tidak ada orang lain yang bergantung padanya; jangan pernah menghapus keyring bersama suatu distribusi.

3a. Penghapusan macOS .pkg secara manual

Penginstal macOS mencatat tanda terima tetapi tidak memilikinyaashuninstaller. Konfirmasikan bahwa ini adalah instalasi .pkg, bukan Homebrew, dan periksa muatan sebenarnya:

pkgutil --pkg-info dev.ash.cli
pkgutil --files dev.ash.cli

Dengan menggunakan tanda terima itu sebagai inventaris, hapus hanya tanda terimanyaashfile milik:/usr/local/bin/ash,/usr/local/bin/ash-broker, file di/usr/local/lib/ash/plugins,/usr/local/share/man/man1/ash.1, yang terdaftar dilokalkanash.1halaman, dan pemberitahuan di/usr/local/share/licenses/ash. Hak istimewa administrator diperlukan. Periksa kepemilikan apakah penginstal lain kemudian mengganti file-file ini; jangan hapus salinannya. Hapus kosongash-hanya direktori, tidak dibagikan/usr/local,bin, atau direktori man.

Setelah menghapus payload, hapus tanda terima secara opsional:

sudo pkgutil --forget dev.ash.cli

Melupakan tanda terima tidak akan menghapus file apa pun yang diinstal.Pertahankan sampai Anda selesai memeriksa muatannya.

3b. Penghapusan arsip pengguna-lokal / Linux / FreeBSD secara manual

Temukan salinan aktif dengancommand -v ashDancommand -v ash-broker. Untuk instalasi skrip default, setelah menonaktifkan kait, hapus dua file spesifik tersebut:

rm "$HOME/.local/bin/ash" "$HOME/.local/bin/ash-broker"

UntukASH_INSTALL_DIRatau arsip yang diekstraksi secara manual, hapus hanya arsip yang diinstal sebenarnyaash/jalur perantara. Hapus plugin arsip/halaman manual/pemberitahuan yang Anda instal menggunakan inventaris file asli Anda; plugin skrip ada diashdirektori data pengguna. Jika file berada di bawah/usr/bin, periksa kepemilikannya terlebih dahulu dengandpkg -S /usr/bin/ash,rpm -qf /usr/bin/ash, ataupacman -Qo /usr/bin/ashsebagaimana mestinya. Salinan milik paket harus dihapus melalui pengelola tersebut, meskipun diinstal dari unduhan mandiri.

4. Opsional: hapus pengaturan lokal, alat, dan riwayat

Cadangkan apa pun yang ingin Anda simpan. Langkah terpisah ini dapat menghapus setelan/token penyedia, alat/plugin khusus, riwayat percakapan, dan file awal. Mencopot pemasangan biner tidak berarti menyetujui penghapusannya.

  • Konfigurasi:$XDG_CONFIG_HOME/ash, bawaan~/.config/ash.
  • Data, plugin, dan lingkungan Python:$XDG_DATA_HOME/ash, bawaan~/.local/share/ash.
  • Sejarah dan negara:$XDG_STATE_HOME/ash, bawaan~/.local/state/ash.
  • Cache:$XDG_CACHE_HOME/ash, bawaan~/.cache/ash.
  • Waktu kerja broker:$XDG_RUNTIME_DIR/ash, atau$XDG_STATE_HOME/ash/runtimeketika tidak ada root runtime yang tersedia.

Periksa penggantian XDG absolut Anda yang sebenarnya sebelum menghapus hanya subdirektori ash ini; jangan pernah menghapus root XDG atau direktori home Anda. Setelah semua shell yang mendukung ash ditutup, hapus file runtime ash yang tersisa jika diperlukan. Kredensial OAuth MCP juga mungkin tetap ada di pengelola kredensial OS: hapus entri khusus ash di sana dan cabut akses di penyedia MCP. Cabut kunci AI yang tidak digunakan di akun penyedia mereka; menghapus file lokal tidak mencabut kunci. Jangan mencopot pemasangan Ollama/models, Python, atau dependensi bersama sebagai bagian dari penghapusan ash.

Pemecahan masalah cepat

Perintah tidak ditemukan atau versi salah
Periksa PATH dancommand -v ash/command -v ash-broker. Sebuah tua~/.local/bincopy dapat membayangi sebuah paket. Gunakan satu pemilik/saluran pada satu waktu dan buka shell baru.
Menu penyedia tidak muncul
Berlariash installdari terminal interaktif. Pengaturan valid yang ada dipertahankan; menggunakankonfigurasi manualuntuk berpindah penyedia. Tanpa integrasi, pastikan pengaturan diekspor ke lingkungan CLI.
Tidak ada model atau koneksi yang ditolak
Untuk Ollama, konfirmasikan servernya sedang berjalan danollama listtermasuk model pilihan Anda. Untuk layanan cloud, periksa titik akhir, kelayakan model, HTTPS, token, dan kuota akun; jangan pernah membagikan log yang mengandung token.
Repositori atau saluran tidak tersedia
Periksa arsitektur dan rilis/repositori yang diterbitkan. Publikasi bisa tertunda; jangan nonaktifkan verifikasi tanda tangan untuk mengatasi repositori yang tidak tersedia.
Penyiapan alat Python gagal
Instal Python dengan venv/ensurepip dan izinkan pengunduhan ketergantungan, lalu jalankan kembaliash install. Dasarashtetap dapat digunakan tanpa alat ini.
